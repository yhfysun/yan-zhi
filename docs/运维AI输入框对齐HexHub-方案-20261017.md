# 运维台 AI 输入框对齐 HexHub —— 实施方案（2026-10-17）

> 用户诉求：「这个 AI 模式输入框参考下 HexHub？可以切模型、命令授权范围？执行指令？AI 任务？这些？」
> 结论：**能做，但要拆成四块分开落地**；其中「静默权限」与现有安全设计正面冲突，必须先定策略。

---

## 0. 一页纸结论

| 能力 | 优先级 | 工作量 | 风险 |
|---|---|---|---|
| 输入框工具条 + **会话内模型切换** | P0 | 中（前后端各一处） | 低 |
| **静默权限三档**（命令 / 改文件 / 读文件） | P0 | 中 | **高（拆安全闸门）** |
| **执行指令**（把输入直接发终端，不过 LLM） | P1 | 小 | 低 |
| **后台执行 / AI 任务** | P2 | 大 | 中（复用现有 job） |

**不照搬的**：HexHub 的「第三方供应商（非官方渠道）」标注 —— 我们用自己配置的平台/模型，没有官方/非官方之分，搬过来只会添乱。

## 2. P0-1：输入框工具条 + 会话内模型切换

### 2.1 UI 结构

```
┌──────────────────────────────────────────────────────────────┐
│ [textarea]  输入运维任务，Ctrl+Enter 发送                      │
├──────────────────────────────────────────────────────────────┤
│ [执行] [Agent]   │  deepseek-flash ▾  │  [权限 ⚙]  [发送]     │
└──────────────────────────────────────────────────────────────┘
      └ 左：动作语义（执行=P1，Agent=P0 默认）  └ 右：模型/权限/发送
```

- 「执行」按钮先占位但**禁用**，等 P1 实现；避免做完 P0 再改一次布局。
- 模型下拉：静态列出 `platformStore.models`（已有），不带"官方/非官方"分组。
- 模型不可用（被删/未授权）时回落默认并提示一次，不静默。

### 2.2 数据

- `OpsWin` 新增 `modelId?: string` —— **会话级**，不落库（窗口本来就是会话态，见 `opsSession.ts` 注释）。
- 空 = 用设置里的默认模型（保持现有行为，零迁移）。

### 2.3 后端

- 对话请求接受可选 `modelId`；**必须校验**（属于已配置平台且可用），非法值 → 400。
  不要静默回落 —— 那会让用户以为切成功了。
- 缺省行为完全不变。

### 2.4 验收

- [ ] 切模型后，下一条消息用的就是新模型（后端日志可证）。
- [ ] 模型被删后发消息：明确提示，不吞异常。
- [ ] 不切模型时行为与现在一致（回归）。

## 3. P0-2：静默权限三档（**风险最高，需先拍板**）

### 3.1 三档定义

| 档位 | 含义 | 放行的操作 |
|---|---|---|
| 静默读取文件 | 读类不再逐条问 | 读文件 / 列目录 / 查状态 |
| 静默修改文件 | 写类不再逐条问 | 上传、覆盖、改名、删除 |
| 静默执行命令 | **直接放行 shell 命令** | 终端命令（仍受危险命令黑名单约束） |

### 3.2 两个必须先定的问题

1. **粒度**：按**连接**存（推荐）—— 同一个人对生产和对测试机的容忍度显然不同；
   全局存会让"图方便全开"变成一次影响所有机器的事故。
2. **生产连接允不允许开「静默执行命令」**：建议**允许但默认关 + 红字警告**，
   而不是直接禁止 —— 否则总有人改代码绕过，比给个带警告的开关更糟。

### 3.3 存储

- 复用连接记录（`connections`），加可选字段：`silent?: { exec?: boolean; write?: boolean; read?: boolean }`。
- 不新增表、不需要迁移（老记录没有该字段 = 全关）。
- 默认值：**全关**。

### 3.4 判定点

- 插在现有"生产连接写操作 → 待批准"判定**之前**：静默命中就不登记审批，未命中走原逻辑。
- 危险命令黑名单**始终优先**：静默不放行黑名单命中项。
- 建议抽成纯函数 `resolveSilent(conn, action) → 'silent' | 'approve'`，单测直接钉矩阵。

### 3.5 审计（**不可选**）

- 静默放行的每一条审计都要带标记（`detail` 里 `[静默放行:exec]`，或新增 `via: 'silent'`）。
- 理由：事后翻日志必须能区分"人批的"和"静默放行的"，否则合规上说不清。

### 3.6 验收

- [ ] 三档各自独立生效，互不影响。
- [ ] 生产连接默认全关；开启时有明显警告。
- [ ] 静默放行的操作在审计里可检索、可区分。
- [ ] 黑名单命中项即使开了静默命令也仍然被拦。

## 4. P1：执行指令（把输入直接发终端）

- 触发：输入以 `/` 开头，或点「执行」。
- 行为：内容直接写当前 xterm，**不经过 LLM**。
- 仍受：危险命令黑名单 + 生产审批（与手工在终端里敲同一口径）。
- 验收：`/ls -la` 直接出现在终端；`/rm -rf /` 被拦并有提示。

---

## 5. P2：后台执行 / AI 任务（单独一轮，别和输入框混做）

- 复用 `SftpJob` 那套：新增 `kind: 'agent'`，进度走同一套 SSE，完成后照样落库到任务历史。
- 输入框的「后台执行」只是"以 agent job 方式提交"，不在 P0 实现。
- 验收：提交后关掉面板，仍能在任务中心看到进度与结果。

---

## 6. 任务拆分（建议按此顺序提交）

1. **P0-1a** 后端：对话接口接受并校验 `modelId`（+ 单测）
2. **P0-1b** 前端：输入框工具条 + 模型下拉 + `OpsWin.modelId`（+ 契约测试）
3. **P0-2a** 后端：`silent` 字段 + 判定 + 审计标注（+ 单测：三档 × 黑名单 × 生产/非生产）
4. **P0-2b** 前端：权限浮层（三开关）+ 生产连接警告（+ 契约测试）
5. **P1** 执行指令
6. **P2** 后台执行 / AI 任务

每步跑：`apps/server` 的 `test/ops-*`、`packages/ui` 的 `src/views/plugin`；
改到类型定义时补 `tsc` / `vue-tsc`。

## 8. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 静默权限被当成"关掉安全" | 默认全关 + 按连接 + 红字警告 + 审计必标 |
| 切模型后上下文/计费口径混乱 | 只改 `modelId`，不动会话结构与压缩阈值 |
| 工具条挤占高度 | 做成 32px 单行；窄屏时模型下拉收成图标 |
| P1/P2 与 P0 抢同一处模板 | 先按 2.1 的骨架留位（「执行」按钮禁用占位） |
