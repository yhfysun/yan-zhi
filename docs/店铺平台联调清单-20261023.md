# 店铺平台真实凭据联调清单（2026-10-23）

> 没有真实凭据时，所有平台客户端只做 mock 测试：验证签名/请求形状/错误分步，
> **不得对外宣称“已连通 / 已同步”**。真实联调按本文逐项核对，每项通过后再把
> 对应能力视为可用。

## 0. 通用纪律

1. 凭据只填在连接弹窗（加密存 `secretEnc`），不要贴到对话、日志、截图里。
2. 先点「自检」（`shop_api_check` / 连接弹窗的 API 自检），确认卡在哪一步：
   凭据 / 网络 / 鉴权 / 限流 / 接口。
3. 写操作先在测试店铺跑，再切生产；生产店铺每次都要额外批准，且禁止批量。
4. 平台返回 2xx 但空 body / HTML（登录页/WAF）一律按失败处理（客户端已内置）。
5. 写后回读：客户端支持回读的动作会返回 `readback`；不支持的会明确写“平台未提供回读”。

## 1. 亚马逊 SP-API

| 项 | 要求 |
|---|---|
| 凭据 | LWA `clientId` / `clientSecret`、`refreshToken`；IAM `awsAccessKeyId` / `awsSecretAccessKey`（可选 `awsSessionToken`） |
| 权限 | 应用角色至少 Product Listing（读写）、Orders（读/写）；具体以开发者中心勾选为准 |
| Marketplace | 默认站点 ID，如美国 `ATVPDKIKX0DER` |
| Seller ID | Listings 接口路径必填 |
| IP 白名单 | SP-API 不要求调用方 IP 白名单（IAM 凭据泄露需立即轮换） |
| 资质 | 卖家账号 + 开发者应用审核 |
| 限流 | 按接口分档；429 会报“触发限流”，客户端对只读请求最多重试 2 次 |
| 已知边界 | 全量商品用 `searchListingsItems`（返回卖家 SKU，pageToken 翻页，最多 1000 条）；关键词/ASIN 搜索走 Catalog（返回 ASIN，价格未知，不能直接推送）。价格未知时拒绝推送，避免把平台价改成 0 |

## 2. 淘宝 / 天猫 TOP

| 项 | 要求 |
|---|---|
| 凭据 | App Key / App Secret / 卖家授权 session（`top` session） |
| 权限包 | 商品管理、交易、物流等 API 需在开放平台申请对应权限 |
| 网关 | 正式 `https://eco.taobao.com/router/rest`；沙箱 `http://gw.api.tbsandbox.com/router/rest`（白名单固定） |
| IP 白名单 | 生产应用通常需要配置调用方 IP；以开放平台应用设置为准 |
| 资质 | 企业开发者认证 + 应用审核 |
| 限流 | 按应用/接口 QPS；错误码含 “App Call Limited” 会报限流 |
| 回读 | 商品写后读 `taobao.item.get` |

## 3. 拼多多

| 项 | 要求 |
|---|---|
| 凭据 | `clientId` / `clientSecret` / 商家授权 `accessToken` |
| 权限包 | 商品、订单、物流接口需在开放平台申请 |
| 环境 | **无沙箱**，联调即正式调用；建议先用测试店铺/小额商品 |
| IP 白名单 | 以开放平台应用设置为准 |
| 资质 | 企业开发者认证 + 应用审核 |
| 限流 | 错误码 70031 / 52101 → 限流；价格字段单位是**分** |
| 订单限制 | 只能查 3 个月内成交订单，`start_confirm_at`/`end_confirm_at` 区间 ≤24h |
| 回读 | 商品写后读 `pdd.goods.detail.get` |

## 5. TikTok Shop

| 项 | 要求 |
|---|---|
| 凭据 | `appKey` / `appSecret` / `accessToken` / `shopCipher` |
| 权限包 | Partner Center 应用审核，按店铺授权 scope |
| 环境 | 生产 `open-api.tiktokglobalshop.com`；沙箱 `open-api-sandbox.tiktokglobalshop.com`（白名单固定） |

## 6. Shopify

| 项 | 要求 |
|---|---|
| 凭据 | `shopDomain`（必须是 `*.myshopify.com`）+ 私有 App `accessToken` |
| 权限 | 读取 `read_products` / `read_orders`；写商品加 `write_products`；发货需要 `write_fulfillments`（或 `write_shipping`） |
| IP 白名单 | 不要求 |
| 资质 | 无需企业审核，店铺后台创建私有 App 即可 |
| 限流 | 按店铺漏桶，429 会报限流 |
| 分页 | REST `Link: rel="next"` 游标已支持（商品/订单各最多 5 页） |
| 发货 | 必须走 fulfillment：订单 → fulfillment_orders → 创建 fulfillment → 回读 |
| SSRF | 域名只接受 `*.myshopify.com`；不跟随重定向 |

## 7. 万邑通（WINIT）

| 项 | 要求 |
|---|---|
| 凭据 | `appKey`（卖家账号）、`token`（授权，有效期约 18 个月）、`platform`（应用 Code）、`clientId`、`clientSecret` |
| 签名 | 双 MD5：`md5(token + sorted(k+v) + token)` 与 `md5(clientSecret + sorted(k+v) + clientSecret)`，大写 |
| 环境 | 生产 `openapi.winit.com.cn`；沙箱 `sandboxopenapi.winit.com.cn`（白名单固定） |
| 资质 | 万邑通客户账号 + 应用授权 |
| 限流 | 按接口；错误码 030… 会如实透出 |
| 出库单 | 必填仓库编码、收件人（姓名/电话/国家/城市/地址/邮编）、`productList[{productCode,qty}]`；字段名以万邑通 API 字典为准 |
| 回读 | 出库后按 `trackingNo` 查 `queryOutboundOrderList` |

## 8. 京东物流

| 项 | 要求 |
|---|---|
| 凭据 | 宙斯 App Key / App Secret / 应用授权 `accessToken` / 商家编码 `customerCode` |
| 网关 | `https://api.jd.com/routerjson`（固定） |
| 签名 | `MD5(appSecret + sorted(k+v) + appSecret)` 大写（与 TOP 同构） |
| 轨迹方法 | `jingdong.ldop.receive.trace.get`，业务参数放 `360buy_param_json` |
| 资质 | 企业开发者认证 + 应用授权 |
| 限流 | 按接口；token 过期返回 error_response（常见 code 19） |
| 已知未联调 | 方法名/参数按公开资料实现；真实账号跑通前不要把状态标成“已连通” |

## 9. 菜鸟速递

| 项 | 要求 |
|---|---|
| 凭据 | `logistic_provider_id`（对接码）+ `secretKey` |
| 签名 | `data_digest = Base64(MD5(logistics_interface + secretKey))` |
| 网关 | 测试 `edi-daily.xpm.cainiao.com`；生产地址由菜鸟提供（只接受 `*.cainiao.com`） |
| 资质 | 菜鸟速递开放平台对接，测试账号/密钥线下提供 |
| 限流 | 轨迹接口用于查询，不要高频轮询；限流会如实报 |
| 已知未联调 | 生产网关地址需向菜鸟确认；body 仅 `{mailNo}` |

## 10. 4PX 递四方

| 项 | 要求 |
|---|---|
| 凭据 | App Key / App Secret / OAuth `accessToken` |
| 签名 | `MD5(sorted(k+v，不含 access_token/language) + body 紧凑 JSON + appSecret)` 32 位小写 |
| 网关 | 生产 `https://open.4px.com/router/api/service`；沙箱 `https://open.sandbox.4px.com/router/api/service` |
| 资质 | 客户账号开通 + APP 审核 |
| 限流 | 按接口；result=0/2 会如实区分失败/部分成功 |
| 轨迹方法 | `tr.order.tracking.get`；body 使用 `{trackingNo}`，联调时按 4PX 控制台字段核对 |
| 已知未联调 | 方法/字段按公开资料实现；沙箱跑通后再切生产 |

## 11. 下单接口差异（本期未实现，原因如实说明）

三家物流的**下单接口与轨迹接口不是同一套网关/凭据**，没有账号文档时硬接会猜字段：

| 服务商 | 下单接口 | 与现有轨迹客户端的关系 |
|---|---|---|
| 京东 | JDL LOP `open.jdl.com` 的 `/ecap/v1/orders/create`（appKey/appSecret/accessToken + 商品/收件人数组） | 轨迹走宙斯 `api.jd.com/routerjson`，两套鉴权不通用 |
| 菜鸟 | 菜鸟国际 `link.cainiao.com/gateway/link.do` 的 `cnge.order.create`（AppKey/appSecret/资源 Code） | 轨迹走菜鸟速递 EDI 网关（logistic_provider_id + data_digest） |
| 4PX | 同一网关 `ds.xms.order.create`（签名相同） | 字段（ref_no/收件人/包裹明细/渠道）需按控制台文档填 |

接入顺序建议：先拿到真实账号与对应接口文档 → 在 `LogisticsClient` 上增加可选 `createOrder` → 用沙箱跑通 → 再开放 UI/AI 调用；下单是资金/履约动作，必须走生产批准闸门。

## 12. 联调验收记录模板

每个平台跑完一轮后记录：

```
平台：
环境：sandbox / production
自检：通过 / 失败（步骤：creds/network/auth/rate/api）
只读：商品列表 / 订单列表（条数）
写：改价 / 改库存 / 发货 / 出库单（成功 or 失败码）
回读：成功值 / 平台未提供
审计：操作日志是否有 approved + executed + 回读结果
遗留：字段差异 / 权限缺失 / 限流阈值
```
