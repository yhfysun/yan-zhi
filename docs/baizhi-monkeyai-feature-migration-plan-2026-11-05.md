# 百智办公（MonkeyAI）功能迁移方案

> 日期：2026-11-05  
> 状态：核心能力已实现（2026-11-07）  
> 原则：迁移产品能力和交互，不依赖百智办公服务、运行时不调用它的 API，也不复制它的代码。所有能力用言智现有技术栈重新实现。

## 0. 实施状态

本轮已经把核心迁移能力落到言智自身代码：

- 企业工作台管理页与成员团队页。
- 团队规则、专家 Manifest、资源版本。
- 组织/用户周期额度、额度账户、消费流水和模型调用额度闸。
- 全局管理审计。
- 集中式 MCP Provider/Connector、共享凭证加密、工具发现、工具策略、调用日志和模型工具。
- 工作节点 Agent、节点注册/心跳、远程命令任务、事件回传、产物登记。
- 云工作区记录、创建/停止任务、TTL 巡检。
- 设计资源库与设计助手提示词注入。
- 团队资源、MCP、节点、任务的模型工具入口。

运行入口：

- 管理端：`/admin/enterprise`
- 成员端：`/team`
- 工作节点：`pnpm --filter @yan-zhi/server enterprise:node`

仍属于部署/商业版配置、不在本轮代码内的项目：

- 企业 OIDC/SSO 的具体身份提供商接入与登录页适配。
- PostgreSQL 多实例适配。
- Windows 云电脑/虚拟机编排。

## 1. 最终结论

言智已经有相当完整的个人智能体产品能力，不需要为了“像百智办公”重做聊天、办公、代码、设计、Skill、MCP 和知识库。真正应该迁移的是它的**企业工作台层**：

1. 团队资源中心：模型、Skill、专家、规则、MCP 连接统一管理、授权和版本分发。
2. 企业治理：用户组、角色、资源 ACL、额度、计费、统计、审计、SSO。
3. 集中式 MCP：服务端持有共享凭证，用户只拿可用工具，不接触上游密钥。
4. 远程执行：设备/工作节点注册，服务端下发任务，回流终端、文件、审批和产物。
5. 云工作区：在远程节点上创建隔离工作区，支持镜像、生命周期、端口预览和资源回收。

言智已有能力继续保留并作为底座，不重复建设：

- 用户、组织树、角色、权限、资源 ACL。
- 模型平台、模型、Skill、智能体、工具、插件的共享和授权。
- MCP 客户端、MCP 凭证保险库、Streamable HTTP/SSE/stdio。
- 费用账本、会话级费用、用户额度字段。
- 本地任务、任务事件、文件、浏览器、办公文档、代码工作台。
- 远程控制、节点互联、插件系统和三端 UI。

目标不是复制一套 MonkeyAI，而是把上述缺口补成言智自己的“团队版能力”。

## 2. 当前能力盘点

### 2.1 言智已经具备

| 能力 | 现有实现 | 处理方式 |
| --- | --- | --- |
| 多用户 | `YZ_AUTH_MODE=multi`、JWT 登录、自助注册关闭 | 直接复用 |
| 组织树 | `org.parent_id`、用户-组织关系 | 直接复用，补资源统计 |
| 角色与权限 | 角色树、权限树、角色继承、组织角色继承 | 直接复用 |
| 资源 ACL | `resource_acl`，支持用户主体和角色主体 | 直接复用，扩展到规则/MCP/节点 |
| 共享资源 | 模型、平台、Skill、智能体、工具、插件支持公开和 ACL | 直接复用，统一入口 |
| 智能体 | harness、workflow、系统提示词、工具、Skill、子智能体 | 复用为“专家”基础 |
| 模型代理 | OpenAI/Anthropic 兼容、Token 池、重试、熔断 | 直接复用 |
| MCP | 客户端连接、凭证加密、工具发现、工具启停 | 扩展为集中式连接 |
| 费用账本 | `usage_event`、`conversation_usage`、单价快照、人民币成本 | 复用并升级为周期额度 |
| 任务 | `llm_task` 持久化、流式事件、暂停/恢复/中止 | 复用并增加远程执行目标 |
| 远程控制 | 配对、白名单、WebRTC、输入注入、审计 | 复用安全模型，不复用“看屏幕”语义 |
| 节点互联 | `chat_peer`、节点注册、心跳、消息 | 可复用注册/心跳经验 |
| 插件系统 | 工具、路由、侧栏、设置页、后端路由 | 用于扩展，不把核心能力做在插件里 |

### 2.2 真正缺少的能力

| 缺口 | 当前状态 | 迁移目标 |
| --- | --- | --- |
| 团队资源中心 | 资源分散在模型、Skill、智能体、工具、MCP 各自页面 | 一个统一的企业资源目录 |
| 规则资源 | 只有项目规则/提示词，不是可授权的一等资源 | 新增 Rule 实体和装配优先级 |
| 专家清单 | 智能体可以挂资源，但没有稳定 Manifest 和版本摘要 | 新增 Expert Manifest、依赖解析、版本校验 |
| 资源包导入导出 | 插件和部分商城有包，规则/专家/Skill 未统一 | 定义 `.yzr` 资源包和资源版本 |
| 集中式 MCP | 凭证主要属于用户，本地连接各自配置 | 服务端共享凭证、OAuth、按工具授权和计费 |
| 周期额度 | 只有用户总额度字段和会话费用 | 用户/组织周期额度、继承、重置、流水 |
| 企业统计 | 有原始用量，没有管理看板 | 用户、组织、模型、工具、任务看板 |
| 全局审计 | 有路径/插件/数据编辑等局部审计 | 管理操作统一审计和查询 |
| SSO | 只有用户名密码 | OIDC/企业 SSO |
| 远程工作节点 | 远控是“操作桌面”，不是“执行任务” | 工作节点注册、任务下发、终端/文件/产物 |
| 云工作区 | 无 | 容器/虚拟机工作区、镜像、TTL、端口预览 |
| 设计资源库 | 有设计生成能力，没有企业设计资源目录 | 后续迁移模板、风格、设计系统 |

### 3.1 模块边界

建议按以下模块实现，避免继续把逻辑堆进 `db.ts` 和 `llm-task-manager.ts`：

| 模块 | 职责 |
| --- | --- |
| `team-resource` | 团队资源目录、版本、Manifest、依赖解析 |
| `quota` | 周期额度、组织继承、账户、流水、冻结/结算 |
| `admin-audit` | 管理操作统一审计、查询、导出 |
| `mcp-hub` | 集中式 MCP、共享凭证、OAuth、工具策略、调用记录 |
| `runtime` | 工作节点注册、能力、租赁、任务下发、事件回流 |
| `workspace` | 远程终端、文件、产物、端口预览 |
| `identity` | OIDC/SSO、会话、企业登录策略 |

这些模块由 `apps/server/src/index.ts` 显式装配，路由按 `/api/admin/v1/*`、`/api/runtime/v1/*` 分组，不改现有业务协议的默认行为。

## 4. 核心数据模型

### 4.1 团队资源与版本

新增：

```text
team_rule
  id, owner_user_id, name, content, scope, enabled, version, created_at, updated_at

resource_version
  id, resource_type, resource_id, version_no, sha256, manifest_json, created_at

resource_package
  id, resource_type, resource_id, file_name, size_bytes, sha256, manifest_json, created_at

expert_manifest
  id, agent_id, manifest_json, manifest_hash, created_at
```

约束：

- 团队资源的修改与使用继续走现有 `resource_acl`，不另造一套授权。
- 资源包只保存不可变版本，更新产生新版本，不覆盖历史。
- Skill、规则、专家、MCP 连接都从统一 Manifest 解析，避免各页面各自拼装。
- 智能体依赖的工具、模型、Skill 自动级联授权，沿用现有 `agentDependencyGrants`。

### 4.2 周期额度与计费

现有 `usage_event` 是逐次调用事实，继续保留。新增：

```text
quota_policy
  id, subject_type(user|org), subject_id, period(day|week|month),
  limit_amount, currency, reset_at, enabled

quota_account
  id, subject_type, subject_id, period_start, period_end,
  used_amount, reserved_amount, status

credit_entry
  id, account_id, kind(grant|consume|refund|adjust|reset),
  amount, frozen_amount, model_call_id, mcp_call_id, note, created_at
```

规则：

- 用户未配置额度时沿组织树向上继承。
- 模型调用和 MCP 调用都写事实记录，再由事实生成消费流水。
- 流水不可修改；修正只能新增退款或调整记录。
- 任务结束、失败、取消都必须完成冻结释放或结算，不能留下悬挂额度。
- 第一期可以继续以人民币计价，不强行引入“积分”；后续需要对外售卖时再加积分映射。

### 4.3 工作节点与远程任务

```text
runtime_node
  id, user_id, org_id, name, platform, arch, version,
  public_key, capabilities_json, status, last_seen_at, created_at

runtime_lease
  id, node_id, user_id, task_id, scopes_json, expires_at, revoked_at

runtime_task
  id, task_id, node_id, workspace_id, state, started_at, ended_at

runtime_event
  id, runtime_task_id, seq, kind, payload_json, created_at

runtime_artifact
  id, runtime_task_id, name, path, mime_type, size_bytes, sha256, created_at
```

节点协议第一期不需要复制百智办公的 yamux 双通道。先实现言智自己的单 WebSocket 控制通道：

- 节点启动后注册公钥、平台、能力、版本。
- 服务端签发短期任务票据。
- 任务消息带 `task_id`、`session_id`、`workspace_id`、`seq`、`type`。
- 心跳、任务事件、审批、取消、文件块、产物引用使用同一帧协议。
- 大文件走独立 HTTP 上传/下载端点，不塞进 WebSocket。
- 断线后按 `seq` 续传事件；任务默认继续执行，用户可以显式取消。

协议必须解决四件事：认证、重放保护、幂等、断线恢复。

## 5. 迁移优先级

### 阶段 1：团队资源中心（2 至 3 周）

目标：管理员能把资源真正组织成“团队资源”，成员只看到被授权的部分。

任务：

- 新增统一资源目录页，聚合模型、Skill、专家、规则、MCP、工具。
- 新增 Rule 一等资源，支持系统规则、专家规则、用户规则三种装配优先级。
- 新增专家 Manifest 和资源版本摘要。
- 将现有智能体作为“专家”视图接入，不另建重复的 Agent 表。
- 统一资源授权、启用/停用、来源、版本、使用量展示。
- 在聊天、智能体、工作流选择器中标记“团队资源”。

验收：

- 管理员创建一个团队专家，挂模型、Skill、规则和工具。
- 授权给角色后，角色下用户可以完整打开该专家。
- 撤权后成员无法继续使用，刷新后缓存同步失效。
- 同一资源更新后生成新版本，旧版本仍可查看。

### 阶段 2：额度、统计和审计（2 至 3 周）

目标：企业能知道谁用了什么、花了多少、什么时候超限。

任务：

- 增加周期额度和组织继承。
- 将模型调用和 MCP 调用写入统一事实表与流水。
- 增加管理看板：用户、组织、模型、MCP 工具、任务成功率、费用趋势。
- 增加全局管理审计中间件，记录操作者、目标、前后值、来源 IP 和 trace ID。
- 管理员支持额度调整、重置、冻结和退款。

验收：

- 父组织额度被子组织继承，子组织可覆盖。
- 超额时按配置提醒或阻断，调用不会绕过额度。
- 同一请求重试不会重复扣费。
- 管理操作可在审计页按人、时间、资源类型查询。

### 阶段 3：集中式 MCP（2 至 3 周）

目标：把 MCP 从“每个人自己配”升级为“企业统一接、按人授权、服务端保管凭证”。

任务：

- 新增 Connector Provider 和 Connector 实例。
- 支持 `none`、`centralized`、`independent` 三种凭证模式。
- 支持 Header 凭证和 OAuth 2.1/PKCE；OAuth Token 只在服务端保存。
- 增加工具发现、按工具启停、白名单/黑名单和每次调用费用。
- 服务端提供自己的 MCP 网关入口，言智 Agent 连接网关，不直接接触上游凭证。
- 增加 MCP 调用事实、失败分类和审计。

验收：

- 管理员配置一个共享 MCP，成员无需知道上游 Token。
- 成员只能看到被授权的工具。
- 撤销凭证或撤权后，下一次调用立即失败。
- 关闭一个工具后不会影响同一连接的其他工具。

### 阶段 4：工作节点与远程任务（4 至 6 周）

目标：把言智任务从“只能在本机执行”扩展为“可以下发到工作节点执行”。

任务：

- 新增工作节点 Agent，支持 Windows/macOS/Linux。
- 完成设备码授权或管理员安装令牌、节点注册、心跳和在线状态。
- 新增执行目标选择：本地、工作节点、云工作区。
- 任务事件映射到现有 `llm_task` 事件流。
- 支持远程终端、工作目录文件浏览、文件上传下载和产物回收。
- 支持 `ask_user`、审批、取消、超时和断线续传。
- 任务结束后回收工作区和短期票据。

验收：

- 节点离线时不能提交任务。
- 关闭言智页面后远程任务继续执行。
- 重连后按事件序号补齐，不重复审批、不重复执行工具。
- 取消任务后节点侧进程真正结束。
- 产物只在授权范围内下载。

### 阶段 5：云工作区（4 至 6 周）

目标：在企业服务器或云主机上按需创建工作区，不依赖用户电脑常开。

任务：

- 节点 Agent 支持容器工作区，后续再评估虚拟机/Windows 云电脑。
- 支持镜像、CPU/内存限额、磁盘、TTL 和最大并发。
- 支持创建、续期、停止、删除和资源回收。
- 支持端口发现、预览和受控访问。
- 支持工作区快照和恢复。

验收：

- 工作区创建失败不会占用额度。
- TTL 到期自动停止并清理临时资源。
- 端口预览默认只对授权用户开放，不暴露任意内网。
- 一个节点上的工作区异常不影响控制面和其他节点。

### 阶段 6：企业与设计资源（本轮已落地设计资源，其余按商业需求）

- OIDC/企业 SSO、邮箱验证码、登录策略（部署/身份提供商适配阶段）。
- 品牌名称、Logo、登录页、邮件模板。
- 设计模板、设计系统、风格资源目录。
- 资源包跨实例导入导出。
- PostgreSQL 适配，用于多实例或更大规模团队（基础设施阶段）。

## 6. 不建议迁移的部分

以下能力不值得为了“功能对齐”硬搬：

- 不迁移它的 Tauri/Rust/Go/React 工程结构。言智是 Vue + Electron + Express + SQLite，技术栈统一更重要。
- 不复制它的远程执行协议。协议可以借鉴安全目标，但字段、帧和状态机必须按言智自己的任务模型设计。
- 不复制它的计费字段。言智已有 `usage_event`，在现有账本上扩展周期额度即可。
- 不重复实现模型代理、MCP 客户端、知识库、办公文档、浏览器和代码工作台。
- 不把团队控制面做成插件。插件适合扩展点，不适合承载权限、额度和审计。
- 不在第一阶段做 Windows 云电脑。容器工作区先覆盖大多数办公、代码和自动化任务，成本低得多。

## 7. 关键设计决策

### 7.1 继续用 SQLite，还是换 PostgreSQL

建议：

- 单实例、50 人以内先继续用 SQLite，减少迁移风险。
- 将数据库访问收口到 repository，避免新模块继续直接散落 SQL。
- 远程任务事件、审计、额度流水先按可迁移的标准化 schema 设计。
- 当出现多实例、高并发写入或超过单机容量时，再增加 PostgreSQL 适配。

不建议第一阶段同时做功能迁移和数据库替换，风险叠加。

### 7.2 专家与智能体的关系

不新增第二套“专家”执行引擎。使用现有 `agent` 作为执行主体：

- `agent` 继续负责提示词、模型、工具、Skill、子智能体。
- 新增 `expert_manifest` 和团队资源版本。
- UI 上把团队发布的 agent 称为“专家”，个人 agent 仍叫“智能体”。
- 这样不会出现两套运行时、两套调试入口和两套权限。

### 7.3 远程任务与远程控制的关系

两者分开：

- 远程控制：人看屏幕、人操作鼠标键盘。
- 远程任务：AI 在工作节点执行任务，返回事件、终端和产物。

可以复用配对、白名单、心跳、审计和短期令牌的经验，但不能把 WebRTC 画面控制当作任务执行协议。

### 7.4 计费用人民币还是积分

第一期继续用人民币成本：

- 现有账本、价格快照和前端金额展示已经可用。
- 周期额度可以直接按人民币配置。
- 如果未来对外售卖，再增加“积分倍率”字段，不推翻底层事实表。

## 8. 实施顺序与依赖

```text
团队资源目录
  ├─ Rule / Expert Manifest
  ├─ 统一授权与版本
  └─ 资源使用统计
          │
          ▼
周期额度 / 流水 / 审计
          │
          ▼
集中式 MCP（共享凭证、OAuth、工具计量）
          │
          ▼
工作节点 Agent
          │
          ▼
远程任务 / 终端 / 文件 / 产物
          │
          ▼
云工作区 / 镜像 / TTL / 端口预览
```

建议严格按此顺序：

- 没有统一资源目录，额度和审计会继续散落在各业务页面。
- 没有额度和调用事实，MCP 计费无法闭环。
- 没有工作节点，远程任务只能做演示，不能稳定交付。
- 没有远程任务，云工作区没有消费者。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 新旧任务链路耦合 | 远程执行改坏本地聊天 | 先抽离执行目标接口，保持本地 provider 行为不变 |
| SQLite 并发写入 | 多节点事件和审计写放大 | 控制面单实例起步，事件批量写，预留 PostgreSQL |
| 远程节点权限过大 | 企业主机被滥用 | 短期票据、最小 scope、任务级临时目录、命令审计、急停 |
| MCP 共享凭证泄露 | 上游系统风险 | 服务端加密、不回显、不进入工具结果、日志脱敏 |
| 双层额度字段漂移 | 超限判断不一致 | 只保留事实表和账户表，`user.quota_cost_cny` 仅做兼容迁移 |
| 资源版本不一致 | 专家运行结果不可复现 | 会话开始时固定资源快照和 Manifest hash |
| 云工作区成本失控 | 资源长期占用 | TTL、最大并发、额度预冻结、孤儿资源巡检 |
| 复制 AGPL 代码 | 商业合规风险 | 只做行为对齐，自研实现，不复制源码 |

## 10. 首个可交付版本边界

首个版本覆盖阶段 1 和阶段 2，只做“团队版工作台”，不做云电脑：

- 团队资源目录。
- Rule、专家 Manifest、版本摘要。
- 统一资源授权入口。
- 用量看板第一版。
- 管理审计第一版。

不进入第一阶段：

- 远程工作节点。
- 云工作区。
- OIDC/SSO。
- 设计资源库。
- PostgreSQL 迁移。

这样可以先交付企业最常用的“共享资源 + 权限 + 用量”闭环，再进入高风险执行层。
