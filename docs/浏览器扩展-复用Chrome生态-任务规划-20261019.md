日期：2026-10-19
分支基线：dev0.1-mobile

## 1. 结论

技术上可行，但**不要自研**。直接采用：

| 包 | 版本 | 作用 | 许可 |
|---|---|---|---|
| `electron-chrome-extensions` | 4.9.0 | 把 Chrome 扩展 API 接到 Electron session；提供工具栏图标/弹窗、右键菜单、MV3 适配 | GPL-3 或 Patron 商业授权 |
| `electron-chrome-web-store` | 0.13.0 | 从 Chrome Web Store 下载 CRX、校验、解包、安装、自动更新 | MIT |

两者同属 `samuelmaddock/electron-browser-shell`，要求 Electron ≥ 35.0.0-beta.8，当前 `44.7.2` 满足。

**授权结论（P0 后更新）**：本仓库 `package.json` 是 `"private": true` + `"license": "UNLICENSED"`，闭源分发。`electron-chrome-extensions` 是 GPL-3，闭源商用必须购买 Patron 授权或开源整个项目。**但 P0 已证明：核心扩展能力用 Electron 内置 API 即可跑通**；GPL 库额外提供的是 `chrome.action` 工具栏/弹窗、`cookies`、`contextMenus`、`webNavigation`、`windows` 等 API 面。白名单 v1 可以先走免费路径，只有白名单中确实依赖 toolbar popup 的扩展才构成采购理由。

## 2. 目标 / 非目标

### 目标
- 用户在应用内打开 `chromewebstore.google.com`，点「添加至 Chrome」即可安装（由库接管商店安装流程）。
- 已安装扩展的图标出现在浏览器工具条，点击可弹 popup。
- 扩展可注入内容脚本、修改页面、拦截请求；支持启用/禁用/卸载/检查更新。
- 跨重启保留（库不记忆，需应用每次启动重新加载）。
- 扩展只作用于 `persist:browser-view`，与应用自身 UI（`defaultSession`）隔离。

### 非目标
- 不承诺商店全部扩展可用（Chrome 专有 API 缺失的部分必然不可用）。
- 不做静默安装、不预装扩展、不批量抓取商店。
- 不支持非持久/隐身 session（库的硬限制）。
- 首版不做扩展之间的互相安装（`chrome.management` 的安装能力）。

## 4. 架构

```
main.cjs
 └─ browser-extensions.cjs（新增，主进程单例）
     ├─ ElectronChromeExtensions({ session: persist:browser-view, license, ... })
     │   ├─ createTab      → 复用 createBrowserTab
     │   ├─ selectTab      → 复用 activateTab / activateTab IPC
     │   └─ requestPermissions → IPC 弹窗，默认拒绝
     └─ electron-chrome-web-store
         ├─ installChromeWebStore({ session, autoUpdate, beforeInstall, allowlist })
         └─ installExtension(id) / updateExtensions()

packages/ui
 ├─ BrowserPanel 工具条 → <browser-action-list partition="persist:browser-view" :tab="activeWcId">
 ├─ 右键菜单 → extensions.getContextMenuItems(tab, params)
 └─ 设置 →「扩展管理」pane（列表/开关/删除/权限/本地导入）
```

数据落盘（库管理，位于 `userData` 下，不能进 asar）：
- 扩展文件：`userData/extensions/` 或库的默认目录
- 安装记录：库内部持久化
- 应用侧只需要保存启停状态（若不使用库的全量管理）

## 5. 任务分解

### P0 可行性 spike（1 天，阻塞后续）

不改主工程，在 `apps/desktop/experiments/extensions-spike/` 起最小 Electron 窗口，同一分区上加载扩展，逐项验证：

| 扩展 | 类型 | 要验证的点 |
|---|---|---|
| uBlock Origin（MV2） | webRequest blocking | 请求拦截是否生效 |
| uBlock Origin Lite（MV3） | declarativeNetRequest | DNR 是否被支持（大概率不支持，记为已知缺口） |
| Dark Reader（MV3） | content script + scripting | 页面注入、开关、popup |
| Tampermonkey（MV3） | service worker + scripting | SW 是否存活、脚本是否注入 |
| 沉浸式翻译（MV3） | content script + network | 双语注入是否正常 |
| Vue DevTools（MV3） | devtools | devtools 面板能否打开 |

**验收**：至少 4/6 核心功能可用；MV3 service worker 能启动；`<webview>` guest 能收到内容脚本。
**产出**：兼容性矩阵 v1，作为产品宣传口径与后续白名单依据。
**否决条件**：MV3 SW 完全不工作，或 webview guest 不注入内容脚本 → 回到「仅支持 MV2/内容脚本类」的降级方案重新评估。

#### P0 实测结果（2026-10-19，Electron 44.7.2）

测试工程：`apps/desktop/experiments/extensions-spike/`（独立目录，不进主工程与打包）。

| 能力 | 内置免费路径 | GPL 库路径 | 结论 |
|---|---|---|---|
| MV2 content script 注入 `<webview>` | ✅ | ✅ | 可用 |
| MV3 content script 注入 `<webview>` | ✅ | ✅ | 可用 |
| MV2 background page | ✅（ping 收到） | ✅ | 可用 |
| MV3 service worker | ✅（SW 运行、ping 收到） | ✅ | 可用 |
| `chrome.webRequest` 阻塞 | ✅（请求被取消） | ✅ | 可用 |
| MV3 `declarativeNetRequest` | ❌ 扩展可加载，规则**不生效** | ❌ | **不支持** |
| 真实商店 CRX 解析/解包/加载 | ✅（Dark Reader + uBlock Lite 均安装成功，Dark Reader SW 运行） | ✅ | 可用 |
| 商店网络下载（经本机代理） | ❌ `fetch`/`net.fetch`/undici 均失败；curl 可完整下载 | 同左 | 需自研带代理的下载器 |
| `<browser-action-list>` 工具栏弹窗 | 无此能力 | ✅（未做 UI 验证） | 仅 GPL 库提供 |

关键结论：

1. **免费路径足以支撑白名单 v1 的核心机制**：内容脚本、MV2 后台、MV3 SW、webRequest 拦截全部在 `<webview>` guest 中生效。
2. **MV3 去广告（DNR）不可用**。uBlock Origin Lite、AdGuard MV3 这类扩展能安装、能启动，但规则不执行。需要拦截能力时，白名单只能用 MV2 `webRequest` 类扩展（如 uBlock Origin MV2），或在应用内自研原生拦截。
3. **工具栏图标/弹窗是免费路径的唯一硬缺口**。可退化为「扩展管理页里点『打开弹窗』，用新标签打开 `chrome-extension://<id>/popup.html`」；若扩展依赖 `chrome.action.onClicked`，则该扩展必须靠 GPL 库或排除。
4. **商店下载需要带代理的下载器**。CRX 端点与重定向均可达（curl 实测 9.1MB 完整下载），但 Chromium/undici 在本机代理下报 `ERR_CONNECTION_CLOSED`。P2 需实现：优先直连，失败时经 `session.resolveProxy()` 取代理，用 Node `https` 手动 CONNECT 下载，再把 buffer 交给 `electron-chrome-web-store` 的解析/解包/加载流程。

### P1 内核接入（2 天）

1. 安装依赖到 desktop workspace，锁定版本，提交锁文件。
2. 新建 `apps/desktop/browser-extensions.cjs`：
   - `initBrowserExtensions()`：在 `app.whenReady` 之后、浏览器 session 配置完成之后调用。
   - 构造 `ElectronChromeExtensions({ session, license, createTab, selectTab, removeTab, createWindow, requestPermissions })`。
   - `createTab(details)` → 调 `createBrowserTab(scope)` 并广播 `browserView:tabCreated`，返回 `[guestWebContents, mainWindow]`。
   - `selectTab(wc)` → 反查 tabId 后走 `browserView:activateTab` 同一路径。
   - `removeTab(wc)` → 走 `closeTabById`。
   - `requestPermissions(extension, permissions)` → 通过 IPC 询问用户，未响应一律拒绝。
3. 在三个收敛点挂钩：
   - `browser:wv:register`（`main.cjs:1956`）：`extensions.addTab(wc, mainWindow)`。
   - `browserView:activateTab`（`main.cjs:2230`）：`extensions.selectTab(wc)`。
   - `browser:wv:unregister` / `closeTabById`（`main.cjs:1983` / `:2045`）：通知库或依赖 `destroyed` 自动清理（P0 确认）。
4. 打包登记：把 `browser-extensions.cjs` 加进 `electron-builder.lite.yml` 与 `full.yml` 的 `files:`；确认 `electron-chrome-extensions` 的 preload 在打包后可解析（库文档要求 node_modules 随包或显式拷贝 preload）。

**验收**：uBlock Origin / Dark Reader 在应用真实浏览器面板中生效；扩展的 `chrome.tabs.query` 能看到应用内标签；应用启动日志无扩展加载错误；打包版同样可用。

> 注意：改 `main.cjs` 会重启应用，在跑的任务会被标 resumable（见工作区记忆）。调试请避开任务运行窗口。

#### P3 实现记录（2026-10-19，右键菜单已完成）

- 授权结论：`electron-chrome-extensions` 的 GPL-3 可免费使用，但闭源分发具有传染性；Patron 商业授权为 GitHub Sponsors **$30/月订阅**（tier 文案即 "Patron license"，停止赞助授权即失效；法人实体同一时间仅一个席位）。**结论：不采购，自研 shim。**
- 新增 `apps/desktop/extension-context-menus.cjs`：菜单注册表（每扩展上限 200 项）、Chrome match pattern / contexts 过滤、父子菜单树、原生 `Menu.popup`、点击事件投递。
- 新增 `apps/desktop/extension-api.preload.cjs`：向 `persist:browser-view` 的 chrome-extension 帧与 service worker 注入 `chrome.contextMenus`（create/update/remove/removeAll/onClicked + create 的 onclick），主世界注入通过 contextBridge 窄桥完成，不向扩展暴露 ipcRenderer。
- 主进程接入：扩展初始化时注册 preload 并安装 shim；`browser:wv:register` 与 `createBrowserViewFor` 两处 guest 挂 `context-menu` 监听；扩展身份按 `senderFrame.url` / `worker.scope` 反查，不信任 preload 自报。
- 打包：三份 electron-builder yml 登记两个新文件。
- 测试：新增 `test/extension-context-menus.test.cjs` 20/20；桌面全量 279 项 277 通过（2 个失败为分支既有：`LOCAL_API_BASE` 守门、`full.yml` 缺 `electronLanguages`）。
- 真实 Electron 集成（spike `SPIKE_CONTEXTMENU=1`）：MV2 后台页与 MV3 service worker 均拿到 `chrome.contextMenus`；`create` 返回 id 且 callback 正常触发（`lastError` 为空）；父子菜单与 `%s` 替换正确；点击事件分别投递到两个扩展，`tab.id` 与 `selectionText` 正确。
- 关键坑：SW preload 中 `self` / `location` / `chrome` 均不可见（Electron 44 实测），无法据此判断是否扩展 SW；改为对全部 service worker 注入，主世界检测 `chrome` 存在后再定义，普通页面的 SW 自动 no-op。
- spike 注意：扩展 SW 脚本会被 Chromium 缓存，改 fixture 后必须删除 `experiments/extensions-spike/userdata` 再跑，否则跑的是旧脚本。
- 已知噪声：Electron 不识别 manifest 的 `contextMenus` 权限，启动日志会打 `Permission 'contextMenus' is unknown`，不影响功能。
- 未做：工具条 `<browser-action-list>`（GPL 库专有）；仍以「扩展管理页 → 弹窗」新标签打开 popup 兜底。

#### P3c chrome.scripting 实现记录（2026-10-19）

- 新增 `apps/desktop/extension-scripting.cjs`：
  - `executeScript`：files / code / func（func 在 preload 序列化成源码），支持 `allFrames` 与 `frameIds`；

  - `registerContentScripts` / `get` / `update` / `unregister`：进程内注册，guest `dom-ready` 时按 URL 匹配注入。
- preload 注入 `chrome.scripting`（7 个方法）以及 MV2 的 `chrome.tabs.executeScript / insertCSS / removeCSS`。
- 主进程把 `scripting.*` 路由到本模块；webview 与 BrowserView 两种引擎的 guest 都挂 `dom-ready` 监听。
- 验证：真实页面注入返回 `42`、标题改写成功、CSS `outline` 生效、注册脚本注入成功；指向扩展页的 tab 被明确拒绝。
- 已知差异：注入执行在页面**主世界**（非 Chrome 的隔离世界），依赖 `chrome.*` 的注入代码不可用；`runAt` 统一按 `dom-ready`；`insertCSS` 只作用于主帧；注册脚本不跨重启持久化。

**验收**：用户全流程无需命令行；禁用后立即失效且页面恢复正常；删除后文件被清理。

### P4 安全与合规（2 天）

1. 安装前二次确认：展示权限清单 + 明确提示「扩展可读取你在本浏览器访问的所有页面内容，包括已登录站点」。默认取消。
2. 来源约束：只接受商店 ID 或用户显式选择的本地包；本地包显示路径与指纹（SHA-256）。
3. 沙箱：保持 guest `contextIsolation: true`、`nodeIntegration: false`；确认发行包未带 `--no-sandbox`。
4. 网络：商店相关域名走系统代理；失败可重试，不静默失败。
5. 可观测：安装/更新/加载失败写入 `server.log` 或独立日志，便于售后归因。
6. 合规：
   - GPL-3 / Patron 授权落实（最高优先级）。
   - CRX 下载必须由用户点击触发，不预装、不批量抓取。
   - 扩展自身的许可证由用户确认，应用不做再分发。

### P5 灰度与发布（1 天）

- 功能开关 `YZ_BROWSER_EXTENSIONS=off|shadow|on`，默认 `off`，沿用 `YZ_BROWSER_BRIDGE` 的档位风格。
- 先内部 dogfood 2 周，收集崩溃率、扩展兼容问题、内存增量（每个扩展可能多一个常驻 SW/后台页）。
- 发布说明附「已验证兼容的扩展清单」，并明确不支持范围。

## 6. 风险表

| 风险 | 影响 | 缓解 |
|---|---|---|

## 8. 拍板结果

1. **Patron 商业授权**：不采购。GPL-3 免费但闭源分发需开源整个项目；Patron 为 $30/月订阅且随赞助停止失效。核心扩展能力与右键菜单均已用免费路径自研跑通。
2. **首版兼容范围**：白名单精选（已定）。首批建议：Dark Reader、沉浸式翻译、Tampermonkey 等以 content script / `chrome.scripting` 为主的扩展；MV3 DNR 类去广告扩展排除。
3. **入口位置**：设置页内的「扩展管理」（已定）。
