## 0. 一句话结论

TRAE 那个"单页 + 免 UAC + 实时逐文件路径 + 绿色扁平进度条"，**根因是 Inno Setup + per-user 安装**，不是皮肤好看：

- winget manifest 记录 `ByteDance.Trae.CN` 为 **Inno Setup / Install scope: Per-user**，与截图标题栏 `(User)` 一致。
- Inno Setup 逐条目 `File` 释放，天然能把当前文件名写进 `FilenameLabel`，所以那行路径一直变。
- 我们是 **electron-builder NSIS + perMachine + 整包 7z 一次性解压**：`Nsis7z::Extract` 把 `app-64.7z` 整个解开到临时目录，再 `CopyFiles /SILENT` 一次拷进 `$INSTDIR`，**底层根本没有逐文件事件**。

因此拆成三件事看：

| 层次 | 能否低成本对齐 | 说明 |
| --- | --- | --- |
| 观感层（单页、文案、配色、品牌图、进度条） | ✅ 能 | 在 `nsis.include` 钩子 + yml 字段内即可完成 |
| 免 UAC（per-user） | ⚠️ 能，但属产品决策 | 要放弃 `Program Files` 与现有覆盖升级路径 |
| 实时逐文件路径 | ⚠️ 必须接管内置 NSIS 模板 | 不接管只能做"进度映射"，是假象 |

**推荐：P0 做观感层对齐（不动解压逻辑），P1 可选做真回调，否决换框架。**

> 第二部分（启动加载页）是**另一套链路**，与 NSIS 无关：现状只有一个 CSS 假滑条，
> 且「数据源 → 主进程转发 → splash 渲染」三环**全部断开**。详见第 12～18 章。

### 2.2 决定体验的几个硬事实

| 事实 | 源码位置 | 后果 |
| --- | --- | --- |

| 图标单一真相源 | `scripts/sync-yanzhi-icons.cjs:126-163`，源包 `assets/icons/yanzhi-original-pack/` 只有**方形**图标，README 写明"不得重绘" | 要做 150×57 头图 / 164×314 侧图，缺素材 |
| 27 种语言未裁剪 | 生成脚本 `builder-debug.yml:144-171` 列出 27 个 `MUI_LANGUAGE` | 硬编码中文 `DetailPrint` 在英文系统上会中英混杂 |

### 2.3 一个额外发现

`nsis7z.dll` 确实导出 **`ExtractWithCallback` / `ExtractWithDetails`**（本机插件目录实测），只是 electron-builder 模板调用的是无细节的 `Extract`。所以"真逐文件"在 NSIS 内是**可行的**，代价是要替换内置模板调用点。

## 4. 三条技术路线

| | 路线 A：钩子层（推荐） | 路线 B：脚本层 | 路线 C：换框架 |
| --- | --- | --- | --- |
| 做法 | 只改 `installer.nsh` + 三份 yml 的 nsis 字段 | `nsis.script` 接管 + 构建期给内置模板打补丁 | 改用 Inno Setup 打 per-user 包 |
| 逐文件 | 进度映射（非真实回调） | ✅ 真回调（`ExtractWithCallback`） | ✅ 原生 |
| 改写面 | 2 类文件 + 测试 | 新增自定义 `.nsi` + 补丁脚本 + 测试 | 整条打包链重写 |
| 与 eb 版本耦合 | 低（只用官方 `custom*` 宏） | **高**（模板原文变了就要重打补丁） | 脱钩 |
| 风险 | low ~ medium | medium ~ high | **high** |
| 结论 | ✅ 先做 | ⚠️ 作为 P1 可选 | ❌ 否决 |

**否决 C 的理由**：electron-builder 现在替我们实现了升级卸载旧版、`--updated` / `force-run` / `keep-shortcuts` 参数、UAC 内外层实例、多用户注册表、`/S` 静默、快捷方式、卸载器。换成 Inno Setup 要全部重写，还要重接三档 edition、`apply-fuses.cjs`、CI 的 `Windows-Installer` 产物路径、签名策略。为观感付这个代价不划算。

## 5. 最贵的三条判据

1. **整包 7z 拿不到逐文件事件** —— 别在 `installer.nsh` 里试图用 `SetDetailsPrint` / `DetailPrint` 让文件名"自己冒出来"。`installSection.nsh:6` 会再次关掉输出，`extractAppPackage.nsh:97` 用的是 `Nsis7z::Extract`，`:108` 是 `CopyFiles /SILENT`。要真实文件名只能改模板调用点（路线 B）。
2. **`oneClick` / `perMachine` 是产品决策，不是 UI 决策** —— `oneClick: true` 会用 `oneClick.nsh` + SpiderBanner 直接单页，但**失去"选择安装目录"**（现在 `allowToChangeInstallationDirectory: true`）；`perMachine: false` 免 UAC，但装到 `%LOCALAPPDATA%`，现有覆盖升级与 `customCheckAppRunning`（`taskkill /F /T /IM yan-zhi.exe`）语义要重验。这两条必须你拍板，不能由方案默认。
3. **三份 yml + 守门测试 + CI 必须同步** —— `full.yml` / `lite.yml` / `shell.yml` 的 nsis 段逐字同源，`installer-progress.test.cjs:15-21` 显式登记三份；`dist-release-shell/builder-debug.yml` 是**构建产物**，不能拿来当断言源或提交依赖。

## 6. 推荐实施（分阶段，均待确认）

### P0 — 观感对齐，不动解压逻辑

| 项 | 具体动作 | 落点 |
| --- | --- | --- |
| 单页化 | 按第 9 节拍板结果：切 `oneClick: true`，或保留向导但把安装页做成极简（**纯钩子无法删除内置 MUI_PAGE_DIRECTORY / FINISH，硬约束**） | 三份 yml `nsis` 段 |
| 状态行 | 移除 `[n/4]` 编号与详情总览，改成一句主文案 + 一行当前动作；`ShowInstDetails nevershow` + 自建单行 Label | `installer.nsh` |
| 进度条着色 | 对 MUI InstFiles 页进度条控件发 `PBM_SETBARCOLOR` / `PBM_SETBKCOLOR`（绿 / 浅灰），保留 `InstProgressFlags smooth`；**需实测 comctl32 v6 视觉样式下是否生效** | `installer.nsh` |
| 品牌 | `installerHeader`(150×57)、`installerSidebar`(164×314)（assisted 专属）或 `installerHeaderIcon`（one-click 专属）；由 `sync-yanzhi-icons.cjs` 生成并纳入单一真相源 | yml + 图标脚本 + `assets/icons/` |
| 文案 | 中文主副标题 + 当前动作；改 `LangString`，`installerLanguages` 裁剪到 `zh-CN` / `en-US` | `installer.nsh` + yml |
| 静默保护 | 所有自定义 UI 在 `${Silent}` 下跳过，保证 `/S` 自动化安装不挂起 | `installer.nsh` |
| 保留 | `customCheckAppRunning` 的杀进程、`customInstall` 的 `ie4uinit -ClearIconCache`、`!ifndef BUILD_UNINSTALLER` 保护 | 原样不动 |

**P0 不做**：不改解压方式、不改 `artifactName`、不改产物路径、不加任何按钮或 tip、不动 `afterPack` / fuses。

### P1 — 真实逐文件（可选，建议做）

- 用 `nsis.script` 指向仓库内的自定义 `.nsi`；构建期脚本从 `node_modules/app-builder-lib/templates/nsis/` **提取** `extractAppPackage.nsh` 并打补丁：`Nsis7z::Extract` → `ExtractWithCallback`，回调把当前相对路径写到 P0 的单行 Label。
- 补丁脚本必须带**模板指纹校验**（原文 hash 不匹配直接 fail fast），避免 electron-builder 升级后静默用错版本 —— 这一条是硬要求。
- 回调刷新节流（建议 ≥100ms），否则 500MB+ 包会闪屏；`CopyFiles /SILENT` 阶段单独显示"正在写入应用文件"，不假装有文件名。
- UAC 内外层实例下回调变量必须 `/GLOBAL`。

> 若 P1 不做，P0 的"当前条目"只能按进度映射构建期文件清单，**那是估算不是真实状态**，不推荐长期保留；宁可退化成"正在解压缩应用文件… 已释放 xx%"的真实数字。

### P2 — 免 UAC / 用户级安装（独立决策，不并入 P0）

需单独评估注册表、`%APPDATA%/yan-zhi/server-data/data.db` 路径、覆盖升级、卸载器、CI 静默安装 smoke test，单独排期。

## 9. 待你拍板的三个点

1. **单页 vs 可改安装目录**：切 `oneClick: true` 才能纯钩子单页，但会失去"选择安装目录"。要哪个？
2. **是否做 per-user 免 UAC**：这是截图里 `(User)` 的来源，但会动覆盖升级与数据路径。建议拆成 P2 单独排期 —— 同意否？
3. **P1 要不要做真逐文件**：不做就只能显示真实阶段/字节数，做就要接管内置模板并承担版本耦合。
4. **品牌横幅素材**：现有源包只有方形 ico 且标注"不得重绘"，150×57 / 164×314 位图谁出？没有素材就先只做极简白底 + 右上角方形图标。

## 10. 风险分级

| 风险 | 级别 | 缓解 |
| --- | --- | --- |
| `oneClick` / `perMachine` 语义变化导致升级、注册表、数据路径异常 | **high** | 单独 P2，先出影响面分析再动；真机覆盖升级回归 |
| `nsis.script` 接管后 electron-builder 升级导致模板漂移 | **high** | 构建期指纹校验 + fail fast + CI 编译守门 |
| `PBM_SETBARCOLOR` 在 XP 视觉样式下被忽略，进度条仍是蓝色 | medium | P0 内先做单控件实测，不生效则退化为自绘 nsDialogs 进度条 |
| 静默安装被自定义页面挂起 | medium | `${Silent}` 全分支跳过 + CI smoke test |
| 三份 yml 漏改，某一档静默产出旧界面 | medium | 测试逐份断言 + 四档产物各出一次 |
| 进度映射与真实解压不同步（若 P1 不做） | medium | 只显示真实阶段/字节数，不伪装成精确文件名 |
| 品牌位图素材缺失 | low | 先用极简白底 + 现有方形图标，素材到位再补 |

## 13. 最贵判据：三环全断，只改任何一环都白做

```
数据源（阶段事件）  ──✂──  主进程转发（pushSplashUpdate）  ──✂──  splash 渲染（apply）
   零阶段打点              payload 无 pct/phase              .bar 是 CSS 动画，不绑宽度
```

- ✅ 主进程**已有**可用的确定性阶段点：`startServer()`(16241)、spawn(1729/1744/1779)、`createSplashWindow()`(16361)、`checkHealth`(16320)、Vite 就绪(16301)、健康通过(16309)、`createWindow()`(16287)、`ready-to-show`(2030)、`ui-ready`(2019)、`show()`(2008)、`destroySplashWindow()`(2011) —— **一个数都没上报**。
- ⚠️ 后端有 20+ 个带模块前缀的 `logger.info` 阶段日志（`index.ts` 176～1296），生产下被 `main.cjs:1786-1787` 原样写进 `server.log`，**不解析、不转发**；dev 分支 `stdio:'inherit'`(1731/1746) 连 `.on('data')` 都没有。
- ✅ 仓内**已有成品范式**可直接照搬：`shell-export:progress` 的 `{ phase, detail?, pct? }`（`export-shell.cjs:103,133-162` + `preload.cjs:81-82`），以及 `splash:get-last-update` 的「回拉防错过」机制。

**必须三环同改**：扩展 payload → 主进程逐阶段打点 → `apply()` 解析并把 `.bar` 从 `animation` 切成 `width: pct%`。任何一环漏了，表现都是"代码改了但界面没变"。

## 14. 为什么不能拿 `/api/health` 当进度源（容易踩的坑）

| 事实 | 源码 |
| --- | --- |
| health 是**静态 JSON**，只有 `ok/time/app/pid/version/buildId` | `apps/server/src/index.ts:287-296` |
| 它注册在 287 行，`app.listen` 在 695 行 → **listen 成功即恒定 200** | 同上 |
| 之后还有一轮初始化：DB 完整性自检(807)、seedRbac(856)、模型同步(870)、迁移(898)、数据预热(964)、调度器(1007)、插件 `mgr.init()`(1048-1296) | `index.ts` |
| 桌面端 `checkHealth` **只判 `res.statusCode === 200`，连响应体都不读** | `main.cjs:16348-16356` |

⇒ `health 200` 只等于"端口活着"，**不等于后端就绪、更不等于进度**。唯一读完整 JSON 的 `getServerHealth()`(1525-1534) 只在「复用旧后端探测 / 崩溃自愈」时调一次，不能拿来驱动进度。

## 15. 真实进度口径（核心设计）

**采用「阶段加权 + 阶段内时间衰减」**，不假装知道总耗时（dev tsx 冷编译实测 60s+，生产可能 2s，无法用时间线性估）：

```
pct = 已完成阶段权重和 + 当前阶段权重 × (1 - exp(-阶段内耗时 / τ))
```

三条硬规则：

1. **绝不倒退**：`pct = max(已显示值, 新算值)`；后端重启/复用分支不得让进度回跳。
2. **绝不提前 100%**：衰减曲线只逼近当前阶段上限，最后一格**必须由真实事件** `mainWindow.show()` 触发。
3. **不做假完成**：15s 双闸兜底(`main.cjs:2021-2027`)强制放行时，若进度未到 100，销毁前也不补满 —— 宁可停在 95%。

| # | 阶段 | 权重 | 累计 | 触发事件（真实行号） | 文案 |
| --- | --- | --- | --- | --- | --- |
| 1 | 准备运行环境 | 8 | 8 | `createSplashWindow()` `main.cjs:16361`（**立即推**，修掉前 3 秒静默） | 正在准备运行环境… |
| 2 | 启动后端服务 | 22 | 30 | `startServer()` 16241 → spawn 1729 / 1744 / 1779 | 正在启动后端服务… |
| 3 | 等待后端就绪 | 30 | 60 | `checkHealth` 每轮 16320；dev 另等 Vite 16301 | 正在连接后端服务… |
| 4 | 创建主窗口 | 15 | 75 | `tryCreateWindow` 16283 → `createWindow()` 16287 | 正在创建主界面… |
| 5 | 加载界面 | 20 | 95 | `ready-to-show` 2030 ∩ `ui-ready` 2019 | 正在加载界面… |
| 6 | 完成 | 5 | 100 | `mainWindow.show()` 2008 | 即将完成… |

> **一个必须拍板的细节**：现在 `destroySplashWindow()`(2011) 紧跟 `show()`(2008)，100% 那一帧用户看不到。
> 建议 `show()` 后延后约 120ms 再销毁（仍在首屏闸门内，不破坏 `splash-gate.test.cjs` 的"只在闸门内销毁"约束，但要同步改该测试）。若不想动闸门，就把 95→100 合进第 5 阶段，不追求看到满格。

**UI 形态（延续极简，只加必要元素）**：logo + 一行阶段文案 + 确定性进度条 + 右侧百分比数字 + 可选一行「当前动作」。
**不加**按钮、tip、图标、说明文字。深色 `#1d1d1c` 保留（与主窗 `backgroundColor` 一致，零闪烁）；失败态红色铺满保留并补齐触发点。
