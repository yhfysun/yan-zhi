# WorkBuddy 布局对齐方案（言智 UX 改版 v2）

> 状态：**方案待确认**，本阶段只出文档不动代码。
> 触发原因：用户纠正「布局不是把菜单全部挪出来」，要求重新分析 WorkBuddy 的页面布局 / 工作流程 / 任务记忆。

---

## 0. 结论先行

我上一版把 `/agents /skills /tools /mcp /models /knowledge` 等管理页平铺进侧边导航的「AI 能力」分组，是**对 WorkBuddy 的误读**。WorkBuddy 的侧边栏是**任务列表**，不是**功能菜单**。

正确对齐应是三段结构 + 任务驱动 + 能力靠对话触发：

- **左栏 = 任务列表**（会话/任务，按空间分组，搜索，底部头像）
- **中间 = 对话区**（任务标题栏 + 消息 + 输入，用 `/` 命令、`@` 引用、工具动态触发能力）
- **右栏 = 结果区**（概览 / 产物 / 变更 / 浏览器 四视图）
- **管理页（智能体/模型/MCP/工具/Skill/知识库）下沉到「设置」，不进主导航**

---

## 1. WorkBuddy 真实结构（官方文档核实）

### 1.1 页面布局（三块）

| 区域 | 内容 | 对应言智现状 |
|---|---|---|
| **侧边栏** | 任务列表（按文件夹分组）+ 搜索 + 底部用户头像 | ❌ 现在是功能菜单堆砌 |
| **对话区** | 任务标题栏 + 消息列表 + 输入框 | ✅ 已有（Chat.vue） |
| **结果区** | 概览（工作空间文件 / 浏览器 / 变更）+ 产物 | ✅ 已有（previewTabs 多 tab） |

### 1.2 工作流程

1. **一句话下达任务**（自然语言，无需操作步骤）
2. **自主规划执行**（自动拆解、规划步骤、调用工具执行）
3. **交付可验收结果**（文档/表格/PPT/报告/网页，右侧结果区查看）

关键：能力是**任务执行过程中动态触发**的（智能体决策 + 工具调用 + ask_user 反问），不是用户在导航里点开管理页。

### 1.3 任务记忆（三层）

| 层 | 位置 | 读写 | 内容 |
|---|---|---|---|
| 云端记忆 | 服务端注入 | 只读 | 用户画像 + `conversation_search` 历史会话检索 |
| 用户级本地记忆 | `~/.workbuddy/MEMORY.md` | 可读写 | 跨项目偏好/规则/习惯 |
| 工作区记忆 | `.workbuddy/memory/{MEMORY.md, YYYY-MM-DD.md}` | 可读写 | 项目约定 + 每日工作日志 |

## 2. 我错在哪（现状诊断）

`packages/ui/src/components/SideNav.vue` 的 `builtinNavItems` 当前为：

```
工作台：  /home 首页、/chat 对话、/browser 浏览器
AI 能力： /agents 智能体、/skills Skill商店、/knowledge 知识库、
          /tools 工具、/mcp MCP服务、/models 模型   ← ❌ 管理页平铺
更多：    /peers 聊天、/chat-hub 消息、/distill Skill蒸馏
```

问题：`AI 能力` 分组把 6 个**管理/配置页**当成了导航入口，这正是用户否定的「把菜单全部挪出来」。

## 3. 修正后的布局方案

### 3.1 左栏 —— 改成「任务列表」

```
┌─────────────────────┐
│ ＋ 新建任务          │   ← 顶部主 CTA
│ ─────────────────── │
│ 🔍 搜索任务          │
│ ─────────────────── │
│ 空间 A               │
│   任务 1  (进行中)    │
│   任务 2  (已完成)    │
│ 空间 B               │
│   任务 3             │
│ ─────────────────── │
│ 👤 头像 → 设置/记忆   │   ← 底部，下拉入口
└─────────────────────┘
```

- 移除所有管理页导航项（`/agents /skills /tools /mcp /models /knowledge`）。
- 移除「更多」组的低频项（`/peers /chat-hub /distill`），其入口归入设置或保留在对话内触发。
- 底部头像下拉改为：**设置 / 记忆 / 数据管理**（对齐 WorkBuddy「头像 → 设置 → 记忆」）。

### 3.2 中间 —— 对话区（保留，方向已对）

- 任务标题栏 + 消息列表 + 输入框（现有）。
- `/` 命令、`@` 文件引用、任务规划卡片（`TaskPlanCard`）**已落地**，作为能力触发的正确形态保留。

### 3.3 右栏 —— 结果区（对齐四视图命名）

现有 `previewTabs` 多 tab 已接近 WorkBuddy 结果区，对齐为四视图：

| WorkBuddy | 言智现状 |
|---|---|
| 概览（工作空间文件） | file tab |
| 概览（浏览器） | browser tab |
| 概览（变更） | git tab |
| 产物 | 交付物 tab（`DeliverableFileCard`） |

（当前 file/browser/git 已覆盖前三者，产物视图可与文件 tab 合并或独立，见 §6 待确认。）

### 3.4 管理页 —— 下沉到「设置」

- 新建统一「设置」页（或 `SettingsDrawer` 扩展），聚合：
  - 模型平台（`/models`）
  - MCP 服务（`/mcp`）
  - 工具（`/tools`）
  - Skill 商店 / 蒸馏（`/skills` `/distill`）
  - 智能体（`/agents`）—— 保留但入口弱化为「设置内」或头像菜单
  - 知识库（`/knowledge`）
  - 记忆管理（`MemoryManage.vue`）
- 快捷触发保留（已做）：`/agent` 切智能体、`/model` 切模型、`/skill` 挂 Skill、`/dir` 设目录、`/new` 新建会话。
