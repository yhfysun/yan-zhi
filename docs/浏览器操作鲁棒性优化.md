# 浏览器操作鲁棒性优化 —— 方案文档

> 状态：已实施（本文档记录实施内容 + 后续可优化项）
> 目标：让浏览器自动化工具在定位失败时自动降级、且提供"视觉框标注截图"辅助，减少智能体往返与盲试循环，对齐豆包/WorkBuddy 的自动化程度。

---

## 一、现状盘点（源码实测）

浏览器工具集已非常成熟，共 **43 个工具**（`packages/core/src/tool/builtin/browser/index.ts`），覆盖：

| 能力族 | 工具 | 状态 |
|---|---|---|
| 导航/输入/点击/按键/滚动/悬停 | navigate/type/click/press_key/scroll/hover | ✅ |
| 页面读取 | get_text/get_dom/get_visible_text/get_page_content/get_page_info/get_a11y_tree | ✅ |
| 表单/搜索/翻页 | fill_form/submit_form/search/next_page/prev_page | ✅ |
| 加标签页/网络/结构化提取 | new_tab/switch_tab/close_tab/get_tabs/wait_for_request/get_network_log/extract_list | ✅ |
| 视觉定位闭环 | visual_locate（截图→image_analyze 识别） | ✅ |
| 上传/下载/拖拽/可见性 | upload/download/drag/scroll_into_view/is_visible | ✅ |

**已有鲁棒性机制（对比豆包/WorkBuddy 不落下风）：**
1. **三级定位**：`ref`（稳定引用 `d1:e12`）→ `index`（编号）→ `selector`（含 `:contains("text")` 伪选择器 / `:has-text` 转换）→ 坐标。
2. **空参兜底**：`click`/`type` 不传定位参数时，自动返回页面编号元素清单（前 25 个）引导模型用 index 重试。
3. **歧义检测**：selector 多匹配时返回带编号的候选列表，而非静默点错。
4. **无聚焦引导**：`type` 遇到"无聚焦元素"时返回引导而非裸报错。
5. **iframe / Shadow DOM 穿透**：DOM 采集与编号注册均已穿透。
6. **视觉定位闭环**：`visual_locate`（截图）+ `image_analyze`（vision 模型识别坐标），兜底弹窗/portal 结构 DOM 拿不到的场景。
7. **变化检测防循环**：`CHANGE_ACTIONS` 采前后快照，`noChangeStreak` 连续无变化会告警。

## 二、本次已实施的优化

### 1. 定位失效自动降级（减往返）⭐
**痛点**：SPA 里点一下按钮导致局部重渲染，后续 `index`/`ref` 全部失效，旧逻辑直接报错"已失效，请重新 get_page_info"，智能体被迫多跑一轮取号，慢且易卡循环。

**改动**：
- `ensureYzReg.register` 额外记录 `index → 稳定 selector` 快照（`selOf(index)`）。
- `click` / `type` 的 `ref`/`index` 失效时，**自动用注册时的 selector 快照重定位一次**；命中就直接点/输，命中不了才报错提示重取。结果里带 `autoRelocated` 标记。
- 双端同步：server Playwright（`apps/server/src/routes/browser.ts`）+ 桌面 BrowserView（`apps/desktop/main.cjs`）。

### 2. 截图元素标注（视觉辅助）⭐
**痛点**：豆包/WorkBuddy 支持"截图叠加可交互元素编号框"，视觉上直接看到可点元素；本项目 `browser_screenshot` 之前只返回裸 base64，视觉定位需两步绕（visual_locate + image_analyze）。

**改动**：
- `browser_screenshot` 新增 `annotate: true` 参数：注入 `z-index` 置顶覆盖层，给每个可交互元素画橙色编号框（编号 = index，可直接用于 click/type）。
- 双端同步：server Playwright + 桌面 BrowserView（`main.cjs` screenshot action）。

## 三、后续可优化项（未实施，供排期）

> 以下为对齐豆包/WorkBuddy 的进一步工程，按投入产出排序。

### P0（高价值、建议下一轮）
1. **统一"页面变化反馈"结构化**：`click`/`type` 返回目前是零散 JSON（`success`/`clicked`/`autoRelocated` 等字段不一），应统一为 `{ status, pageChanged, urlChanged, candidates?, hint? }` 单一结构，降低模型解析成本。
2. **`:has-text` 的精确匹配**：`genSel` 生成的选择器在文本变化后失效，快照降级命中率受文本漂移影响；可补"同标签 + 同 aria/text 模糊匹配"二级降级。

### P1（中价值）
3. **操作后自动校验**：click 后自动 `get_page_info` 对比目标元素状态（是否点了/页面是否跳转），返回"已确认变化"而非仅"已点击"。
4. **截图标注可选高亮目标**：`annotate` 支持 `highlight: {selector}` 高亮特定元素，聚焦定位。
5. **录屏/操作轨迹**：操作历史回放（排查自动化卡点用）。

### P2（低价值/锦上添花）
6. **跨站登录态快照**：浏览器状态持久化与一键恢复（当前已用 partition 持久化，缺"导出/导入会话"）。
7. **下载进度/断点续传**。
