# 店铺同步增强方案（2026-10-23，D 项）

> 目标：在已有「一次性导入/推送」之上，补**定时 + 手动全量、冲突策略、失败重试、审计汇总**。
> 原则不变：本地业务库是真源；演示店铺不触达平台；生产店铺每次写都要人工批准。

## 1. 触发方式

| 方式 | 入口 | 说明 |
|---|---|---|
| 手动单次导入 | 商品页「从平台导入」/ 订单页「从平台导入」 | 保留原有行为，冲突策略默认 `platform-first` |
| 手动全量 | 商品页「全量同步」→ `POST /connections/:id/sync/all` | 商品 + 订单各拉最多 5 页；生产店铺需 `approveProduction` |
| 定时 | 连接设置 `syncIntervalMin`（≥5 分钟） | 插件激活后每 60s 检查；**生产/演示店铺不自动跑** |
| AI | `shop_platform_sync action=sync-all` | 与手动全量同一实现；生产走 `runWriteGate` |

## 2. 冲突策略

连接字段 `syncPolicy`：

- `platform-first`（默认）：平台值覆盖本地标题/价格/图片/上下架状态；库存按平台值调整。
- `local-first`：保留本地价格/标题/库存，只更新平台 ID 与同步状态。

订单状态是硬底线，**任何策略都不允许倒退**：

```
pending → paid → sourcing → shipped → completed
任意未终态 → refunded
```

平台仍返回 `paid` 而本地已 `shipped` 时：保留本地，`conflicts+1`，`sync.status=failed` 并写原因。
`completed/refunded` 为终态，不再被平台改写。

## 3. 失败重试

- 只对**只读**请求（列表/商品/订单）在 `network` / `rate` 时重试，最多 2 次，间隔 400/800ms。
- **写操作绝不自动重试**（避免重复发货/重复下单）。
- 单条记录失败不中断整批：计入 `errors`，其余继续；最终汇总如实返回。

## 4. 审计与可观测

- 每次同步写一条 `sync.run` 审计：触发方式、新增/更新/冲突/失败、失败明细摘要。
- `plugin_storage.syncLog` 保留最近 100 条（shopId/时间/触发方式/计数/note），
  `GET /plugin/shop-ops/sync/log?shopId=` 可查；商品页「同步设置」显示最近 5 条。
- 单条商品/订单同步状态仍在 `attrs.sync = {status,at,error}`。

## 5. 分页与边界

- 淘宝/拼多多/1688/TikTok 按页循环（最多 5 页，页大小按各平台上限）。
- Shopify 支持 REST `Link: rel="next"` 游标分页（商品/订单各最多 5 页，每页最多 250）。
- 亚马逊全量商品走 `searchListingsItems`（卖家 SKU + summary/offers，pageToken 翻页，
  单次最多 5 页 × 20 条；官方上限 1000 条）；关键词/ASIN 搜索仍走 Catalog。
- 万邑通没有订单导入，出库单走 `order.ship`。
- 定时同步只写本地库；生产店铺必须手动批准后执行。

## 6. 验收

- `shop-platform-sync.test.ts`：导入/推送/状态倒退/冲突策略/拼多多分值/亚马逊零价/采购无部分写入。
- `shop-write-gate.test.ts`：连接编辑保留三层语义、同步日志与 `sync.run` 审计。
- 四条验收命令全绿（见会话交付记录）。
