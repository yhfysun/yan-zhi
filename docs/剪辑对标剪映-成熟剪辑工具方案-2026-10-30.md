# 剪辑对标剪映 · 成熟剪辑工具方案

> 日期：2026-10-30　｜　范围：剪辑模式（`/clip`）、`clip_project` 工具、剪辑师智能体、`skill_video_editing`
> 结论先行：**我们缺的不是"效果数量"，是三块地基——轨道模型、实时预览、智能层。** 效果库已经比大多数国产剪辑 App 全（32 滤镜 / 25 转场 / 17 特效 / 14 蒙版 / 8 文字动画 / 10 字幕模板），但因为地基是「单条顺序轨 + 抽单帧预览」，这些效果**叠不出"酷炫"，只能叠出"参数"**。

---

## 一、结论摘要

| 维度 | 剪映（CapCut） | 我们现在 | 差在哪 |
|---|---|---|---|
| 时间轴 | 多视频轨 + 无限音频轨 + 贴纸轨 + 多时间线 | **固定 4 行**（视频/字幕/BGM/画中画），视频轨首尾相接 | 不能分层叠加，做不出"主画面 + 补充镜头 + 贴纸"的复合画面 |
| 预览 | 实时 60fps 所见即所得 | **拖动播放头抽单帧**（PNG），无连续播放 | 手感不是"剪辑"，是"参数表单" |
| 关键帧 | 任意属性可打点 + 缓动曲线 | 只有 scale/offset/opacity 三个属性，**纯线性** | 运镜一律"机械匀速"，一眼就是模板味 |
| 调色 | 色轮 + HSL + RGB 曲线 + 浮点 | **32 个预设**，无手动调节 | 预设套不上时无解；不同素材拼不到一个色调 |
| 变速 | 曲线变速（速度曲线） | **恒定倍速**（0.25~4） | 做不出"突然慢放"的爆点 |
| 蒙版 | 线性/圆形/文字/钢笔（贝塞尔） | 14 种参数化形状 + 5 种色键 | 无自由形状、无蒙版关键帧 |
| 音频 | 多轨 + 升降调 + 人声分离 + 踩点 | 单 BGM + 整片音效链 | 没有独立音效轨，不能放"叮"「咚」这类点状音效 |
| 文字 | 花字/气泡/字体/字距行距 | 8 动画 + 10 模板，**只有字号/颜色/描边/位置** | 做不出"综艺花字"那种观感 |
| 智能 | 智能抠像/美颜/补帧/超分/剪口播/踩点 | **只有 whisper 自动字幕** | 智能层几乎空白 |
| 基础操作 | 分割/复制/定格/倒放/镜像/旋转 | 分割/复制/删除/修剪，**缺定格/倒放/镜像/旋转** | 缺的是最常用的那几个 |

**一句话定位**：我们现在的剪辑器是「**能按指令把素材装订成片**的自动化产线」，剪映是「**能让人反复试出感觉**的创作工具」。要让"趋于成熟"，必须补上"试"的回路——实时预览 + 可关键帧化的通用图层属性。这两件做完，现有 100+ 个效果立刻从"能选"变成"能调"，观感跃一个档。

### 2.2 效果库实况（数量足够，深度不足）

- **调色 32 项 / 转场 25 项 / 动态特效 17 项 / 蒙版形状 14 项 + 色键 5 项 / 文字动画 8 项 / 字幕模板 10 项 / 音效 9 项** — 数量对标剪映的"免费档"。
- 但是：**每一项都是"选中即生效"的二值开关**。没有强度、没有时长、没有曲线、没有组合。剪映的"特效"是有时长、可叠加、可调强度的**图层**；我们的是挂在片段上的**固定滤镜**。

### 2.3 三个结构性缺口（决定能力上限）

#### 缺口一：时间轴是「单条顺序数组」，不是「多轨图层」

```ts
// 现状：clips 首尾相接，没有"开始时间"这个概念
clips: ClipSegment[]     // 主视频轨
texts: ClipText[]        // 字幕轨（有绝对时间）
overlays: ClipOverlay[]  // 画中画（有绝对时间，但只有 file/pos/scale 四个字段）
bgm?: { file, volume, duck }  // 只能一条
```

后果：
- 不能两段视频同时出现（除画中画）→ 做不出"叠化双画面""蒙版分屏对比"
- 不能放点状音效（"叮""咚"）→ 转场音效只能靠 BGM 硬凑
- 画中画**不能有动画**（无关键帧），只能静态贴一个角
- 不能加贴纸轨
- 所有叠加层都在"字幕之下、主画面之上"的唯一层级，没有图层顺序

#### 缺口二：预览是「抽单帧」，不是「播放」

`clip-preview.ts` 的注释很诚实：

> 不做逐帧视频流……而剪辑中最需要的是"参数调对了没"的即时反馈，单帧抽图已覆盖。

**这个判断在"参数表单"阶段是对的，在"创作工具"阶段是错的。** 剪辑的核心手感是**节奏**——0.3 秒的转场、2 帧的卡点、渐快的推镜，单帧永远看不见。用户改用剪映往往不是因为效果多，是因为**能来回播着改**。

#### 缺口三：没有「通用可动画属性」

现状只有 `keyframes: [{t, scale, offsetX, offsetY, opacity}]`，且**只作用在视频段上**。字幕、画中画、贴纸都不能动。这直接封死了：
- 贴纸弹跳入场
- 画中画滑入
- 文字路径运动
- 转场遮罩移动

## 四、方案设计

### 4.1 数据模型 v2：向后兼容的「图层化」

**核心决策：不做「主轨自由布局」，做「主轨 + 通用图层」。**

理由：
1. 短视频剪辑 95% 是"顺序叙事"，主轨留空隙通常是误操作，剪映手机版也是"主轨磁吸"；
2. 主轨首尾相接让 `xfade` 链、时长累计、字幕时间推算全部保持简单；
3. 真正需要的"复合画面"用图层解决，成本低一个数量级；
4. v1 工程文件不用重写，老用户草稿不会坏。

```ts
// clip-project.ts — v2（version: 2，读 v1 时自动迁移）
interface ClipProjectV2 {
  version: 2;
  name: string;
  output: { size: string; fps: number; bitrate?: 'low' | 'std' | 'high' };
  /** 主视频轨：仍首尾相接（保持既有渲染/时长语义） */
  clips: ClipSegment[];
  /** 通用图层：字幕/贴纸/画中画/特效层/音频共用一套 */
  layers: Layer[];
  /** v1 的 texts/overlays/bgm 读入时迁移为 layers，写出时不再产生 */
  texts?: ClipText[];       // @deprecated v2 读时迁移
  overlays?: ClipOverlay[]; // @deprecated
  effects?: FxLayer[];      // 特效层（有时长）
}

type LayerKind = 'text' | 'image' | 'video' | 'sticker' | 'audio' | 'effect';

interface Layer {
  id: string;
  kind: LayerKind;
  file?: string;              // image/video/sticker
  text?: ClipText;            // kind=text 时沿用现有字幕结构
  start: number;              // 绝对时间轴秒
  end: number;
  /** 轨道序号（同层重叠时按 order 决定上下） */
  track: number;
  /** 变换：全部可关键帧 */
  transform: {
    x?: number; y?: number;            // 比例 -0.5~0.5
    scale?: number;
    rotation?: number;                 // 度
    opacity?: number;
    /** 混合模式 */
    blend?: 'normal' | 'screen' | 'multiply' | 'overlay' | 'softlight' | 'add' | 'darken' | 'lighten';
  };
  keyframes?: LayerKeyframe[];  // 任意属性打点 + easing
  /** 音频层专属 */
  audio?: { volume?: number; fadeIn?: number; fadeOut?: number };
}

interface LayerKeyframe {
  t: number;            // 0~1 图层内比例
  /** easing 到下一个点 */
  ease?: 'linear' | 'in' | 'out' | 'inout' | 'bezier';
  bezier?: [number, number, number, number];
  // 属性值同 transform
}
```

**迁移规则**（`migrateV1ToV2`，纯函数 + 单测）：

| v1 | v2 |
|---|---|
| `texts[]` | `layers[] kind=text, track=1` |
| `overlays[]` | `layers[] kind=video, track=0`（pos 换算成 transform.x/y） |
| `bgm` | `layers[] kind=audio, start=0, end=总长` |
| `audioFx[]` | 保留为工程级（不迁移），另加 `layers[] kind=audio` 用于点状音效 |

**为什么必须迁移而不是并存**：两套模型并存 = UI、工具、渲染三处都要写双分支，三个月内必然漂移（这个坑在效果库那 45 项→7 项的先例里已经踩过）。

### 4.2 关键帧与缓动：性价比最高的一个改动

现状 `buildPiecewiseExpr` 生成的是**分段线性**表达式，所以所有运镜都是"匀速起、匀速停"，这是"模板味"的最大来源。

**做法：在生成表达式之前，把缓动曲线采样成 N 个线性点。**

```ts
// clip-effects.ts 新增（纯函数，零渲染改动）
export function easePoints(pts: KfPoint[], ease: Ease, samples = 16): KfPoint[]
```

- `ease-in-out`（三次贝塞尔 0.42,0,0.58,1）采样 16 点 → 肉眼即"丝滑"
- 成本：**约 1 人日**（含单测）
- 渲染侧：**零改动**（还是分段线性，只是点变多）
- 感知收益：**极大**——同样的缩放关键帧，加缓动前后是两个时代的东西

> 这是整份方案里 ROI 最高的单项。建议**第一个做**。

### 4.3 实时预览：渐进式三档

现状（A）单帧抽图 → 目标（C）实时合成。直接上 C 风险太大，走 B 过渡。

| 档 | 方案 | 优点 | 缺点 | 成本 |
|---|---|---|---|---|
| **A 现状** | 播放头拖动 → ffmpeg 抽一帧（已带完整滤镜链 + 帧缓存） | 零漂移、零成本 | 不能播放；节奏看不见 | — |
| **B 分片代理缓存** | 每段按**工程指纹**渲染 480p 代理 mp4，缓存命中直接播；前端用 `<video>` 序列预加载下一段 | 与导出同一滤镜链（零漂移）；编辑单段只重渲那一段；实现简单 | 首次编辑有 0.3~1.5s 延迟；长片内存/磁盘占用需管理 | M |
| **C WebCodecs + WebGL** | `VideoDecoder` 解码 + WebGL 着色器做颜色/几何 + canvas 合成图层/文字 | 60fps 拖动；图层可直接鼠标拖；文字/贴纸零延迟 | **要把 32 滤镜 + 17 特效重写一遍 shader**，与 ffmpeg 必然有细微差异；工作量大 | XL |

**推荐：B 现在做，C 拆两半做。**

- **B（P0-12）**：代理缓存放 `<dataDir>/clip-proxy/`，键 = 段指纹（复用 `projectFingerprint` 思路），LRU 清理。
- **C-1（P1-10）**：只把**矢量图层**（文字、贴纸、形状蒙版、画中画位置）搬到前端 canvas/DOM 实时合成——这些不需要重编码，也不存在滤镜漂移问题。视频底层仍播代理。这一步就能实现"拖动贴纸/改字幕立刻看到"。
- **C-2（P2）**：像素级滤镜/特效上 WebGL，仅当"手感"真的成为瓶颈时再做。

> 诚实边界：C-1 之后，文字/贴纸是"真·实时"，颜色/特效是"代理近似"。这个混合方案剪映早期也这么干，可接受；但**必须在 UI 上标注**"代理预览"，避免用户以为成片就是这个码率。

### 4.4 渲染管线演进

**现状**（5~6 次编码）：分段重编码 → concat/xfade → 画中画重编码 → 字幕重编码 → 音效链 → BGM 混音 → 落盘

**问题**：多次编码掉画质、慢；图层顺序被写死在流程里（叠加层永远在字幕下）。

**阶段一（P0）**：保持步骤式，但把「画中画」升级为「图层链」：
```
[主轨成片] + [layer1] overlay(blend=screen, enable=between) + [layer2] ...
```
一个 `filter_complex` 里按 `track` 排序叠完所有图像层，字幕仍在最后（libass 必须在最上）。

**阶段二（P1）**：合并为**单次编码的全时间线 filtergraph**：
```
各段 normalize → xfade 链 → 图层 overlay 链 → subtitles → 音频图（amix + sidechain）→ 一次 -c:v libx264
```
- 收益：**画质只掉一次**、渲染快 30~50%、图层顺序严格可控
- 风险：filtergraph 复杂度爆炸（>10 段易触发 ffmpeg 内部限制）
- 缓解：**按 10 段分块**，块间仍 concat -c copy；同时保留现有 `buildRenderPlan` 纯函数 + 真实渲染验证脚本（`verify-effects.cjs` 的思路）

**红线**：无论怎么改，**渲染出口只能有一个**（`clip-render.ts`）。UI 与预览不得自己拼 ffmpeg 命令。

### 4.5 UI 信息架构（对应原型）

```
┌ 顶栏：项目 / 规格 / 质量档 / 预览档 / 导出 / 后台队列 ──────────────┐
│ 素材库(tab)   │      预览监视器        │    属性检视器            │
│ · 媒体        │  [安全区/网格/参考线]   │  · 图层（变换/混合/关键帧）│
│ · 贴纸        │  可直接拖动图层         │  · 调色（预设+手动+HSL）  │
│ · 花字        │                        │  · 蒙版（形状/羽化/关键帧）│
│ · 音效        │                        │  · 音频（音量/淡入淡出）  │
│ · 特效        │                        │  · 变速（曲线编辑器）      │
│ · 转场        │                        │  · 特效（强度/时长）      │
│ · 模板        ├────────────────────────┤                          │
│               │ 工具条 + 多轨时间轴     │                          │
└───────────────┴────────────────────────┴──────────────────────────┘
轨道（可增删/锁定/隐藏/调高）：主视频 ┃ 图层1 ┃ 图层2 ┃ 文字 ┃ 音效 ┃ BGM
```

关键交互补齐：
1. **预览里直接拖图层**（替代"属性面板改数字"）—— 拖 = 写 transform，松手落盘
2. **关键帧轨道缩略条**（每个属性一行菱形点，可拖点改时间）
3. **磁吸**：图层边缘吸播放头/其他图层边缘
4. **右键菜单扩充**：定格、倒放、镜像、分离音频、复制属性、粘贴属性

## 六、关键技术选型对比

### 6.1 轨道模型：重构 vs 渐进 vs 双写

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A 直接重构 | 一次性改成 `tracks[]`，clips 也变图层 | 模型最干净 | 渲染/UI/工具全改，回归面极大；老工程易坏 | ✗ |
| B 主轨 + 通用图层（推荐） | clips 保留，texts/overlays/bgm 迁进 layers | 兼容、增量、风险可控；覆盖 95% 需求 | 主轨不能自由留空/重叠 | ✓ |
| C 双模型并存 | v1/v2 各跑一套 | 表面平滑 | 三处双分支，必漂移（已踩过同类坑） | ✗ |

### 6.2 预览：代理 vs WebCodecs vs 现状

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 现状抽帧 | 零成本零漂移 | 无播放，无节奏 | 保留作"单帧精查" |
| **分片代理（B）** | 零漂移、单段增量、实现简单 | 编辑后 0.3~1.5s 延迟 | **P0 采用** |
| WebCodecs+WebGL（C） | 60fps、可直接拖图层 | 效果要重写 shader，必与 ffmpeg 有差异 | P1 只做矢量层，P2 再考虑像素层 |

### 6.3 渲染：多次编码 vs 单图一次编码

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 现状步骤式 | 简单、每步可排查 | 5~6 次编码掉画质、慢 | P0 保留（升级图层链） |
| 单图一次编码 | 画质只掉一次、快 30~50% | filtergraph 复杂，>10 段易炸 | P1 采用，按 10 段分块 |

### 6.4 曲线变速：切片 vs 表达式

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 切片（N 段不同 setpts + concat） | 确定、可单测、音频可逐片 atempo | 段边界可能有 1 帧抖动；N 大时重编码多 | **采用**，N=12~24，边界用 `tpad`/短重叠补齐 |
| setpts 表达式 | 无切片 | ffmpeg 无法表达"变速导致的时长变化"，音画会脱 | ✗ |

### 6.5 贴纸/花字素材从哪来

| 方案 | 优点 | 缺点 |
|---|---|---|
| 买素材库 | 现成好看 | 版权成本、包体 |
| **程序化生成（SVG→PNG / ASS 绘制）** | 零版权、可换色、包体小 | 审美上限低，需要设计投入 |
| 用户导入 | 灵活 | 无"一键好看" |

> 建议：**内置 30~50 个程序化模板打底 + 支持用户导入**，不做素材商店。

## 七、风险与红线

| 风险 | 影响 | 缓解 |
|---|---|---|
| filter_complex 复杂度爆炸 | 渲染失败、报错指向不明 | 每步 label 化 + 失败回报具体步骤（已有）；>10 段分块 |
| 代理预览与成片不一致 | 用户信任崩塌 | 代理**用同一份滤镜链**；UI 明确标注"代理";导出前强制"预览档" |
| v1→v2 迁移坏老草稿 | 用户成果丢失 | 迁移前备份 `.clipproj.v1.bak`；纯函数迁移 + 全量 fixture 单测 |
| 效果数量继续膨胀 | 面板难用、模型选错 | 效果必须有 `group` + `desc`；新增先进注册表，禁止散落 |
| 真实播放拖累主进程 | 应用卡顿 | 代理生成走子进程 + 队列；前端只读缓存 |
| 智能层模型体积 | 安装包/首启 | 一律按需下载 + 显式告知（沿用 whisper 模式） |

**红线（不可破）**：
1. 渲染出口唯一（`clip-render.ts`），UI 与预览不得自拼命令
2. 工程单一事实源，UI 与智能体操作同一份 json、同一组 op
3. 效果注册表唯一（`clip-effects.ts`），新增效果只改一处
4. 预览与导出共用滤镜链定义
5. 老工程必须能打开

### 顺带修掉的两个真实缺陷（都是"不报错但画面错"）

1. **起点锚被丢弃** —— `normalizeKeyframes` 旧规则"偏离恒等值才算有意义"，于是 `{t:0, scale:1}` 被丢。剩下的 `{t:1, scale:1.4}` 变成**全程 1.4（画面是静的）**，用户以为在推镜。缓动更依赖端点锚，必须修。
   → 改为「给了属性就保留该点」，最后再判断整条曲线是否恒定（恒定才整体丢弃）；同 t 去重保留后者。
2. **透明度淡出 → 整段全黑** —— `opacityKfExpr` 旧实现只取 `opacity < 0.999` 的点，`[{t:0,opacity:1},{t:1,opacity:0}]` 只剩一个点，`buildPiecewiseExpr` 对单点返回常量 `0` → `a=0` → **整段全黑**，ffmpeg 不报错。
   → 改为带上所有给了 `opacity` 的点，并先判断"是否存在压到 1 以下的点"。

> 这两个都属于典型陷阱：**单点关键帧在分段线性表达式里会退化成常量**。凡是"逐属性过滤关键帧点"的地方都要警惕。

### 做了什么

| 层 | 改动 |
|---|---|
| 工程模型 | `ClipSegment` 新增 `rotate`(90/180/270) / `flip`(h/v/both) / `reverse`；归一化只收合法值，`0`/空串不落字段 |
| 渲染 | 旋转/镜像排在**规格化之前**；`reverse` 排在**淡入淡出之前**；音轨同步 `areverse`（配音替换、原声混音、kf 合成三条分支都覆盖） |
| 预览 | `projectFingerprint` 纳入三个新字段（否则旋转后预览帧不刷新 → 预览骗人） |
| UI | 片段属性面板新增「方向」：旋转下拉 / 镜像下拉 / 倒放勾选 |
| 工具面 | `add_clip` items 补三个字段，描述里写清限制 |

### 三个非显然的顺序问题（都写进了注释）

1. **旋转必须在规格化之前**。先 `scale/crop` 到 W×H 再旋转会输出 H×W，concat 时规格不一致 → 失败点在"拼接"那一步，报错指不到这里。
2. **倒放必须在淡入淡出之前**。`reverse` 只倒帧序；淡入淡出要按"成片时间"生效，否则倒放后原来的淡出会跑到开头。
3. **倒放会给进程灌内存**。ffmpeg 的 `reverse` 把整段帧读进内存（1080×1920 一帧约 3MB），所以设了 `REVERSE_MAX_SEC = 10`：超了**在计划阶段就拒绝**并说明原因，而不是等 ffmpeg 把进程拖垮（OOM 的表现是"进程消失"，完全看不出是倒放引起的）。

### 定格（已补）

定格 = **抽一帧落盘 → 作为图片段插到该段之后**。为此补了两块：

1. **`POST /api/clip/freeze`**：定位播放头所在段 → 按 `trimStart + 段内偏移 × speed` 换算回素材时间 → 抽一帧 PNG 落到会话素材目录 → 登记 `conversation_file`（同时出现在素材库）。抽的是**素材原始帧**，前端把源段的调色/特效/裁剪/蒙版继承到新片段上，观感才接得上。
2. **`kenburns.direction: 'none'`**：图片段原本必须有运镜才能自定时长（否则固定 3 秒）。加 `none` 后 = 恒定 1 倍速的静止画面 + 任意时长，正是定格需要的东西。顺带让**所有图片段**都能在属性面板选「静止/推近/拉远 + 时长」——此前图片时长是锁死的 3 秒。

UI：片段属性面板头部一个定格按钮；图片段显示「静止/运镜 + 时长」而不是「变速」。

## 十三、P0-5 实施记录（手动调色 + 滤镜强度）

### 做了什么

| 层 | 改动 |
|---|---|
| 工程模型 | `ClipSegment` 新增 `colorStrength`(0~1) 与 `adjust`{brightness/contrast/saturation/temperature/sharpness/vignette}；等于默认值的项不落字段 |
| 渲染 | 预设强度走 `split + blend=all_opacity`；手动调节走 `eq → colorbalance → unsharp → vignette`，叠在预设**之后**、特效之前 |
| UI | 有预设时出现「滤镜强度」滑杆；新增「手动调节」折叠组（6 个滑杆 + 一键复位） |
| 工具面 | `add_clip` 补 `colorStrength` / `adjust`（含值域与用法说明） |
| 技能 | 参数表、选型表（预设太浓/素材偏色/产品不锐/情绪压暗）同步 |

### 两个设计取舍

1. **强度为什么用 `blend` 而不是逐个参数插值**
   预设里有 `noise`（颗粒）、`vignette`（暗角）、`curves` 这类**无法线性插值**的效果 —— "半个噪点"没有意义，参数也不可能通用地缩放到 50%。做法是：把原片与"上过滤镜的画面"按 `all_opacity` 混合。对**任意**预设都成立，代价是一次 `split` + 一次 `blend`（每像素运算，可接受）。

2. **手动调节为什么在预设之后**
   用户的真实意图是"先选个风格，再在上面微调明暗冷暖"。反过来的话，微调会被预设整体覆盖掉，等于白调。

### 顺序铁律

`eq`（整体明暗）→ `colorbalance`（色温）→ `unsharp`（锐化）→ `vignette`（暗角）。
**暗角必须最后**：它按"画面边缘"压暗，先压暗再锐化会把暗角糊开成脏边。

- [x] 单测：越界钳制、默认值不落盘、`update_clip` 可清除、强度=1 不加 blend / <1 加 blend、六个滤镜的先后顺序、预设与手动调节可叠加
- [x] core / server 类型检查通过；server 65 条 clip 单测全过

### 为什么参数写在注册表里而不是 UI 里

效果注册表现在同时驱动四件事：UI 列表、工具 enum、渲染实现、**参数声明**。
参数一旦在 UI 里手写第二份，就会出现"滑杆范围 0.1~0.8、ffmpeg 实际能吃 0~1"这类漂移——调到头也没区别，且不报错。守门测试专门钉了两条双向一致性：filter 里的 `{key}` 必须在 params 里声明；params 声明的键必须真的被 filter 用到。

### 一处刻意的取舍：`ghost` 去掉了权重串

原来用 `tmix=frames=6:weights='1 1 1 1 1 1'` —— 权重个数**必须等于帧数**，参数化后帧数一变就得重建权重串，等于把参数化这件事做成了字符串拼接。改用 `tmix=frames=N`（等权），观感几乎无差别，但帧数可以安全地调到任意值。

### 时长

「特效时长」这一项**没有做**：现有特效挂在片段上，时长天然等于片段时长。要支持"片段里只有 2 秒有故障效果"，需要的是**特效图层**（P1-3），不是给特效加一个 duration 参数。这里不硬塞。

## 十六、P0-6 实施记录（曲线变速）

### 为什么是"切片"而不是一条表达式

理论上可以写一条分段 `setpts` 表达式（输出时间 = 速度的积分，分段线性速度 → 分段二次）。**但音轨做不到**：`atempo` 只接受常量，`rubberband` 也不支持时变。视频动了音频不动就是音画分离。

所以定案：**按源时间切成 8 片 → 每片恒定倍速（视频 `setpts` + 音轨 `atempo`）→ 拼回**。音画共用同一套切片边界。

### 三层共用一份切片数学（关键）

新增在 `clip-effects.ts` 的纯函数：`speedSlices` / `speedCurveDuration` / `speedCurveOutToSrc`。

| 用处 | 用哪个 |
|---|---|
| 渲染切片 | `speedSlices` |
| 段时长 / 时间轴长度 / 字幕推算 | `speedCurveDuration` |
| 预览抽帧定位（输出偏移 → 源偏移） | `speedCurveOutToSrc` |

★ 这三处**必须**同源。各写一份的话，典型症状是"时间轴长度与成片对不上、字幕整体偏移"，而且完全不报错——只能靠肉眼发现。

### 渲染结构

```
段处理（1 倍出整段，视觉/调色/蒙版/淡入淡出都在源时间里生效）
  → 变速片 ×8（-ss/-t 取区间 + setpts=PTS/speed + atempo）
  → concat -c copy 拼回 segOut
```

代价：曲线段多 1 + 8 次编码。段长被拉长的同时也拉长了淡入淡出——这是**有意的**：淡入淡出属于画面内容，内容被时移，淡变也该跟着时移。

### 顺带修掉一个"只有真跑才炸"的 bug

排查切片分支时发现：**透明度关键帧 + 有原声**、以及**透明度关键帧 + 无音轨**这两条分支，`args` 拼到 `-map [a]` 就结束了，**没有推输出文件路径**。ffmpeg 会报 "At least one output file must be specified"，而纯函数测试只看字符串，所以一直没暴露。已补上输出参数。

> 这类"args 拼漏一个参数"的问题，只有真跑才看得出来；单测能守住的是**结构**（有没有输出、顺序对不对），守不住"这个值合不合法"。所以真机出片验证这一步不能省。

### UI

属性面板「变速」下加一个「曲线变速（起 / 中 / 止三段）」开关 + 三个倍速输入。勾选后恒定倍速滑杆禁用（两者互斥）。拖拽式曲线编辑器留作后续（当前三段式覆盖"慢动作爆点 / 快进过场 / 由慢到常速"三类主场景）。

- [x] shared：插值/clamp、切片数与连续性、恒定 2× 时长、慢动作时长变长、输出→源映射单调且两端对齐、平直判定

### 三个刻意的取舍

1. **节拍不明显直接拒绝**。自研检测器只抓鼓点/重音，连绵弦乐会漏。硬凑点让用户逐个删，比说"换一首"糟糕得多——沿用 `clip-beats` 的 `MIN_BEATS=6` 纪律。
2. **曲线变速段整段跳过**。曲线是"整段源时间上的倍速函数"，从中间切开后每片都会从自己的 0% 重跑曲线，观感与预期不符。如实跳过并在 note 里报数。
3. **关键帧重映射而不是丢弃**。关键帧的 t 是段内输出时间比例；切开后每片各占原段一段比例，直接等比缩放会让切点处值不连续（画面跳一下）。所以在**切点处插值出两个锚点**，保证接缝处取值连续。

### 为什么切点换算要单独写

成片时间 → 段内偏移 → 素材时间，恒定倍速是线性的（`× speed`），但曲线变速不是。切点换算目前复用 `segmentDuration`（支持曲线），曲线段本身被跳过，所以落点是安全的；将来若要支持曲线段切分，换算必须改走 `speedCurveOutToSrc`。

### 做了什么

| 层 | 改动 |
|---|---|
| 新服务 `services/clip-proxy.ts` | 段指纹（只含本段画面/声音字段）→ 缓存键 = sha1(版本\|段指纹\|代理画幅\|fps)；`ensureSegmentProxy` 生成或命中；`pruneProxyCache` 磁盘 LRU（上限 500 条，超限淘汰到 75%，只删 .mp4） |

| 守门 | UI 测试同步三态签名；`clip-proxy.test.ts` 19 条 |

### 三个设计点

1. **渲染出口唯一不破**：代理不是"第二套滤镜实现"——它派生单段工程走 buildRenderPlan，和导出共用 buildSegmentFilters/assembleSegmentChain。改滤镜链一处，预览与导出同时变。
2. **改一段只重渲一段**：指纹只含本段字段（trim/变速/调色/特效/蒙版/运镜/淡入淡出/音频），别的段改参数不牵连本段键；URL 带 `v=工程版本` 穿透浏览器缓存。
3. **半成品不占缓存位**：产物先落 `tmp-*` 临时目录，runRenderPlan 全步成功 + 非空校验后才 rename 进缓存位；失败清理临时目录。

### 诚实边界

- **本机无 ffmpeg，实渲染路径未验证**：单测覆盖纯函数层（指纹/键/画幅/时长换算/缓存清理）；
  真实出片、连播流畅度、"改一段 ≤2s"的体感需真机验收（有 ffmpeg 的环境打开工程切「代理」）。
- 代理不含字幕/BGM/画中画/音效链（整片级元素，单段代理叠不进去；字幕核对走"出预览档"）。
- BGM 缺席意味着代理是无声的：节奏看得到，声音听不到（声音核对走成片模式）。
