# 即梦签到自动化失败：问题分析与修复方案

> 分析时间：2026-08-30 ｜ 分析对象：言智（yan-zhi）内置 Skill「即梦每日签到」
> 证据来源：桌面端会话数据库 `%APPDATA%\@yan-zhi\desktop\yan-zhi.db`（7 个"即梦签到"会话，约 380 条消息）
> 涉及代码：`apps/desktop/main.cjs`、`apps/server/src/routes/browser.ts`、`packages/ui/src/stores/agent.ts`、`packages/core/src/db/schema.ts`、`.claude/skills/jimeng-daily-checkin/SKILL.md`

## 一、问题概述

用户多次对言智说"即梦签到"，期望模型驱动内置浏览器自动登录即梦（jimeng.jianying.com）完成每日签到领取灵感值。实际**反复尝试近 3 小时（02:47 → 05:17）、开了 7 个会话、最长一个会话循环 185 轮，最终全部失败**。最长会话以 LLM 平台请求崩溃收尾，其余会话要么放弃改给手动步骤，要么子智能体调用挂起。

## 三、根因分析（按致命度排序）

### 🔴 R1. 即梦登录强依赖人工，自动化无法闭环（最根本）

即梦签到必须先登录，登录方式只有**抖音扫码**或**手机号+短信验证码**——两者都需要人介入（扫码 / 收短信）。Skill 文档虽写"首次扫码后 cookie 复用"，但实际：

- BrowserView 使用独立 partition `'browser-view'`（`main.cjs:226`），**非持久化 partition**，cookie 不落盘，每次新开浏览器登录态丢失，又要重新扫码；
- 模型走偏成"代填手机号+验证码"死胡同：ask_user 要手机号 → 要验证码 → 验证码按钮点不动 → 死循环。

### 🔴 R2. `browser_get_dom` 拿不到登录弹窗的 DOM（直接技术卡点）

`browser_get_dom`（`main.cjs:715-747` / `browser.ts:183-216`）从 `document.body` 向下走 DOM 树，受 `maxDepth=8 / maxNodes=500` 限制，且**只遍历 `el.children`，不穿透 iframe / Shadow DOM**。即梦登录弹窗渲染在深层 portal / iframe 里，返回只有 65 个外层节点（倒计时 banner、导航"灵感/生成/资产/画布/登录/领积分"），**弹窗内的 input、按钮根本没出现在 DOM 里**。模型看不到弹窗结构，只能靠截图盲猜。

### 🔴 R3. CSS 选择器全 miss + 坐标盲点无视觉闭环

即梦用动态 hash class（`input-xrB84C`、`button.code-bu`、`.method-button-Dyg8I8`），模型从截图猜的选择器对不上；`:contains("发送验证码")`（`main.cjs:480-487` 的伪选择器实现）也找不到（按钮文字不符 / 不在 `button` 标签 / 弹窗在 iframe）。于是模型退化为 **截图 → 猜坐标 (600,500)/(850,100)/(1380,50) → 点击 → 再截图** 的盲点循环，185 条里循环 80+ 次无终止条件。

### 🟠 R4. pageAgent 子智能体调用不稳定

- 首次 `call_agent` 直接 `{"error":"子智能体执行失败: Failed to fetch"}`；
- 第二次返回 `(已达最大步数)`——pageAgent 内部 ReAct `maxReReactSteps=15`（`agent.ts:165`）用完还没搞定就退出；
- 多个会话 call_agent 发出后结果未落库，子智能体链路有稳定性问题。

### 🟠 R5. 外部 LLM 平台与搜索服务挂掉

- 最长会话结尾：`apihub.agnes-ai.com/v1/chat/completions` 请求失败（CORS / 网络不通，signal aborted）——**模型连推理都调不通，对话循环直接崩**；
- `web_search` 多次返回 `HTTP 500`，模型失去信息补充渠道。

### 🟡 R6. Skill 未真正激活 + 目标站不一致

Skill 文档写的是 `jimeng.jianying.com`（中文版），但模型有时自作主张访问 `dreamina.ai`（国际版英文站，"Sign in"），目标网站都搞错；且 Skill 的标准流程**没作为强约束注入 pageAgent 的 systemPrompt**，pageAgent 自己乱走。

## 四、修复方案

按"代码层可改、高价值、低风险"优先，实施 4 项修复。R5（外部 LLM 平台/搜索服务）属运行时配置，不在代码修复范围，文档给出建议。

### 修复 1：`browser_get_dom` 穿透 iframe + 提高上限（对应 R2）

**文件**：`apps/desktop/main.cjs`（`get_dom` 分支）、`apps/server/src/routes/browser.ts`（`get_dom` 分支）

**改动**：
1. 默认 `maxDepth` 由 8 → **12**，`maxNodes` 由 500 → **1000**；
2. `walk` 遇到 `<iframe>` / `<frame>` 时，尝试递归进入其 `contentDocument.body` 继续遍历，并在节点上标注 `iframe: true`（同源才可进入，跨域捕获异常跳过）；
3. 遇到 `element.shadowRoot` 时递归进入 Shadow DOM；
4. 返回结果增加 `iframes` 字段，列出穿透到的 iframe 数量与跨域被跳过的数量，便于模型判断弹窗是否在跨域 iframe（若是则提示需另寻定位方式）。

**预期效果**：登录弹窗（即使在 iframe/Shadow DOM/深层 portal）能被 `get_dom` 抓到，模型据此构造准确选择器，告别盲猜。

### 修复 2：BrowserView partition 持久化登录态（对应 R1）

**文件**：`apps/desktop/main.cjs`（`ensureBrowserView`）

**改动**：partition 由 `'browser-view'` → `'persist:browser-view'`。Electron 中 `persist:` 前缀的 partition 会将 cookie / localStorage / 缓存落盘到 userData 目录，跨会话保留。

**预期效果**：用户首次扫码登录即梦后，cookie 持久化；后续签到（含定时任务）无需重复扫码，直到 cookie 过期。这是 Skill 文档承诺的"cookie 复用"得以真正生效的前提。

**副作用**：BrowserView 会持久化所有访问过站点的 cookie。本应用 BrowserView 仅用于 pageAgent 自动化操作，可接受；若需隔离可后续加清理工具。

### 修复 3：pageAgent systemPrompt 强化（对应 R3 / R6 / R1 流程走偏）

**文件**：`packages/ui/src/stores/agent.ts`（`PAGE_AGENT_DATA.systemPrompt`）

**改动**：在 systemPrompt 末尾追加"硬约束与终止条件"段：
1. **目标站固定**：即梦签到只允许访问 `https://jimeng.jianying.com/`，**禁止访问 dreamina.ai / dreamina.com 等国际版**（国际版无中文签到入口）；
2. **登录流程强约束**：检测到未登录 → **必须** `ask_user` 提示用户在浏览器面板扫码登录 → 等用户确认 → `browser_get_page_info` 复核已登录。**禁止代填手机号 / 代填验证码**（验证码需用户手机接收，代填必死循环）；
3. **已知稳定选择器**：注入即梦已确认的选择器——领积分入口 `#SiderMenuCredit`；登录弹窗出现后优先用 `browser_get_dom`（已支持穿透 iframe）抓弹窗结构再定位，而非盲猜 hash class；
4. **终止条件**：同一选择器连续 miss **2 次**即停止盲试，改用 `ask_user` 请求用户手动操作或 `browser_screenshot` 重新分析；坐标盲点击连续 **3 次**无页面变化即停止；
5. **优先级**：定位元素顺序 = `browser_get_dom` 抓结构 → ARIA/role → 稳定 id → `:contains(可见文本)` → 坐标（最后手段）。

**预期效果**：杜绝目标站搞错、代填验证码死循环、盲点 80+ 次不收敛三个问题。

### 修复 4：Skill 文档与 seed 修正（对应 R6）

**文件**：`.claude/skills/jimeng-daily-checkin/SKILL.md`、`packages/core/src/db/schema.ts`（`skill_jimeng_daily_checkin` seed）

**改动**：
1. SKILL.md 顶部加 **⚠️ 重要约束**：固定站 `jimeng.jianying.com`，禁止 dreamina.ai；登录只走扫码流程，不代填手机号验证码；
2. 明确"登录态持久化"依赖 `persist:browser-view` partition（修复 2），首次扫码后自动复用；
3. seed `bodyMd` 同步加固定站与扫码流程约束，确保新装用户看到的 Skill 描述一致。

**预期效果**：Skill 触发时模型拿到的流程指引与 pageAgent systemPrompt 一致，不再自作主张访问国际版。

### R5（外部平台）建议（不在代码修复范围）

- `apihub.agnes-ai.com` 不稳定 / CORS：在模型平台配置中换稳定网关，或配置本地代理；
- `web_search` HTTP 500：检查后端搜索服务（`apps/server`）是否启动、搜索 API key 是否配置；
- ~~`call_agent` Failed to fetch：检查子智能体调用链路网络，必要时加重试~~ → 已由修复 5 覆盖（网络错误自动重试 1 次）；若仍频繁失败，需排查 LLM 平台本身的网络/ CORS。

## 六、验证建议

实施后按以下顺序验证：

1. **get_dom 穿透**：桌面端打开即梦，点"领积分"弹登录框，调用 `browser_get_dom`（depth 12, maxNodes 1000），确认返回节点数 > 65 且包含登录弹窗的 input/button；
2. **登录态持久化**：扫码登录即梦 → 关闭 BrowserView → 重新打开 → `browser_get_page_info` 确认仍为已登录态；
3. **端到端签到**：新会话发"即梦签到"，确认模型：① 访问 jimeng.jianying.com（非 dreamina.ai）；② 已登录则直接找签到入口；③ 未登录则 ask_user 扫码（不代填验证码）；④ 签到成功回报灵感值；
4. **终止条件**：构造一个选择器 miss 场景，确认模型 2 次失败后停止盲试转 ask_user，不再循环 80+ 次。

## 七、遗留问题与后续

- **跨域 iframe**：若即梦登录弹窗在跨域 iframe 内，`get_dom` 无法穿透（浏览器同源策略），需改用坐标定位或让用户手动登录后复用 cookie（修复 2 已覆盖此场景）；
- **UI 变更**：即梦可能调整 UI，`#SiderMenuCredit` 等选择器失效，需定期用 `browser_get_page_info` 动态查找兜底；
- **定时任务签到**：cookie 过期后定时任务无法自动扫码，需通知用户手动续登（建议后续加 cookie 过期检测 + 通知）；
- **R5 外部平台稳定性**：需用户侧配置稳定 LLM 网关，代码层无法根治。
