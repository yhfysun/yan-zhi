# ADR-0001: 桌面与移动端采用分层的应用壳

## Status

Proposed

## Date

2026-11-17

## Context

言智当前三端共享 Vue UI，但桌面、Web 和 Capacitor 仍容易退化成同一套网页导航和页面布局：

- 桌面端顶部使用横向网页导航；
- 窄窗仍保留 Web 顶栏；
- 店铺运营在移动端直接隐藏工作台；
- 管理页和日常任务共享一级导航；
- 输入、菜单、状态栏等交互没有明确区分桌面和触屏。

用户明确要求减少 Web 应用气息，同时保留现有 Electron、Capacitor 和 Vue 技术栈。

## Decision

采用三层应用壳：

1. **Desktop App Shell**：窗口标题栏 + 模式栏 + 上下文栏 + 主任务区 + 检查器 + 状态栏。
2. **Web App Shell**：顶部轻量导航 + 主内容，允许功能降级，不反向约束桌面布局。
3. **Mobile App Shell**：顶栏上下文 + 单主内容 + 最多四个底部主入口 + 底部抽屉/全屏单步流程。

三端共享业务组件和设计 Token，不共享一级导航形态。

店铺运营使用独立的运营台骨架：

- 桌面：看板、待办、表格、右侧检查器；
- 移动：总览、待办、商品、订单、发货；
- AI 始终作为上下文检查器或命令入口，不再与工作台争夺数据真相。

## Alternatives Considered

### 继续使用单一 Web 响应式壳

- Pros：改动最小，路由共用。
- Cons：桌面像网页，移动像压缩后台，难以建立窗口语义和触屏优先级。
- Rejected：无法满足“去 Web 应用化”的核心目标。

### 为桌面和移动建立两套独立前端

- Pros：平台体验上限最高。
- Cons：重复业务组件、状态和测试，维护成本过高。
- Rejected：当前阶段不适合拆仓或拆框架。

### 只改颜色和圆角

- Pros：最快。
- Cons：不解决信息架构、键盘路径、触控区和层级问题。
- Rejected：只能得到“换皮的 Web 后台”。

## Consequences

- `WebTopBar`、`SideNav`、`App.vue` 和状态栏需要按平台拆分职责；
- 店铺和设备工具页需要增加桌面/移动专用布局组件；
- 设计 Token 必须增加桌面尺寸和触控尺寸两类；
- 所有改造必须做桌面、Web 窄窗和 Capacitor 三端回归；
- 管理页会从主顶栏下沉，需要保证 `Ctrl+K` 和头像菜单完整可达。

## Verification

- 桌面 1440px / 1024px 截图；
- Web 390px 截图；
- Capacitor 真机一次触控回归；
- 无横向溢出、无焦点丢失、无隐藏入口；
- UI 测试、typecheck 和 Web 生产构建通过。
