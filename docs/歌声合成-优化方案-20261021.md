# 歌声合成（DiffSinger）优化方案

> 2026-10-21。当前状态：opencpop 模型全链路可用（`music_compose` → `vocalEngine=diffsinger`）；
> 绮萱（可商用声库）推理能出声但**字听不清、效果不如 TTS**。
> 本文档给下轮会话直接当输入用。

## 一、结论先行

正版 SVS 应该明显好于 TTS 变调。现在比 TTS 还差，说明**喂给模型的序列是错的**（音素/时长/音高），
而不是模型或声码器不行。优化顺序必须是「先对齐正确性，再调自然度」，不要先去调音色。

## 二、按可能性排序的根因与验证方法

| # | 可能原因 | 症状 | 怎么验证 |
|---|---|---|---|
| 1 | **音素 id 基数错位**（phonemes.json 是 1 起，模型 embedding 0 起；或缺少 BOS/EOS） | 全句含糊、像念另一个语言 | 打印 token 序列与 id；与 OpenUTAU 导出的 `.ds` 文件对比（.ds 里就是音素序列） |
| 2 | **拼音→音素映射是自写的**（zh/ir、zh/i0、y/w、ü→v 等规则） | 个别字错、声母丢失 | 拿同一句在 OpenUTAU 里导出 `.ds`，逐音素比对 |
| 3 | **时长分配错误**（我按"声母占 28%"硬切；真实音素器有 head/tail、连音规则） | 语速怪、字糊在一起 | 对比 OpenUTAU 的 `PaddedPhoneDurations` 输出 |
| 4 | **f0 曲线过于平直**（每个音符恒定、无滑音/颤音） | 机械、跑调感 | 看 f0 数组；OpenUTAU 会做采样曲线+滑音 |
| 5 | **表情参数默认值不对**（breathiness/voicing/gender/velocity） | 发闷/发虚 | 取 OpenUTAU 源码里的默认值 |
| 6 | **depth / steps 不对**（浅扩散深度 0.6、步数 32 是猜的） | 音质糊或金属 | 对照 OpenUTAU Preferences 默认值；扫 depth 0.3~0.8 |
| 7 | **mel 是否已反归一化** | 整体闷/炸 | 看导出说明；必要时按 config 的 spec_min/max 处理 |
| 8 | 声码器不匹配（pc_nsf 是 NC 授权且版本可能与模型训练配置不同） | 音色怪 | 换官方推荐的 vocoder 版本对比 |

> 最快的破局方法：**用 OpenUTAU 渲染同一句，导出 `.ds` 与参考音频**，把 `.ds` 直接灌进我们的 runner。
> 如果这样声音正常 → 问题 100% 在映射/时长；如果仍不对 → 才是模型接口问题。

## 三、优化方案（分阶段，每阶段有验收）

### P0 正确性对齐（必须先做）
1. 拿到 OpenUTAU 的 `.ds` 导出（同一句歌词），逐字段对齐：音素序列、durations、f0 长度。
2. 核对 `phonemes.json` 的 id 基数和是否需要首尾 `SP`。
3. 用官方音素器规则重写拼音→音素（含 zh/ir、zh/i0、y/w、ü→v、er）。
4. 验收：同一句连续 3 次渲染，**盲听能辨认 ≥4/5 字**；与 OpenUTAU 参考音频的 mel 谱距离显著下降。

### P1 自然度
1. f0：音符内轻微颤音、音符间滑音；休止符 f0=0 且在边界平滑。
2. 表情参数：从 OpenUTAU 源码取默认（不要拍脑袋）。
3. depth/steps 扫描，选主观最好的一组并固定。
4. 验收：不刺耳、无爆音、句尾不截断。

### P2 产品集成
1. 声库做成**可配置目录**（`singing/voices/<name>/`），Node 侧按配置选引擎。
2. 安装器增加"声库包"安装（当前只装 opencpop 模型）。
3. 许可合规：**声码器必须换成可商用版本**，否则整条链不能商用（绮萱声库本身可商用，但社区 pc_nsf 声码器是 CC BY-NC-SA）。
4. 验收：换声库只改配置不改代码；工具返回里标明声库名与授权提示。

## 七、P0 审计结果（2026-10-21 第二会话，源码级）

基准不再是"凭 OpenUTAU 导出"，而是直接读 OpenUTAU 源码：
`OpenUtau.Core/DiffSinger/{DiffSingerUtils,DiffSingerRenderer,DiffSingerBasePhonemizer}.cs`。

| # | 旧桥做法 | OpenUTAU 实际 | 影响 |
|---|---|---|---|
| 1 | 自写 `split_pinyin` | 查声库 `dsdur/dsdict-zh.yaml`（135k 条，grapheme=拼音 → phonemes） | 月=yue 丢 `zh/y0`；五=wu 丢 `zh/w`；卷=j+**uan**（应 j+van）；云=y+vn（应 y0+vn）；翁=ueng（应 w+ueng）。系统性错。 |
| 2 | 每字后插 5 帧 SP，无头 SP，尾 26 帧 | 头 SP **8 帧** + 仅"音符间真空档"插 SP + 尾 SP **8 帧**；音符内声母/韵母之间**不插** SP | 字被切断、句首缺静音上下文 |
| 3 | languages 全填 zh=3 | SP/AP 填 **0**，真实音素填 3 | 静音段的语言 embedding 错位 |
| 4 | velocity = 0 | **1.0**（VELC 100 → 2^0） | 相当于半个速度的 embedding |
| 5 | 每个音素各自 round | 毫秒**累加后**取整再作差 | 长句时长漂移 |
| 6 | 输出直落盘，峰值 1.0（0.26% 削顶） | — | 削波失真（刺耳来源之一），已归一化到 0.95 |

已实现：`apps/server/vendor/diffsinger-voicebank/qixuan_bridge.py`
（运行时副本 `%APPDATA%/yan-zhi/server-data/singing/voices/qixuan_bridge.py`），
支持 `"dump": true` 只打印序列不渲染，便于零成本核对。

验证（「床前明月光」，283 帧 / 3.29s）：序列
`SP(8) ch uang q ian m ing y0 ve g uang SP(8)`，token 4/79/106/99/86/29/91/118/114/60/106/4，
lang 0/3…3/0；成音 f0 实测 261/294/329/294/262 Hz，与音符一致且周期性强（非噪声）。

### P0 剩余（下一步）
1. ✅ 声母时长已换成 `dsdur` 模型（linguistic + dur，按音符网格缩放）；失败自动回落 28% 经验切分并回传 warning。
   实现：`DurationModel` 类，返回 `durSource: 'dsdur' | 'heuristic'`。
2. 盲听验收：3 次渲染，≥4/5 字可辨。

## 八、第二条路：外部音乐大模型（与本地并存）

三条路线并行，互不替代：

| 工具 | 引擎 | 可控性 | 适用 |
|---|---|---|---|
| `music_compose` | 本地合成器（可选 DiffSinger 人声） | 和弦/BPM/旋律/每个字时值全可控 | 卡点 BGM、需要精确编曲 |
| `music_generate` | 外部音乐模型（Suno 路由） | 只给歌词+风格，旋律由模型决定 | 要好听的人声演唱 |

平台探测结论（2026-10-21 实测）：
- `apihub.agnes-ai.com`：只有 LLM / image / video，**没有任何音频模型**；
  它是 OpenAI 兼容中转，`/v1/audio/speech` 路由存在但当前 token 分组没开 TTS 模型，且 TTS 也只能朗读不能唱。
- `http://192.168.10.42:3000`（本机 new-api）：**内置 Suno 路由** `/suno/submit/music`，
  实测返回 `No available channel for model suno_music` —— 缺的是上游渠道，不是代码。

实现：`apps/server/src/services/music-generate.ts`
- 凭证解析顺序：工具入参 → `YZ_MUSIC_API_URL` / `YZ_MUSIC_API_KEY` → 库里 `type=audio` 的模型 → 本机网关兜底。
- 提交 → 轮询 `/suno/fetch/{id}` → 下载音频 → ffmpeg 转 m4a；把 `No available channel` 翻成「请在 new-api 后台加 Suno 渠道」。
- 工具名 `music_generate`，已进 `SUPPORTED_API_TOOLS` 与产物登记 `MEDIA_TOOLS`。

启用步骤：new-api 后台「渠道」新增一个 Suno 渠道（模型名 `suno_music`）。
