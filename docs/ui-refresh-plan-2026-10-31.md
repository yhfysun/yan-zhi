# 界面观感升级方案（2026-10-31）

> 结论先行：现在的「低端感」不是配色问题，是**结构问题**——画布/侧栏/正文几乎同色、正文裸奔无卡片承载、字号集中在 11–13px、Element Plus 默认皮肤占主导、强调色只出现在 Logo 上。
> 推荐路线：**方案 A（纸墨进阶）为主干，先做结构；深色 B 作为可选皮肤后置**。原型：`docs/mockup-ui-refresh-2026-10-31.html`（可切「现状 / A / B」）。
> 现状截图：`docs/ui-refresh-before-2026-10-31.png`

---

## 1. 现状诊断（有据可查）

| # | 问题 | 证据 |
|---|------|------|
| P1 | **没有面板层级**：画布 `#F7F8FA`、面板 `#FFFFFF`、侧栏 `#FFFFFF`，三层几乎同色，只靠 1px `#E7EAF0` 分隔 → 视觉上是一张长纸 | `styles/tokens.css:8-16`；`views/chat.css:22-25` |
| P2 | **没有间距节奏**：字号聚在 11/12/13px 三档，行高 1.45–1.6；token 里只有字号，没有间距阶梯 | `tokens.css:29-40`（无 `--space-*`） |
| P3 | **Element Plus 默认脸**：表格 `#EBEEF5` 边框 + `#FAFAFA` 表头、默认滚动条、32px 灰边按钮 → 一眼「管理后台」 | 截图；`views/chat.css:672` 起的 markdown 容器样式 |
| P4 | **强调色不成体系**：`--color-primary` 只在 Logo、登录按钮、激活条出现；列表状态、链接、工具调用、选中态没有统一色语言 | `tokens.css:45-49`；截图 |
| P5 | **内容裸奔**：`.msg` 无卡片承载，标题与正文同号（h2 与 p 视觉差仅靠字号差 2px），长路径/长链接直接铺开，工具调用无卡片化 | `components/chat/ChatMessageList.vue:34/91`；`views/chat.css` |
| P6 | **顶栏像网页**：36px 平顶白条 + 12px 文字导航，与内容无分隔层级 | `components/WebTopBar.vue`；截图顶部 |
| P7 | **侧栏像调试列表**：23 条会话全是同一个小蜗牛图标、同字号、同灰度，状态只用一个小点，无法扫读 | 截图左侧 |

**观感差的本质**：眼睛看到的是「一堆等权重的灰字」——没有层级、没有留白、没有色彩指引，所以显得廉价。参考图（TRAE）恰恰在这三点上做到了极致。

---

## 2. 对标参考拆解（截图里的 TRAE）

可迁移的五条：

1. **三层深色面板**（侧栏 / 编辑区 / 对话区各差 2–4% 明度）→ 空间有纵深，不靠线也能分区。
2. **紧凑但有节奏**：行高 28–32px、字号 11–13px，但标题/正文/辅助文字三档对比明确（600 / 400 / 30% 透明）。
3. **强调色克制且统一**：只用一个绿（状态点、激活 Tab、发送键），其余全部中性。
4. **内容容器化**：消息是卡片、工具输出是深色块、路径是等宽字体、状态是 pill。
5. **滚动条/hover/焦点态全部定制**，没有一处原生控件裸露。

不照搬的：深色不是我们的品牌色（默认皮肤是「瓷·冰」亮色），且 47 个页面全量深色适配成本高，不适合作为第一步。

---

## 3. 三条路线对比

| 路线 | 好处 | 坏处 | 成本 | 风险 |
|------|------|------|------|------|
| **C. 现状微调**（只改配色/圆角） | 1 天见效，零结构风险 | 治不了根：面板层级、字号节奏、Element 默认脸都还在；1 个月后仍会觉得「廉价」 | 1–2 天 | 低（但收益也低） |
| **A. 纸墨进阶**（结构 + 精修，亮色） | 保留品牌资产；改动 80% 在 CSS/Token，不动业务流程；聊天页观感提升最直接 | 亮色天花板不如深色高；需统一 20+ 页面才能完全一致 | 6–8 天 | 中低（视觉回归为主） |
| **B. 深空工作台**（深色专业感） | 观感拉满，最接近参考图；截图传播力强 | 47 页逐页适配；白天强光下可读性需实测；品牌亮色资产要重做 | 10–14 天 | 中高（每页都要回归） |

**推荐：A 先做（1 周）→ 用 1 周观察 → 再上 B 作为「深色皮肤」**。A 的 token 与结构改动是 B 的地基，B 不是推倒重来。

## 4. 方案 A 规格（纸墨进阶）

### 4.1 Token 增补（`packages/ui/src/styles/tokens.css`）

```
/* 间距阶梯：所有 margin/padding 只允许取这六档 */
--space-1: 4px; --space-2: 8px; --space-3: 12px;
--space-4: 16px; --space-5: 24px; --space-6: 32px;

/* 字号：正文上移到 14px，UI 13px，辅助 12/11 */
--text-ui: 13px;  --text-body: 14px;  --text-h2: 17px;  --text-h1: 20px;
--lh-body: 1.72;

/* 语义色：强调/成功/警告/危险 各自补 soft + ring 两档 */
--accent-soft: #ECECFD;  --accent-ring: rgba(79,70,229,.20);
--ok-soft: #E8F5EE;      --warn-soft: #FDF3E4;  --danger-soft: #FCECEC;

/* 面板层级：画布 / 面板 / 浮起 */
--surface-panel: #FFFFFF;  --surface-canvas: #EEF1F6;  --surface-float: #FFFFFF;
```

### 4.2 布局（`App.vue` + `chat.css`）

- 顶栏 36 → **44px**，导航项 30px 高、圆角 7px，激活用 `accent-soft` 底 + 主色字。
- 新增 **52px 图标轨**（一级：任务/智能体/浏览器/工作流；底部设置+头像），把侧栏的职责收敛成「当前模块的列表」。
- 会话列表宽 280 → **292px**，行高 34px；每行改为「图标 + 标题 + 状态点&时间」两行式；分组标题 10.5px 大写字距。
- 正文列 **max-width 760px 居中**（现在铺满 1600px，一行 100+ 字，阅读疲劳）。
- 新增可选的 **右侧上下文面板 300px**（空间 / 工具数 / 上下文占用 / 产物），桌面端 ≥1400px 才出现。
- 输入区：卡片圆角 14px、聚焦 `0 0 0 3px accent-ring`，工具条左侧图标、右侧「确认模式 + 模型 + 发送」。

### 4.3 关键组件

| 组件 | 现状 | 改成 |
|------|------|------|
| 消息 | 无容器，标题与正文同号 | **卡片**：1px 边框 + 12px 圆角 + 18/20 padding；用户消息右对齐 `accent-soft` 气泡 |
| markdown | h2 只大 2px | h2 17px/600 + 24px 上间距 + 段间距 12px；列表标记用主色；行内 code 等宽 + 浅底 |
| 表格 | Element 默认 | 去掉竖线，表头 11px 大写灰、行高 40px、`tabular-nums`、圆角外框 |
| 工具调用 | 纯文本行 | **工具卡片**：图标 + 文件名 + 参数摘要 + 状态 pill，可展开为等宽深色块 |
| 路径/链接 | 直接铺开 | `font-mono 11.5px` + `text-3` 色 + 单行省略，hover 显示完整 |
| 滚动条 | 原生 | 6px、透明轨道、hover 才显形 |
| 空/错/载 | 多为裸文案 | 统一空状态组件（图标 + 一句说明 + 主操作）+ 骨架屏 |
| 按钮 | 32px 灰边 | 32px、圆角 8、无边框；主要=实心主色，次要=浅底，危险=红字浅底 |

### 4.4 移动端

- 图标轨在 <768px 隐藏，TabBar 保留现状；
- 会话列表改抽屉（已有巡检方案），正文列宽 100%、字号回 14px；
- 消息卡片在窄屏去掉外边框改「无卡片 + 分隔线」，避免双层留白。

## 5. 方案 B 规格（深空工作台，可选皮肤）

不改结构，只加一套 skin：`packages/ui/src/styles/skin.css` 增加 `[data-skin="midnight"]`。

| 角色 | 值 |
|------|-----|
| 画布 | `#0B0D11` |
| 面板 | `#12151B` |
| 面板-2 / hover | `#171B23` |
| 边框 | `#232933`（强 `#2E3542`） |
| 文字 / 次 / 弱 | `#E9ECF2` / `#99A1B0` / `#6B7382` |
| 强调 | `#7A78FF`（soft `rgba(122,120,255,.14)`） |
| 成功 | `#35D399` |
| 阴影 | 深色不用大投影，用 `inset 0 1px 0 rgba(255,255,255,.02)` + 低透明度外阴影 |

规则：深色下**不叠灰度层级**（不要用 opacity 压暗文字），一律给明确的色值；表格/代码块用比面板更深一档，而非更浅。

## 6. 分批实施

| 批次 | 内容 | 文件 | 工期 |
|------|------|------|------|
| **P0 地基** | Token 增补（间距/字号/语义色/面板层级）；Element Plus 全局覆盖（表格/按钮/输入/滚动条）；顶栏 44px | `styles/tokens.css`、`App.vue`、`WebTopBar.vue` | 2–3 天 |
| **P1 聊天工作台**（重点，70% 使用时长） | 图标轨 + 列表两行式 + 正文 760 列 + 消息卡片 + 工具卡片 + 输入区 + 上下文面板 | `views/chat.css`、`components/chat/{ChatSidebar,ChatMessageList,ChatInputArea,ChatTopbar}.vue` | 3–5 天 |
| **P2 管理页统一** | 页面头（标题+说明+操作）、筛选条卡片化、表格去竖线、详情抽屉、空状态 | `views/{Models,Agents,ToolMarket,Skills,Settings}.vue` | 4–6 天 |

## 7. 验收标准

1. 1600px 下聊天页：正文单行 ≤ 42 个汉字（760px 列宽）；
2. 消息区可扫读：100px 外能区分「谁说的 / 说了什么标题 / 工具干了什么」；
3. 全应用只允许一个强调色家族 + 三个语义色，不允许再出现新的蓝/紫；
4. 表格、按钮、输入框在任何页面视觉一致（抽 10 页对比截图）；
5. 亮/暗皮肤切换后无「未定义颜色」的回退（深色下不允许出现白底块）；
6. 交互反馈：所有可点击元素 hover 有背景变化、focus 有 3px ring、禁用态 40% 透明；
7. 375px 无横向溢出（沿用既有移动端巡检清单）；
8. `vitest run --no-file-parallelism` 全绿；UI 回归用关键 5 页截图对比。

## 8. 风险与规避

| 风险 | 规避 |
|------|------|
| 改了 `tokens.css` 会波及全部页面 | 增量为先（新增变量，不改旧变量值）；旧变量只做「换值」不做「删名」 |
| 深色皮肤逐页遗漏 | 用「黑色测试页」法：所有页面在深色下截图，找白底块；CSS 里禁止硬编码 `#fff` |
| 消息卡片让长文更拥挤 | 卡片内 padding 18–20，列宽 760，实际行宽比现在更小但更好读；先在小范围灰度 |
| 改 `chat.css` 破坏行内定位（手风琴/树） | 只加新类，不改既有选择器优先级；每改一段跑一次对应测试 |
| 多会话并行改动冲突 | 开工前 `git status` 核对；本方案只碰样式与本方案列出的组件 |
