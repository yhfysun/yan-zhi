## 2. 「注释」与「注解」到底差在哪（本次重点）

### 2.1 先把学术事实摆清楚：两个词在辞书上是近义词

- 《现代汉语同义词词典》：「注解」强调对难明白处加以说明，多用于**字眼或较短的语句片段**；「注释」侧重解释清楚，可用较长文字衍说，书面语色彩更强。二者**常互换，没有绝对界限**。
- 景海峰《论儒家经义训解的基本方式》：讲经典解释时「注解」「注疏」「注释」**大多是统称**；「注」自郑玄以后成为释经之通名（「注者，即解书之名」孔颖达）；真正可操作的二分是马瑞辰说的——「**诂训，第就经文所言者而诠释之；传，则并经文所未言者而引申之**」。
- 古注体式本身有严格层级：诂 / 训 / 传 / 注 / 笺 / 疏（正义）/ 集解（集注）/ 补注 / 章句 / 音义 / 征引。其中「疏」是**注的注**，「集解」是汇多家，「章句」是分章析句串讲。
- 古籍整理学中「注释」的四项工序：校正文字、解字注音、阐释典故、解析文意。

**所以：如果只按辞书讲，这两词讲不出区别；要区分，必须落到「解释对象」和「谁在说」上做工程约定。**

### 2.2 本产品约定（沿用 `types.ts` 已定口径，不改字段名）

| 维度 | 注释 `Annotation` | 注解 `Interpretation` |
|---|---|---|
| 一句话 | **注「字词」** | **注「义理」** |
| 回答什么 | 这个字在此处怎么读、什么意思、什么典故、有无异文 | 这一句/这一卦**历代谁怎么讲**、依据什么家法、分歧在哪 |
| 解释对象 | 原文中可定位的字、词、短语（`term` 必须命中 `text`，测试钉死） | 整句、整爻、整卦、整篇的义理阐发 |
| 性质 | 客观、可核查、训诂层 | 有主名、有出处、可多家并陈、可互相攻驳 |
| 判据 | 求「**对不对**」 | 求「**谁这么说**」 |
| 典型内容 | 注音、释词、通假、名物、典出、句式、句读、校勘异文 | 传 / 注 / 笺 / 疏 / 正义 / 集解 / 章句 / 音义 / 补注 / 今按 |
| 是否可无主名 | 可以（编者共拟） | **不可以**，必须带 `school` + `dynasty` + 出处 |

> 命名提醒：`annotation` 在通用英文里常被译作「注解」，与本项目中文标签相反。仓库已在 `types.ts` / `curriculum.ts` 定下口径，**本方案不重命名、不新造同义类型**；靠 UI 中文标签、类型注释和一条测试断言把含义钉死，避免"同一语义两处实现"。

### 2.3 五层内容栈（防止串层）

| 层 | 字段 | 内容 | 反例（不该放这里） |
|---|---|---|---|
| 1 原文 | `text` + `source` + `variants[]` | 公版底本原文、底本说明、版本异文 | 白话、按语 |
| 2 **注释** | `annotations[]`（**必非空**，§2.6） | 字词训诂 | 「这一爻讲物极必反」是义理，不是注释 |
| 3 **注解** | `interpretations[]`（**必非空**，§2.6） | 历代注家之说，含注疏层级 | 自编的解释不许冒充某家注语 |
| 4 白话 | `plain` / `plainSummary[3]` | 逐句译文、篇级三句总览 | 不许当"注解"塞进 `interpretations` |
| 5 今按 | `structure` / `quickCheck` | 脉络串讲、编者按语、自测 | 不许写进 `annotations` |

**判定规则（写内容时逐条过）**：能回答"这个字念什么/作什么讲" → 注释；能回答"某某注家怎么说" → 注解；能回答"用现在的话怎么说" → 白话；能回答"这一篇怎么串起来" → 今按；回答"另一版本写成什么字" → 异文 `variants`。

### 2.4 示例：《乾》上九「亢龙有悔」五层拆解（真实引文，非杜撰）

| 层 | 内容 |
|---|---|
| 原文 | `text: '上九：亢龙有悔。'`，`source: '《周易》通行本（王弼定本）· 乾卦'`，`variants[]` 待核对帛书本/《经典释文》后填写 |
| 注释 | `{ term:'亢', pinyin:'kàng', gloss:'极高、过甚', type:'释词' }`；`{ term:'上九', gloss:'最上一爻，阳爻称九', type:'名物' }` |
| 注解（传） | `{ kind:'传', school:'《象传》（小象）', dynasty:'先秦', text:'亢龙有悔，盈不可久也。', paraphrase:false, plain:'满盈不能长久，所以上九有悔。' }` |
| 注解（传） | `{ kind:'传', school:'《文言传》', dynasty:'先秦', text:'亢之为言也，知进而不知退，知存而不知亡，知得而不知丧。', paraphrase:false, plain:'只知进不知退，就是「亢」。' }` |
| 注解（疏） | 孔颖达《周易正义》疏文 → **须逐字核对阮元校刻本影印后再入库**；核对前一律 `paraphrase:true` + UI 标「大意转述」，绝不编造 |

### 2.6 「两个都得有」：行级覆盖率硬约束（用户 11:25 拍板）

**问的是内容，不是字段。** 方案里 `annotations` / `interpretations` 两栏一直都在，但存在两个真实缺口：

| 现状（源码实测） | 后果 |
|---|---|
| `types.ts:45-48` 明写「注释：字词训诂（**可空数组**）」「注解：历代大家（**可空数组——文库层/讲义行可为空**）」 | 编译期就允许某一行只有一类 |
| 内容包里 `interpretations: []` **37 处**（`lessons-mengxue-shici.ts` 22、`lessons-wujing.ts` 9、`lessons-sishu.ts` 6）、`annotations: []` **6 处** | 这些行进「注解步」是空白，点进去没东西看 |
| `culture-curriculum.test.ts:79-82` 只断言「每课至少一行有注释」、`:129-132` 只断言「精读课至少一行有历代注解」 | **课级下限，不是行级**；单行空着照样全绿、零报错 |

⇒ 典型「字段存在 ≠ 内容生效」。把「两个都得有」落成下面 7 条，全部写进正式测试类。

1. **适用范围 = 每一条 `CanonLine`**：精读课、讲义课，以及测算结果页 `canonRefs` 的每一条，必须 `annotations.length >= 1` **且** `interpretations.length >= 1`，**行级覆盖率 100%**。文库层 `canon_work` 是浏览/检索层可暂不适用，但一旦进入精读或测算结果就必须补齐。
2. **类型收紧（只收紧周易自己）**：在新建的 `zhouyi/types.ts` 定义 `annotations: [Annotation, ...Annotation[]]` / `interpretations: [Interpretation, ...Interpretation[]]`（非空元组），前端镜像同步；**不改 `culture/types.ts` 与 `culture-types.ts`**（准则 §5，且并行会话正在改这两个文件）。`Annotation`/`Interpretation` 的**形状**用 `import type` 从 `culture/types.ts` 复用——只借类型、不借数据、不改对方行为。这样 `tsc` 只会把**周易 48 门课**里的空数组列出来，禁止用 `as any` / `!` / 默认值绕过；传统文化那 43 处空数组不受影响、不会炸红。
3. **两者不互相替代**：不许把注释复制进注解充数、不许把白话当注解、不许合并成一个数组。注释答「字词怎么讲」，注解答「历代谁怎么说」，判定规则见 §2.3。
4. **注释侧兜底**：整行没有生字难词时也要出至少 1 条——讲句读、句式、关键词或名物（`type:'句式'|'名物'|'释词'`），不许空。
5. **注解侧三级兜底**（关键：既不空，也绝不编造）：

   | 优先级 | 做法 | 字段与标识 |
   |---|---|---|

### 3.1 分类依据（不拍脑袋堆词条）

1. **主干**：《四库全书总目·经部·易类小序》「**两派六宗**」——象数派（太卜遗法 / 京焦禨祥 / 陈邵造化）、义理派（王弼老庄 / 胡瑗程子儒理 / 李光杨万里史事）；小序原话「易道广大，无所不包，旁及天文、地理、乐律、兵法、韵学、算术，以逮方外之炉火，皆可援《易》以为说」。
2. **修正**：当代学界对「图书（易图）之学」的归属有争议，陈岘提「象数 / 义理 / 图书」三分，高怀民《宋元明易学史》单列「图象易」。本方案**把易图学独立成一条路径**，并在课内讲清争议，不硬塞进象数派。
3. **术数另立**：四库把风水、六壬、奇门、命书相书等放在**子部·术数类**（七属：数学、占候、相宅相墓、占卜、命书相书、阴阳五行、杂技术），与经部易类分开。本方案照此分 T5/T6：**课程层**以文献与思想史为主干（见 §7.3），**实践层**另设测算实践台把起卦、排盘、体用生克这些手艺做成可操作推演（见 §6）。
4. **分期**：朱伯崑《易学哲学史》五期说（《易传》/战国、两汉、晋唐、宋、清代汉学）作为 T3 骨架。

### 3.3 三类课型的步骤序列（一次一步，不铺开）

## 6. 测算实践台（传统手艺的动手层，本次追加）

### 定位：不是算命小程序，是把课上那套手艺亲手算一遍

- 追加要求原话：「简单测算功能也要有啊，这个传统的手艺不能丢」「像算命小程序啊这些功能也能有」「除了学习理论知识也要有实践的功能」。
- 因此**撤回上一版「不提供起卦/排盘测算服务」的表述**，改为完整闭环：**课程讲理论 → 实践台按古法推演 → 结果回到原文与注疏 → 跳回课程复盘**。
- 与算命小程序的关键差别：小程序只给一个结论，实践台给**完整推演过程**。每一步都写明「用的哪条古法、出自哪本书哪一卷、对应哪门课」，把体用生克、纳甲装卦、飞星顺逆这些**手艺算给用户看**——这比给断语更接近传统手艺本身，也才是学习产品该有的实践。
- 结果口径：允许展示**古籍规则里的吉凶用语**（如《梅花易数》「用生体及比和则吉」），但必须逐字引自预写规则表、带出处、标「古籍规则演示」；**不生成新的、面向用户个人处境的预测断语**。
