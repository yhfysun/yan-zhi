# 快捷键管理方案（全局热键收口）

日期：2026-10-17 ｜ 风险等级：low ｜ 状态：待确认

## 一、背景与现状

系统级快捷键（`globalShortcut`，任意应用在前台都能触发）目前只有两条，且管理能力不对等：

| 快捷键 | 作用 | 可配 | UI 入口 | 现状 |
|---|---|---|---|---|
| `Ctrl+Alt+A` | 全局截图 | ✅ | 设置页「截图快捷键」 | 完整：录制/恢复默认/禁用/冲突提示 |
| `Ctrl+Alt+Esc` | computer-use 急停（POST `/panic`） | ❌ 硬编码（`main.cjs:6294`） | ❌ 无 | 被占用时用户无从知晓，也无法换键 |

范围界定：本方案只收口**系统级**热键。应用内快捷键（Enter 发送、Shift+Enter 换行、
Esc、@ 引用、命令面板等）是前端 keydown，不占系统资源、无跨应用冲突，**不做管理**，
仅在设置分区里以只读清单展示（一眼可见"有哪些"，不可改）。

## 二、方案（设置页加「快捷键」分区，不做独立页面）

### 1. main.cjs：抽公共注册函数，两条热键同一实现

`setScreenshotHotkey` 的「unregister 旧值 → register 新值 → 失败回传原因」模式抽成：

```ts
function setGlobalHotkey(current, target, handler, logTag): { ok, accelerator, error? }
```

- 截图与急停都走它（同语义只能有一处实现）。
- 急停从硬编码改为变量：启动时先用默认 `Control+Alt+Escape` 注册（保证渲染层
  未起来时急停也可用），渲染层就绪后由渲染层 sync 用户设置值覆盖（与截图键
  现有 sync 模式一致）。
- IPC：新增 `shortcut:getPanic` / `shortcut:setPanic`（对齐 `shortcut:get/setScreenshot`）。
- 互相冲突自检：设置 A 键等于 B 键时，`globalShortcut.register` 会因已被自己占用
  而失败 → 复用既有 error 回传链路提示「与另一条快捷键相同，请换一个」。

### 2. preload：暴露 `panicHotkey: { set, get }`（对齐 `screenshot.setAccelerator`）

### 3. settings：加 `panicAccelerator: 'Control+Alt+Escape'` 字段（默认值见名）

### 4. Settings.vue：复用现有录制链路加一行

- 「截图快捷键」行下方加「AI 急停快捷键」SettingRow，复用同文件的
  `accelFromEvent`（唯一实现）+ readonly 录入框 + 恢复默认。
- ★ 急停**不提供「禁用」**（用户拍板 2026-10-17）：它是 computer-use 高危工具的
  唯一安全阀，禁用等于拆掉保险 → 只允许换键 / 恢复默认；main 启动兜底注册默认键，
  任何时刻至少有一条急停通道在线。
- 应用内快捷键可配项（用户拍板 2026-10-17）：**发送键三态互换** ——
  `Enter 发送`（Shift+Enter 换行，现状）/ `Ctrl+Enter 发送`（Enter 换行）。
  settings 加 `sendKeyMode: 'enter' | 'ctrlEnter'`（默认 'enter' 保持现状）；
  ChatInputArea 的 onEnter 按 mode 分派：enter 模式行为完全不变；
  ctrlEnter 模式下 Enter 不 preventDefault（走默认换行）、Ctrl+Enter 发送。
  输入框 placeholder 与发送按钮 tooltip 文案随 mode 联动（`Ctrl+Enter 发送`）。
- 其余应用内快捷键（Esc、@ 引用、命令面板等）只读展示，不可改。

## 三、影响点盘点

| 位置 | 改动 |
|---|---|
| `apps/desktop/main.cjs`（~6059-6114、6294） | 抽 `setGlobalHotkey`；急停改变量 + 默认注册（无禁用路径） |
| `apps/desktop/preload.cjs` | 加 `panicHotkey` 桥接 |

| `apps/server/src/plugins/computer-use.ts` | **不动**（`/panic` 路由与急停语义不变） |

## 四、测试

1. `accelFromEvent` 单测（若已有则补急停场景断言）。
2. Settings 源码结构锚点（仿 `input-send-affordance.test.ts` 手法）：急停行存在、
   **不含「禁用」入口**、数据源用 settings.panicAccelerator / sendKeyMode。
3. ChatInputArea onEnter 分派单测：enter 模式（Enter 发送 / Shift+Enter 默认换行不拦）、
   ctrlEnter 模式（Ctrl+Enter 发送 / Enter 不 preventDefault 走换行）、
   IME 组合态两种模式下都照旧拦截不发送。
4. 手工验收：改急停键 → 触发生效；设成截图键同款 → 收到冲突提示；重启后设置保持；
   切 ctrlEnter 模式 → Enter 换行、Ctrl+Enter 发送、placeholder 文案同步。

## 五、风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 急停键被换成一个难按的组合 | low | 只能换键不能禁用；恢复默认一键回 `Ctrl+Alt+Esc`；main 启动兜底注册默认键 |
| 渲染层未就绪时窗口期用旧键 | low | main 启动即注册默认键，sync 只做覆盖，无真空期 |
| sendKeyMode 影响发送链路 | low | onEnter 仅在分派点分支，IME 拦截、入队、锁等下游逻辑零改动；默认 'enter' 行为与现状逐字节一致 |
