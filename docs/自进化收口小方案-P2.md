> 2026-10-12 · 状态：待确认后实施
> 前置：P0（经验档案层）+ P1（skill 草稿提炼）已上线

## 一、现有链路还缺什么（诚实盘点）

| # | 短板 | 影响 | 严重度 |
|---|---|---|---|
| 1 | **条目命中无统计**：经验注入进提示词后，没记"哪条被命中过、帮上忙没有" | 无法评估条目价值 → Dreaming 想整理也没有淘汰依据；高价值条目和垃圾条目同等对待 | high |
| 2 | **档案碎片化**：LLM 每次给的 topic 可能漂移（dev-打包 vs dev-构建） | 同主题经验散落多个文件，注入时命中分散 | medium（已有 topicHint 缓解） |
| 3 | **单文件膨胀**：条目只增不减，注入保尾部 1600 字 → 旧条目事实上"死"了 | 占磁盘但没人看；写它的成本白花 | medium |
| 4 | **草稿确认没有一键操作**：只有一条文字消息，用户要自己挪目录或口头指挥模型 | 确认成本高 → 草稿容易积压变成没人管的死目录 | medium |
| 5 | **提炼质量无拦截**：小模型可能写出空泛条目（"注意细节"这类），提示词约束非硬保证 | 垃圾条目污染档案，注入还占预算 | low（可后置） |
| 6 | **跨工作目录不共享**：经验按工作目录隔离，机器级通用坑（node22 ABI 这类）在每个目录各记一份 | 通用经验重复积累 | low（有意为之的隔离，暂不动） |
| 7 | **端到端没实测**：编译+单测过了，但没在 dev 实例跑真实双任务对比 | — | 需要用户侧验证 |

## 二、P2 实施（两块，都小）

### P2a：命中统计 + Dreaming 整理（核心，解决 #1/#2/#3）

**命中统计（写入侧）**：
- 注入命中条目时**不写盘**（提示词组装是同步热路径，写盘有并发冲突风险）→ 内存 `Map<条目键, {hitCount, lastHit}>`（条目键 = `topic + 标题hash`）
- Dreaming deep 阶段把内存计数 flush 回条目行尾 meta：`（×N 成功｜命中M，最近 YYYY-MM-DD）`——同一次写入，无并发问题

**Dreaming 整理（deep 阶段新增一类任务）**：
1. **topic 归并**：同根 topic（Jaccard ≥0.5，如 dev-打包/dev-构建）→ 合并条目到长者，旧文件顶部留一行 `> 已并入 dev-打包` 的 tombstone（不删文件，人工可核）
2. **淘汰标记**：`updated > 30 天 && 命中数 = 0` 的条目 → 行首加 `[待淘汰]` 标记（**不直接删**，下轮仍无命中才真删——两轮确认制，防误删）
3. **skill-drafts 积压**：drafts 下超过 7 天未确认的草稿 → 会话外记录，下次任务注入一行提醒"你有 N 个待确认的技能草稿"

改动文件：`services/experience.ts`（hit map + flush 导出）、`services/memory-dreaming.ts`（deep 阶段接线，复用其已有调度，不动调度本身）。

### P2b：草稿一键管理工具（解决 #4）

新增两个 API 工具（走三段注册 + 权限清单，老规矩）：
- `api_skill_draft_list`：列出 drafts 目录草稿（name/path/created）——只读，进 READONLY_SAFE_TOOLS
- `api_skill_draft_enable {slug}`：把草稿移入 `.yan-zhi/skills/<slug>/` 并（可选）调 `api_skill_create` 入库 —— 写类，进 WRITE_TOOLS
- 丢弃 = 用户直接删目录（文件即真相源，不加 delete 工具）

用户侧体验：草稿提示消息后说"启用草稿 X"即可，模型一个工具搞定。

### 暂不做（记录理由）

- **#5 提炼质量拦截**：现有"最多 3 条 + 标题具体性提示词约束"先跑着看，垃圾率真高了再加硬校验（标题长度/禁词/与既有条目相似度门槛）
- **#6 全局共享经验层**：隔离是有意设计，先不动
- **#7 端到端实测**：等你重启 dev 实例后双任务对比（同站点抓文两次，看第二次步数/耗时；同流程成功两次看草稿提示）
