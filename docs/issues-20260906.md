## 3. 大模型调浏览器工具弹独立浏览器窗口 ❓（机制已锁定，触发路径待确认）
- 根因机制：`apps/server/src/routes/browser.ts:47` `BROWSER_MODE` 默认 `'launch'` → `chromium.launch({ headless: BROWSER_HEADLESS })`。
- 桌面正常路径：main.cjs 起 server 时注入 `BROWSER_MODE=cdp + CDP_ENDPOINT`（连 Electron 自身，不弹窗）。
- 漏洞路径：`bin/dev.mjs server` 直启 / web 端(5173)调 /api/browser / llm-task-manager 离线兜底——这些路径没有 cdp env，走 launch 模式起独立 Chromium。
- 待确认：现场 env 里是否被设过 `BROWSER_HEADLESS=false`（默认 true 不该可见）。
- 修复方向（未动）：与既定"单一执行面"对齐——桌面在线时浏览器工具绝不落 server 路由；launch 模式强制 headless；bin/dev.mjs server 补 cdp env。

## 4. click 经常没传坐标/index ✅
- 原因：主智能体（非 pageAgent）也挂了 browser_* 工具，但其 prompt 没有"先 get_page_content 拿编号列表再 click(index)"的约束，模型直接空参 click。
- pageAgent 已收口（四件套 + index 定位 + v3 迁移），主 agent 未收口。
- 修复方向（未动）：① click/type 无 index 且无 selector 时主进程返回引导性报错（"请先调 browser_get_page_content 获取编号"）；② 主 agent prompt 补同样约束。

## 5. 浏览器页与对话预览 browser tab 串扰 ❓（需先明确"串"的具体表现）
- 设计现状（用户此前拍板的单一执行面）：两处共用同一 browser store + 同一组 BrowserView，tab 列表本来就该是同一份。
- 若"串"指 tab 列表两边一样 → 是设计使然，不是 bug；
- 若"串"指激活互踩（一边切 tab 另一边跟着跳/预览抢走浏览器页的激活）→ 双实例没有双向同步激活事件的仲裁，需定谁是激活源。
- 下一步：用户描述一个具体复现序列。
