### ★ 边界判据（避免矫枉过正）

**五线谱是记谱工具，不是「国外乐理」本身** —— 中国传统曲目同样大量用五线谱 / 简谱出版。
所以要分域的不是「记谱法归谁」，而是 **乐理体系 / 术语 / 调式概念 / 曲目**：

- ✅ 允许：传统方向的民歌用五线谱或简谱「对照显示」，但必须标注这是通用记录方式。
- ❌ 禁止：五线谱课上把「宫调式」当默认调式概念、把《小星星》说成宫调式、在西方方向出现工尺谱术语。
- 当前产品的错，正是把工具（五线谱）和体系（五声调式）混在一个控件里。

## 二、目标：一个「音乐」科目，两条并列方向（Track）

| 方向 | 名称 | 概念与术语 | 记法 | 曲目（公版） | 产出 |
| --- | --- | --- | --- | --- | --- |
| **A · western** | 现代通用乐理（西方体系） | 音名 C D E F G A B、唱名 do re mi fa sol la si、十二平均律与半音、高音谱号与线间、调号/拍号/时值/休止符、大调与自然小调、音程、简易三和弦 | 五线谱（主）、音名唱名（辅）、简谱（对照） | 小星星（**原版含 fa**）、欢乐颂、友谊地久天长、巴赫小步舞曲片段 | 看五线谱能唱出 do–sol、能编 8 小节大调小曲 |
| **B · traditional** | 中国传统音乐 | 宫商角徵羽、五声正音与偏音（凡/乙）、五声调式、工尺谱上尺工六五、简谱（注明近代传入、中国通用）、字调与依谱写词、民歌与曲牌 | 工尺谱（主）、宫商角徵羽（主）、简谱（辅）、五线谱（仅对照） | 茉莉花、康定情歌、沂蒙山小调、彩云追月、五音阶练习 | 听出宫调/羽调色彩、给民歌填词、编 4 小节五声小曲 |
| **桥梁** | 两套体系对照（独立一步，不占主流程） | 「同一段音在两套体系里怎么写」「为什么不能混」 | 对照表 | — | 消除「五线谱 = 国外」的误解 |

> **不拆成两个科目**：`LEARNING_SUBJECTS` 保持一个「音乐」，方向是科目内的一等字段 `track`。
> 理由：进度 / 陪练 / 课程地图 / 扩展表接线全部按 subject 分块，拆科目会把 `subject` 语义扩散到 10+ 处，收益为零。
> **两条方向都必须能实践**：学完就进编曲台做作品（见第三章），不是只做知识测验。

## 三、编曲实践台：三种编曲模式 + 真播放 + 作品沉淀

> 按用户「人工自动编曲 + ai 辅助编曲 + 还要能播放」拆成三种模式：**① 人工手动 ② 规则自动（离线、不依赖 LLM）③ AI 辅助**；三者产出同一份可编辑 `Score`，都能播放成成品。

### 3.1 ★ 地基已存在，不用从零造（本轮最大发现）

| 现成能力 | 位置 | 复用方式 |
| --- | --- | --- |
| `MusicSpec → 多声部 NoteEvent[]` 纯函数 | `services/music-plan.ts:46-98,179-278` `arrangeMusic()` | 调性/和弦/旋律/风格/鼓型/歌词/seed 一次展开；**同 seed 同编曲**（`mulberry32`）；`parseChord` / `pitchToMidi` 校验，非法字段退默认值并回传 `warnings` |
| 乐谱 → 音频 → 落盘 | `services/music-render.ts:53` `composeMusic()` → `music-synth.ts:65` `renderArrangement()` | 纯 JS 合成 WAV，ffmpeg 可用转 m4a；**完全本地、零版权、BPM 精确**；无 ffmpeg 降级交付 wav，不整段失败 |
| 工具链与产物目录 | `packages/core/src/tool/builtin/api-tools/media.ts:172-231` `music_compose` schema、`api-tool-executor.ts:2717-2781` 执行分支、`mediaTarget({kind:'audios'})`、`services/artifact-dir.ts` | 学习科目**直接调 service**，不走工具白名单（避开 2026-10-22「注册表有、白名单漏登」同族坑）；产物目录与 URL 沿用规范通道 |
| 内联音频播放器 | `components/media/AudioPlayer.vue`、`chat/ToolMediaPreview.vue:39-48` | 播放/暂停/进度拖拽/倍速/另存为现成，作品台直接挂 |
| 服务端 LLM 唯一出口 | `services/llm-call.ts:67` `chatViaRow()`（走 LlmClient，与聊天同源） | AI 辅助编曲复用它，**不新写 callModel**（memory-dreaming 平行实现漂移的坑已收口） |

> ★ 架构沿用 2026-10-21 已拍板判据（`music-plan.ts:3-8`）：**模型写「乐谱决定」，代码做编曲与合成**。
> 理由：同样的和弦，代码出来的伴奏永远一致；模型直接吐音频则不可逐音符编辑、不可判卷、不可复现。
> **诚实边界**（`music-plan.ts:10-12`）：本地合成器**不能唱**，音色是合成器不是真实采样；要人声走 `music_generate`（外部模型、需 Key），本轮不做，也不宣传「商业编曲质感」。

### 3.2 三种编曲模式

| 模式 | 触发 | 实现 | 依赖 |
| --- | --- | --- | --- |
| ① 人工手动 | 点格子 / 拖音块 | 格子升级：8~16 小节、时值（全/二分/四分/八分）、休止、撤销重做、BPM、调性/调式切换、行按 track = 7 音 / 5 声；课程「写/奏」步一键「在编曲台打开」 | 零依赖，离线 |
| ② 规则自动 | 「补全空白」「按动机变奏」「换风格重编」三个动作 | 纯函数 `autoArrange({track, mode, bars, seed, motif?})`：复用可复现 PRNG + 调式和弦 / 五声度数生成旋律与伴奏；结果**落回同一份 Score 继续手改**，不是黑盒产出 | 零 LLM、零网络、零延迟 |
| ③ AI 辅助 | 一句话描述（「8 小节明亮大调小曲」/「徵调式、古筝、婉转」） | `POST /learning/music/compose/assist`：按 track 注入**分域约束** → LLM 输出结构化 `MusicSpec` JSON → 服务端强校验（和弦可解析 / 音名合法 / 五声集 / 术语不越界）→ 不合法**回落规则生成并如实告知**，不静默串体系 → 产谱可编辑、换 seed 再生成 | `chatViaRow()` |

- ✅ **分域约束硬闸**：A 只给十二平均律 + 大小调和弦 + 西方术语；B 只给五声正音 + 国风乐器（`guzheng/dizi/erhu`）+ 工尺/宫调术语；AI 输出出现另一方向术语即判不合格（单测钉死）。
- ✅ AI 只产 `MusicSpec`，**不产音频、不产散文式乐理**；`origin` 记 `manual | auto | ai`，界面如实标注来源。
- ✅ AI 不可用时降级到 ②（离线也能编曲），不弹阻塞提示。

### 3.3 播放（三档，从「点一下就响」到「成品可交付」）

| 档 | 实现 | 用途 |
| --- | --- | --- |

## 四、数据模型：把「体系」提升为一等字段

```ts
// learning/music/types.ts（重写；十二平均律是唯一音高内核，五声是视图而非内核）
export type MusicTrack = 'western' | 'traditional';
export type Step = 'C' | 'D' | 'E' | 'F' | 'G' | 'A' | 'B';
export type NoteEvent = {
  step: Step; alter?: -1 | 0 | 1;   // 升降号；不写 = 0
  octave: number; beats: number;
  lyric?: string; rest?: boolean;
};
export type ScoreMode =
  | { kind: 'major' | 'minor'; tonic: Step }
  | { kind: 'pentatonic'; tonic: 'gong' | 'shang' | 'jue' | 'zhi' | 'yu' };
export type Score = {
  id: string; title: string; track: MusicTrack;
  clef: 'treble' | 'bass'; key: string; meter: [number, number];
  mode: ScoreMode; notes: NoteEvent[];
};
```

**关键约束**：

- ✅ `LETTER_SEMI`（C0 D2 E4 F5 G7 A9 B11）为**唯一**音高换算表；`PENTA_VIEW`（宫商角徵羽 ↔ 1/2/3/5/6 ↔ 上尺工六五 ↔ C/D/E/G/A）降级为**只读视图**。
- ✅ `transposeScore()` 按 track 分两种实现：西方 = 半音移调（含升降号重算），传统 = 五声度数换调式（保留现有算法）。
- ✅ 记法集合按 track 派生：`NOTATION_BY_TRACK = { western: [...], traditional: [...] }`，**不再有全局四记法 Tab**。
- ✅ 调式控件按 track 分域：A 显示「C 大调 / a 小调 / G 大调…」，B 显示「宫 / 商 / 角 / 徵 / 羽调式」；**跨方向术语禁止出现在同一控件**（单测钉死）。
