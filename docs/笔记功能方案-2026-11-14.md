# 笔记功能方案 · 2026-11-14

> 定位：**独立功能模块「笔记」**——笔记 + 计划 + 收藏三位一体；学习模式可一键沉淀内容；大模型可读可写；时间类计划到点智能提醒。
> 原则：全部复用既有地基（SQLite 建表范式 / 学习上下文注入 / 工具用户态注入 / 桌面提醒轮询），零新框架。

---

## 一、数据模型（db.ts 增量段，照 learning 表范式）

```sql
-- 分类：用户拍板「分类名是唯一索引」
CREATE TABLE IF NOT EXISTS note_category (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  name TEXT NOT NULL,             -- 唯一索引按 (user_id, name)，同名不同用户不冲突
  sort INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  UNIQUE(user_id, name)
);

CREATE TABLE IF NOT EXISTS note (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  kind TEXT NOT NULL DEFAULT 'note',  -- 'note' 笔记 | 'plan' 计划
  category_id TEXT,                   -- 可空 = 未分类
  title TEXT NOT NULL,
  content TEXT NOT NULL DEFAULT '',   -- Markdown
  source TEXT,                        -- 'manual' | 'learning:step:<id>' | 'chat' | ...
  pinned INTEGER NOT NULL DEFAULT 0,  -- 置顶（顶部固定）
  starred INTEGER NOT NULL DEFAULT 0, -- 收藏（唯一收藏位）
  plan_at INTEGER,                    -- kind='plan'：计划时间(ms)
  remind_at INTEGER,                  -- 提醒时间(ms)；到点未处理 → 智能提醒
  remind_done INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_note_user ON note(user_id, kind, updated_at DESC);
CREATE INDEX IF NOT EXISTS idx_note_remind ON note(user_id, remind_at) WHERE remind_done = 0;
```

设计要点：
- **分类唯一索引**：`UNIQUE(user_id, name)` 兜底；自动创建用 `INSERT ... ON CONFLICT(user_id,name) DO NOTHING` 再查回，并发下不炸。
- **收藏 = `starred` 字段**，与 `pinned`（置顶）分离：收藏是"重要"维度，置顶是"常用"维度，互不干扰。删分类时该分类下的笔记自动迁到「未分类」，不丢数据。
- **计划 = kind='plan'**：与笔记同表不同形态（计划就是有时间维度的笔记），避免两套 CRUD。
- 重复计划（每天/每周）放 P1，首版一次性提醒。

## 二、API（`routes/notes.ts`，挂 `/api/notes`，authMiddleware 同款）

| 端点 | 说明 |
|---|---|
| `GET /categories` | 分类列表 + 每类计数 |
| `POST /categories` | `{name}` 幂等创建（存在即返回既有） |
| `PATCH /categories/:id` / `DELETE /categories/:id` | 重命名（保唯一索引校验）/ 删除（笔记迁到未分类） |
| `GET /notes?kind=&category=&starred=&q=&sort=` | 列表（q 全文搜 title+content，LIKE 即可首版） |
| `POST /notes` | 创建。**`category_name` 直传字符串：不存在自动创建**（用户拍板的交互语义） |
| `PATCH /notes/:id` | 改标题/内容/分类/计划时间等 |
| `POST /notes/:id/star` · `POST /notes/:id/pin` | 收藏 / 置顶切换 |
| `DELETE /notes/:id` | 删除 |
| `GET /notes/reminders/due` + `POST /notes/reminders/ack` | **drain 范式**（照 plugin reminders 先例）：取回到期待提醒并标记，桌面端轮询消费，天然幂等不重复提醒 |

## 三、大模型接入（**只提供工具，按需调用，不做摘要注入**）

> 用户拍板：**不往 system prompt 注入任何笔记摘要**——不是什么问题都一股脑放进去。智能体只有当用户明确问到（"我的 XX 笔记"、"记成笔记"、"我有什么计划"）才通过工具加载笔记内容。

1. **工具（挂全部聊天智能体，含学习智能体）**：`notes/tools.ts` 照 learning/tools.ts 范式：
   - `notes_add(title, content, category_name?, kind?, plan_at?, remind_at?)` —— **仅当用户明确要求**（"这个不错，记录成笔记"）才调用；`category_name` 不存在自动创建（智能体可按用户口述选/建分类）
   - `notes_update(id, title?, content?, category_name?, plan_at?, starred?)` —— 用户要求修改某条笔记/计划时调用
   - `notes_search(q?, kind?, category?, starred?)` —— 用户问"我之前记过 XX 吗 / 我的 XX 笔记"时按需查询
   - `notes_manage_categories(action: 'list'|'create'|'rename'|'delete', ...)` —— 用户要求整理分类时调用
   - 工具 description 写明边界：「仅在用户明确要求记录/查询/修改笔记或计划时使用，不要主动记录对话内容」。
   - 用户态注入：`setNoteToolUser(task.userId)` 加在 `registry.execute` 唯一出口旁（llm-task-manager.ts:6493 学习工具旁一行）。
2. **没有摘要注入**：`buildSystemPromptForBackend` 不加笔记块；token 零开销。

## 四、智能提醒（桌面端）

- 照抄 main.cjs 插件提醒轮询（main.cjs:12785-12885）：`setInterval` 15s → `GET /api/notes/reminders/drain` → 命中即：
  ① 宠物气泡 `pet:say`（优先）→ ② 系统 `Notification`（降级），点击通知 → 打开 `/notes` 并定位该条。
- 到点判定纯 SQL：`remind_at <= now AND remind_done = 0`，ack 后置 1，天然不重复。
- Web 端（无系统通知）：笔记页顶部红点 + 列表内高亮。

## 五、UI 设计（独立模式页 `/notes`，三栏骨架照 Learning.vue 契约）

```
┌──────────┬────────────────────────┬──────────────────────┐
│ 左栏      │ 中栏                    │ 右栏                  │
│          │ ┌筛选固定顶部──────────┐ │ ┌详情/编辑──────────┐ │
│ 全部     │ │ 🔍搜索 [笔记|计划|全部]│ │ │ 标题（大字编辑）    │ │
│ ★ 收藏   │ │ 排序: 更新时间▾       │ │ │ 分类[下拉·可输入]   │ │
│ ☑ 计划   │ └──────────────────────┘ │ │ kind=plan → 时间选择│ │
│ 未分类   │ ┌列表独立滚动──────────┐ │ │ + 提醒开关          │ │
│ ─────── │ │ ★置顶项（灰底）      │ │ │ ──────────────────  │ │
│ 英语     │ │ ▢ 标题               │ │ │ Markdown 编辑       │ │
│ 工作     │ │   一行摘要…          │ │ │ （分屏预览）         │ │
│ + 新分类 │ │   [分类chip][时间] ☆ │ │ │ ──────────────────  │ │
│          │ │ …                    │ │ │ 保存 · 删除 · 置顶   │ │
└──────────┴────────────────────────┴──────────────────────┘
```

- **分类交互（用户拍板的核心）**：右栏分类控件 = 下拉列出既有分类 + **直接键入新名字回车即创建**（allow-create 语义）；列表项上分类 chip 可点改。
- **列表行**：星标（点击收藏）、置顶灰底置顶区、计划条目显示时间 chip（逾期红 / 今日橙 / 未来灰）。
- **极简**：无多余图标与 tip 文案，筛选固定顶部、列表独立滚动（遵守既定 UI 规范）。
- **学习模式联动（「别的地方创建笔记」核心交互，人工触发为主）**：
  - 主线课程页 / 阅读页 / 词书页加「记到笔记」入口 → 弹轻量创建窗：标题预填（课程名/文章名）、内容预填（要点/选中文本/释义），分类下拉（可选可输入即建）→ `POST /api/notes` 带 `source=learning:...`。成功即静默（不打断学习节奏）。
  - 聊天里：用户说「这个不错，记成笔记」→ 智能体调 notes_add（写前把将写入的标题/分类口述给用户，无需额外弹窗）；用户没说就不记。

## 七、分期

- **P0（本轮）**：三表 + 全部 API + `/notes` 三栏页 + 分类自动创建 + 收藏/置顶 + 学习页「记到笔记」 + **4 个笔记工具（挂全部智能体，仅用户明确要求时调用，无摘要注入）** + 桌面提醒轮询 + 测试。
- **P1**：重复计划（每天/每周）、Markdown 图片粘贴、`[[双向链接]]`、导出 .md、计划改期建议（模型主动"要不要推到明天？"）。
- **不做**：多人协作、富文本所见即所得编辑器（Markdown + 预览够用）、云同步（本地 SQLite 即全部）。

## 八、风险

| 风险 | 等级 | 对策 |
|---|---|---|
| 提醒重复/漏发 | 中 | drain+ack 幂等（照 plugin reminders 已验证范式） |
| 分类乱建 | 低 | 唯一索引 + 下拉优先引导；P1 可加"最近使用分类"排序 |
| 智能体抢记内容 | 低 | 工具 description 写明「仅用户明确要求时使用」；笔记以人工创建为主，智能体只是执行者 |
