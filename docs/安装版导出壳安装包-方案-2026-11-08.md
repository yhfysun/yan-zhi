# 安装版「导出壳安装包」方案（2026-11-08）

> 需求：完整安装版里，设置页提供「导出安装包」——默认以本机内网 IP 为后端源头，
> 导出的壳包发给同事；同事装上后聊天 / 远控 / 自身能力全部正常，只是后端跑在导出者机器上；
> 导出者可以创建 / 管理同事账号。
> 附带验收要求：壳功能与「正常安装带后台的安装包」对等，仅后端远程。

---

## 一、结论：能实现，且大部分地基已存在

2026-11-01/02 已落地的能力（本轮只需补最后一公里）：

| 能力 | 现状 | 位置 |
|---|---|---|
| **轻量壳（无后端）打包链** | ✅ 已有 | `electron-builder.shell.yml`、`scripts/package-desktop-shell.cjs`、`apps/desktop/scripts/build-shell.cjs` |
| 壳连远程后端 | ✅ 已有 | `packages/ui/src/api/client.ts` 的 `yz_server_base`（用户手填，最高优先级）+ `server-base.json` 烘焙地址（main.cjs 读取，仅壳模式生效） |
| 壳开箱直连、免手填 | ✅ 已有 | `resources/server-base.json` 经 preload 下发 `electronAPI.serverBase` |
| **多用户模式** | ✅ 已有 | `apps/server/src/rbac.ts:160` `YZ_AUTH_MODE=multi`；`auth.ts` JWT 登录、首个管理员引导（`setupRequired`） |
| **用户管理后台** | ✅ 已有 | `routes/admin.ts` 用户/组织/角色/权限完整 CRUD；前端 `/admin/users|orgs|roles`（`views/admin/`）、`api/admin.ts` |
| **远控 / 本机能力回连** | ✅ 已有 | `plugins/desktop-capability.ts`：浏览器自动化与 computer_* 工具路由回同事的壳机器；壳侧 `local-capabilities`、`rcLocalEndpoint.ts` |
| 后端局域网可达 | ✅ 已有 | `index.ts:543` HOST 默认 `0.0.0.0` |
| 局域网节点发现 | ✅ 已有 | `routes/lan.ts` `/api/lan/discover-nodes`；设置页「局域网」pane |
| **安装版内导出壳包** | ❌ 缺 | 本轮核心新增 |
| **主机端 multi 模式开关** | ❌ 缺 | 桌面版 spawn 后端恒为 guest（main.cjs:1438 未传 `YZ_AUTH_MODE`） |

**为什么壳包可以「运行时导出」而不用打包工具链**：壳与完整版的
`app.asar` 内容完全一致（两份 yml 的 `files:` 段同源，壳只少 `extraResources` 里的
`server/*`、python 运行时、预置码），Electron 运行时也一致。
⇒ **完整安装目录 = 壳安装目录 + 后端专属资源**。
导出 = 拷贝自身安装目录 → 剔除后端资源 → 写入 `server-base.json` → 压缩。
零外部工具链依赖，且**壳版本与主机后端版本天然一致**（比另打一个壳包还可靠）。

## 二、总体架构

```
导出者（主机，完整版）                        同事（壳）
┌─────────────────────────┐   http(LAN)   ┌──────────────────┐
│ Electron 完整版          │◄─────────────►│ Electron 壳(无后端)│
│  ├ 内嵌后端 :3001        │  /api /ws /mcp │  ├ app.asar(同款) │
│  │   YZ_AUTH_MODE=multi │               │  ├ server-base.json│
│  ├ SQLite(共享库)        │               │  └ local-capabilities│
│  └ 用户管理(/admin/*)    │  WS 能力回连   │     (浏览器/截屏/   │
│    创建同事账号/角色      │◄──────────────│      电脑使用→壳机) │
└─────────────────────────┘               └──────────────────┘
```

- 业务数据（会话、文件产物、智能体配置）在**主机**；同事用账号登录，RBAC 隔离。
- 浏览器自动化 / 电脑使用 / 剪贴板等**本机能力**在**同事机器**执行（能力回连已实现）。
- 远程控制：`RemoteControl.vue` + peers 信令，被控端信令走壳本机能力服务（已实现）。

## 三、缺口设计

### D1（核心）安装版内「导出壳安装包」

**主进程新增 `export-shell.cjs`**（须登记三份 electron-builder yml 的 `files:`，守门测试
`packaged-entry-modules.test.cjs` 会拦漏登记）：

1. **定位自身**：`process.execPath` 所在目录 + `process.resourcesPath`。
2. **拷贝排除清单**（相对安装目录）：
   - `resources/server/**`（后端产物 + web-dist + 内置插件 + 预置码）
   - `resources/python*/**`
   - 其余全部保留（exe、dll、pak、app.asar、locales 等）。
3. **写入 `resources/server-base.json`**：
   `{"serverBase": "http://<内网IP>:3001"}` —— IP 用 `os.networkInterfaces()` 取
   非内部 IPv4 私网地址，多网卡时让用户在下拉里选（设置 UI 已有「本机 IP」pane 可复用探测）。
4. **压缩**：优先 PowerShell `Compress-Archive`（Windows 内置、零依赖，约 200MB / 1~2 分钟）；
   备选直接输出文件夹（免压缩，同事解压那步省了）。
5. **产物**：`<导出目录>/yan-zhi-shell-<版本>-<日期>.zip`（+ 可选 `安装说明.txt`：
   解压 → 运行 `yan-zhi.exe`；如需快捷方式运行随包 `创建快捷方式.bat`）。
6. **前端入口**：设置新增「共享服务」pane（见 D2），「导出壳安装包」按钮 +
   进度条（拷贝/压缩分阶段回报，走 `electronAPI` IPC 事件）。
7. **首次导出前自检**（向导内联提示，不通过则给一键修复）：
   - 后端是否 multi 模式（未开则引导 D2 开关）；
   - 3001 防火墙入站是否放行（`netsh advfirewall firewall` 探测；一键放行走 UAC 提权）；
   - 本机内网 IP 是否可取。

### D2 主机「共享服务」开关

1. `main.cjs` spawn 后端处（1438 行 env 组装点）按 userData 配置注入
   `YZ_AUTH_MODE=multi`（仿 `editionEnv` / `guardEnv` 的既有模式），切换后重启内嵌后端。
2. 设置「共享服务」pane：
   - 开关：共享模式（guest ↔ multi），文案明确「开启后同事需账号登录」；
   - 首个管理员引导：multi 模式且 `!hasRealUsers()` 时（`auth.ts` `setupRequired` 已下发）
     跳转注册首个管理员；
   - 账号管理入口：复用既有 `/admin/users`（用户/组织/角色/权限全套已有，无需新做）；
   - 内网地址展示 + 复制 + 局域网自检（复用「局域网」pane 的发现能力）。
3. 安全：multi 模式 JWT 必带；媒体/WS 已有 `?token=` 兜底（`client.ts` 同口径已做）；
   建议（非本轮必做）开 `YZ_LICENSE_GUARD=1` 门禁给同事包发码。

### D3（增强，可选）壳支持便携覆盖

`main.cjs` 读 `server-base.json` 处加第三优先级：**exe 同目录的 `server-base.json`**
（优先于 resources 内置）。收益：改后端地址不用重新导出——发一个 300 字节的小文件
给同事替换即可；也方便 IP 变了以后统一换发。

### D4 功能对等性验证矩阵（发人前的最后一道关）

按 `PACKAGING-NOTES` 的「包内产物回放」方法论执行（回放壳产物 + 连真主机后端）：

| 项 | 预期 | 验证方式 |
|---|---|---|
| 登录 / 账号 | 壳首启直连主机，同事账号登录可用 | 回放 + 真机 |
| 聊天 / 工作流 / 智能体 | 与完整版一致（数据在主机） | 逐 pane 回放断言 |
| 浏览器自动化 / 电脑使用 | 在**同事机器**执行；壳掉线报错不回落主机 | 断开壳复测（desktop-capability 已有守卫） |
| 远控 | 可互相远控（信令走主机、画面/输入走对端） | 双端真机 |
| 文件产物 | 落在**主机** server-data；壳上预览走媒体代理 | 上传/生成各 1 例 |
| ⚠️ exec/dev/ops 命令执行 | 在**主机**执行（设计使然，见风险 R1） | 明示而非静默 |
| 插件 / 皮肤 | 走主机插件层（multi 已适配） | 装 1 个插件复测 |

## 五、风险与开放问题

- **R1 执行位置语义**：dev/ops 模式的命令、Python 脚本在**主机**执行，不在同事机器。
  这是「后端远程」的自然结果，但对同事来说 dev 能力等价；需在导出说明里明示。
- **R2 性能/容量**：多同事并发 = 共享一个后端 + SQLite。小团队（<10 人）没问题；
  并发重活（长工作流）建议在设置里展示在线用户数。
- **R3 内网明文 http**：LAN 内为明文传输（含 API Key）。内网可信前提下可接受；
  后续可上自签 https。
- **R4 IP 漂移**：主机 DHCP 换 IP 后同事壳全断 → D3 便携覆盖是解法；建议主机设静态 IP。
- **R5 导出体积**：zip 约 190~200MB，与原安装包同量级，属预期。
