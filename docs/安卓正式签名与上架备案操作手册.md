# 安卓正式签名与上架备案操作手册

更新日期：2026-11-27

适用版本：言智移动端 `0.1.1`

## 1. 先分清两件事

Android 正式签名证书由项目自己生成和保管，OPPO、一加应用商店不会签发 APK 私钥。
商店只核验证书指纹和 APK 签名，不接收 `keystore`、密码或私钥。

项目当前正式证书：

| 项目 | 值 |
|---|---|
| keystore | `apps/mobile/signing/yan-zhi-release.jks` |
| 密码配置 | `apps/mobile/signing/keystore.properties` |
| alias | `yan-zhi` |
| 算法 | RSA 4096 |
| 证书 SHA-256 | `0C:4F:BF:A2:7B:5D:D4:E8:14:97:E2:EB:88:7F:03:4B:77:D5:86:2B:97:02:0D:4A:4F:00:E2:54:AF:23:00:B4` |
| 证书 SHA-1 | `4B:EF:34:4C:86:03:13:55:A9:42:59:9F:8A:E3:94:9D:0F:45:9F:C7` |
| 证书 MD5 | `2D:01:B4:62:C7:FF:1C:35:DB:D7:58:3B:04:16:D2:63` |
| 有效期 | 2054-04-12 |

`keystore.properties` 已设置正式密码，但该文件被 `.gitignore` 排除。
不要把 keystore、属性文件、密码写入 GitHub、公开网盘或普通聊天记录。

## 2. 正式构建

正式发行固定使用：

```powershell
pnpm package:android
```

正式链会依次执行：

1. 从 `apps/mobile/package.json` 读取版本，当前为 `0.1.1`。
2. 按 `major * 10000 + minor * 100 + patch` 生成 `versionCode=101`。
3. 每个 ABI 单独运行 `gradlew clean assembleRelease`。
4. 使用固定 keystore 签名。
5. 校验包名、版本号、证书指纹和 `application-debuggable`。
6. 输出两个单 ABI APK。

产物：

```text
dist-release/android/0.1.1/yan-zhi-0.1.1-arm64-v8a.apk
dist-release/android/0.1.1/yan-zhi-0.1.1-armeabi-v7a.apk
```

`arm64-v8a` 用于 64 位 ARM 真机，`armeabi-v7a` 用于 32 位 ARM 真机。
`x86_64` 只用于模拟器，不能提交 OPPO/一加应用商店。

调试包只在明确需要模拟器排障时生成：

```powershell
pnpm build:mobile:android:dev
```

调试包不能提交商店。

## 3. 签名自检

查看证书：

```powershell
keytool -list -v `
  -keystore apps/mobile/signing/yan-zhi-release.jks `
  -alias yan-zhi
```

签名 APK：

```powershell
$sdk = "$env:LOCALAPPDATA\Android\Sdk"
$apksigner = Get-ChildItem "$sdk\build-tools\*\apksigner.bat" |
  Sort-Object FullName -Descending |
  Select-Object -First 1
& $apksigner.FullName verify --print-certs `
  dist-release/android/0.1.1/yan-zhi-0.1.1-arm64-v8a.apk
```

必须看到相同的 SHA-256：

```text
0c4fbfa27b5dd4e81497e2eb887f034b77d5862b97020d4a4f00e254af2300b4
```

查看包名、版本和 debuggable 状态：

```powershell
$aapt = Get-ChildItem "$sdk\build-tools\*\aapt.exe" |
  Sort-Object FullName -Descending |
  Select-Object -First 1
& $aapt.FullName dump badging `
  dist-release/android/0.1.1/yan-zhi-0.1.1-arm64-v8a.apk
```

正式包必须满足：

- 包名是 `com.yanzhi.mobile`。
- `versionName='0.1.1'`。
- `versionCode='101'`。
- 输出中没有 `application-debuggable`。

## 4. 同步到家里的电脑

不能只复制 APK。家里电脑要以后继续升级同一个应用，必须同时保存 keystore。

建议复制以下本地目录或迁移压缩包：

```text
apps/mobile/signing/
  yan-zhi-release.jks
  keystore.properties
  cert-sha256.txt
dist-release/android/0.1.1/
  yan-zhi-0.1.1-arm64-v8a.apk
  yan-zhi-0.1.1-armeabi-v7a.apk
docs/安卓正式签名与上架备案操作手册.md
```

正式 APK 构建完成后，可自动生成上述迁移目录：

```powershell
pnpm package:android:transfer
```

默认输出：

```text
dist-release/mobile-transfer/0.1.1/
```

该目录含私钥和密码属性，只通过加密移动存储、受控局域网或公司网盘传输。

家庭电脑首次配置：

1. 安装 Git、Node.js 24、pnpm 11、JDK 21 和 Android SDK 36。
2. 克隆同一仓库并检出 `dev0.1-mobile` 分支。
3. 把 `signing` 目录完整复制到 `apps/mobile/signing/`。
4. 执行 `pnpm install`。
5. 执行 `pnpm package:android`。
6. 用第 3 节命令比较证书 SHA-256。
7. 指纹完全一致后才允许发布新版本。

如果只是迁移现有安装包，可以不重新构建，但以后升级仍必须使用同一份 keystore。

## 5. 更新 GitHub Actions Secrets

密码改变或换电脑后，GitHub 中的签名属性 Secret 必须同步更新。

生成 keystore Base64：

```powershell
[Convert]::ToBase64String(
  [IO.File]::ReadAllBytes('apps/mobile/signing/yan-zhi-release.jks')
) | Set-Clipboard
```

把剪贴板值写入 GitHub Secret：

```text
ANDROID_KEYSTORE_BASE64
```

生成签名属性 Base64：

```powershell
[Convert]::ToBase64String(
  [IO.File]::ReadAllBytes('apps/mobile/signing/keystore.properties')
) | Set-Clipboard
```

把剪贴板值写入 GitHub Secret：

```text
ANDROID_SIGNING_PROPERTIES_BASE64
```

不要在终端打印 Secret，也不要把 Base64 内容贴到 Issue、日志或文档中。

## 6. OPPO/一加企业开发者认证

国内一加手机应用分发走 OPPO 开放平台。

1. 打开 `https://open.oppomobile.com/`。
2. 注册并登录欢太账号。
3. 进入管理中心，选择企业开发者认证。
4. 填写申请人姓名、身份证、手机号、邮箱。
5. 完成支付宝人脸识别。
6. 填写营业执照上的企业全称、统一社会信用代码、地址和法人信息。
7. 优先使用对公打款认证：填写对公账户和联行号，输入 OPPO 打入的随机金额。
8. 没有对公账户时使用人工审核：提交法人身份证和法人手持身份证照片。
9. 人工审核通常需要 1 至 3 个工作日。
10. 认证成功后再创建应用。

官方说明：`https://open.oppomobile.com/documentation/page/info?id=10446`

## 7. APP 备案

APP 备案不是 OPPO 自行发放的证书，而是通过国家备案系统完成。

### 7.1 准备材料

- 企业营业执照。
- 法人姓名和证件信息。
- 备案负责人、应急联系人及手机号。
- 应用名称：言智。
- 包名：`com.yanzhi.mobile`。
- 签名 MD5：`2D:01:B4:62:C7:FF:1C:35:DB:D7:58:3B:04:16:D2:63`。
- 签名 SHA-256。
- App 图标、版本号、安装包和功能说明。
- 公网域名、服务器和网络接入服务商。
- 隐私政策网址和用户协议。

### 7.2 提交路径

1. 确认 App 后端公网服务所在的云厂商。
2. 如果使用阿里云、腾讯云、华为云等，登录对应云厂商的备案控制台。
3. 选择“APP 备案”或“移动应用备案”，不要只做网站 ICP 备案。
4. 填写企业主体、App 名称、包名、签名、域名和服务器信息。
5. 上传营业执照、承诺书和负责人核验材料。
6. 接入商初审通过后，材料提交至企业注册地省级通信管理局。
7. 管局审核期间保持负责人电话畅通，按退回意见补正。
8. 材料齐全时，官方办理时限约为 20 个工作日。
9. 获得备案编号后，在 App 设置或关于页面展示编号，并链接至 `https://beian.miit.gov.cn/`。

政策依据：

`https://www.gov.cn/zhengce/zhengceku/202308/content_6897341.htm`

### 7.3 一致性检查

以下名称必须一致或可解释：

- App 桌面名称。
- OPPO 后台应用名称。
- APP 备案名称。
- 软件著作权名称。

包名发布后不能修改。备份、隐私政策或功能变化时，需要及时办理备案变更。

## 8. 生成式人工智能备案与安全评估

言智包含 AI 对话和内容生成能力，提交 OPPO 前需要按生成式人工智能服务准备材料。

1. 打开 `https://beian.cac.gov.cn/`。
2. 注册企业账号。
3. 选择“生成式人工智能服务备案”。
4. 填写服务名称、应用名称、模型来源和服务形态。
5. 自研模型填写模型训练、语料、算法和安全机制。
6. 使用第三方模型时填写合作方、接口方式和合作协议，并提交合作方相应备案材料。
7. 建立输入和输出内容安全审核、敏感内容拦截、日志留存和应急处理机制。
8. 在全部生成文本、音频界面增加显著 AI 标识，例如“本内容由 AI 生成”。
9. 提供便捷的投诉举报入口和处置流程。
10. 提供青少年模式及未成年人保护措施。
11. 编制加盖公章的安全评估报告。
12. 向企业注册地省级网信部门提交备案和安全评估材料。
13. 按反馈整改后，在全国互联网安全服务管理平台提交评估结果。
14. 结果截图中的状态必须为“通过”。

OPPO 对生成式 AI 应用通常要求同时提交：

- 算法备案或生成式 AI 服务备案回执。
- 盖章安全评估报告。
- 全国平台“通过”截图。
- App 内 AI 生成内容显式标识证明。
- AI 生成内容隐式标识说明函。
- APP 备案。
- 软件著作权或电子版权证书。
- 大模型/算法承诺函。

官方资质表：`https://open.oppomobile.com/documentation/page/info?id=12133`

## 9. 提交 OPPO/一加商店

1. 管理中心 → 产品列表 → 移动应用列表 → 创建应用。
2. 填写应用名称“言智”和包名 `com.yanzhi.mobile`。
3. 选择“多包上传”。
4. 同时上传 `arm64-v8a` 和 `armeabi-v7a` 两个 release APK。
5. 准备 512×512 PNG 图标，直角、不透明、小于 1 MB。
6. 准备 3 至 5 张 1080×1920 截图。
7. 填写简体中文介绍、年龄分级、隐私政策、敏感权限说明和测试账号。
8. 上传 APP 备案、软著、AI 备案和安全评估材料。
9. 提交审核，官方说明通常为 1 至 3 个工作日。
10. 审核被拒后按驳回原因修改，提升 `versionName` 和 `versionCode` 后重新打包。

官方发布流程：`https://open.oppomobile.com/documentation/page/info?id=10035`

官方审核规范：`https://open.oppomobile.com/documentation/page/info?id=12131`

## 10. 发布前硬检查

- 两个 APK 都是 `assembleRelease`。
- 两个 APK 都是固定证书签名。
- 两个 APK 的 SHA-256 指纹相同。
- 两个 APK 都没有 `application-debuggable`。
- 包名均为 `com.yanzhi.mobile`。
- 两个 APK 的版本号一致。
- `versionCode` 高于此前所有已上传版本。
- 一个包只包含一个 ARM ABI。
- 未混入 x86/x86_64。
- Git 索引中没有 keystore、密码或属性文件。
- 家里电脑和 GitHub Secrets 使用同一份 keystore。
