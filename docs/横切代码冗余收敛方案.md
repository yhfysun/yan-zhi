## 一、分批实施

### P0：统一「文件指纹缓存 + 项目目录资产加载」（含 zcode 改动收口）✦ 小改动
- 新建 `apps/server/src/services/project-assets.ts`：
  - `cachedDirFiles(dir, ext, loader)` —— mtime+size 指纹缓存的唯一实现（带 LRU/TTL 上限，修 Z4）
  - `truncateSkillBody(body, max)` —— 截断常量与文案单点（修 Z2/Z3）
- `loadProjectRules` / `loadProjectSkills` 改为薄封装调用上述函数。
- 影响面：`llm-task-manager.ts` 两个函数 + import，无行为变化。
- 验证：现有 system prompt 相关测试 + 手工对比改前后同一会话的 system prompt 输出一致。

### P1：工具执行统一包装 `runToolCallUnified` ✦ 安全收益最高
- **现状**：同一套「emit start → 执行 → abort 分支 → 错误串 → hooks → capToolResult → 落库 → emit result」有 4 份：
  - 主循环 `llm-task-manager.ts:1943-2002`
  - 子智能体循环 同文件 `:3692-3741`（逐行复制，代码注释自认"入口漂移"）
  - UI 试跑 `routes/tools.ts:88-137`
  - 工作流节点 `workflow-runner.ts:467-546`
- **安全口径不一致（本项最大动机）**：`workflow-runner.ts:428-462` 的 ReAct 循环**没有任何 path-guard / danger-guard / user-hook 守卫**，chat 版全有。收敛即顺手修掉。
- 方案：在 server 侧新建 `services/tool-execution.ts`，`runToolCallUnified(ctx)` 统一守卫/审计/落库/事件；各入口保留差异化处置（弹窗 / fail-safe throw / fail() 返回）作为回调注入。
- 验证：四入口各跑一条真实工具调用（读文件 + cmd_exec 越界拒绝）；对照 `path_access_audit` 与 `message` 落库行为改前改后一致。

### P2：三份平行 callModel 收口到 LlmClient ✦ 行为漂移修复
- **现状**：`services/memory-dreaming.ts:73`、`services/scheduled-tasks.ts:232`、`routes/llm-proxy.ts:229` 各自拼 headers/URL/错误文案；鉴权头构造共 4 处；`anthropic-version: '2023-06-01'` 裸写 4 处。
- **漂移实锤**：三份都不吃 LlmClient 里后来修的 sanitize/空参自愈逻辑。
- 方案：`LlmClient` 增加非流式 `chatOnce(platform, messages, opts)` 静态/独立入口；`core/llm/client.ts` 内部 4 份错误 hint 块与 2 份 fetch-catch 包装先内部收敛为私有函数。
- 风险：medium——scheduled-tasks 有 token-pool 逻辑，需确认并入后的 key 轮换语义。
- 验证：memory-dreaming / scheduled-tasks / llm-proxy /preview-models 各跑一次真实调用。

### P3：core 侧 `toolOk/toolError` 结果助手 ✦ 纯机械，量最大
