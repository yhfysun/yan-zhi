## 0. 结论先行

两件事，**都能在现有代码上长出来，不需要新造执行引擎**——但有一处硬约束必须先解决（§4.6）：

| 能力 | 缺口 | 复用谁 | 新增什么 |
|---|---|---|---|
| **页面内对话** | 面板里只有「🤖 交给 AI」（把 URL 丢回主对话输入框），**没有就地对话** | 运维控制台每窗口的对话面板（`OpsConsole.vue`）+ `/llm/tasks` 任务链路 + 已有浏览器工具（支持 `tabId` 钉页） | 面板内停靠的对话面板 + 按 tab 隔离的消息状态 + **会话/锚归属**（§4.6） |
| **页面指令** | 全仓零命中：既没有"指令"数据模型，也没有匹配/新建/执行入口 | `browser_run_script`（脚本通道已存在）+ 主 agent 任务链路（任务描述型） | 指令表 + 匹配规则 + 列表/新建 UI + 执行分流 |

一句话设计：
**「页面内对话」= 把 OpsConsole 那套停靠对话搬到浏览器面板：读类问答由宿主喂页面上下文（不依赖锚），
写类动作才用现成的「显式 tabId + 建锚」口径，会话按 tab 隔离；
「页面指令」= 按站点匹配的指令库，`kind='task'` 走对话通道（自然语言任务），`kind='script'` 走已存在的 `run_script` 通道（脚本），执行前统一过权限闸门。**

## 4. 页面内对话（详细设计）

### 4.1 会话模型

- **按 tab 隔离，但归属到"面板所属会话"**：`Map<tabId, PageChatState>`，
  `PageChatState = { conversationId, messages: ChatMsg[], streaming: boolean, abort?: AbortController }`。
  `conversationId` = 面板所属会话（`preview` 空间=当前对话的会话；`page` 空间=该浏览器页的专用会话，见 §4.6）。
- **消息默认不落进主任务列表**：面板内自己渲染消息流（对齐对标"对话不会保存"）；
  需要留痕时点「↗ 追加到任务」把消息摘要 + 页面 URL 引用进主对话（复用 `addQuotedUrl`）。
- **关闭 tab 即清**：面板消息随 tab 一起丢弃（in-flight 任务 abort）。
- **不串空间**：`preview` 与 `page` 各自独立（tabs 本就分 store，`stores/browser.ts:56-90`）。

### 4.2 上下文装配（决定"懂不懂这一页"）

| 级别 | 内容 | 取法 | 触发 |
|---|---|---|---|
| L0 基础（每次必带） | URL + 标题 + host | 渲染层现成（`tab.url`/`tab.title`） | 全部消息 |
| L1 选区（有则带） | 页面内选中文字（≤4k 字） | `window.getSelection()`（渲染层/`run_script` 只读取） | 有选区 |
| L2 可视文本 | 可见文本（≤8k 字） | `browser_get_visible_text` | 问题涉及"这页/内容/表格" |
| L3 结构 | 元素编号树，供点击/填写 | `browser_get_page_content` / `get_dom` | 任务涉及"点/填/提交" |

> 口径：**宿主只保证 L0+L1**；L2/L3 由模型用工具按需取 —— 轻问答不付整页 token。

### 4.3 执行通道（读走上下文，写才建锚）

- **读类**（问答/总结/提取）：只要 L0~L2，**不需要 tab 归属** ⇒ 页面内对话可安全回答，不受 §4.6 限制。
- **写类**（点击/填写/提交）：走**同一会话 + 显式 `tabId`**；未建锚时先 `switch_tab`（属"建页类动作"，
  可由"当前可见页"回落建锚，见 §4.6）。写类动作照旧受"人工批准"闸门约束（见 `6fcf2d2`）。
- **重任务**（跨页/数据分析/报告）：面板提示 + 「移交给主智能体」（= 现有 `handPageToAgent`）。
- **执行智能体**：轻任务建议用 `a_builtin_page_agent`（`pageAgent`）承接，或主 agent + 浏览器工具；
  两种都在既有链路上，**不新增第二条抢锚链路**（历史见 `docs/pageAgent-导航跑偏-诊断报告-2026-10-15.md`）。

### 4.4 生命周期与清理（必须写死的三条）

1. **关 tab 即清**：`closeTab`/`ctxClose` 连带清 `PageChatState` 并 abort 在跑任务。
2. **切 tab 不串**：`switchTab` 切到目标 tab 状态；后台 tab 的流式不抢当前视图（沿用 `background` 打标，`stores/browser.ts:29-34`）。
3. **面板卸载即回收**：组件卸载 abort 所有 in-flight 任务，避免"关掉页面还在烧 token"。

### 4.5 UI 形态

- 入口：工具条 `🤖 AI ▾`（对标截图 AI 按钮）；首项「开启对话 / 关闭对话」。
- 布局：`BrowserPanel` 内 flex 并列（视口 + 助手面板）；宽度可拖并记忆；窄屏改抽屉式覆盖，与 `browserExpanded` 全屏互斥。
- 空态："描述要做什么，或点下面的指令" + 命中指令 chips。

### 4.6 ★ 硬约束：执行面的「锚 / 归属」（必须先拍板）

现有闸门是**按会话认页**的，这决定了页面内对话的会话怎么选：

- 每个 tab 的"谁用过"记在 `agentTouchedTabs` 上，`isMine(t)` = `agentTouchedTabs.get(t) === convId`；
  显式传了**不属于本会话**的 tabId 一律**拒绝**：`browser-target.cjs:117-124`。
- 无显式 tabId 时用"锚"；**未锚定**只有"建页类动作"（`navigate`/`new_tab`/`switch_tab`）能从
  "当前可见页"回落建锚（`browser-target.cjs:142-169`），其它动作直接报"该会话尚未绑定浏览器页面"。
- 归属**别的会话**的页不回落（防跨会话互踩，`browser-target.cjs:158-167`）。
- `/browser` 独立页（`scope='page'`）是**用户自己的空间**，agent 收尾一律不碰（`main.cjs:328`、`:2019`）。

⇒ 两条推论：

1. **`preview` 空间（对话右栏）**：面板本就属于当前会话 ⇒ 页面内对话直接用当前 `conversationId`，
   与主 agent 共用同一把流键（`convId::shared`），行为与今天一致。
2. **`page` 空间（/browser 独立页）**：页面里**没有**会话上下文。若为对话新建一个"临时会话"，
   它**既没有锚也不是 isMine** ⇒ 读页要显式 tabId 会被拒，写页要么报错、要么另建新页（正是"孤儿页"的成因）。
   ⇒ 选定方案（推荐）：**为 /browser 空间引入"浏览器专用会话"**（每空间一个，懒创建），
   该会话代表"用户自己开的这些页"，并让**首次"动手"动作走 `switch_tab`（建页类）回落建锚**——
   复用现有"当前可见页可回落"的安全通道，**不新增任何越权口子**；
   读类问答仍走宿主上下文（§4.2），**不依赖锚**，所以即使没建锚也能用。

## 5. 页面指令（详细设计）

### 5.1 数据模型

新增一张表（与现有 `skills` / `scheduled_tasks` 同级，随 DB 迁移）：

```ts
browser_page_commands
  id            TEXT PRIMARY KEY      -- 'pc_1'
  name          TEXT NOT NULL         -- '提取本页表格'
  description   TEXT                  -- 一行说明（列表里展示）
  kind          TEXT NOT NULL         -- 'task' | 'script'   ← 用户明确要的两类
  body          TEXT NOT NULL         -- kind=task：自然语言任务描述；kind=script：JS 源码
  match_host    TEXT DEFAULT '*'      -- '*.fanqieopen.com' / 'www.baidu.com' / '*'（全局）
  match_url     TEXT                  -- 可选：URL 正则，优先级高于 match_host
  variables     TEXT                  -- JSON：声明可用变量（见 5.3）
  scope         TEXT DEFAULT 'user'   -- 'builtin' | 'user'
  enabled       INTEGER DEFAULT 1
  need_confirm  INTEGER DEFAULT 1     -- 执行前是否要二次确认（script 默认 1）
  run_count     INTEGER DEFAULT 0     -- 使用统计（P3）
  created_at / updated_at TEXT        -- ISO8601（与现有表同口径）
```

内置指令以 `scope='builtin'` 随 DB 种子写入（**注意**：本仓种子真相源在 DB，改完要跑对应 sync 脚本）。

首批内置（6–8 条，全部 `kind='task'`，零脚本风险）：

| 名称 | 匹配 | 任务描述（body 摘要） |
|---|---|---|
| 总结本页 | `*` | 读当前页可见文本，输出 5 条要点 |
| 提取表格 | `*` | 把页面主表格结构化成 markdown 表格 |
| 提取全部链接 | `*` | 列出本页所有可点击链接（去重，带文本） |
| 翻译本页 | `*` | 把本页正文译成中文（保留原链接） |
| 填这个表单 | `*` | 用我提供的信息填当前表单（**不提交**，等我确认） |
| 找错误信息 | `*` | 找页面上的报错/警告文本并解释 |
| 发作品（站点指令示例） | `*.fanqieopen.com` | 按 skill 里的发布流程发一章 |

### 5.2 匹配规则

`match_url`（正则）> `match_host`（通配）> `'*'`。页面导航落定后（`applyNavigated`）算命中集合，
顺序：**站点专属在前，全局在后**；"所有指令"抽屉按 scope 分组。命中 0 条显示"当前页面暂无匹配指令 + 新建指令"。

### 5.3 变量插值

`body` 可用 `${url}` `${title}` `${host}` `${selection}` `${input:提示文案}`（运行前弹一次输入框）。
例：`给这个页面写摘要：${url}（选中内容：${selection}）`。变量在**发送前**由宿主替换；
脚本型指令额外注入只读 `ctx = { url, title, host, selection }`。

### 5.4 执行与权限（争议点，单独说）

| kind | 执行路径 | 权限口径（建议） |
|---|---|---|
| `task` | `POST /llm/tasks`（与页面内对话同一通道） | 与现有 agent 工具同权：读类直接跑；**写类**（提交表单/删除/发送）沿用"人工批准"闸门 |
| `script` | `POST /browser/action {action:'run_script', script, tabId}` | **默认 `need_confirm=1`**：执行前弹脚本预览 + 变量值，确认才跑；单条指令可标"信任"（需在设置里显式开启）；所有脚本执行**写审计记录**；风险口径与安全模式 `RiskLevel` 统一，`I`（intrusive）级别禁止免确认 |

> 为什么脚本必须默认确认：`run_script` 在**页面主世界**跑，可读同源 cookie、可带凭据 `fetch`、可改表单并提交。
> 指令库一旦能"一键执行脚本"，等于给用户装了一个**可被投喂/导入的按钮**。
> ⇒ 三条硬约束：① 默认确认；② 来自插件/外部导入的 `script` 指令**不允许**免确认；③ 审计留痕。

### 5.5 UI

- AI 菜单 →「页面指令」→ 子菜单：「所有指令（N）」「新建指令」。
- 管理抽屉：列表（名称 / 类型徽标 `任务`|`脚本` / 匹配域 / 启用 / 最近使用）+ 新建、编辑、复制、删除。

## 6. 与既有机制的边界（避免平行实现漂移）

1. **不新造"命令"概念**：页面指令 = 安全模式方案里的 `CommandDef` + `{ scope:'page', match, kind:'task'|'script' }`；
   命令中枢 P0 落地时作为其 `group:'PAGE'` 提供方接入；未落地前先用自己的小 store，**字段名与 `CommandDef` 对齐**。
2. **不新开浏览器执行面**：一切动作落到既有 `POST /browser/action` 与 `browser_*` 工具。
3. **不新增越权口子**：跨会话认页规则（§4.6）**逐字不改**；`/browser` 用户空间继续"agent 收尾不碰"。
4. **空间归属不变**：`preview` 与 `page` 各自独立，页面指令两边可用、会话互不可见。
5. **移动端**：`supportsBrowser=false`（`BrowserPanel.vue:4-7`）整块占位，无需额外适配。

## 8. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **跨会话越权闸门被绕过** | 页面内对话若用"任意临时会话"，要么被拒、要么动错页 | §4.6：会话/锚按既有规则选定，**不新增口子**；写类动作显式 `tabId` |
| **抢锚 / 导航跑偏复发** | 又多一条驱动页面的链路 | 复用 pageAgent 执行面与"显式 tabId 送达"口径，不新增第二条锚 |
| **脚本指令 = 可投喂的按钮** | 主世界脚本可读 cookie / 带凭据 fetch / 改表单 | 默认确认 + 审计 + 导入来源强制确认（§5.4） |
| **资源堆积** | 每 tab 一个渲染进程 + 每会话一次任务 | 消息随 tab 清、面板卸载 abort、复用 tab LRU 上限 |
| **token 成本** | 整页灌 prompt 很贵 | 宿主只给 L0+L1，L2/L3 模型按需取 |
| **双引擎差异** | webview（默认）与 BrowserView（回退）行为不同 | 执行全走 `browser/action` 抽象层；两引擎 `run_script` 已存在（`main.cjs:4861` / `routes/browser.ts:1888`） |
| **"不保存"的排障代价** | 临时对话无据可查 | 长留走「追加到任务」；审计只记脚本执行元信息，不存页面内容 |
