## 0. 结论先行

两件事，**都能在现有代码上长出来，不需要新造执行引擎**——但有一处硬约束必须先解决（§4.6）：

| 能力 | 缺口 | 复用谁 | 新增什么 |
|---|---|---|---|
| **页面内对话** | 面板里只有「🤖 交给 AI」（把 URL 丢回主对话输入框），**没有就地对话** | 运维控制台每窗口的对话面板（`OpsConsole.vue`）+ `/llm/tasks` 任务链路 + 已有浏览器工具（支持 `tabId` 钉页） | 面板内停靠的对话面板 + 按 tab 隔离的消息状态 + **会话/锚归属**（§4.6） |
| **页面指令** | 全仓零命中：既没有"指令"数据模型，也没有匹配/新建/执行入口 | `browser_run_script`（脚本通道已存在）+ 主 agent 任务链路（任务描述型） | 指令表 + 匹配规则 + 列表/新建 UI + 执行分流 |

一句话设计：
**「页面内对话」= 把 OpsConsole 那套停靠对话搬到浏览器面板：读类问答由宿主喂页面上下文（不依赖锚），
写类动作才用现成的「显式 tabId + 建锚」口径，会话按 tab 隔离；
「页面指令」= 按站点匹配的指令库，`kind='task'` 走对话通道（自然语言任务），`kind='script'` 走已存在的 `run_script` 通道（脚本），执行前统一过权限闸门。**

## 4. 页面内对话（详细设计）

### 4.1 会话模型

- **按 tab 隔离，但归属到"面板所属会话"**：`Map<tabId, PageChatState>`，
  `PageChatState = { conversationId, messages: ChatMsg[], streaming: boolean, abort?: AbortController }`。
  `conversationId` = 面板所属会话（`preview` 空间=当前对话的会话；`page` 空间=该浏览器页的专用会话，见 §4.6）。
- **消息默认不落进主任务列表**：面板内自己渲染消息流（对齐对标"对话不会保存"）；
  需要留痕时点「↗ 追加到任务」把消息摘要 + 页面 URL 引用进主对话（复用 `addQuotedUrl`）。
- **关闭 tab 即清**：面板消息随 tab 一起丢弃（in-flight 任务 abort）。
- **不串空间**：`preview` 与 `page` 各自独立（tabs 本就分 store，`stores/browser.ts:56-90`）。

### 4.2 上下文装配（决定"懂不懂这一页"）

| 级别 | 内容 | 取法 | 触发 |
|---|---|---|---|
| L0 基础（每次必带） | URL + 标题 + host | 渲染层现成（`tab.url`/`tab.title`） | 全部消息 |
| L1 选区（有则带） | 页面内选中文字（≤4k 字） | `window.getSelection()`（渲染层/`run_script` 只读取） | 有选区 |
| L2 可视文本 | 可见文本（≤8k 字） | `browser_get_visible_text` | 问题涉及"这页/内容/表格" |
| L3 结构 | 元素编号树，供点击/填写 | `browser_get_page_content` / `get_dom` | 任务涉及"点/填/提交" |

> 口径：**宿主只保证 L0+L1**；L2/L3 由模型用工具按需取 —— 轻问答不付整页 token。

### 4.3 执行通道（读走上下文，写才建锚）

- **读类**（问答/总结/提取）：只要 L0~L2，**不需要 tab 归属** ⇒ 页面内对话可安全回答，不受 §4.6 限制。
- **写类**（点击/填写/提交）：走**同一会话 + 显式 `tabId`**；未建锚时先 `switch_tab`（属"建页类动作"，
  可由"当前可见页"回落建锚，见 §4.6）。写类动作照旧受"人工批准"闸门约束（见 `6fcf2d2`）。
- **重任务**（跨页/数据分析/报告）：面板提示 + 「移交给主智能体」（= 现有 `handPageToAgent`）。
- **执行智能体**：轻任务建议用 `a_builtin_page_agent`（`pageAgent`）承接，或主 agent + 浏览器工具；
  两种都在既有链路上，**不新增第二条抢锚链路**（历史见 `docs/pageAgent-导航跑偏-诊断报告-2026-10-15.md`）。

### 4.4 生命周期与清理（必须写死的三条）

1. **关 tab 即清**：`closeTab`/`ctxClose` 连带清 `PageChatState` 并 abort 在跑任务。
2. **切 tab 不串**：`switchTab` 切到目标 tab 状态；后台 tab 的流式不抢当前视图（沿用 `background` 打标，`stores/browser.ts:29-34`）。
3. **面板卸载即回收**：组件卸载 abort 所有 in-flight 任务，避免"关掉页面还在烧 token"。

### 4.5 UI 形态

- 入口：工具条 `🤖 AI ▾`（对标截图 AI 按钮）；首项「开启对话 / 关闭对话」。
- 布局：`BrowserPanel` 内 flex 并列（视口 + 助手面板）；宽度可拖并记忆；窄屏改抽屉式覆盖，与 `browserExpanded` 全屏互斥。
- 空态："描述要做什么，或点下面的指令" + 命中指令 chips。

### 4.6 ★ 硬约束：执行面的「锚 / 归属」（必须先拍板）

现有闸门是**按会话认页**的，这决定了页面内对话的会话怎么选：

- 每个 tab 的"谁用过"记在 `agentTouchedTabs` 上，`isMine(t)` = `agentTouchedTabs.get(t) === convId`；
  显式传了**不属于本会话**的 tabId 一律**拒绝**：`browser-target.cjs:117-124`。
- 无显式 tabId 时用"锚"；**未锚定**只有"建页类动作"（`navigate`/`new_tab`/`switch_tab`）能从
  "当前可见页"回落建锚（`browser-target.cjs:142-169`），其它动作直接报"该会话尚未绑定浏览器页面"。
- 归属**别的会话**的页不回落（防跨会话互踩，`browser-target.cjs:158-167`）。
- `/browser` 独立页（`scope='page'`）是**用户自己的空间**，agent 收尾一律不碰（`main.cjs:328`、`:2019`）。

⇒ 两条推论：

1. **`preview` 空间（对话右栏）**：面板本就属于当前会话 ⇒ 页面内对话直接用当前 `conversationId`，
   与主 agent 共用同一把流键（`convId::shared`），行为与今天一致。
2. **`page` 空间（/browser 独立页）**：页面里**没有**会话上下文。若为对话新建一个"临时会话"，
   它**既没有锚也不是 isMine** ⇒ 读页要显式 tabId 会被拒，写页要么报错、要么另建新页（正是"孤儿页"的成因）。
   ⇒ 选定方案（推荐）：**为 /browser 空间引入"浏览器专用会话"**（每空间一个，懒创建），
   该会话代表"用户自己开的这些页"，并让**首次"动手"动作走 `switch_tab`（建页类）回落建锚**——
   复用现有"当前可见页可回落"的安全通道，**不新增任何越权口子**；
   读类问答仍走宿主上下文（§4.2），**不依赖锚**，所以即使没建锚也能用。

## 5. 页面指令（详细设计）

### 5.1 数据模型

新增一张表（与现有 `skills` / `scheduled_tasks` 同级，随 DB 迁移）：

```ts
browser_page_commands
  id            TEXT PRIMARY KEY      -- 'pc_1'
  name          TEXT NOT NULL         -- '提取本页表格'
  description   TEXT                  -- 一行说明（列表里展示）
  kind          TEXT NOT NULL         -- 'task' | 'script'   ← 用户明确要的两类
  body          TEXT NOT NULL         -- kind=task：自然语言任务描述；kind=script：JS 源码
  match_host    TEXT DEFAULT '*'      -- '*.fanqieopen.com' / 'www.baidu.com' / '*'（全局）
  match_url     TEXT                  -- 可选：URL 正则，优先级高于 match_host
  variables     TEXT                  -- JSON：声明可用变量（见 5.3）
  scope         TEXT DEFAULT 'user'   -- 'builtin' | 'user'
  enabled       INTEGER DEFAULT 1
  need_confirm  INTEGER DEFAULT 1     -- 执行前是否要二次确认（script 默认 1）
  run_count     INTEGER DEFAULT 0     -- 使用统计（P3）
  created_at / updated_at TEXT        -- ISO8601（与现有表同口径）
```

内置指令以 `scope='builtin'` 随 DB 种子写入（**注意**：本仓种子真相源在 DB，改完要跑对应 sync 脚本）。

首批内置（6–8 条，全部 `kind='task'`，零脚本风险）：

| 名称 | 匹配 | 任务描述（body 摘要） |
|---|---|---|
| 总结本页 | `*` | 读当前页可见文本，输出 5 条要点 |
| 提取表格 | `*` | 把页面主表格结构化成 markdown 表格 |
| 提取全部链接 | `*` | 列出本页所有可点击链接（去重，带文本） |
| 翻译本页 | `*` | 把本页正文译成中文（保留原链接） |
| 填这个表单 | `*` | 用我提供的信息填当前表单（**不提交**，等我确认） |
| 找错误信息 | `*` | 找页面上的报错/警告文本并解释 |
| 发作品（站点指令示例） | `*.fanqieopen.com` | 按 skill 里的发布流程发一章 |

### 5.2 匹配规则

`match_url`（正则）> `match_host`（通配）> `'*'`。页面导航落定后（`applyNavigated`）算命中集合，
顺序：**站点专属在前，全局在后**；"所有指令"抽屉按 scope 分组。命中 0 条显示"当前页面暂无匹配指令 + 新建指令"。

### 5.3 变量插值

`body` 可用 `${url}` `${title}` `${host}` `${selection}` `${input:提示文案}`（运行前弹一次输入框）。
例：`给这个页面写摘要：${url}（选中内容：${selection}）`。变量在**发送前**由宿主替换；
脚本型指令额外注入只读 `ctx = { url, title, host, selection }`。

### 5.4 执行与权限（争议点，单独说）

| kind | 执行路径 | 权限口径（建议） |
|---|---|---|
| `task` | `POST /llm/tasks`（与页面内对话同一通道） | 与现有 agent 工具同权：读类直接跑；**写类**（提交表单/删除/发送）沿用"人工批准"闸门 |
| `script` | `POST /browser/action {action:'run_script', script, tabId}` | **默认 `need_confirm=1`**：执行前弹脚本预览 + 变量值，确认才跑；单条指令可标"信任"（需在设置里显式开启）；所有脚本执行**写审计记录**；风险口径与安全模式 `RiskLevel` 统一，`I`（intrusive）级别禁止免确认 |

> 为什么脚本必须默认确认：`run_script` 在**页面主世界**跑，可读同源 cookie、可带凭据 `fetch`、可改表单并提交。
> 指令库一旦能"一键执行脚本"，等于给用户装了一个**可被投喂/导入的按钮**。
> ⇒ 三条硬约束：① 默认确认；② 来自插件/外部导入的 `script` 指令**不允许**免确认；③ 审计留痕。

### 5.5 UI

- AI 菜单 →「页面指令」→ 子菜单：「所有指令（N）」「新建指令」。
- 管理抽屉：列表（名称 / 类型徽标 `任务`|`脚本` / 匹配域 / 启用 / 最近使用）+ 新建、编辑、复制、删除。

## 6. 与既有机制的边界（避免平行实现漂移）

1. **不新造"命令"概念**：页面指令 = 安全模式方案里的 `CommandDef` + `{ scope:'page', match, kind:'task'|'script' }`；
   命令中枢 P0 落地时作为其 `group:'PAGE'` 提供方接入；未落地前先用自己的小 store，**字段名与 `CommandDef` 对齐**。
2. **不新开浏览器执行面**：一切动作落到既有 `POST /browser/action` 与 `browser_*` 工具。
3. **不新增越权口子**：跨会话认页规则（§4.6）**逐字不改**；`/browser` 用户空间继续"agent 收尾不碰"。
4. **空间归属不变**：`preview` 与 `page` 各自独立，页面指令两边可用、会话互不可见。
5. **移动端**：`supportsBrowser=false`（`BrowserPanel.vue:4-7`）整块占位，无需额外适配。

## 8. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **跨会话越权闸门被绕过** | 页面内对话若用"任意临时会话"，要么被拒、要么动错页 | §4.6：会话/锚按既有规则选定，**不新增口子**；写类动作显式 `tabId` |
| **抢锚 / 导航跑偏复发** | 又多一条驱动页面的链路 | 复用 pageAgent 执行面与"显式 tabId 送达"口径，不新增第二条锚 |
| **脚本指令 = 可投喂的按钮** | 主世界脚本可读 cookie / 带凭据 fetch / 改表单 | 默认确认 + 审计 + 导入来源强制确认（§5.4） |
| **资源堆积** | 每 tab 一个渲染进程 + 每会话一次任务 | 消息随 tab 清、面板卸载 abort、复用 tab LRU 上限 |
| **token 成本** | 整页灌 prompt 很贵 | 宿主只给 L0+L1，L2/L3 模型按需取 |
| **双引擎差异** | webview（默认）与 BrowserView（回退）行为不同 | 执行全走 `browser/action` 抽象层；两引擎 `run_script` 已存在（`main.cjs:4861` / `routes/browser.ts:1888`） |
| **"不保存"的排障代价** | 临时对话无据可查 | 长留走「追加到任务」；审计只记脚本执行元信息，不存页面内容 |

## 11. P3-5：会话来源标记 + 面板「历史」+ 总结成 Skill（**已落地 2026-10-16**）

> 即把 §9 第 3 条待拍板项定为**落库**（放弃"关闭即清除"的临时语义），并给出三件事的入口。

### 11.1 三件事

| 事 | 入口 | 行为口径 |
|---|---|---|
| **来源标记** | 办公侧栏 + 四模式任务段的会话行 | 页面对话带「页面」徽标（tooltip 指向历史入口）；**只标不改行为** |
| **历史** | 浏览器面板头部「🕘 历史」 | **列表 / 打开 / 删除**：按来源查、与当前模式无关；打开 = 切本 tab 的会话绑定并读回消息；删除 = 软删进回收站（可恢复） |
| **总结成 Skill** | 浏览器面板头部「✨ 技能」 | 复用主对话那套蒸馏弹窗（`DistillDialog`：蒸馏 → 改造 → 存草稿/存进技能商店），**不另造一套** |

### 11.2 数据模型（唯一的来源出口）

```ts
// packages/core/src/db/conversation-source.ts —— 白名单 + 规范化只有这一处
conversation.source            TEXT  -- NULL/'' = 普通会话；'browser-page' = 浏览器页面对话
conversation.source_meta_json  TEXT  -- {"url":"https://example.com/a","host":"example.com","scope":"page"}
```

- **为什么是列而不是靠 `agent_id` / 标题前缀反推**：preview 空间复用主会话（智能体是用户自己的），
  page 空间才自建 —— 靠智能体认来源，同一功能会给两个答案；靠标题前缀，用户改名即失效（§4.6 的推论）。
- **为什么解析入口只有一处**：`normalizeConversationSource` / `sourceFilterClause` / `normalizeSourceMeta` /
  `parseSourceMeta` 都在上面那个文件里，服务端写入、服务端过滤、前端 store、两个列表组件全部 import 它，
  不写字面量（这是本仓反复出事故的地方：同一语义两处实现必然漂移）。
- **迁移两套都要加**（服务端**不跑** `initSchema`，见 `routes/page-commands.ts:9`）：
  `core/src/db/schema.ts` 的 `initSchema`（客户端库）+ `apps/server/src/db.ts` 的 ALTER（服务端库）。
  ★ 顺带修掉一个真缺陷：core 侧索引一度照抄服务端的 `(user_id, source)`，而 **core 的 conversation 表没有
  `user_id` 列** ⇒ CREATE INDEX 静默失败（被 `catch {}` 吞成"索引已存在"）。现在 core 侧是单列索引。

### 11.3 顺手修掉的缺陷：/browser 里**每发一句就新建一条会话**

`send()` 原来只认调用方传来的 `convId`（page 空间恒为空）⇒ 每条消息都走 `createOwnConversation`。
后果：历史列表被"一句一条"的会话灌满（本次功能会直接显得不可用）、面板头部的「本页专属会话」名不副实、
每次发送都从零上下文开始 —— 而且**不报错**。现在改为：显式 `convId` 优先，否则**复用本 tab 已有的
`state.conversationId`**，确实没有才新建。守门测试：`stores/page-chat.test.ts`（连发两条只建一次）。

   没有钉页动作，仍走"锚 + 建页类未锚定时回落 `activeTabId`"的软语义 —— 那条回落是 2026-10-10
   为治"锚永不建立"专门加的，**不能顺手删**（删了 agent 第一步就走不动，见 `browser-target.cjs` 的
   长注释）。要不要给普通任务也钉页，是产品取舍（钉了更稳，但"跨页操作"这类正常用法会被拒）。
3. **「打开」不重放任务**：只读回消息。要接着干活就正常发一条（走同一条 `send` 通道）。

### 11.6 P3-6：目标页**硬冻结**（2026-10-16）

用户拍板「2 搞啊」——漂移不能只靠事后提示。

**问题**：页面内对话承诺"在**这一页上**问答/点击/填写"，但执行面是共用的。模型（或编排层把
`navigate(openInNewTab)` 改写成 `new_tab`）另开一页作答后，锚也跟着走，"面板跟随锚"再把用户视野
带到新页 —— 用户看到的是"看起来正常、答的却是别的页"的结果。P0.1 只能事后提示。

**做法**：任务开始时把该流**钉在用户此刻指的那一页**上（`flowPins: Map<flowKey, tabId>`）：

| 情形 | 行为 |
|---|---|
| 无显式 tabId 的动作（读/点/填/截图/navigate） | **一律落在锁定页**（不走锚、**不再回落 `activeTabId`**） |
| `new_tab` / `switch_tab` | **拒绝**（错误信息里给出口：跨页操作用「页面移交给主智能体」） |
| 带显式 tabId 的定向读 | 仍放行（工具契约允许，且它**不改**本流的操作目标） |
| 跨会话的显式 tabId | 仍拒绝（锁定**不放松**越权闸门） |
| 页内导航（`navigate` 到别的 URL） | 放行 —— 点链接→翻页→读结果本身就是这类任务的一部分 |

**关键实现点**：

1. **钉的是 tab，不是 URL**。页内换地址是任务的一部分；要禁的是"跳到别的标签页"。
2. **⓪ 必须排在"显式 tabId 优先"之前**：`switch_tab` 自带 tabId，排在后面会被静默放行
   （守门测试专门用"属于本流的 tabId 调 switch_tab"钉住这个顺序）。
3. **判定本体在 `browser-target.cjs`**（`createFlowPinRegistry` + `resolveTarget` 的 ⓪/②' 分支），
   与锚表同级的纯逻辑、可真跑验证；`main.cjs` 只持有实例并注入"tab 还在不在"。
4. **flow 传 `null` 而不是 `'shared'`**：`SHARED_FLOW` 在桌面端与后端已各有一份字面量，
   渲染层再抄第三份必然漂移 ⇒ 由 `flowKeyOf` 兜缺省。面板钉的键（`convId::shared`）与服务端
   主循环桥调用传的 `browserFlowKey || SHARED_FLOW` **是同一把**（否则锁在一把键、钉在另一把）。
5. **生命周期归 `send()` 的 finally**：成功/失败/中止都解锁（漏解锁 ⇒ 下一次任务被上一页钉死）。
   tab 关闭、会话收尾（`closeConvTabs`）各自也会清。
6. **面板措辞跟着锁定状态走**：`pinnedTabId` 非空才说"结果仍来自该页"，否则保留原来的
   "结果可能来自新页面" —— 不去声称一个没生效的锁定（这是本仓最忌讳的那类"看起来正常的错"）。
7. **没钉上就是没钉上**：web 端 / 老 preload / 主进程拒绝 ⇒ `pinnedTabId` 为空，行为退回改动前。

**守门测试**：`apps/desktop/test/browser-target-pin.test.cjs`（9 例，真跑判定本体：锁定落页 /
两者拒绝 / 定向读放行 / 不放松越权 / 解锁可逆 / 幽灵锁定自清 / 按 tab 收口 / **没锁定时行为逐字不变** /
main.cjs 与 preload 接线静态守卫）+ `packages/ui/src/stores/page-chat.test.ts` 的 P3-6 组
（钉页参数、任务进行中处于锁定态、失败也解锁、拒绝时不谎称已锁）。

### 11.7 「命令中枢」底座 + 页面指令接入（2026-10-16，用户拍板"一起做"）

§9 第 5 条不再是"等 P0 一起做"——底座已经落地，页面指令已进总线：

| 层 | 落地内容 |
|---|---|
| core 扩展点 | `plugin/types.ts` 的 `CommandDef` + `PluginContributes.commands`；`plugin/registry.ts` 的 `commands` 集合（`addContributes` / `removeByPlugin` / `snapshot` 各一处） |
| 前端聚合 | `stores/plugin.ts` 的 `commands` computed（只聚合**已启用**插件） |
| 命令总线 | `stores/commands.ts`：内置命令（从 `ChatInputArea.vue` 搬来，逐字保留文案）+ 插件命令 → `globalCommands` / `globalGroups` / `search` / `pageDefsFor(url)` / `pageCommandById(id)` |
| 唯一适配点 | `utils/commandBridge.ts`：`PageCommand → CommandDef`（`kind:'page'` + `pageKind`/`matchHost`/`matchUrl`/`pageCommandId`）、搜索、分组、前缀补全 |
| 消费方 | 聊天框 `/` 菜单（`ChatInputArea.vue`，按 `run` 动作 id 分发，不再按 `'/xxx'` 字符串）+ 浏览器面板 chips（`PageChatDock.vue`，按 `pageCommandId` 回查原始行后走**原有** `runCommand`） |

**三条设计取舍（都写进了代码注释）**：

1. **不合并两边的字段名**：`description→desc`、`kind` 语义这类强统一要动 19 个引用文件 +
   表迁移 + 三端种子 + 已上线的导入/导出协议（代价约 10 倍），且会破坏"旧导出文件仍可导入"。
   ⇒ 两边各保持最适形状，中间架一层适配（`commandBridge.ts`），**映射只有一处**。
2. **页面指令不进 `globalCommands`**：它要有"当前页"才有意义，聊天输入框没有页上下文，
   列出来只会是一堆点了没用的项。⇒ 经 `pageDefsFor(url)` 按页取。
3. **命令总线不成为第二条执行链**：它只回答"有哪些命令、怎么搜、怎么分组、要执行哪一条"；
   真跑仍走各自既有通道（内置命令的 `switch`、页面指令的 `runCommand` /
   `runScriptCommand` —— 后者带着脚本确认与审计）。
4. **注册了但没人接的命令要说出来**：`enterSlashCommand` 对未知动作 id 给一条明确提示，
   不静默吞掉（插件以后能贡献命令，执行器得有人接 —— `kind:'tool'` 还依赖安全模式的 `guard()`）。

### 11.8 命令面板交互 + 安全命令集（2026-10-16 续，用户「剩下的命令中枢也一起做」）

**交互部分**（`commandParser.ts` 纯逻辑 + `ChatInputArea.vue` 渲染）：

| 能力 | 落点 | 关键取舍 |
|---|---|---|
| 分组 | `slashRows` | 分组头**不占键盘索引**（否则连按三次下键停在标题上，看着像键盘坏了） |
| 模糊搜索 | 总线 `search`（名称 / 别名 / 说明） | 组件不再各写一份 `includes` |
| Tab 补全 | `onTab` | 只在**唯一候选**时补（多候选是猜，猜错比不补更烦） |
| ↑↓ 历史 | `pushHistory` + `localStorage:yz_cmd_history` | 仅菜单关闭时生效，去重封顶 50 |
| `;` 串联 | `splitChain` | 引号内的 `;` 是内容；需交互的命令拒绝进串联并说明 |
| `/help` | `formatHelp` / `formatCommandHelp` | 由 CommandDef **自动生成**（手写清单必然漂移） |
| 命令行取值规则 | `parseCommandLine` | 短选项 `-p 80` 吃下一个词；长选项 `--banner` 是布尔，带值写 `--url=x`（没有参数 schema，规则必须可预测） |

★ 顺手修掉一个真缺陷：`watch(input)` 只认 `/单词` 形态来开菜单，`/help agent`、`/a; /b`
这类带空格/分号的行不开菜单 ⇒ 回车走到 `send()`，**整条命令被当成聊天内容发给模型**。
现在回车前先过 `planCommandInput`（返回 `chat / run / interactive / unknown` 四态），
这条"命令绝不能被送去聊天"的规则因此**可以被真跑验证**，而不用断源码里有哪个分支。

**安全命令集**：18 个 sec-lab 工具在**插件 manifest** 里声明为命令（`sec-lab.ts` 的
`contributes.commands`），`mode:'sec'` 只在安全模式的面板出现。执行走 `POST /plugin/sec-lab/run`
—— 与安全控制台的「▶ 执行」按钮**同一条链路、同一套 `withGuard`、同一份审计**；
命令层没有新增任何绕过路径。

为此给 `CommandDef` 补了三个字段，各自都有"不这么办就会错"的理由：

- `pluginId`：命令由谁提供 ⇒ 定执行端点（不是新造执行面，就是控制台在用的那个）。
- `params: string[]`：位置参数的**有序字段名**。没有它 `/portscan 10.0.0.1` 拼不出
  `{target:'10.0.0.1'}`。（方案里的 `args?: JsonSchema` 更完备，但要写 18 遍且会与工具
  自己的 schema 漂移；等真要做参数补全/校验时再升级。）
- `confirm`：**交互闸门**，与 `danger`（风险标签）分开。靶场部署/停止的风险级是 `active`，
  可它的 schema 要求 `confirmed: true`；只在 `danger` 上做文章就会把"主动"误标成"侵入"，
  或者让用户敲完命令收到一句看不懂的"必须为 true 才真正部署"。

**守门测试**：`apps/server/test/sec-lab-commands.test.ts`（10 例，拿**同一份真相源**比对：
`activate()` 真注册出来的工具实例 + `sec-lab-guard` 的 `TOOL_RISK`）——
命令与工具一一对应、tool 名不拼错、`params` 每个字段名都在工具 schema 里、
**必填项必须能从位置参数或 usage 给到**、`params` 里必填项顺序与 schema 一致、
`danger` 与护栏推导逐条一致、`confirm` 与 schema 的 `confirmed` 字段同源。
（这套比对当场抓出两处错：`toolchain` 我标了主动而护栏是被动；
`range_deploy`/`range_stop`/`android_launch` 漏了 `confirm`，会让用户敲完命令只收到一句报错。）
