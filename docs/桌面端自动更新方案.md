# 桌面端自动更新方案（GitHub Releases + electron-updater）

> 状态：待确认
> 目标：桌面端启动时自动检测 GitHub Releases 是否有新版本，手动确认后下载安装。

---

## 一、现状

- 仓库：GitHub `yhfysun/yan-zhi`（公开），当前分支 `dev0.1`
- 桌面端：Electron 33，`apps/desktop/main.cjs`（CommonJS），入口 `app.whenReady()`（约 2743 行）
- **未接入任何自动更新**：无 `electron-updater` 依赖、无 `autoUpdater` 代码、无 GitHub Release 发布
- CI（`.github/workflows/build-desktop.yml`）目前只构建 + 上传到 Actions artifact，**不发布 Release**

---

## 二、目标与范围

1. 应用启动后，后台检查 GitHub Releases 最新版本
2. 发现新版本 → 弹窗提示「发现新版本 x.x.x」，让用户**手动确认**是否更新
3. 用户确认 → 下载安装包 → 完成后提示重启安装
4. CI 打包后自动把 `latest.yml` + 安装包发布到 GitHub Release，供应用检测

---

## 三、技术方案

### 1. 依赖

```bash
apps/desktop 增加依赖 electron-updater（^6.x）
```

`electron-updater` 的 GitHub provider 原生读取 GitHub Releases：
- 读仓库最新 Release 里的 `latest.yml`（electron-builder 打包时自动生成）
- 比较版本号：`latest.yml.version` vs 本地 `app.getVersion()`
- 有新版本 → 触发下载 → 下载完调 `quitAndInstall()` 静默重启安装

### 2. 主进程接入（apps/desktop/main.cjs）

在 `app.whenReady()` 内、`createWindow()` 之后初始化：

```js
const { autoUpdater } = require('electron-updater');

// 仅打包版启用（开发环境跳过，避免 dev 打扰）
if (app.isPackaged) {
  autoUpdater.autoDownload = false;          // 关键：不自动下载，等用户确认
  autoUpdater.autoInstallOnAppQuit = false;  // 不自动装，等用户确认退出时再装

  autoUpdater.on('update-available', (info) => {
    // 弹窗提示「发现新版本 info.version」，让用户选「更新」/「稍后」
  });
  autoUpdater.on('update-downloaded', () => {
    // 下载完成，弹窗「是否现在重启安装」，确认则 autoUpdater.quitAndInstall()
  });
  autoUpdater.on('error', (e) => { /* 静默，不打扰 */ });

  // 启动后延迟几秒再检查，避免抢启动
  setTimeout(() => autoUpdater.checkForUpdates(), 5000);
}
```

### 3. 更新策略（手动确认）

| 环节 | 行为 |
|------|------|
| 检测到新版本 | 弹窗提示，不动手下载 |
| 用户点「更新」 | `autoUpdater.downloadUpdate()` 下载 |
| 下载完成 | 弹窗「重启安装」，确认后 `quitAndInstall()` |

> 说明：`electron-updater` 的「手动确认」就是 `autoDownload: false` + 用户触发 `downloadUpdate()`。下载仍是静默的，安装需用户确认重启。

### 4. 发布侧（CI）

改 `.github/workflows/build-desktop.yml`，构建完成后：

```yaml
- name: 发布到 GitHub Release
  env:
    GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  run: |
    # 用 electron-builder 自带 publish，或 softprops/action-gh-release 上传 dist-release/*.exe + *.blockmap + latest.yml
```

关键产物要一起发布（electron-updater 靠它们）：
- `言智-Setup-<version>-x64-lite.exe`
- `言智-Setup-<version>-x64-lite.exe.blockmap`
- `latest.yml`（记录版本号 / 文件名 / sha512，electron-builder 自动生成）

### 5. 版本号约束（重要）

- electron-updater 判断「有没有新版」**只看版本号**：`latest.yml` 的 version 必须 > 本地 `app.getVersion()`（读 `package.json` 的 version / `buildVersion`）。
- 所以**每次发版必须 bump 版本号**（0.1.0 → 0.1.1 → …），否则永远提示「无更新」。
- 本次已把版本 bump 到 `0.1.1`。

## 四、影响点与风险

| 项 | 影响 / 风险 | 等级 |
|----|-----------|------|
| 新增 `electron-updater` 依赖 | 需 `pnpm install`；打包体积微增 | 低 |
| 主进程接 autoUpdater | 只在 `app.isPackaged` 生效，dev 不受影响 | 低 |
| CI 发布配置 | 需正确上传 `latest.yml`+`blockmap`，否则检测失败 | 中 |
| GitHub 国内下载慢 | 更新包从 GitHub 下载，国内用户可能慢/失败（对比：Gitee 快） | 中 |
| macOS 签名 | 未公证的 dmg，electron-updater 在 mac 上要求签名/公证才可自动更新，否则会失败（本次只做 Windows，mac 后续） | 中 |
| 手动确认的 UX | 需要弹窗 UI（主进程 dialog 或渲染层提示） | 低 |
