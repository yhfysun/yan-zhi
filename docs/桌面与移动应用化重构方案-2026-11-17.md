# 桌面与移动应用化重构方案

> 日期：2026-11-17
> 状态：第一轮已落地（移动五模式壳、桌面九模式应用栏、图书馆阅读器、控制台窄屏）；其余业务页继续迭代
> 范围：桌面端应用壳、移动端应用壳、店铺运营、桌面管理助手、超级剪贴板、桌面宠物
> 依据：真实桌面/Web/窄屏截图、现有 Vue/Electron/Capacitor 代码、仓库设计文档与已安装 UI Skill

## 0. 结论先行

当前界面的主要问题不是颜色，也不是圆角，而是**信息架构仍然像 Web 管理后台**：

- 顶部是横向网页导航，而不是桌面应用的模式/窗口控制；
- 主工作区用等权页签和卡片承载所有能力，当前任务、当前对象、下一步动作没有稳定层级；
- 店铺运营在桌面端是三栏挤压，在移动端只是把桌面表单纵向拉长；
- 剪贴板功能很全，但入口、操作和元信息同时争夺注意力；
- 宠物已经有状态和任务能力，但菜单、动作、任务面板之间仍像多个独立工具，缺少“余光产品”的克制。

建议统一改造为：

> **桌面端：专业桌面工作台。窗口即工作区，左栏是上下文，中间是主任务，右栏是检查器，底部是状态栏。**
> **移动端：任务优先的掌上助手。顶部只保留身份与上下文，底部最多四个主入口，复杂操作进入底部抽屉或全屏单步流程。**

本轮只出方案，不直接改业务代码。评审通过后从 P0 壳层和设计 Token 开始，禁止先零散改单页。

## 1. 假设与边界

1. 保留现有 Vue 3、Element Plus、Electron、Capacitor 技术栈，不迁移框架。
2. 第一轮不改店铺、剪贴板、宠物后端契约，只重组 UI、交互和现有 API 的调用方式。
3. 店铺运营以现有本地业务库和适配器为准；平台后台、登录、付款、验证码边界不变。
4. 学习模式继续遵守 `docs/学习模式设计准则.md`：总览与沉浸学习分层，一次只显示一个学习步骤。
5. 桌面端体验以 Electron 窗口为主；Web 只做兼容降级，不用 Web 版约束桌面设计。
6. 移动端优先做“运营和审批”而不是桌面功能等比缩小：快速看数、处理异常、批准变更、发货、问 AI。
7. 原有用户数据、皮肤、壁纸、学习进度、快捷键和本地业务数据不得被迁移脚本破坏。

## 3. 现状诊断

### 3.1 全局壳层

证据：

- 桌面截图顶部仍是「首页 / 当前模式 / 浏览器 / 消息 / 更多 / 刷新」的网页导航；
- 页面内容几乎铺满窗口，没有稳定的“应用模式栏 + 当前上下文栏 + 主任务区”；
- 底部状态栏只有模式、模型和空闲状态，未承担任务队列、同步和错误中心职责；
- 窄屏截图仍保留 Web 顶栏，导致图标压缩、标题拥挤、内容从 47px 左右开始。

结论：

- 需要把“导航链接”改成“模式切换 + 工作区上下文”；
- 管理页从主顶栏下沉到命令面板、头像菜单或设置；
- 桌面壳与 Web 壳需要明确分层，不能共用一套网页导航习惯。

### 3.2 店铺运营

证据：

- `ShopConsole.vue` 当前是 `ConsoleShell` 三栏：项目/资源、页签工作区、AI 对话；
- 创建店铺时左栏、开店向导、AI 欢迎和对话同时争夺注意力；
- 工作区先显示“开店向导”，其次才是概览、商品、订单、发货、库存；
- 移动端 `<900px` 直接把工作台隐藏，只显示 AI 对话，不是移动运营界面；
- 现有功能已经覆盖商品、订单、发货、库存、平台后台和审计，但缺少“今天先处理什么”的优先级中心。

结论：

- 桌面以运营看板 + 待办队列 + 工作表格为主，AI 作为常驻检查器；
- 移动以总览、待办、商品、订单四块为主，复杂编辑用底部抽屉；
- 人工/AI 是模式内部的工作方式切换，必须放在模式标题旁，不只藏在聊天栏头部。

### 3.3 剪贴板

证据：

- 现有面板已经支持搜索、文本/链接/图片/文件、置顶、快贴、分组、标签、快捷键、AI、拖出；
- 顶栏同时有品牌、快捷键、多选、布局、关闭，搜索下方再有 6 个类型 Tab；
- 每条记录同时显示编号、类型图标、两行正文、类型、时间、字数、分组、多个标签、快捷键；
- 操作使用内联 SVG，视觉语言与仓库已有 Lucide 图标体系不一致；
- 真实记录可能包含密钥、连接串等敏感信息，当前列表默认直接显示正文。

结论：

- 快贴态和管理态要分开，不能一个 456px 面板同时承担所有任务；
- 搜索和键盘选择应成为绝对主路径；
- 敏感内容默认遮蔽，显式操作后才展开；
- 图标统一为 Lucide 或现有设计系统图标。

### 3.4 桌面助手与宠物

证据：

- 桌面端已有独立剪贴板入口、任务状态、模式切换和系统状态栏；
- 宠物已有 2D/3D、六态、任务面板、快问、半圆菜单、换形象；
- `PetPopup.vue` 同时承载半圆菜单、任务、动作、形象、目录、快问、活动气泡；
- 任务面板里使用 emoji 作为静音、置顶等操作图标，和桌面 App 图标体系不一致；
- 宠物状态价值高，但面板层级和快捷入口仍多。

结论：

- 保持宠物“低打扰、高信号”；
- 同一时刻只允许一个宠物弹层；
- 用状态、任务标题、进度和下一步动作表达，不靠装饰图标；
- 桌面助手由命令面板、全局搜索、任务状态栏和剪贴板/宠物原生窗口共同组成。

## 4. 设计方向

### 4.1 去 Web 化规则

以下规则作为后续所有页面验收门槛：

1. 桌面端一级导航按真实工作模式组织，不再把所有管理页平铺成网页菜单；“工作台”不是独立模式，办公模式承载办公工作台。
2. 窗口顶部必须承担品牌、模式、当前工作区、全局搜索和窗口控制，不出现浏览器式标签导航。
3. 主工作区优先使用主从布局、分栏、表格、检查器和命令面板，不用整页卡片网格承载复杂工作。
4. 页面不出现营销 Hero、满屏渐变、漂浮卡片、圆角玻璃岛和装饰性光斑。
5. 桌面控件以 28–36px 高为主，正文 14px，辅助 12–13px；移动端触控目标至少 44px。
6. 页面必须有键盘路径：`Ctrl+K` 命令面板、`Ctrl+B` 上下文栏、`Ctrl+J` 检查器、`Esc` 退出浮层。
7. 所有加载、空状态、错误和离线状态必须保留页面结构，不用全屏 Spinner 或空白页。
8. 动效只用于反馈、方向和连续性；常规 120–200ms，面板 200–300ms，支持减少动态。
9. 产品界面只显示终端用户需要的文案。设计说明、实现备注、验收规则和“原型可点击”等评审提示只能写在文档或代码注释里，禁止出现在页面、弹窗、Toast 或空状态中。
10. 标题栏模式下拉属于浮层态：必须叠在上下文栏与检查器之上，打开时阻断底层侧栏点击，点击外部、再次点击触发器或按 `Esc` 只关闭浮层，不改变当前模式或侧栏状态。
11. 任何临时页面和浮层都必须有可见退出路径：剪贴板、宠物、记忆等 AI 子页面显示“返回对话”；通知、账号、工作区、表格行菜单点击外部可关闭；设置、命令面板和剪贴板管理保留明确关闭按钮。

### 4.2 桌面信息架构

```
┌ 56px 应用模式栏：品牌 │ 九个一级模式常驻 │ 全局搜索 │ 剪贴板/助手/系统按钮 ┐
├ 280px 可收起上下文栏 │ 主任务区（表格/看板/编辑器） │ 320px 检查器 ───────────────┤
│ 项目、对象、筛选 │ 固定标题、工具条、内容、批量操作 │ 详情/AI/变更单 │
├──────────────────────────────── 24px 状态栏：任务/同步/模型/权限/错误 ───────────────┤
└───────────────────────────────────────────────────────────────────────────────┘
```

桌面模式固定为：

- 办公：文档、表格、任务、产物与浏览器；
- 店铺运营：总览、商品、订单、履约；
- 开发：项目、代码、会话、变更；
- 运维：服务、告警、发布与审批；
- 安全：风险、扫描、修复与审计；
- 工作流：节点编排、运行、调试与定时；
- 自动化：录制、固定脚本与运行记录；
- 剪辑：素材、时间线、字幕与成片；
- 学习：科目总览、课程、沉浸学习；

桌面模式栏常驻九个一级模式，当前模式直接高亮；页面、工具与管理入口收进“更多”，不再把管理页平铺成浏览器式导航。上下文栏与检查器必须支持拖动调宽、双击收起，并在收起后通过模式栏保留始终可见的恢复入口。

各模式必须使用与其任务形态匹配的布局原型，不得共用同一套卡片页：

- 办公：三列任务台（执行中 / 等你输入 / 待验收）+ 最近任务；
- 店铺运营：经营总览、待办队列、趋势和订单表格；
- 开发：项目文件树、代码编辑器和 Agent 会话的 IDE 布局；AI 方式仍必须保留项目文件树、测试状态和 Git 插件，Git 提供独立变更/diff/提交面板；
- 运维：深色服务矩阵、事故面板和实时日志控制台；
- 安全：风险队列、攻击面面板和审计条；
- 工作流：可缩放节点画布与底部运行队列；
- 自动化：脚本库、实时执行轨迹和历史记录；
- 剪辑：节目监看、播放控制与多轨时间线；
- 学习：课程阅读桌面、步骤路径、目标侧栏和课程路线。

开发、剪辑和店铺运营属于项目中心模式，继续沿用现有成熟的项目上下文 + 主工作画布交互，不把这些页面改造成同构任务卡片页。项目中心模式在 1024px 窗口默认收起检查器；用户主动打开时，检查器覆盖在主画布右侧，而不是继续压缩代码区、监看区或运营表格。

设置、模型、MCP、工具、Skill、知识库、智能体管理下沉到：

- `Ctrl+K` 命令面板；
- 头像菜单；
- 设置页；
- 当前对象的右键菜单。

所有可切换 AI/人工的模式都必须保留完整 AI 工作界面，不允许只放命令入口或快捷卡片：

- 消息流显示用户、智能体和模型来源；
- 输入框发送前始终可见当前智能体、已挂载 Skill、模型和工具权限；
- `+` 菜单提供文件、图片、浏览器页面、剪贴板、记忆和工作流；
- 输入框支持 `Enter` 发送、`Shift+Enter` 换行；
- 设置中心使用独立面板，至少包含通用、模型与平台、智能体、Skill 与工具、权限与审批、通知、快捷键；
- 通知、账号、工作区、表格行、剪贴板、宠物和设置菜单保持独立层级，不互相套娃。

### 4.3 移动信息架构

全局底部只保留 4 个入口：

1. 工作
2. 店铺
3. 文件
4. 我的

规则：

- 工作页承载“当前移动模式”：日常办公、运维、安全、学习；店铺使用独立高频 Tab。
- 运维与安全以“监控、告警、审批、止损、报告”为主，不提供终端、扫描编排或规则编辑。
- 开发、工作流、视频剪辑、RPA 编排不进入移动一级模式；任务通知可打开只读结果和审批页。
- 当前上下文放顶栏：`店铺运营 ▾`、`当前店铺 ▾`、当前任务标题；
- 页面内二级导航使用横向可滚动的分段控件或 chips，不再叠第二条底部导航；
- 复杂筛选、商品详情、订单发货、库存调整用底部抽屉；
- 新建商品、长表单、权限确认使用全屏单步流程，底部固定主操作；
- 顶部不放高频操作；主 CTA 固定在底部拇指区；
- 任何页面不得横向溢出，文字不得遮挡相邻内容。

## 5. 店铺运营重构

### 5.1 桌面运营台

必须保留“从 0 开店”独立入口，进入后使用五步向导：

1. 选择平台：淘宝/天猫、Amazon、拼多多或 1688；
2. 店铺类型：演示、测试或生产；
3. 货源方式：有货源、无货源或混合；
4. 连接方式：官方授权、浏览器连接或手工导入；
5. 确认创建并进入开店清单。

向导必须支持保存草稿、上一步、下一步和随时返回店铺；生产店铺创建前保留权限、授权和审计提示。

建议首屏结构：

```
店铺名 / 平台 / 店铺类型 / 有货源或无货源 / 日期范围 / 对比周期 / 搜索 / AI 指令
───────────────────────────────────────────────────────────────────────────────
今日销售额   今日订单   待发货   低库存   异常同步
───────────────────────────────────────────────────────────────────────────────
需要你处理（最高优先级）                订单与履约趋势
- 3 单待发货                          线图 + 峰值/异常标记
- 4 个 SKU 低库存                     最近 14 天
- 1 个平台同步失败
───────────────────────────────────────────────────────────────────────────────
最近订单表（固定表头/首列，支持密度、筛选、批量操作）
───────────────────────────────────────────────────────────────────────────────
右侧检查器：选中订单详情 / AI 变更单 / 审计记录 / 平台跳转步骤
```

必须新增的交互：

- **待办中心**：待发货、低库存、异常、未归档审计统一为可执行队列；
- **批量操作栏**：选中商品/订单后浮出，显示影响条数和撤销入口；
- **表格密度**：舒适 52px / 标准 40px / 紧凑 32px，持久化；
- **保存视图**：筛选、排序、列宽、日期范围可命名保存；
- **键盘操作**：`↑↓` 选行、`Enter` 打开检查器、`Space` 预览、`Delete` 走确认；
- **AI 变更单**：固定在右检查器，先预览再批准，不允许对话区和工作区状态不一致；
- **人工/AI 工作台开关**：放在运营台工具条，不藏在聊天栏头；
- **表格导出**：CSV/Excel 导出保留当前筛选和排序；
- **同步状态**：平台同步显示“排队 / 同步中 / 成功 / 需重新登录 / 失败可重试”。

### 5.2 移动店铺

首页：

- 店铺切换器；
- 3 个核心数字：销售额、订单、待发货；
- “现在需要你处理”列表；
- AI 今日摘要；
- 吸底主按钮：`问 AI` 或 `处理待发货`，按当前最高优先级切换。

商品：

- 搜索 + 上架状态 chips；
- 紧凑商品行；
- 点击进入底部详情抽屉；
- 批量上下架/改价进入全屏确认页；
- 无货源模式显示“货源”而不是库存。

订单：

- 状态 chips：待付款、待发货、运输中、已完成、退款；
- 订单卡显示金额、商品数、买家尾号、超时风险；
- 主操作：创建发货、标记采购、联系买家；
- 发货表单底部固定“确认发货”，成功后保留可撤销提示。

更多：

- 库存、物流、操作日志、口径速查、平台后台；
- 不把所有入口塞进“更多”网格，而是按“经营 / 履约 / 系统”分组。

### 5.3 功能补强优先级

P0：

- 待办中心与异常聚合；
- 批量操作和撤销；
- 订单/发货状态闭环；
- 低库存与利润异常提示；
- AI 变更单检查器；
- 移动端订单发货和审批。

P1：

- 保存视图、列配置、导出；
- 同步任务队列与重试；
- 无货源采购清单与比价记录；
- 客服/售后消息占位和待处理角标；
- 库存预测和补货建议。

P2：

- 多店汇总；
- 平台 API 真实同步；
- 客服消息中心；
- 自动投放与内容运营。

## 6. 桌面管理助手

桌面助手不新增一个“网页首页”，而由四层组成：

1. **窗口标题栏**：模式、工作区、全局搜索、剪贴板、宠物、窗口控制；
2. **命令面板 `Ctrl+K`**：任务、页面、店铺、商品、订单、文件、动作统一检索；
3. **状态栏**：正在运行的任务、同步、模型、权限和错误；
4. **原生工具窗口**：剪贴板、宠物任务/Wiki、独立任务窗。

命令面板结果按四类：

- 动作：新建任务、打开店铺、切换到当前模式的 AI 工作方式、导出表格；
- 导航：去订单、去商品、打开设置；
- 实体：某店铺、某订单、某 SKU、某会话；
- 最近：最近任务、最近剪贴板、最近产物。

## 7. 超级剪贴板重构

### 7.1 双形态

**快贴态**：420 × 520

```
[搜索剪贴板.....................] [Esc]
[全部] [文本] [图片] [文件] [置顶] [分组]
1  图标  两行预览                  时间
2  图标  两行预览                  时间
...
Ctrl+Alt+V 召唤 · ↑↓ 选择 · Enter 粘贴 · Space 预览
```

**管理态**：1040 × 700

```
左栏：全部 / 类型 / 分组 / 置顶
中栏：搜索 + 列表 + 多选
右栏：完整预览、来源、标签、快捷键、AI 操作
```

### 7.2 关键交互

- 单行点击只选中；再次点击或 `Enter` 才粘贴，避免误触；
- `Space` 打开 Quick Look 预览；
- `P` 置顶，`Ctrl+Enter` 交给 AI，`Delete` 删除前确认；
- 1–9 快贴保持；
- 敏感内容默认打码，按“显示原文”后 10 秒自动重新遮蔽；
- 分组作为紧凑 chips 或左栏，不占列表主空间；
- 标签默认只显示 2 个，其余折叠；
- 原生窗口不再使用满屏白底和网页顶栏，使用桌面工具窗风格；
- 所有图标改为 Lucide 或统一图标组件，移除以 emoji 表示操作的写法。

### 7.3 数据与性能

- 列表只渲染可视区域；
- 搜索 120ms 去抖；
- 图片预览使用缩略图，完整图按需加载；
- 面板打开后首项选中，搜索框即焦点；
- 1000 条记录下滚动保持 60fps；
- 面板打开到可用 P95 < 250ms。

## 8. 宠物重构

### 8.1 交互原则

- 宠物的第一职责是表达任务状态，不是展示功能菜单；
- 同一时间只显示一个弹层；
- 默认只显示宠物本体和必要状态文案；
- 只有 running / needs-input / error / completed-unread 才出现任务气泡；
- 任务完成默认 12 秒淡出，错误持续到用户处理或关闭；
- 支持安静时段、静音、减少动作和“仅需要输入时提醒”。

### 8.2 分层

| 操作 | 层 | 内容 |
|---|---|---|
| 左键 | 任务面板 | 需要处理、进行中、刚完成 |
| 右键 | 半圆菜单 | 新建任务、任务面板、逗一下、换形象、隐藏、设置 |
| 双击 | 形象托盘 | 只负责换形象 |
| 悬停 | 快问入口 | 不默认展开，避免遮挡工作 |
| 状态变化 | 动作 + 一句短文案 | 不叠加光环、数字和多个气泡 |

任务面板：

- 宽度 340px；
- 行内只保留：状态图标、标题、进度、已用时和最重要的一个操作；
- `needs-input` 行才显示输入框；
- 行点击跳会话，行内按钮必须 `stopPropagation`；
- 底部只保留一个主操作“查看全部任务”；
- emoji 按钮替换为 Lucide 图标；
- 不显示重复的“点击行 = 跳转会话”这类说明文案。

### 8.3 移动端

移动端不常驻浮动宠物，使用：

- 顶栏小头像/状态点；
- 任务详情页中的表情/动作反馈；
- 设置中的形象选择。

## 9. 设计 Token 与动效

在现有 `tokens.css` 上增量补充：

- `--desktop-titlebar-h: 56px`
- `--desktop-mode-rail-h: 56px`
- `--desktop-context-pane-w: 280px`
- `--desktop-inspector-w: 320px`
- `--desktop-statusbar-h: 24px`
- `--mobile-tabbar-h: 56px`
- `--touch-target: 44px`
- `--table-row-compact: 32px`
- `--table-row-standard: 40px`
- `--table-row-comfortable: 52px`

动效：

- hover/按压：120ms；
- 选中/展开：180ms；
- 抽屉/检查器：220–280ms；
- 页面切换只做 6–10px 位移，不做透明度闪烁；
- 宠物复杂动作可 400–800ms，但必须可被新状态打断；
- `prefers-reduced-motion` 下关掉非必要动画。

## 10. 可访问性与状态

- 所有 icon-only 按钮必须有 `aria-label` 和 title；
- 键盘焦点环清晰可见；
- 表格支持固定表头、`aria-sort` 和键盘导航；
- 移动端 Touch target ≥44px，元素间距 ≥8px；
- 颜色不作为唯一状态表达，状态必须有图标或文本；
- 每个页面必须覆盖 loading、empty、error、offline、permission-denied；
- 弹层必须锁焦点、Esc 关闭、打开后焦点进入第一个可操作元素；
- 关闭弹层后焦点回到触发元素。

## 11. 实施顺序

| 阶段 | 内容 | 预计 |
|---|---|---:|
| P0 | 设计 Token、桌面模式栏、上下文栏、状态栏、移动全局壳 | 2–3 天 |
| P1 | 店铺桌面运营台与待办中心 | 3–5 天 |
| P2 | 店铺移动总览、商品、订单、发货 | 3–4 天 |
| P3 | 剪贴板快贴态/管理态重构 | 2–3 天 |
| P4 | 宠物任务面板、半圆菜单和状态反馈重构 | 2–3 天 |
| P5 | 命令面板、快捷键、错误/空状态、清屏验收 | 2 天 |

总计约 14–20 人日。P1 与 P3 可在 P0 完成后并行；P2 依赖 P1 的数据视图；P5 最后统一回归。

## 12. 验收标准

### 桌面

- 1440px 与 1024px 下首屏清楚区分模式、上下文、主任务和检查器；
- 1024px 下开发、剪辑和店铺运营保留可用的主工作画布，检查器不得以常驻第四栏挤压内容；
- 主导航使用真实的办公、店铺、开发、运维、安全、工作流、自动化、剪辑、学习入口；AI/人工不作为一级模式；
- 当前任务、同步状态、模型和错误在状态栏可见；
- 主表格可键盘操作，固定表头和首列；
- 页面无营销式 Hero、满屏渐变和无意义卡片墙。

### 移动

- 320px、375px、390px、428px 无横向溢出；
- 所有触控目标 ≥44px；
- 底部主导航最多 4 项；
- 移动模式仅开放日常办公、运维、安全、学习、店铺；开发/工作流/剪辑/RPA 不出现一级入口；
- 首屏主操作位于拇指区；
- 表单一次一列，底部固定主操作；
- 移动端店铺流程可在 2 次点击内进入待发货订单。
- 沉浸学习层必须完全覆盖底层总览，不得露出课程卡、全局 TabBar 或底层滚动内容；

### 剪贴板

- `Ctrl+Alt+V` 到搜索框可输入 ≤250ms；
- 搜索到粘贴完成常见路径不超过 3 次键盘操作；
- 1000 条记录滚动无卡顿；
- 敏感内容默认不显示原文；
- 快贴态与管理态职责清晰，无菜单套菜单。

### 宠物

- 同一时刻最多一个宠物弹层；
- `needs-input` 在 1 秒内可见；
- 任务面板不超过三层信息；
- 静音、减少动态、安静时段生效；
- 宠物隐藏后仍可从托盘/快捷键恢复。

### 工程

- UI typecheck 通过；
- 相关 Vitest 通过；
- Web 生产构建通过；
- 桌面主进程/preload Node 语法检查通过；
- 桌面 1440/1024 与 Web 390 截图验收；
- 移动真机或 Capacitor 环境完成一次触控回归。

## 13. 风险与规避

| 风险 | 影响 | 规避 |
|---|---|---|
| 一次改 20+ 页面 | 高 | 先改壳层和设计 Token，业务页按模式迁移 |
| 桌面/Web 共用壳导致回归 | 高 | Electron、Web、Capacitor 三套壳判定保持显式 |
| 店铺业务状态在多栏重复 | 中 | 工作区为唯一数据真相，AI 栏只读取和提交变更单 |
| 移动端功能缺失 | 中 | P2 先做审批、发货、问 AI，不追求桌面全功能 |
| 剪贴板敏感信息泄露 | 高 | 默认遮罩、显式显示、不上传、不自动读取 |
| 宠物层级过多 | 中 | 单弹层原则，动作/形象/任务互斥 |
| 皮肤系统覆盖新组件 | 中 | 新组件只使用语义 Token，补暗色和图片皮肤截图 |

## 14. 待评审决策

默认建议如下，评审时只需确认或修改：

1. 桌面模式固定为“办公 / 店铺 / 开发 / 运维 / 安全 / 工作流 / 自动化 / 剪辑 / 学习”，管理页全部下沉。
2. 店铺桌面采用“看板 + 待办 + 表格 + 右检查器”，不再以页签作为主骨架。
3. 移动底栏保留“工作 / 店铺 / 文件 / 我的”，工作页只开放日常办公、运维、安全、学习四种移动模式。
4. AI/人工是每个模式内部的工作方式；办公只有一个一级入口，AI 办公与人工工作台属于同一模式。
5. 剪贴板分快贴态和管理态，管理态独立大窗。
6. 宠物保持独立桌面窗口，但菜单/任务/动作一次只开一个。
7. P0 完成后先截图评审，再进入店铺和剪贴板业务页改造。
