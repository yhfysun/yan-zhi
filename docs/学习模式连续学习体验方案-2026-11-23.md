# 学习模式连续学习体验方案（2026-11-23）

> 状态：待评审。本轮只出方案与原型，不修改正式学习页面。
>
> 原型：
> - 可交互 HTML：`docs/prototypes/learning-continuous-session-2026-11-23.html`
> - 桌面学习 / 练习 / 实践截图：`docs/prototypes/learning-continuous-session-desktop-*.png`
> - 移动端学习 / 实践截图：`docs/prototypes/learning-continuous-session-mobile-*.png`
> - 正式页面验收截图：`docs/prototypes/learning-continuous-session-live-*.png`

## 1. 结论

当前“学习、练习、实践”不是视觉细节不统一，而是产品结构仍像三套独立页面：

1. 三套不同的壳体：课程页是深色固定学习台，实践页是深色栏 + 浅色内容区，练习页又出现一套二级工具栏。
2. 三套入口同时存在：顶栏工具条、课程页工具条、实践页工具条、练习页二级栏、移动端五宫格，重复且语义不稳定。
3. 课程上下文会漂移：练习页有独立的章节选择器，实践页跟随全局当前课程，课程页又有自己的步骤状态。用户切换一次工具后，很难确认“我还在原来那一课吗”。
4. 学习完成后的动作是分支而非连续：完成本课后可选择练习或下一课；章节练习页与实践页仍可脱离当前知识点单独进入。
5. 页面切换是整棵内容树替换，顶部、背景、阅读宽度、按钮位置都改变，所以即使代码没有整页刷新，用户仍感觉“跳走了”。

本方案不改课程数据、不扩内容，只把交互收束为一个模型：

> **一条课脉，三种工作面：先学，再练，后用。外框不换，只换中央工作面。**

## 3. 目标体验

### 3.1 一条课脉

一个知识点对应一条连续学习会话语义：

```text
学习 → 练习 → 实践 → 结课
```

- **学习**：理解问题、机制、例子与边界。
- **练习**：用 1-3 个短任务验证理解，错题能回到具体阅读段落。
- **实践**：把同一知识点用于一个可验收的小产出或模拟任务。
- **结课**：汇总本课证据、掌握状态、下一课桥接。

三个阶段的先后顺序固定，但允许学习者回看已解锁阶段。阶段不是一级导航，而是同一课脉上的检查点。

### 3.2 一套固定外框

进入一个知识点后，以下信息始终保留且位置不变：

- 返回教材；
- 科目 / 课程 / 当前知识点；
- 当前阶段与整体进度；
- 左侧本课结构和步骤定位；
- 右侧本步目标、完成证据、下一步桥接；
- 底部朗读、笔记、上一步、继续。

只有中央工作面替换。练习和实践不再重画一套顶栏、返回按钮或阅读宽度。

### 3.3 上下衔接必须显性

每次阶段切换先给出“桥接句”，而不是无解释跳转：

- 学习 → 练习：`你已经理解 threshold = capacity × load factor。接下来判断第几个元素会触发第一次扩容。`
- 练习 → 实践：`你已经能判断扩容时机。接下来为 10 万条缓存选择初始容量，并写出取舍理由。`
- 实践 → 下一课：`本课证据已收齐。下一课从“如何避免不必要扩容”继续。`

桥接句同时说明“刚学了什么、下一步要用什么”，这是课程衔接感的主要来源。

### 3.4 完成状态由证据而非点击决定

- 学习完成：读完当前知识点必要步骤。
- 练习完成：提交并看到反馈；错题进入复习，不阻塞继续。
- 实践完成：提交产出或验收清单。
- 课程完成：三类证据齐备后显示“本课已掌握”，并允许进入下一课。

不强制满分，不新增硬门禁；允许“看提示 / 看答案 / 稍后回来”。

## 4. 统一界面骨架

### 4.1 桌面

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 返回教材   编程 / Java / 3.2 HashMap 扩容             朗读 笔记 退出 │
├──────────────────────────────────────────────────────────────────────┤
│ 学习 3/5 ───────── 练习 0/3 ───────── 实践 0/1                       │
├──────────────┬──────────────────────────────────┬────────────────────┤
│ 本课结构     │ 当前工作面                       │ 本步目标           │
│              │                                  │ 完成证据           │
│ 学习步骤     │ 阅读 / 题目 / 实践任务           │ 下一站桥接         │
│ 练习节点     │                                  │                    │
│ 实践节点     │                                  │                    │
├──────────────┴──────────────────────────────────┴────────────────────┤
│ 朗读本步  记笔记                   上一步       继续 / 提交 / 完成  │
└──────────────────────────────────────────────────────────────────────┘
```

规则：

- 顶栏高度、背景、字号和按钮位置在三阶段保持一致。
- 阅读正文、题目、实践任务共用同一最大阅读宽度或同一工作区边界。
- 左栏只承担定位，不再承担一级导航。
- 右栏只放当前动作相关信息，默认不放大段正文。
- 底部主按钮只有一种语义：推进当前阶段。

### 4.2 移动端

```text
┌────────────────────────────┐
│ ← 教材   Java · 3.2     ⋯ │
│ 学习 3/5 · 练习 0/3 · 实践 │
├────────────────────────────┤
│                            │
│ 当前阶段单任务工作面       │
│                            │
├────────────────────────────┤
│ 上一步    朗读    继续     │
└────────────────────────────┘
```

- 不显示桌面左右栏；本课结构用顶部进度条 + 底部 `目录` 抽屉。
- 科目、课程、知识点固定在顶栏；进入练习或实践时不换顶栏。
- 底部只保留一个主要前进按钮，避免五宫格式的并列入口。
- 目录、笔记、提示使用 bottom sheet，不叠加第二套头栏。
- 触摸目标 ≥ 44px；步骤条与题目选项不能造成横向溢出。

## 5. 视觉统一规则

| 项 | 统一规则 |
| --- | --- |
| 底色 | 同一浅色学习表面，不再出现“深色课程台 / 浅色练习页 / 另一套实践栏”的反复切换 |
| 顶栏 | 三阶段共用一条深色上下文栏，科目色只用于当前状态和进度 |
| 卡片 | 只给独立题目、实践任务、桥接提示使用；页面区块用分隔线和留白，不堆叠卡片 |
| 圆角 | 统一 8px；按钮 7-8px，不使用超大圆角胶囊作为所有动作 |
| 字体 | 顶栏 12-13px，工作面标题 26-32px，正文 15-16px，辅助 12-13px |
| 按钮 | 主按钮用于“继续 / 提交 / 完成”，次按钮用于“上一步 / 提示 / 看来源” |
| 动效 | 只替换中央工作面，160-220ms 淡入；不整屏闪白、不重置外层 |
| 科目差异 | 用科目 accent、图标、案例语气区分，不改变壳体和交互模型 |

## 6. 课程衔接设计

### 6.1 进入

- 总览层“继续学习”必须深链到：`知识点 + 阶段 + 步骤 + 滚动锚点`。
- 如果上次停在练习题，恢复题目草稿；如果停在实践任务，恢复输入内容。
- 从课程列表直接打开知识点时，默认落在此前未完成的阶段，而不是永远回到阅读第一步。

### 6.2 阶段间

- 每阶段末显示桥接卡，主按钮文案明确：`去做第 1 题`、`带着结论去实践`、`收下本课证据`。
- 练习错题展示“回到原文”链接，定位到对应段落，但不打断当前题。
- 提示与答案逐级展开，记录是否使用过提示，用于后续复习排序。

### 6.3 结束

- 结课页显示三列证据：`理解了`、`判断对了`、`做出来了`。
- 主按钮是下一知识点，次按钮是回到本课复习或进入今日复习。
- 若本课是章末节点，则进入章末练习 / 章测，不直接跳到下一章。

### 6.4 总览层

- 课程卡显示当前停在“学习 / 练习 / 实践”的哪一段，以及最近一次学习时间。
- “继续学习”按钮不再只写课程名，而写具体动作：`继续练习：扩容判断题`。
- 章节点显示三段完成度，不把“读完”误标为“掌握”。

## 7. 与当前实现的对应改造

### P0：建立会话模型，不动内容

- 新增 `LearningSessionState`：
  - `subjectKey`
  - `courseId`
  - `knowledgePointId`
  - `stage: learn | practice | apply | done`
  - `activityId`
  - `drafts`
  - `evidence`
  - `mastery`
- 把 `activePage` 中 `lesson / studio / practice` 的学习内切换映射到 session stage；`coach` 改为会话侧栏，不再占页面。
- 练习页的独立课程选择器改为“退出本课 / 更换知识点”的显式动作，不在当前题内暗换上下文。

### P1：统一学习会户外框

- 抽出 `LearningSessionShell.vue`：顶栏、课脉、左目录、右证据栏、底部操作条。
- 中央工作面通过 slot 渲染 `LearnSurface / PracticeSurface / ApplySurface`。
- 三阶段共享背景、字体、按钮和状态条；专项学科只替换中央渲染器。
- 先迁移通用课程，再迁移英语、网安、编程、算法、易学、医学等专项；不跨范围一次性重构。

### P2：阶段桥接与课程衔接

- 为每个知识点建立 `activityChain`，把阅读步骤、随堂题、实践任务按课程 id 串联。
- 添加桥接卡和“回到原文”锚点。
- 完成状态从“点击完成”改为“学习 + 练习 + 实践证据”。
- 总览页读取 session 恢复具体阶段与草稿。

### P3：收敛入口与专项迁移

- 顶栏移除学习态里的“实践 / 练习 / 陪练”三个并列 chips；图书馆保留独立入口。
- 一级层只保留“教材 / 今日复习 / 我的”；学习态内不再出现第二套页面栏。
- AI 陪练进入右侧抽屉或按需侧栏，不再作为独立页面。
- 每个专项工作台先接 `LearningSessionShell`，再逐步统一其内部视觉变量。

## 8. 验收标准

| 项目 | 验收 |
| --- | --- |
| 连续感 | 学习、练习、实践切换时，顶栏、左栏、右栏、底部位置不移动；浏览器无整页闪白 |
| 上下文 | 任一阶段顶部均显示同一科目 / 课程 / 知识点；练习题不再暗中切换课程 |
| 衔接 | 每次阶段切换都有上一阶段结论与下一阶段动作的桥接句 |
| 恢复 | 退出后再次进入，恢复阶段、题目草稿、实践输入、滚动锚点 |
| 视觉 | 三阶段的背景、标题层级、按钮尺寸、阅读宽度一致；科目 accent 不改变壳体 |
| 操作 | 主按钮每次只推进一个动作；提示、答案、来源逐级展开 |
| 移动端 | 390 / 375 / 320 宽无横向溢出；主按钮在底部安全区可见；触摸目标 ≥ 44px |
| 无障碍 | 键盘可完成阶段切换、题目选择与提交；焦点不丢失；状态变化有 live 提示 |
| 引导 | 学习完成后不自动跳页；由明确主按钮进入下一阶段或下一课 |

## 9. 风险与默认决策

| 风险 | 默认决策 |
| --- | --- |
| 一次性重构 22 科工作台风险过高 | 先做通用学习会户外壳，专项逐个接入；不修改内容与判分逻辑 |
| 用户仍想跳过练习直接实践 | 允许探索已解锁阶段，但主按钮保持顺序；跳阶段时显示桥接提示 |
| 题目与实践数据不足 | 阶段占位使用“本课自测清单”与通用实践任务，不制造假题库 |
| 现有深色皮肤与浅色稿冲突 | 外框读取皮肤 token；原型展示默认浅色学习表面，保留深色皮肤的等价层级，不硬编码整页色 |
| 旧深链和会话失效 | 一个版本内保留 `activePage` 到 stage 的映射，旧 session key 自动迁移 |

## 10. 本轮原型说明

原型是单页可交互稿，不是正式实现：

- `学习 / 练习 / 实践 / 结课` 可在同一壳体内切换；
- 左侧课脉、右侧目标、底部操作条始终存在；
- 练习题可点选并提交；
- 实践任务可填写容量与理由；
- 提供桌面与移动布局；
- 原型只演示 Java `HashMap 扩容` 一个知识点，设计规则适用于其他科目。
