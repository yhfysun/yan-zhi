# 流式渲染卡顿修复方案（2026-10-20）

## 背景与证据

dev 跑长任务时，渲染进程主线程被占死 17~23 秒，看门狗（`apps/desktop/main.cjs:7203`，15s 心跳停摆判定）强制 reload 窗口。表现：界面卡住 → 自动刷新 → 任务断连重连，且 reload 触发又一次全量重渲，有恶性循环风险。

日志证据：

```
[watchdog] 渲染进程 2 心跳停止 17361ms → 自动重载窗口
[watchdog] 渲染进程 2 心跳停止 23002ms → 自动重载窗口
```

## 根因

`packages/ui/src/composables/chat/useChat.ts:1393`：

```js
const messageRounds = computed(() => buildMessageRounds(store.currentMessages, isToolErrorContent))
```

`buildMessageRounds`（`composables/chat/message-rounds.ts`）是**纯函数、全量重扫**所有消息。流式每 flush 一次就原地改一条消息的 `content`（`stores/chat.ts` 的 flush）→ 深层字段被 computed 追踪 → 整条 rounds 数组从头重建 → `visibleRounds` 重算 → 模板 v-for 所有可见轮次全重渲。

已做的缓解**都只是减 DOM 规模，没治全量重算**：

- 轮窗口化（~30 轮懒扩窗）
- 步骤开窗 `ROUND_STEP_RENDER_LIMIT=40`
- 消息驻留上限 600
- 自适应 flush 50/160/320ms

## 目标

流式期间只重算/重渲「正在流式的那一轮」，历史轮复用上一次结果，让 flush 成本与总消息数脱钩。

## 方案（推荐：增量复用 + v-memo）

核心思想：流式只追加「最后一个 user 消息之后」的内容，历史轮（最后一个 user 之前）在流式期间**不变**。让 computed 复用历史轮的**对象引用**，配合 `v-memo` 让 Vue 跳过历史轮的重渲。

### 实现要点

1. **增量 buildMessageRounds**：给 `messageRounds` computed 加一层缓存
   - 缓存 `{ rounds, boundaryKey }`，`boundaryKey` = 最后一个 user 消息的 id（或其下标 + id）
   - 每次 recompute：找到当前 messages 里最后一个 user 消息；若 `boundaryKey` 未变且「稳定前缀」（boundary 之前的消息数量与首尾 id）未变 → 复用缓存里 boundary 之前的 rounds（**保持对象引用**），只对 boundary 之后重建尾轮
   - 否则全量重建

2. **稳定前缀签名**：边界之前「消息数 + 首/尾消息 id」通常够用；但要防「原地编辑历史消息」。最稳妥：前缀签名带上各消息 `content`/`toolCalls` 的轻量哈希，或后端消息版本的递增号（若有）。至少先做到「prepend / 新增 user / 删除」三类结构变化必定触发全量重建。

3. **模板 v-memo**：`ChatMessageList.vue` 的轮次 v-for 加 `v-memo="[round]"`（依赖 round 对象引用）。引用不变 → 跳过该轮子树重渲。`round` 必须是稳定引用，这正是第 1 步复用引用的目的。

### 关键文件

- `packages/ui/src/composables/chat/message-rounds.ts`（buildMessageRounds 纯函数）
- `packages/ui/src/composables/chat/useChat.ts:1393`（messageRounds computed）
- `packages/ui/src/components/chat/ChatMessageList.vue`（轮次 v-for 模板）

## 边界与风险（必须逐条验证）

1. **分页 prepend**（loadMoreHistory 前插旧消息）→ 所有轮边界移位 → 必须全量重建（boundaryKey 检测到首消息 id 变了自然触发）
2. **子智能体消息**（parentToolCallId）流式期间乱序到达 → 都落在尾轮，不碰稳定前缀；但首拉整页都是子消息时（`message-rounds.ts:77` 已修的白屏问题）不能误判
3. **压缩标记**（role=system + compactMarker）穿插 → 落在尾轮
4. **消息编辑/删除** → 若改的是历史消息，原地 mutation 可能绕过「数量 + id」签名，需更严的签名或显式失效
5. **新 user 消息** → 上一轮从「尾」变「历史」，缓存需吸收（boundaryKey 更新，复用上一轮的 rounds）

## 验证

- **复现**：dev 里跑一个会持续产出工具调用的任务（flutter 分析 / 长命令），观察是否还触发 watchdog「心跳停止」
- **单测**：给增量版 `buildMessageRounds` 加行为测试，钉住三条不变量：
  - 只改尾轮内容时，历史轮对象引用不变
  - prepend / 新增 user 时全量重建
  - 子智能体消息 / 压缩标记不破坏分组
- **回归**：message-rounds 现有测试（白屏修复等）全过；`chatRenderPerf` 相关测试全过
