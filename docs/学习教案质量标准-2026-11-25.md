# 学习教案质量标准

日期：2026-11-25

## 一、适用范围

本文件适用于 Learning V2 全部 22 科、1387 门课程。旧教案、旧审计和旧 `curated` 标签不自动满足本标准。

## 二、统一教案结构

每门课程必须具备以下内容：

1. **课程定位**：本课在章节中的位置、先修知识和一个核心问题。
2. **可观察目标**：学完后能完成什么动作，不使用“了解”“熟悉”“掌握”作为唯一动词。
3. **五个教学步骤**：
   - 情境与诊断：呈现问题、前测或冲突案例，暴露学习者已有误解。
   - 材料与概念：提供定义、事实、文本、图形、实验或代码证据。
   - 示范与推导：教师展示如何阅读、推理、计算、实验或编写。
   - 引导练习：给部分提示，学习者完成关键环节并即时检查。
   - 独立迁移：撤去提示，在新情境中完成可观察产出和自评。
4. **两个以上常见错误**：错误必须可识别，并给出修正动作。
5. **练习与答案**：至少包含一个跟做任务、一个独立任务和完整答案边界。
6. **题库**：至少四道四选一题，分别覆盖事实、材料/推导、误区和迁移。
7. **来源**：至少三条可核来源，其中至少两条指向具体正文、馆藏或专题页。
8. **安全或伦理边界**：医学、网络安全、军事、易学、占卜等科目必须明确不替代专业判断。
9. **重大事件档案**：历史事件、政策转折、重大工程、经典案例和关键实验不能只靠课程正文一句概括。必须提供可点击详情，包含事件背景、逐节点时间线、结局、意义和逐条来源卡；每个时间线节点必须绑定至少一条来源。

## 三、五步质量要求

### 第一步：情境与诊断

- 用一个具体问题、材料、异常现象或任务开场。
- 必须包含可回答的前测问题。
- 不能先灌入大段结论。

### 第二步：材料与概念

- 明确概念的定义、条件、适用范围和反例。
- 历史课要给材料类型与形成时间；科学课要给变量、单位和模型条件；代码课要给运行环境和样例。
- 正文只写学科内容，不写“本页将……”“学习者应该……”等流程提示。

### 第三步：示范与推导

- 必须展示完整推理链，不只给结论。
- 历史课示范如何由材料到判断；数学课示范如何从条件到结果；代码课示范代码、运行和错误排查。
- 至少指出一个可能的替代解释、错误路径或失败条件。

### 第四步：引导练习

- 任务必须与第三步同构，但不是原题复述。
- 给出可检查的中间产物，如表格、时间线、式子、程序输出或标注文本。
- 答案检查必须能指出错在哪一层。

### 第五步：独立迁移与评价

- 提供新材料、新数据、新案例或新代码情境。
- 明确产出尺寸、格式和四条以内的评价标准。
- 不要求学习者复制教师的结论。

## 四、来源标准

### 可用来源

- 国家课程标准、教育考试说明和官方教材目录。
- 大学开放教材、开放课程、权威百科全书与专业学会指南。
- 公版原典、官方公开档案、博物馆专题和具体馆藏页。
- 一手论文、标准原文和技术文档。

### 不可单独作为依据

- 机构首页、搜索页、聚合导航页。
- 没有作者、日期、版本或正文的二手摘要。
- 自媒体文章、营销稿、AI 摘要和无法追溯的题库。
- 现代商业教材或教案的大段复制。

### 引用记录

每条来源至少写明：标题、作者或发布机构、日期/版本、用途和完整 URL。若使用公版原文，必须标出篇目；若为整理笔记，必须明确不是逐字引文。

## 五、学科附加标准

| 学科类型 | 必须增加 |
|---|---|
| 党史、政治、历史、百家思想 | 一手材料、解释与评价分层、至少一个反例 |
| 经济学、数学、物理 | 假设、变量、单位、图形或推导、边界 |
| 英语、日语 | 听读说写至少两类任务、中文对照、错误纠正 |
| 书法、音乐 | 图像/音频样例、可观察动作或听感、练习量 |
| 网络安全、军事 | 授权边界、历史/理论限定、不得提供现实攻击指导 |
| 编程、算法 | 可运行代码、预期输出、失败条件和复杂度证据 |
| 医学 | 合成病例、证据等级、危险信号、就医边界 |
| 易学、占卜 | 原文、古注、现代解释分层、概率与伦理边界 |
| 记忆、思维训练 | 可测量前后变化、迁移任务、避免伪科学承诺 |

## 六、题库校验

每课至少四题，按以下功能各出一题：

1. 事实或定义：可唯一核对。
2. 材料或推导：必须依据正文给出的证据。
3. 常见误区：干扰项来自真实误判。
4. 迁移应用：换情境后仍能用本课方法。

题解必须说明正确依据、关键干扰项错在哪里，不能只写“因此选某”。

## 七、重大事件档案

重大事件档案在课程正文之外独立展示，避免把完整过程塞成长篇段落。

必须包含：

- 事件名称、时间范围和一分钟内可读完的摘要。
- 背景：事件为什么发生，此前有哪些连续节点。
- 时间线：至少六个关键节点；每个节点写日期、发生了什么、为什么改变后续，并绑定来源。
- 结局：事件最后形成什么结果，哪些问题仍保留。
- 意义：使用什么评价尺度，作用边界和争议是什么。
- 来源卡：标题、发布者、日期、具体 URL 和该来源用于核对什么。

交互要求：

- 从当前学习步骤一键打开，关闭后回到原步骤和原滚动位置。
- 事件档案使用独立全屏阅读层，不能把章节目录、练习和事件详情同时堆在一页。
- 支持键盘 Esc 关闭、焦点进入与返回、移动端滚动和安全区。

## 七、章节验收

章节只有同时满足以下条件才算 `已验收`：

- 课序和先修关系成立。
- 术语、时间线、公式体系或代码版本前后一致。
- 章节内没有重复正文、重复任务或换皮题。
- 每课有专项测试。
- 抽查至少两条来源可访问且正文与引用用途一致。
- 做一次独立反方审阅，记录已修正的问题。
- 更新台账并运行相关类型检查。
