# 统一文件打开入口 · 方案

> 2026-09-15 · 起因：消息里点「浏览文件」被丢进 Git 目录树

## 问题

通用阅读能力（`FilePreview`）早就有 —— 图片 / PDF / Excel / CSV / Markdown / 代码 / 文本都能内嵌渲染，
不可内嵌的也有「详情 + 本机应用打开 + 打开目录」。**缺的是统一入口**，各处各写各的：

| 入口 | 原行为 | 问题 |
|---|---|---|
| 消息工具结果的「浏览文件」按钮 | 调 `openInGit()` → 切 Git 面板，且静默改 `workspaceDir` | 名字是浏览文件、行为是进目录树，还得自己在树里找 |
| 正文里的本机路径 | 纯文本，不可点 | 看到路径只能自己复制去开 |
| 视频文件 | `FilePreview` 无视频分支 → 落到 binary | 不能播放，也没有下载 |

## 结论

**一个入口，一处判定，两条出口。**

```
openPath(path)
  └─ stat().isDir ?
       ├─ 是 → 预览窗 git tab（目录树，可继续点进里面的文件）
       └─ 否 → 预览窗 file tab → FilePreview 通用阅读
```

## 两条负向断言（测试抓出来的真实误判，别删）

```
(?<![\w/\\])  →  否则 http://x.cn/c:/d 里的 c:/d 被当成盘符路径
(?!/)         →  否则 https://a/b 里的 s:/ 被当成盘符
```

## 视频

- 新增 `VIDEO_EXTS`（mp4 / webm / mov / m4v / ogv / mkv）→ 原生 `<video controls>` 内嵌播放
- 用 **Blob URL**（不是 dataURL），换文件 / 卸载时 `revokeVideoSrc()` 回收
- **> 80MB 不内嵌**，降级到 binary 出口（整段字节读进渲染进程会拖垮页面）

## 另存为

元信息条与 binary 分支都有：桌面端走系统保存框（`dialog.saveFile({ sourcePath })`，按路径复制不读字节），
Web 端 blob 触发下载。

## 已知限制

路径含空格时会在空格处截断（`C:\Program Files\x`）—— 放宽会把后续正文一起吞掉，误伤大于收益。
