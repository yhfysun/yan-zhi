# 安全模式（sec-lab）2.0 增强方案

> 状态：**方案待评审**（2026-10-16）
>
> 一句话：**已有的「授权治理 + 护栏 + 审计」内核不动，把交互从"八个表单 Tab"收敛成一个命令行，再把能力面补齐到商用渗透工具的水位线。**
>
> 参考对象：`C:\Users\yhfys\Desktop\VulnClaw-0.4.1`（开源 AI 渗透 Agent）＋ 市面工具（Nessus / Burp / Nuclei / Goby / 灯塔 ARL / XBOW / NodeZero 等）

---

## 〇、为什么要改

现有 `sec-lab`（`apps/server/src/plugins/sec-lab.ts`，19 工具 / 922 行）内核其实很扎实：

- 授权范围强校验（`sec-lab-guard.ts:167` `inScope`）、风险三级、环境上限、公网归属验证、人工闸门、全量审计——**这套东西市面上多数工具都没有**，是合规底线，必须保留。
- 缺的不是"护栏"，是**交互**和**能力纵深**：
  - 交互：`SecConsole.vue`（1891 行）是 8 个 Tab 的结构化表单，每加一个能力就加一个 Tab，已经到顶了；熟手要的是敲命令，不是点表单。
  - 能力：侦察只有 DNS/TLS/HTTP + 40 词子域字典；Web 探测是固定 18 条路径字典；**没有模板化 POC、没有漏洞验证、没有带外检测、没有报告导出、没有 CVE 情报**（对照渗透标准流程的缺口见 §六）。

本方案两根支柱：**① 把交互做简单（一个命令行）；② 把指令做多（60+ 条，按流程分组）；顺带把能力补齐。**

## 二、对标：别人有什么

### 2.1 VulnClaw-0.4.1（主要参考）

它是 **CLI / REPL / TUI / Web 四形态**的模型主导渗透 Agent。值得抄的：

| 它的做法 | 我们的价值 |
|---|---|
| **命令即入口**：`run / solve / recon / scan / exploit / report / code` 等子命令 + `--flags` | 正是"指令多"的样板 |
| **模型主导 solve 引擎**：不预设阶段模板，模型自选下一步，**证据闸门**（结论必须在真实工具输出里逐字符命中才采信） | 反幻觉机制，可直接借鉴到 secAgent |
| **AgentState 证据记忆**：工具结果全量落 `evidence`，active context 只注入高信号预览，`evidence_search/view` 按需回查 | 解决"扫描输出撑爆上下文"（我们现在只靠 16KB 截断） |
| **50+ Skill**（core 7 + specialized 40+：web/内网/CTF/逆向/CVE 分诊/OSINT…），作为**参考索引**按需加载，不强制注入 | 知识库形态可直接对齐我们已有的 skill 目录约定 |
| **流量证据**：每请求原始报文落盘 `evidence/traffic/`，`traffic_list/view/repeat/sitemap` | 证据可回放，报告能出真实请求包 |
| **29 种编解码/加解密工具**（base64/hex/AES/JWT/Morse…） | 低成本高价值的纯函数工具箱 |
| **MCP 工具链**：fetch / memory / chrome-devtools / burp | 我们已有内置浏览器（browser/pageAgent），可对位 |
| **报告**：Markdown + 可运行 Python PoC（`report/poc_builder.py`、`pdf_exporter.py`） | 我们只有对话框里的 Markdown |
| **持续性渗透**：100 轮/周期 × 10 | 对位我们的"定时巡检"规划 |
| **plugins 体系**：`builtin.web.headers / js_endpoints / jwt` 等只读检测插件 | 对位我们的 findings 生产者 |
| **执行审批（ExecutionGate）**：每次 shell/python/php 执行**逐条批准**（内容哈希、无会话白名单、超时自动拒、**无通道 fail-closed**）；三档 `ask / auto_review / full_access` | 比我们的 `confirmed` 布尔闸门更细；可作 §九 的加固项 |
| **Skill 确定性路由**：`resolver.py` **用打分而非 LLM** 选技能；显式 `/skill` 或 `@skill` 才注入正文，否则只注入"参考索引"，正文靠 `load_skill_reference` 按需拉 | 直接对位我们 §五 的 `/skill` 与 §六 #15 |
| **Skill 结构**：57 个（core 7 + specialized 50，208 篇 references），frontmatter 带 `routing:` 词表 + `requires_target:` 门禁 | 我们照 `.claude/skills` 约定即可，无需新格式 |
| **`target_state/`**：每目标 `state.json` + 快照 **list / preview / diff / rollback** + 恢复规划器；约束违规事件持久化 | 我们有 `asset_monitor` 的 snapshot/diff，**缺 rollback** |
| **`traffic/`**：mitmproxy + Playwright + Burp overlay，统一 `CapturedExchange`；**写前 scope 过滤**；JSONL 索引 + raw 报文；`replay` | 抓包代理是我们目前完全没有的一环 |
| **`report/` 闸门**：`is_report_included == verified` —— **只有已验证的发现进 SARIF**；`poc_builder` 生成可运行 PoC 且经审批门执行校验 | 对位 §六 #8 #12 的误报闭环 |
| **`intel/`**：CVE(NVD) / OSINT(crt.sh·RDAP) / compliance(PCI DSS·NIST 800-53·OWASP·ISO27001) / remediation(**20 条自动修复规则**) / topology / **MITRE ATT&CK 映射** | 对位 §五 的 `/cve /osint /baseline` 与 §六 #6 #10 |
| **`kb/`**：JSON 知识库 + 检索三级降级（ChromaDB → 中文 BM25 → 禁用）+ 可选 cross-encoder 重排；`experience` 自学习**须人工审批后**才生效 | 对位 §六 #15；"自学习须审批"值得抄 |
| **`warstories/`**：人工战报库，命名 `YYYY-MM-DD_类型_关键词.md`（元信息/攻击链/关键突破/弯路/Payload/经验） | 对位 §五 `/warstory`，命名约定可直接沿用 |
| **多智能体**：`team` 引擎产 3–7 步计划 + 波次调度 + adviser 复盘 replan；角色带**硬工具白名单**（越角色调用执行前拦截）；子代理有**预算/超时/取消树** | 对位 §六 #17；"角色硬白名单 + 预算/超时/取消"要一并设计 |

**不抄**：`codex-redteam-mode` 破限内容、C2、免杀、流量隐匿（与合规定位冲突，见 §十）。

> ⚠️ **一个反向结论**：VulnClaw **没有"证明目标已授权"的校验点**——它只在系统提示里框定合规，README 自己警告 `full_access` 模式下有提示注入风险，且 scope 约束是运行期黑名单式的 `TaskConstraints`。
> **我们的 `scope_add`（授权人 / 证明材料 / 有效期 / 归属验证）+ `guard()` 是更硬的资产**：本次改造必须保证它不被"更好用的命令入口"稀释。

### 2.2 市面工具的能力水位（用来定"功能齐全"的标准）

| 工具 | 拿它的什么 |
|---|---|
| **Nessus / OpenVAS / Qualys** | 配置基线 + 合规检查表（CIS/等保）、漏洞库分级、扫描策略模板 |
| **Burp Suite / ZAP** | 代理抓包 + 重放 + **主动/被动扫描**、Collaborator **带外检测（OAST）** |
| **Nuclei** | **YAML 模板化 POC** 引擎（今天事实标准）、模板市场 |
| **Goby / 灯塔 ARL** | 资产测绘 + 指纹 + POC 联动、子域/端口/服务的"资产视图" |
| **fscan / kscan** | 内网一键综合扫描（存活→端口→服务→弱口令→漏洞） |
| **sqlmap / hydra / ffuf / dirsearch** | 单点验证工具（我们走 B 轨白名单接管） |
| **Shodan / FOFA / 微步** | 空间测绘/威胁情报（对位 OSINT + CVE 情报） |
| **XBOW / NodeZero / PentestGPT / CAI** | 自主渗透 Agent：目标驱动、自动验证、**误报闭环**、报告带复现步骤 |

> 结论：我们要补的是 **模板化 POC、漏洞验证、带外检测、抓包代理、认证扫描、基线合规、报告导出、情报分级** 这八块；前面已有的是 **护栏、审计、扫描基础、蓝队、靶场**。

## 三、设计原则

1. **UI 只留一处输入**：一个命令行 + 一个结果流 + 三个只读面板。功能增长靠"加命令"，不靠"加 Tab"。
2. **指令是一等公民**：可注册、可补全、带别名、有 `--help`、有历史、按流程分组。
3. **护栏零妥协**：所有命令走**同一个** `guard()`、同一份 scope、同一份审计；命令层不新开任何后门。
4. **能力双轨**：本机装了 nuclei/nmap 等就接管（B 轨），没装就自研兜底（A 轨）——**功能不中断**。
5. **人在环**：侵入级动作（爆破/注入验证/带外投递）永远 `confirmed` + 交战模式；模拟类永远人工点击。

### 4.3 关键交互组件

1. **命令面板（Cmd Palette）**：输入 `/` 弹出；按**流程分组**（RECON/SCAN/WEB/VERIFY/CREDS/AUDIT/ASSET/BLUE/REPORT/KB/LAB/SYS）；模糊搜索；`Tab` 补全命令与枚举参数；`↑↓` 翻历史（localStorage 持久化）。
2. **运行卡（Run Card）**：一条命令 = 一张卡。状态（排队/运行/完成/被拦）、耗时、进度、findings 徽标、"展开原始输出"、`/export` 出证据包。**卡可折叠**，长输出默认折叠。
3. **焦点目标（active target）**：`/target staging.example.com` 设定后，后续命令可省略 target。命令执行前仍走 scope 校验。
4. **状态条**：现有 header 元数据（scopes/findings/audit/sim）保留，是最省事的"一眼看状态"。

> **"UI 简单"的量化标准**：新增任何能力，**界面零改动**——只加一条命令。这是本次改造最硬的验收条件。

## 五、指令系统：指令多

### 5.1 基建改造（全局一次性，所有模式受益）

**a) 插件扩展点新增 `commands`**（`packages/core/src/plugin/types.ts`）

```ts
export interface CommandDef {
  name: string;                 // 'portscan'（不带 /）
  aliases?: string[];           // ['ps', 'ports']
  desc: string;                 // 一行说明
  usage?: string;               // '/portscan <target> [-p spec] [--banner]'
  args?: JsonSchema;            // 参数 schema：驱动补全、校验、/help
  group: string;                // 'SCAN'（面板分组）
  mode?: AppMode;               // 限定模式（'sec'）；不填=全局
  danger?: RiskLevel;           // 展示用风险级（执行仍由 guard 决定）
  kind: 'tool' | 'ui' | 'builtin';
  tool?: string;                // kind=tool：映射到插件工具名
  run?: string;                 // kind=ui：前端动作 id（如 'open-tab:findings'）
}
// PluginContributes 增： commands?: CommandDef[]
```

**b) `ExtensionRegistry` 新增 `commands` 集合** + `snapshot()` 暴露（`registry.ts`），与 sidebar/routes 同构。

**c) 前端命令总线**（新 `packages/ui/src/stores/commands.ts`）

- `ChatInputArea.vue:1470` 的硬编码 `COMMANDS` → **内置命令 + 插件命令合并**。
- 解析器：`/cmd req [opt] --flag val`；`;` 串联；`--json` 直出结构化。
- 执行分流：`kind=tool` → 走后端插件工具（**自动过 guard**）；`kind=ui` → 前端动作；`kind=builtin` → 内置。
- `/help`、`/help <cmd>` 由 `CommandDef` 自动生成；`/` 空查询列出全部并按 group 折叠。

**d) `@` 提及扩展**：文件（现有）＋ **剧本**（`@信息收集`）＋ **技能**（`@web-pentest`）。

## 九、护栏（不改，重申）

1. 所有 `kind=tool` 命令 → `withGuard` → `guard()`（范围→风险≤maxRisk→intrusive需交战模式+confirmed→黑名单→规模）。
2. **命令层不新增任何绕过路径**：命令只是"更好用的入口"，不是新的权限面。
3. `HUMAN_ONLY_TOOLS`（`attack_sim`）不可被命令改成自动执行。
4. 公网资产、环境上限（public 仅 passive / lab 才能 simulate）规则原样生效。
5. 新能力全部登记 `TOOL_RISK` 与 `TOOL_ACTION_CLASS`；`intrusive` 默认拒绝。
6. 全量审计不降级：命令执行 = 一次审计条目。
7. **（加固项，向 VulnClaw `ExecutionGate` 看齐）逐条执行审批门**：高危动作（shell/脚本/侵入验证）由"一次 `confirmed` 布尔"升级为**逐条批准 + 内容哈希 + 超时自动拒 + 无确认通道时 fail-closed**；三档 `ask / auto_review / full_access` 与现有 `engagementMode` 合并而非并列。

> **我们的护栏比 VulnClaw 更硬**：它有运行期 `TaskConstraints` 黑名单但**没有"证明目标已授权"的校验点**，合规靠系统提示框定（README 自陈 `full_access` 下有提示注入风险）。我们的 `scope_add` + `guard()` 是更扎实的资产——本次改造的第一验收项就是**它不被新命令入口稀释**。

## 十、明确不做

- ❌ 匿名化 / 代理跳板 / 流量隐匿 / Tor 链（攻击侧需求，与"授权评估"定位冲突）
- ❌ 免杀 / 载荷生成 / C2 框架
- ❌ 公网随机目标批量扫描（授权模型天然拒绝）
- ❌ 自动漏洞利用（拿到 shell 之后的横向、持久化）
- ❌ 移动端注册 sec-lab（无本地 shell 与扫描环境）
- ⚠️ WAF 绕过只出**建议**，不自动执行绕过

## 十一、风险与对策

| 风险 | 级别 | 对策 |
|---|---|---|
| 命令多了记不住 / 误敲危险命令 | 中 | 分组面板 + `/help` + 危险命令二次确认 + 历史回显；`intrusive` 命令面板标红 |
| 命令直连工具绕开人工闸门 | **高** | `kind=tool` 一律走后端工具 + `guard`；`HUMAN_ONLY` 在服务端硬拒（不信任前端） |
| 带外检测（OAST）需要公网回调，暴露面 | 中 | 默认关闭；本地模式；token 一次性、TTL 短、仅记录不执行 |
| 模板库/POC 被用于未授权目标 | 中 | 模板执行同样过 scope 校验；模板只描述"发什么请求+怎么匹配"，不含破坏性动作 |
| 上下文被扫描输出撑爆 | 中 | 落证据 + 高信号预览（对齐 VulnClaw `AgentState`），不再只靠 16KB 截断 |
| 外部工具输出解析随版本漂移 | 中 | adapter 容错 + 版本探测 + A 轨兜底 |
