# 模型选择器上下文窗口快捷设置 · 方案

> 2026-09-15 · 对齐 WorkBuddy 的模型 hover 面板

## 背景

上下文窗口（`model.context_window`）此前只能进「配置模型平台 → 编辑模型」弹窗改，路径深。
模型选择时想按当前任务调窗口（长文档放宽到 1M、小模型收到 64K）必须先离开会话去改配置。

目标：**hover 模型即改**，两个模型入口行为一致。

## 交互

模型项 hover → 左侧（顶栏为右侧）弹出面板：

```
┌──────────────────────────┐
│ DeepSeek-V4.1-Flash  256K│   ← 模型名 + 当前值
│ 上下文窗口                │
│ [ 32K ] [ 64K ] [ 128K ] │   ← 档位，当前档高亮
│ [ 256K] [ 512K] [ 1M   ] │
│ [ 256        ] K         │   ← 自定义输入，回车/失焦生效
└──────────────────────────┘
```

- 模型项右侧常显当前窗口值（不必 hover 就知道哪个是 1M）
- 档位/输入变更即时落库，不加 toast —— 高亮态变化即反馈
- 未匹配档位时（如手填 300K）该行不出现高亮，输入框承担显示

## 入口

| 入口 | 位置 | 浮层 |
|---|---|---|
| 输入区模型下拉 | `ChatInputArea.vue` | Teleport + fixed，优先往左弹 |

> 顶栏（`ChatTopbar.vue`）曾有一个模型 pill 下拉，已按用户要求整体移除 —— 那里只留任务名与操作按钮，
> 模型切换统一收口到输入区。`AppMenu` / `AppMenuPanel` 因此暂无调用方（组件保留）。

保存链路与面板组件仍只有一份，不因入口减少而分叉。

## 数据链路

```
hover 档位 → ModelContextPanel emit('change', tokens)
  → platformStore.updateModel(id, { contextWindow: tokens })
  → PATCH /platforms/models/:mid           (apps/server/src/routes/platforms.ts:169)
  → UPDATE model SET context_window = ?    (model 表)
  → 回读 models → modelGroups 重算 → 面板当前值/档位高亮同步
```

后端消费：`llm-task-manager.ts:788 / :1474` → `new ContextWindow(model.contextWindow || 262144, 6)`，超限走滑动窗口 + LLM 摘要。

与「配置模型平台」是**同一个值**，改一处两处同步。

## 边界与取舍

- **范围 = 模型级（全局）**。改的是模型配置本身，所有会话立即生效 —— 与 WorkBuddy 面板语义一致，也复用现成链路，无需给会话加字段
- **档位** 32K / 64K / 128K / 256K / 512K / 1M。默认档 256K 必须落在档位内，否则默认值无法高亮
- **未覆盖**：`/model` 斜杠命令浮层（键盘场景，hover 面板会干扰）、移动端模型选择器（无 hover）
- `model.is_builtin` 在所有 INSERT 里恒为 `0`，`assertEditableModel` / 403 实际不会触发；若将来出现内置模型只读，面板会走 `ElMessage` 报错分支

### 必须处理的交互冲突

**点击面板被判定为外部点击**：输入区浮层 Teleport 到 body，落在 `el-popover` 的 popper 之外 ——
其 outside-click 判定发生在 document 捕获阶段，在目标元素上 `stopPropagation` 无效 →
必须在 **window 捕获阶段** 拦截面板内 `mousedown`（只阻止传播，不影响输入框/按钮聚焦）。

> 同类问题在顶栏 `AppMenu` 上也存在（子面板 Teleport 后不在 `panelRef` 内），已用 `.app-menu-sub` 放行 +
> `sub-open` 抑制关闭判定修掉；顶栏模型入口移除后该路径暂无调用方，修复保留。
