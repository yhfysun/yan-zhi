# 浏览器批注（Browser Annotation）方案 · P0

> 2026-10-28 · 分支 `dev0.1-mobile`
> 交互原型：[docs/prototypes/browser-annotation-proto.html](prototypes/browser-annotation-proto.html)

## 一、要解决什么

现在让 agent 改前端，用户只能靠文字描述「右上角那个按钮」「图表那块」。批注把这句话变成：
**在渲染好的页面上点一下 / 框一下 → 写一句话 → 连同截图和组件路径一起发给模型。**

对标 Codex 的内嵌浏览器批注。我们有两个它没有的便宜：

1. **组件路径能自动反查** —— 预览跑的是我们自己的 Vue 应用，`el.__vueParentComponent.type.__file` 直接给出 `packages/ui/src/components/Xxx.vue`。Codex 要靠站点手动声明。
2. **截图进模型的链路已经通了** —— `attachImagesToMessages`（[apps/server/src/llm-task-manager.ts:1607](../../apps/server/src/llm-task-manager.ts#L1607)）会自动扫消息里的图片路径挂成多模态输入。不用改消息协议。

## 二、非目标（P0 明确不做）

| 不做 | 留到 |
|---|---|
| 批注面板里的「样式微调 / 实时预览」（Codex 的 `Adjust`） | P1 |
| 单条批注的裁剪截图（P0 只发整页截图） | P1 |
| 批注持久化、进会话产物、可回看 | P1 |
| canvas / 图表内部图元的选择 | P1 |
| 跨 tab 累积批注 | P1 |
| 文字选区（选中一段正文） | P1 |

## 三、关键技术决策

### 决策 1：批注层注入在 guest 页内，不覆盖 Vue 层

**做法**：批注 UI（悬停框、编号框、评论输入框）全部注入到 webview 的 guest 页面里，放在 Shadow DOM 中做样式隔离。

**为什么**：命中测试要在页面坐标系里做。如果让 Vue 层盖一层透明 div 接管鼠标，每次 mousemove 都要 IPC + `executeJavaScript` 往返问「(x,y) 是什么元素」—— hover 高亮会明显掉帧。注入到 guest 里就是纯本地 DOM 操作。

**代价**：评论输入框会拿到站点的键盘/样式环境 → 用 `all: initial` 的 Shadow DOM 宿主隔离，这是浏览器扩展的标准解法。

### 决策 2：结果靠轮询取回，**不动 webview 的 preload 硬化**

**做法**：guest 内挂一个收集器 `window.__yzAnnotation`，暴露 `take()` 取走并清空待处理的批注。主进程用 `executeJavaScript` 每 120ms 拉一次。

**为什么**：`will-attach-webview` 里明确写了 `delete webPreferences.preload`（[main.cjs:1222](../../apps/desktop/main.cjs#L1222)），这是刻意的安全硬化。为了一个批注功能去恢复 guest preload、开 `sendToHost` 通道，等于给所有被浏览的页面加了一条通往主进程的路 —— 不划算。

**代价**：点击到 UI 反馈有最多 120ms 延迟。这个延迟只影响**底部队列计数**，评论框和编号框是 guest 内即时渲染的，用户感知不到。轮询只在批注模式开启时跑，关闭即停。

### 决策 3：P0 只发整页截图 + 坐标，不做逐条裁剪

**做法**：发送时调一次现有 `screenshot` 动作拿整页图（已落盘到 `userData/screenshots/`），批注里带 rect 坐标给模型做方位参考。

**为什么**：`capturePage` 已经写好并踩过坑（面板收起时快速失败，[main.cjs:6451](../../apps/desktop/main.cjs#L6451)），直接复用。裁剪要引入额外的图像处理路径，P0 收益不抵成本。

### 决策 4：与 agent 控制、与编号框**三方互斥**

三个状态任意时刻只能有一个：批注模式 / agent 占用浏览器 / agent 编号框截图。

**为什么**：Codex 已经有这个 bug（[openai/codex#49935](https://github.com/openai/codex/issues/49935)）—— agent 持有浏览器时批注不可用，但 UI 没提示，用户以为坏了。我们自己更踩过一次：编号层和常驻高亮叠成两套编号（[main.cjs:6513](../../apps/desktop/main.cjs#L6513) 的注释记着这次事故）。

## 四、P0 任务拆解

### P0-1 · 数据模型

`packages/shared/src/types/index.ts` 新增：

```ts
export interface BrowserAnnotation {
  id: string;
  type: 'element' | 'region';
  label: string;            // 人读的标签：button「卡片 CTA · Growth」
  selector?: string;        // CSS 选择器，element 类型才有
  componentFile?: string;   // packages/ui/src/components/PricingCard.vue
  componentName?: string;   // PricingCard
  rect: { x: number; y: number; w: number; h: number };  // 视口坐标
  comment: string;
  pageUrl: string;
  createdAt: number;
}
```

**验收**：类型被 shared 导出，UI 与 desktop 都能引用。

### P0-2 · 注入层（desktop 主进程）

`apps/desktop/main.cjs` 的 `browserView:action` 里新增三个 action：

| action | 行为 |
|---|---|
| `annotation_begin` | 注入批注 overlay（幂等，先清旧的）；返回 `{ok:true}` |
| `annotation_end` | 移除 overlay + 返回剩余未取走的批注 |
| `annotation_drain` | `executeJavaScript('window.__yzAnnotation?.take() ?? []')` |

注入脚本要点：

- **悬停**：`mousemove` → `document.elementFromPoint` → `closest('[data-comp]')` 兜底取元素 → 画橙色框（`#f97316`，与现有编号框同色）+ 顶部标签显示组件路径。
- **单击**：锁定元素，就地弹出评论框。
- **拖拽**：位移 > 6px 判为框选，画虚线矩形，松开弹评论框。
- **组件反查**：`el.__vueParentComponent?.type?.__file` / `.__name`，取不到就不写这两个字段。
- **选择器生成**：向上最多 5 层，带 `nth-of-type`，`>` 连接。
- **收集器**：`window.__yzAnnotation = { push, take, clear, active }`。
- **清理**：`annotation_end` 与 `navigate` 后都必须移除 overlay（新文档本来就没有，但旧文档的计时器要清）。

**验收**：dev server 页面上开批注 → 悬停有高亮和组件路径 → 点元素能弹框 → 写评论保存 → `annotation_drain` 能取回完整记录。

### P0-5 · 互斥与守卫

- `annotation_begin` 前检查 agent 是否持有浏览器控制权（复用现有 action 锁），占用则拒绝并回错误码。
- agent 开始执行 action 时，若批注开着 → 自动 `annotation_end` 并在 UI 提示。
- 截图走现有 `screenshot` action，因此面板收起时会命中 [main.cjs:6451](../../apps/desktop/main.cjs#L6451) 的快速失败。
  **实现取舍（与初版方案不同）**：截图失败不拦截发送，而是降级成「只发文字批注」并提示原因 ——
  用户已经按下发送再被弹回来，体验比丢一张截图更差；而组件路径与评论本身已足够定位。

**验收**：agent 跑任务时批注按钮点不动；面板收起时发送仍成功，且提示说明本次没有带截图。

## 五、已知风险

| 风险 | 影响 | 应对 |
|---|---|---|
| **生产构建没有 `type.__file`** | 打包版预览反查不到组件路径 | 降级为 selector；`componentFile` 设为可选字段，拼消息时缺就省略该行。P0 主要服务 dev server 预览，可接受 |
| SPA 重渲染后元素替换 | selector 悬空、坐标失效 | 批注在「保存那一刻」固化快照（含 rect + 元素文本），不依赖事后解析 |
| webview 隐藏时 `capturePage` 失败 | 发送拿不到截图 | 复用现成快速失败分支，提示展开面板；批注本身不丢 |
| 注入脚本与站点 CSP | 部分站点禁 inline script | 我们走 `executeJavaScript`（主进程注入，不受页面 CSP 限制），但 `<style>` 内联到 Shadow DOM 是安全的 |
| 轮询泄漏 | tab 关闭后定时器还在跑 | `useBrowserAnnotation` 在 `onUnmounted` 和 tab 关闭时统一 `clearInterval` |
| iframe / 跨域内容 | 内嵌 iframe 里的元素拿不到 | 现有 `annotate` 注入已有 iframe 穿透代码（[main.cjs:6502](../../apps/desktop/main.cjs#L6502)）可复用，但跨域 iframe 无解 → 降级成区域框选 |

## 六、实现中发现并修掉的问题（2026-10-28）

真机跑链路时踩到的三处，已修：

1. **`/browser` 独立页点「发送到对话」会静默不发。** 该页用 `page` scope 的 store，而 `useChat`
   只读 `preview` 那份队列 —— 两边对不上，点了什么都不发生。修法：加一个**一次性交接槽**
   （`stashAnnotations` / `takeStashedAnnotations`），独立页发送前把批注交过去。
2. **未配置模型时批注被吞。** `sendInner` 的「没平台/没模型」分支自带一条空内容守卫，
   它不认识批注，于是空输入 + 有批注直接 `return`。修法：批注块在**分叉之前**就拼好，
   两条分支都带。
3. **组件路径反查必须沿组件链上溯。** 真实 UI 里点击落点的最近组件常是第三方包装层
   （实测得到 Element Plus 的 `ElOnlyChild`，它没有 `__file`），只看最近一层永远拿不到
   `.vue` 路径。改成往上找第一个带 `__file` 的实例；同时点击会吸附到最近的
   `button/a[href]/[role=button]` 祖先，标签与选择器才对得上用户本意。
4. **`sendInner` 里还有第三道只认输入框文字的闸。** 前两道改完之后仍然发不出去，
   toast 是「请输入消息」（`if (!userContent.trim())`，在 `let userContent = content` 之后、
   批注块追加之前）。**这是最难查的一处**：前面的代码都跑到了（截图动作真的发出去了），
   但没有落库，看上去像"发送成功但没存"。
   ⇒ 以后任何"非输入框内容"（文件、引用、批注）接入发送链路，都要把这处守卫一并检查。

**结论**：批注 → 消息 → 落库 → 截图存档 全链路已在真机跑通（2026-10-28 18:20）。

## 七、完成标准

两条路都走通才算 P0 完成：

1. **元素批注**：dev server 预览 → 批注 → 点「立即升级」→ 写评论 → 发送 → 对话里出现含组件路径的批注块 → agent 改的就是 `PricingCard.vue`。
2. **区域批注**：框选图表区域 → 写评论 → 发送 → 模型能说出截图里 tooltip 的位置关系。

外加三个守卫生效：agent 占用时禁用、面板收起时给可操作提示、编号框与批注不共存。
