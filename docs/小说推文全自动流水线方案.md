# 小说推文全自动流水线 · 完整方案

> 目标：人只负责注册/登录各平台账号，其余（选书 → 授权申请 → 改编 → 绘图 → 配音 → 合成 → 发布 → 挂车回传 → 数据回收）全部由自动化链路完成。
> 参考来源：巨日禄【小说推文】工具宝箱（飞书文档）

---

## 0. 能不能"全自动"？（先对齐现实）

| 环节 | 自动化可行性 | 方式 |
|---|---|---|
| 选书 | ✅ 全自动 | 爬推文平台榜单，LLM 打分排序 |
| 授权申请 | ✅ 浏览器自动填写申请 | 有验证码时暂停问你 |
| 文案改编 | ✅ 全自动 | LLM 生成口播脚本 + 分镜 JSON |
| AI 绘图 | ✅ 全自动 | ComfyUI 本地 / 即梦 API |
| TTS 配音 | ✅ 全自动 | Edge-TTS（免费）/ 豆包 TTS |
| 视频合成 | ✅ 全自动 | ffmpeg 模板合成（4:3） |
| 发布到抖音/快手 | ⚠️ 浏览器自动操作可行 | 桌面浏览器自动化模拟人工 |
| 挂车/回传链接 | ⚠️ 同上 | 推文平台回传页自动填写 |
| 数据回收 | ✅ 全自动 | 定时抓创作者后台数据出报表 |

**结论：可以做到"人只注册登录"，但要接受两条现实约束：**
1. 抖音/快手有风控，浏览器自动化必须"拟人化"（随机延时、真人鼠标轨迹、单号单浏览器指纹），并且新号前 1-2 周建议人工发，养出权重后再交给自动化。
2. 遇到滑块/短信验证码，流程自动暂停，弹窗通知你点一下，之后继续。

## 1. 整体架构

```
┌─────────────────────────────────────────────┐
│                调度中心（每日定时任务）          │
└─────────────────────────────────────────────┘
      │
      ├─ ① 选书模块：爬授权平台榜单 → LLM 评估 → 今日书单
      ├─ ② 授权模块：浏览器自动登录推文平台 → 自动申请授权 → 拿推广链接/回传ID
      ├─ ③ 改编模块：原文 → LLM → 分镜脚本 JSON（文案+画面描述+时长+钩子）
      ├─ ④ 素材模块：ComfyUI 出分镜图 + Edge-TTS 出配音 + 字幕对齐
      ├─ ⑤ 合成模块：ffmpeg 模板（4:3、Ken Burns、字幕、BGM）→ 成片
      ├─ ⑥ 发布模块：浏览器自动登录抖音/快手创作者端 → 上传 → 填标题/话题 → 发布
      ├─ ⑦ 回传模块：浏览器自动到推文平台回传视频链接 → 确认挂车
      └─ ⑧ 数据模块：每日抓播放/完播/点击/佣金 → 汇总报表
```

每个环节产出一个明确的中间产物（JSON/CSV/MP4），环环解耦，任何一环失败可单独重跑。

## 2. 各环节详细设计

### ① 选书（全自动）
- 数据源：巨日禄 / 番茄推文 / 知乎盐选 / 掌中云 等平台的**公开榜单页**（浏览器自动化抓取，不碰需要破解的接口）。
- 打分维度（LLM 评估）：题材热度、开头钩子强度、完播潜力、竞争度（同书视频数少优先）。
- 产物：`booklist-YYYYMMDD.csv`（书名/平台/题材/评分/授权状态），每天早上给你看一眼，默认取 Top3 自动进入下一环节。

### ② 授权申请（浏览器自动化）
- 自动登录推文平台（登录态持久化在浏览器 profile，之后不用你再登）。
- 自动进入"申请推广"页 → 填写达人信息 → 提交。
- 遇验证码：暂停 → 系统通知 → 你点完 → 流程继续。
- 产物：`授权记录.csv`（书名、推广链接、回传参数、有效期）。
- ⚠️ 红线：**只申请、只发布已授权书目**，未授权一律不进合成队列。

### ③ 文案改编（LLM 全自动）
Prompt 产线（做成可复用模板）：
- 输入：章节原文（控制 3000 字内）。
- 输出：分镜脚本 JSON：
```json
{
  "hook": "前3秒钩子文案",
  "segments": [
    {"text": "口播文案", "scene": "画面描述（给绘图用）", "duration": 8}
  ],
  "ending": "悬念结尾 + 引导看评论区/链接"
}
```
- 规范：总时长 60-180 秒；每 15-20 秒一个悬念点；结尾必须留钩子促点击。

### ④ 素材生产（全自动）
- **绘图**：ComfyUI 本地（你机器已装）跑固定 LoRA/角色一致性工作流，按 `scene` 字段批量出图；兜底走即梦/通义 API。
- **配音**：Edge-TTS 免费（多音色），关键角色对话用不同音色；产 wav + 逐句时间戳（subtitle 轴）。
- **字幕**：按 TTS 时间戳生成 SRT，杜绝音画不同步。

### ⑤ 视频合成（全自动 ffmpeg）
- 画面：4:3（文档明确要求，别 16:9，别关联中视频）。
- 分镜图 + Ken Burns 缓动缩放 + 字幕烧录 + BGM（音量 -18dB 压在配音下）+ 片尾引导帧。
- 一条 90 秒视频合成时间约 1-2 分钟，日更 10 条无压力。
- 产物：`output/{书名}_{日期}.mp4`。

### ⑥ 发布（浏览器自动化，拟人化重点区）
- 单账号 = 单浏览器 profile（隔离指纹，避免关联）。
- 流程：打开创作者中心 → 点上传 → 选文件 → 自动填标题（书名+题材词）+ 话题标签（#小说 #推文 等 3-5 个）→ 选封面帧 → 发布。
- 拟人化措施：随机操作间隔 2-8 秒、鼠标轨迹模拟、发布时间错峰（账号 A 早 10 点、账号 B 晚 8 点…）。
- 新号前 1-2 周人工发，权重稳定后切自动。

### ⑦ 回传挂车（浏览器自动化）
- 发布成功后拿视频链接 → 自动到推文平台"视频回传"页填写 → 等平台审核挂车。
- **没回传 = 白做**，此环节失败会触发强提醒。

### ⑧ 数据看板（全自动）
- 每晚自动登录各创作者后台抓：播放/完播率/点击车次数。
- 平台侧抓：确认佣金。
- 产物：`数据日报.csv` + 周报（哪类书、哪类开头钩子出单，反哺选书和改编模板）。

## 3. 技术落点（结合本机现有能力）

| 模块 | 实现 |
|---|---|
| 调度 | yan-zhi 定时任务/自动化（每日 08:00 产片、错峰发布、22:00 数据回收） |
| 浏览器自动化 | **yan-zhi 内置浏览器（Electron BrowserView）+ pageAgent / Playwright 鼠标键盘模拟**，登录态存各账号独立 profile，用户只需首次注册登录 |
| 桌面兜底 | yan-zhi 桌面应用自动化 skill，处理客户端形态的发布入口 |
| LLM 改编 | 接现有 LLM 链路，改编模板做成 yan-zhi skill / 自定义工具 |
| 绘图 | 本机 ComfyUI 工作流 + API 兜底 |
| TTS | Edge-TTS（零成本起步） |
| 合成 | ffmpeg 直调（已有成熟滤镜经验，bash 直调不走 node spawn） |
| 报表 | CSV + 简单 HTML 看板，可在 yan-zhi 预览窗直接查看 |

> 说明：发布/回传环节直接在 yan-zhi 内置浏览器里由 pageAgent 执行拟人化操作（打开创作者中心→上传→填标题话题→发布→回传），无需额外安装自动化环境。

## 4. 实施节奏

- **第 1 周**：手动跑通 1 个号（巨日禄全流程），验证闭环 + 摸出单书型；同时我把 ③④⑤（改编→TTS→合成）做成自动出片链路。
- **第 2 周**：接入 ①②（选书+授权自动化），日产能提到 5-10 条；新号养号期人工发布。
- **第 3-4 周**：接入 ⑥⑦⑧（发布/回传/数据），账号切全自动；开始矩阵第 2、3 个号。

## 5. 风险清单

| 风险 | 等级 | 对策 |
|---|---|---|
| 未授权发布侵权 | 高 | 只发布平台授权书目，授权记录留档 |
| 抖音/快手风控封号 | 高 | 新号人工养 1-2 周；单号单指纹；拟人化操作；日发 ≤3 条/号 |
| 小红书 | — | 明确不发（官方打击推文，封号） |
| 验证码打断流程 | 中 | 暂停+通知机制，人工点一下继续 |
| 音画不同步/画质差 | 中 | TTS 时间戳对齐字幕；合成后抽帧自动质检 |
| 前期不出单 | 确定 | 心理预期：日更+持续回传 2-4 周才见数据，文档原话"坚持更新才有爆单机会" |

## 6. 你需要做的事（全部）

1. 注册：巨日禄（或番茄/盐选推文平台）达人账号 ×1
2. 注册：抖音、快手账号（矩阵期再扩）
3. 各平台首次登录一次（让自动化保存登录态）
4. 偶尔帮流程过一下验证码
