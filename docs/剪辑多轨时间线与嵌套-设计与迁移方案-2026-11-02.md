## 1. 为什么现在不做"直接改"

现状（v2）刻意选择了「主轨 + 通用图层」：

- 主轨 `clips[]` **顺序首尾相接**，不支持空档、重叠；
- 字幕/画中画/贴纸/音频/特效是**定时图层**（`layers` 唯一持久化，内存派生 v1 视图）；
- 渲染出口 `clip-render.ts` 是**步骤式**：分段 normalize → concat/xfade → 画中画/贴纸 overlay → 特效层 → 字幕 → 音频链 → BGM。

这套模型覆盖了 95% 短视频场景，且已有 500+ 条测试与真机验证。直接改成 `tracks[]` 会把渲染、UI、工具、预览、代理、剪映导出全部推倒，回归面极大。

**结论：多轨不是"重写"，而是"增量加一层"** —— 先冻结 v2 出片路径，再新增 v3 轨道模型与独立渲染分支，双写迁移完成后切换。

---

## 2. 目标与非目标

### 目标

1. 主轨可**留空/重叠**（B-roll 盖在 A-roll 上、插入空档）。
2. 支持**多条视频轨 + 多条音频轨**，每轨可独立静音/隐藏/锁定。
3. 支持**嵌套**：把一段选区打包成"复合片段"（compound clip），可整体移动/缩放/再加效果。
4. 多机位从"拍平"升级为"同一时刻多角度可切换"（可选，建立在多轨之上）。
5. 现有工程（v2）与现有渲染行为**零变化**；不改 `clip-render.ts` 的 v2 路径。

### 非目标（本期不做）

- 自由曲线关键帧编辑器（仍用现有点位关键帧）。
- 多时间线并行编辑（一个工程多条独立时间线）—— 属于另一个数量级。
- 实时多轨 WebGL 预览（仍用代理/抽帧，多轨代理按轨生成）。
- 音频总线/发送效果（sidechain 已有 BGM duck，不做 DAW 级路由）。

## 3. v3 数据模型（提案）

```ts
interface ClipProjectV3 {
  version: 3;
  name: string;
  updatedAt: number;
  output: { size: string; fps: number; quality?: 'low'|'std'|'high'; encoder?: 'cpu'|'auto'; interpolate?: 'off'|'blend'|'mci' };
  /** 轨道：顺序 = 合成顺序（后面的盖前面） */
  tracks: Track[];
  /** 音频总线（BGM/音效链）保持工程级，不放进轨道 */
  audioFx?: string[];
  bgm?: { file: string; volume: number; duck: boolean };
  /** 多机位组/配方等旁路元数据原样保留 */
  multicamGroups?: MulticamGroup[];
}

interface Track {
  id: string;
  kind: 'video' | 'audio';
  name?: string;
  muted?: boolean;      // 音频轨静音 / 视频轨不参与合成
  hidden?: boolean;     // 仅视频轨
  locked?: boolean;     // 仅 UI
  /** 视频轨：合成权重；audio 轨忽略 */
  blend?: BlendModeId;
  opacity?: number;     // 0~1，整轨透明度
  items: TrackItem[];
}

type TrackItem = ClipItem | CompoundItem;

interface ClipItem {
  type: 'clip';
  id: string;
  /** 在成片时间轴上的起点（**绝对秒**，不再隐式首尾相接） */
  start: number;
  duration: number;     // 成片时长（变速后）
  /** 源素材与本段裁剪（语义同 v2 ClipSegment） */
  segment: ClipSegment; // 复用现有字段：file/trim/speed/调色/mask/keyframes/matte…
}

interface CompoundItem {
  type: 'compound';
  id: string;
  start: number;
  duration: number;
  /** 嵌套内容：内部是一条独立时间线（可再嵌一层，深度上限 3） */
  project: ClipProjectV3; // 内部时间从 0 开始
  transform?: { x?: number; y?: number; scale?: number; rotation?: number; opacity?: number };
  audio?: { volume?: number; muted?: boolean };
}
```

关键取舍：

| 取舍 | 选择 | 理由 |
|---|---|---|
| 时间位置 | 绝对 `start + duration` | 多轨必须允许空档/重叠；继续用"顺序累加"会在插入/移动时隐式改时间 |
| 旧 clips | 迁到 video 主轨的 ClipItem | 迁移是机械映射，渲染顺序不变 |
| 旧 layers | 按 kind 映射到对应轨或保留为"定时图层轨" | 字幕/贴纸/特效本质是"整段区间 + 变换"，与 ClipItem 的语义不同，不硬塞 |
| 嵌套 | 内嵌完整 project | 与剪映/PR 的 compound clip 一致；限制深度 3 与总时长预算 |
| 主轨概念 | 保留"第一条视频轨 = 主轨"约定 | 兼容现有"主轨无空隙"的快捷键、卡点、剪口播、ripple 等逻辑 |

> ⚠️ v3 中"主轨"不再是唯一时间基准，但**现有功能默认操作第 1 条视频轨**，用户不主动加轨时体验与 v2 完全一致。

## 4. 渲染映射（如何不炸 filtergraph）

### 4.1 分层渲染，不做"单图一次编码"

现有 4.4 阶段二（单 filtergraph 一次编码）在多轨下复杂度爆炸，**不采用**。改用**按轨预合成 + 顶层一次叠加**：

```
每个视频轨（自上而下）：
  items 按 start/duration 排 → 每段 normalize（现有 assembleSegmentChain）
  → 轨内 concat（空档补黑/透明，重叠处按轨内优先级取上层）
  → 轨产物 = 该轨整段成片（含 alpha，若轨有透明度/混合）

顶层：
  base = 第 1 条视频轨
  for 其他视频轨: overlay/blend(该轨, enable=全段)
  → 定时图层（贴纸/画中画/特效层）按 v2 既有顺序
  → 字幕（libass 最后）
  → 音频：各音频轨 amix + BGM duck + audioFx
```

优点：

- 每轨复用现有分段/滤镜/转场实现，v2 代码几乎不动；
- 轨数量线性增加编码次数（每轨一次 + 顶层一次），可用 `-c:v libx264` 中间产物控制画质；
- 空档/重叠在轨内解决，顶层只做全段叠加。

代价与红线：

- 编码次数 = 视频轨数 + 1；3 轨以上长片会慢，需要中间产物用高质量 crf 或硬件编码；
- **渲染出口仍唯一**：所有轨道合成都在 `clip-render.ts` 内新增 `buildTrackPlan`，UI 与代理不得自拼 ffmpeg；
- 现有 v2 `buildRenderPlan` 保留为"1 条主轨、0 复合"的特例，保证旧工程零变化。

### 4.2 嵌套渲染

复合片段 = 对内部 project **递归构建轨道计划**，产物作为该片段的一段"源视频"参与外层轨内拼接：

- 缓存键：`compoundId + 内部工程指纹 + 输出规格`；内部改动只重渲该复合片段；
- 深度限制 3，超出直接拒绝（防递归/爆炸）；
- 复合片段内的音频可整体静音/调音量（`audio` 字段），默认继承内部混音。

### 4.3 代理与预览

- **已实现（主轨 + 非主轨）**：代理粒度从"段"扩展到"轨片段 + 复合片段"，普通段与 compound 均按 `trackId + itemId` 定位；
- **已实现（动态叠放）**：主轨继续顺序连播；非主轨只加载播放头当前窗口内的 clip/compound 代理，按轨道顺序用多层 `<video>` 叠放，并应用轨道透明度/混合模式；
- 非主轨代理层固定静音，声音只由主轨与音频轨输出；多机位角度参考轨、隐藏轨、静音轨和 `opacity=0` 轨不参与代理叠放；
- UI 不允许自行拼 ffmpeg：代理仍由 `clip-render.ts` 的渲染计划生成，compound 缓存继续按内部工程指纹失效。

## 5. UI 方案

```
时间轴（可滚动，轨道头固定）
┌ 轨头 ┬ 时间刻度 ────────────────────────────────
│ 视频3 │ [clip]      [clip]                       ← 可隐藏/静音/锁定
│ 视频2 │      [B-roll clip]                        ← 可拖入空档
│ 视频1 │ [clip][clip][clip]                        ← 主轨（默认操作对象）
│ 字幕  │    [text][text]
│ 音频2 │  [sfx]      [music]                       ← 可静音
│ 音频1 │ [原声]
└───────┴──────────────────────────────────────────
```

交互要点（第一版只做必要项）：

1. 轨道头：新增/删除轨道、静音/隐藏/锁定、拖拽调轨顺序（顺序=合成顺序）。
2. 片段拖拽：跨轨移动、吸附到相邻边缘/播放头/节拍点；重叠时同轨后者覆盖前者（或拒绝并提示，二选一，建议**同轨拒绝、跨轨允许**）。
3. 主轨保持"首尾相接"提示：主轨有空档时显示虚线占位，允许，但剪口播/卡点等批量操作只作用于主轨且跳过空档。
4. 复合片段：选中多段 → "打包为复合片段"；双击进入内部编辑（面包屑返回）；内部编辑时外部只读预览。
5. 多机位：多轨就绪后，多机位组可改为"多角度轨 + 激活开关"，不再拍平（作为第二阶段）。

## 6. 迁移方案（v2 → v3）

**原则：迁移而不是并存。** 落盘只写 v3；读取 v2 时内存迁移，首次保存写 v3 并保留 `.v2.bak`。

映射表：

| v2 | v3 |
|---|---|
| `clips[]`（顺序） | `tracks[0]`（video，items 按累计时长转 `start`） |
| `texts[]` | 字幕定时图层（保留为 `tracks.text` 或 v3 的 `timedLayers`，倾向后者） |
| `overlays[]` / `stickers[]` | 定时图层（v3 保留 `timedLayers`，不塞进视频轨） |
| `effects[]` | 定时图层（同上） |
| `audios[]` | audio 轨（每层一条或合并，建议一条轨内多个 ClipItem） |
| `bgm` / `audioFx` | 工程级字段保留 |
| `multicamGroups` | 原样保留（指向主轨 clip id） |

迁移风险与守卫：

- 旧工程出片**逐字节不变**：v2 读取后若用户不改轨道结构，渲染走"迁移后的单主轨 + 定时图层"特例路径（与 v2 计划一致）；用快照测试钉住。
- 字幕/画中画时间语义不变（相对成片）。
- 剪口播/卡点/多机位等现有批量操作只操作主轨；写守门测试防误伤其它轨。
- 老工程迁移失败 → 不写盘，原文件保持 v2。

| 阶段 | 内容 | 产出 | 风险 |
|---|---|---|---|
| **S0（已完成）** | v2 主轨 + 通用图层；定时图层覆盖字幕/画中画/贴纸/音频/特效 | 现网能力 | — |
| **S1（已完成）** | v3 模型 + v2→v3 迁移 + 读写（不开放多轨 UI） | 数据层可切换，出片零变化 | 迁移破坏旧工程 |
| **S2（已完成）** | 渲染 `buildTrackPlan`（多视频轨叠加 + 音频轨混音）；>1 视频轨或 compound 自动触发，`CLIP_MULTITRACK=1` 保留为强制开关 | 多轨渲染能力 | filtergraph/编码次数 |
| **S3（已完成）** | UI 多轨时间轴（轨道头、跨轨拖拽、空档/重叠规则） | 用户可用多轨 | 交互复杂度 |
| **S4（已完成）** | 复合片段（打包/区间打包/进入编辑/递归渲染/缓存） | 嵌套 | 递归/缓存 |

每阶段都必须满足：四包类型检查、clip 套件全绿、旧工程出片快照不变、真机验收清单相应项通过。

## 8. 关键决策清单（需拍板）

1. **是否进入 v3**：愿不愿意承担 S1~S3 的迁移与 UI 工作量（估计 2~3 个大版本周期）。
2. **定时图层是否保留独立概念**：建议保留（`timedLayers`），而不是把所有东西塞进轨道 —— 语义清晰、迁移简单。
3. **同轨重叠规则**：建议拒绝（提示"移到新轨"），避免隐式覆盖带来的"素材消失"投诉。
4. **嵌套深度**：上限 3，超限拒绝。
5. **多机位路线**：先保留拍平（现状可用），还是 S5 直接切多角度轨。
6. **预览策略**：第一版多轨代理只做主轨，还是全轨代理（成本高）。

## 9. 验收标准（若进入实现）

- 旧 v2 工程打开/保存/导出与迁移前**逐字节一致**（快照 + 真机出片）。
- 新增轨道后：空档/重叠/静音/隐藏行为可预测，且 UI 明示合成顺序。
- 复合片段：内部编辑只重渲该片段；缓存命中正确；递归被限制。
- 多轨出片：层级、透明度、混合模式、音频混音结果与设计一致；性能在可接受范围（每多一轨多一次编码，文档如实标注）。
- 渲染出口唯一：UI/代理不出现第二套 ffmpeg 拼接。
