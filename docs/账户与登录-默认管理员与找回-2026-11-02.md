# 账户与登录：默认管理员、首启设置密码、忘记密码找回（2026-11-02）

> 起因：首启看到登录页却报 401，用户问「默认管理员不是 yanZhiPower 吗？文档里没写？」。
> 之前只有代码注释，没有文档，这里补齐。

## 一、默认管理员是怎么来的

代码：`apps/server/src/rbac.ts` 的 `ensureDefaultAdmin()`，由 `apps/server/src/index.ts` 在启动时调用。

- **触发条件**：multi 模式下，只要 `yanZhiPower` 占位行**不存在**就补种（2026-11-02 由「零用户才种」改为「缺了就补」）。
- **创建内容**：账号 `yanZhiPower`，`password_hash` 为**空串**（不是某个默认密码），
  `must_change_password = 1`，绑定系统管理员角色 `role_admin`。
- 空密码不等于后门：登录时**密码留空**，登录后立刻被强制改密闸挡住（改密前除 `/change-password`、`/me` 外全部 403）。
- 若用户名 `yanZhiPower` 已被历史数据占用，占位账号会退化为 `yanZhiPower-default`（日志里能看到）。

> 2026-11-02 之前是「库里除 guest 外一个用户都没有才种」。开发库/老库里早有 test1、admin 等历史账号，
> 条件永不成立 → 登录页填 yanZhiPower 必然 401。这是本次修改的直接原因。

## 二、首次打开会发生什么（2026-11-02 起）

`hasRealUsers()` 把「空密码的预置占位账号」排除在外：

| 库状态 | `/api/auth/status` | 前端行为 |
|---|---|---|
| 空库 + 刚种下 `yanZhiPower`（空密码） | `setupRequired: true` | 跳 `/setup`，**自己设置用户名和密码** |
| 任何已配置账号 | `setupRequired: false` | 显示登录页 |

`POST /api/auth/setup` 成功后**就地接管**那条占位账号（改名 + 设密码 + 清 `must_change_password`），
不会留下「空密码即可登录」的管理员后门。

## 三、401 的排查顺序

1. 账号是否存在：库里若没有 `yanZhiPower`，用它登录必然 401。
2. 服务器地址是否指向本机：登录页「服务器地址」存在 `localStorage.yz_server_base`，
   优先级高于打包内置地址。填了别的机器的 IP，请求就打到那台机器上了。
3. 空密码账号必须**密码留空**登录（后端会明确提示，而不是笼统 401）。

## 四、忘记密码 / 需要一个能登录的管理员

脚本：`apps/server/scripts/reset-admin.cjs`（先彻底退出应用再跑）。

```bash
node apps/server/scripts/reset-admin.cjs --list
```

```bash
node apps/server/scripts/reset-admin.cjs --username admin --password 新密码
```

不传 `--password` 会生成随机密码并打印；已有账号则重置密码并清零强制改密标记，
不存在则新建并绑定管理员角色。默认库：`%APPDATA%/yan-zhi/server-data/data.db`（`--db` 可覆盖）。

## 五、打包形态与后端地址

| 形态 | 命令 | 含后端 | 后端地址从哪来 |
|---|---|---|---|
| 完整版（lite/basic/pro） | `pnpm build:desktop:basic` | 是 | 本机 3001（或商城设置里的端口） |
| 轻量壳 | `pnpm package:desktop:shell -- --server-url http://IP:3001` | 否 | 打包内置 `resources/server-base.json`，登录页可改 |

- 壳包产物固定落在 `dist-release/desktop/shell/<版本>/`（后缀 `-shell`）。
- 壳模式启动时健康检查打的是**内置远程地址**，不是 `127.0.0.1`。
- 被连接的那台机器：后端默认监听 `0.0.0.0`，注意 Windows 防火墙入站规则。
