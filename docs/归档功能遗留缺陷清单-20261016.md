## 🔴 High（影响数据正确性 / 用户找不到东西）

### H1. 本地模式「永久删除」清理不全（purgeConversation / emptyTrash）

`packages/ui/src/stores/chat.ts:1155-1182`

| 函数 | DB | 内存清理 |
|---|---|---|
| `purgeConversation` | `DELETE message` + `DELETE conversation` | ✅ messagesByConv / queuedByConv / clearHistoryPaging / plansByConv ⚠️ **缺 `dropBrowserOpChain`** |
| `emptyTrash` | 同上（循环） | ❌ **一处都没清**（messagesByConv / queuedByConv / plansByConv / browserOpChains / currentConvId 全留） |

对比 `deleteConversations`（1499-1521）是**清全了**（含 `dropBrowserOpChain`）的 —— 说明这是漏写，不是设计。
后果：清空回收站后内存里仍挂着已抹掉的会话的消息、计划、浏览器串行链；若 `currentConvId` 正好指向被抹的会话，
界面会停在一条不存在的会话上。

> 注：本地 core schema 无 `message_summary` / `task_plan_item` 表，所以 DB 层只删 message + conversation 不算漏；
> `conversation_file` 有 `ON DELETE CASCADE`，随之清除。缺口在**内存**那一半。

### H2. 恢复（restore）的去向与提示不一致 —— 会话「消失」

`apps/server/src/services/conversation-lifecycle.ts:78-83` 的 `restoreRow` 只清 `deleted_at`，
**保留 `archived_at`**（注释也写了「归档标记不动」）。但：

- `packages/ui/src/composables/chat/useChat.ts:3760-3768` `restoreConv` 提示的是
  `ElMessage.success('已恢复到主列表')`
- 而 `store.restoreConversation`（chat.ts:1145-1153）末尾只 `await loadConversations()`（拉 **active**）

⇒ 一条「先归档、再删除」的会话，恢复后 `archived_at` 仍在 → 落在**已归档**列表，
但主列表不会刷到它、提示却说「已恢复到主列表」→ 用户以为丢了。

### H3. 剪辑项目列表不过滤生命周期 —— 归档/回收站的项目仍显示在首页

`apps/server/src/routes/clip.ts:82-86`：

```sql
SELECT id, title, created_at, updated_at FROM conversation
WHERE user_id = ? AND COALESCE(NULLIF(mode,''),'office') = 'clip'
ORDER BY updated_at DESC
```

无 `deleted_at IS NULL` / `archived_at IS NULL`。配套的 `conversationExists`（clip.ts:59-66）
也只 check 存在性。⇒ 已删除的剪辑项目仍在剪映首页出现，点进去还能读写它的工程文件。

## 建议修法（最小改动，按依赖排序）

1. **H2**：要么 `restoreRow` 一并清 `archived_at`（回主列表，与提示一致），要么前端按
   `conv.archivedAt` 分别提示 + 刷对应列表。**推荐前者**——「从回收站恢复」的直觉就是回到可用状态。
2. **H1**：`purgeConversation` 补 `dropBrowserOpChain`；`emptyTrash` 复用同一段内存清理
   （抽一个 `dropConvRuntime(id)` 本地函数，两个删除点都调——**同一语义唯一实现**）。
3. **H3**：`clip.ts` 的 `/projects` 与 `conversationExists` 加 `lifecycleClause('active')`。
4. **M1/M2**：把「归档=只读」的判断抽成 `assertWritable(cid, userId)`，PATCH / files 各写点都过一遍
   （不要逐处手写 `archived_at IS NULL` —— 会漂移）。
5. **M4**：本地 `addMessage` 同步 `last_activity_at`。
6. **M5**：重新构建 `apps/server/dist`（并确认 `apps/mobile/*/dist` 同步）。

> M1/M2 要先定**边界**：归档会话到底允不允许改名、传附件？
> 建议：**改名允许**（无害且不改会话内容），**传附件 / 改模型 / 改 agent 拦掉**（会改变会话产出）。
