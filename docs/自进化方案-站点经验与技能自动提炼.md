# 自进化方案 v2：通用任务经验沉淀 + 技能自动提炼

> 2026-10-09 · 状态：**P0 + P1 已实施并通过验证**（P2 待立项：需条目命中统计基建）
> v2 变更：从"浏览器站点经验"泛化为**所有任务类型**的通用经验自进化（开发任务、bug 排障、好步骤、SOP 全覆盖）

## 一、问题根因

| 现象 | 根因 |
|---|---|
| 每次访问页面都重新探索 DOM，又慢又久 | pageAgent 每次实时拉取，全仓无 site memory / selector cache（已 grep 确认） |
| 抓文章/发布/评论流程每次"从零来" | 仅有 URL 级浏览记录（browser-memory），不含操作序列/选择器经验 |
| 开发/排障经验也不沉淀 | memory 表 / progress.md / decisions.md 是追加流水，不结构化、不按需召回、不反哺执行 |
| 好的做法、踩过的坑，下次还犯/还摸索 | 任务收尾只写"结论摘要"，不提炼"可复用步骤"和"坑与规避" |
| skill 不会自己长 | `api_skill_create` 存在但只能模型主动调，收尾无提炼机制 |

## 二、总体设计：统一经验层，三类沉淀物

```
任意任务（开发/排障/页面/办公）
   │ 任务收尾钩子（成功 & 失败都提炼！）
   ▼
① 领域经验档案 Experience Files（通用层，按领域分文件）
   │  重复出现 ≥2 次的完整流程
   ▼
② Skill 草稿（好步骤 → SKILL.md + 模板文件，用户确认后启用）
   │  Dreaming 每日整理
   ▼
③ 定期整理：去重合并 / 过时降权 / 草稿催确认
```

### 关键设计原则

1. **统一存储**：`<工作目录>/.yan-zhi/experience/` 目录，**Markdown 文件即真相源**（人工可看可改，git 可管）。按领域分文件而不是按任务散落：

```
.yan-zhi/experience/
  sites/<domain>.md          ← 站点档案（浏览器任务的领域文件）
  dev-<主题>.md              ← 如 dev-bug-排障.md、dev-打包.md、dev-依赖.md
  ops-<主题>.md              ← 部署/环境/网络类
  workflow-<主题>.md         ← 办公流程类（发微信、做表、抓数）
```

2. **经验条目结构**（每条，追加式 + 去重合并）：

```markdown
- [2026-10-09] ⛔坑 | better-sqlite3 在 node22 下 ABI 不匹配必红
  规避：server 单测用 node24 | 命中场景：跑 server 测试报 NODE_MODULE_VERSION
- [2026-10-09] ✅步骤 | Excel 大表清洗：先 read_table 抽样 → run_command 分块 → 核对行数
  来源：任务 xxx | 成功 3 次
```

   三种条目类型：**⛔坑（+规避）**、**✅步骤（可复用 SOP）**、**📌事实（环境/配置/路径）**。

3. **失败任务也提炼**（v1 的"失败不提炼"作废）：bug 排障、失败尝试里的"坑"恰是最值钱的经验。收尾钩子按任务出口分类：
   - completed → 提炼 ✅步骤 / 📌事实
   - failed / aborted → 提炼 ⛔坑 + 规避（"这次为什么卡住"）
   - 用户显式纠正（confirm/ask_user 中驳回）→ 提炼 ⛔坑

---

### ① 领域经验档案（P0）

**写入（自动进化）**：
- 新工具 `api_experience_write(kind, topic, content)`：kind = pit(坑)/step(步骤)/fact(事实)，topic 决定落到哪个领域文件（缺省按当前 task_type 归档）
- 收尾钩子 `distillExperienceFromTask()`（非阻塞，独立小模型）：`llm-task-manager.ts` 任务 5 个出口的 `recordTaskProgress()` 调用点处追加调用——**所有任务类型通用**，不只浏览器
- pageAgent / 各业务 agent 提示词加一条规则：**任务过程中遇到"查了半天才搞定的坑"或"验证出的好路径"，当场调用 `api_experience_write` 记一条**（不等收尾，防止长任务丢失）
- 去重：写入前对同领域文件做语义/关键字比对，重复条目改为"成功次数 +1"（meta 记在条目尾注）

**读取（反哺执行）**——两个注入点：
- **任务启动注入**：`buildSystemPromptForBackend()`（llm-task-manager.ts）中，按 task_type + 用户任务文本关键词，选取相关领域文件（每个文件先注入标题索引，命中再展开条目；总量上限 3000 字）。这就是"上次踩过的坑这次直接看到规避"
- **按需查询工具** `api_experience_read(topic?)`：模型干到一半觉得似曾相识，可主动查

**召回匹配**：先用轻量方式（文件名 + 条目关键词倒排，内存 map）就够；不引入 embedding 依赖（memory 表已有 embedding，如后续要语义召回可挂靠）。

### ② 收尾自动提炼 Skill（P1）

触发条件（都满足才触发）：
- 任务 completed 且全程 ≥3 次工具调用
- 同一 `task_type + 领域` 的 ✅步骤 累计 ≥2 次（从经验文件计数读，不再单独判重）

流程：
- 独立小模型把会话流程提炼为 SKILL.md 草稿 + 模板/参考文件（发布类附平台差异表、开发类附命令清单），落 `<工作目录>/.yan-zhi/skill-drafts/<slug>/`
- drafts 目录不在项目技能加载路径，**不静默生效**；会话内回一条轻量消息："检测到重复流程，已生成技能草稿 X，确认后启用"
- 用户确认 = 移入 `.yan-zhi/skills/`（或 `api_skill_create` 入库）

### ③ Dreaming 每日整理（P2）

- 扫 `experience/`：条目合并去重、30 天未命中且 success=0 的条目标记"待淘汰"（不直接删）
- 扫 `skill-drafts/` 积压 → 提醒处置
- 高频 ⛔坑（同坑反复出现）→ 提示"该坑适合固化进内置 agent 提示词/skill"，由用户决定

### （可选）④ 经验 → Workflow / 一键任务（P2 备选）

固定步骤序列半自动生成 workflow 草稿进工作台画布，用户微调保存。仅做入口。

## 三、实施清单

| 期 | 改动 | 文件 |
|---|---|---|
| P0 | experience 服务（read/write/matchByTask，条目去重计数） | 新 `apps/server/src/services/experience.ts` |
| P0 | 两个 API 工具 + 三段注册 + 权限清单（write 需非 readonly） | 新 `packages/core/src/tool/builtin/api-tools/experience.ts`、`api-tool-executor.ts`、tool-permission |
| P0 | 收尾钩子：5 出口接 `distillExperienceFromTask()`（成功/失败分别提炼） | `llm-task-manager.ts` |
| P0 | 任务启动注入 + 提示词规则（主 agent + pageAgent + 内置业务 agent） | `llm-task-manager.ts`（buildSystemPromptForBackend）、`db.ts`（PAGE_AGENT_SYSTEM_PROMPT 等） |
| P1 | skill 草稿提炼（复用 experience 计数判定） | 新 `services/skill-distill.ts` |
| P2 | Dreaming 整理 experience / drafts | `services/memory-dreaming.ts` |

**与现有记忆的关系**：memory 表 = 用户/画像事实（不变）；MEMORY.md = 长期结论（不变）；experience/ = **可执行的操作经验**（新，面向"下次怎么做"）；progress.md 继续做明细流水。四者职责分开，不合并。

**风险**：low～medium。纯新增链路；经验文件人工可改可删；注入有 3000 字封顶，不挤爆上下文（对齐"有效预算"原则）。注意点：提炼钩子必须非阻塞 + try/catch（清理失败不拖垮任务出口）。

**验证方式**：
1. 同站点连续两次相同抓文任务 → 第二次探索步骤数/耗时明显下降，`experience/sites/<domain>.md` 生成且第二次被注入
2. 造一个必失败的排障任务 → 收尾后 `experience/dev-*.md` 出现 ⛔坑条目；再造同主题任务 → 提示词里能看到该坑的规避
3. readonly 会话调 `api_experience_write` → 被权限清单拒绝
