- `packages/ui/src/views/Models.vue`（+33/−2）、`Models.modelCounts.test.ts`（新增 210）
- 解决 **「点管理模型后其他平台计数全变 0」**：根因是共享缓存被单实体加载整体替换
  （进平台详情触发 `loadModels(pid)`，覆盖跨实体视图依赖的全量清单）。
- 修法：跨实体视图自带**独立全量清单 + 幂等加载**，绝不共用「当前实体」缓存。

### `527528a` fix(desktop): main.cjs 启动即炸 —— executeJavaScript 模板内的注释不能含反引号

- `apps/desktop/main.cjs`（+5/−1，约 L3849-L3854）
- 现象：`App threw an error during load ... main.cjs:3850 SyntaxError: missing ) after argument list`，dev 完全起不来。
- 根因：注释位于 `L3772 return await wc.executeJavaScript(\`(function(){` 的**模板字符串内部**，
  注释里用来包选择器名的**反引号会提前终止模板**，后面的注入代码被当外层 JS 解析。
- 修法：该段及同模板内任何注释一律禁用反引号，引用代码名改用单引号；并留了护栏注释说明原因。

### `acc35e0` chore(server): vitest cacheDir 固定到项目内 tmp/

- `apps/server/vitest.config.ts`（+6）
- 现象：同一份代码跑出 164 / 163 / **165 files** 三种结果，测试被**随机静默丢弃**，看着像回归。
- 根因：vitest 默认缓存写 `%TEMP%\<随机>\ssr\`，本机沙箱该路径只读 → 写缓存 EPERM → 对应文件被跳过且不报错。
- 修法：`cacheDir: './tmp/vitest-cache'`，EPERM 归零、文件数稳定。

## 3. 会话归档 + 回收站（`36c5cf1`）

### 3.1 行为

| 项 | 实现 |
|---|---|
| 归档 | 移出主列表但数据全留，会话**只读**（对齐 ChatGPT / Anthropic Agent SDK 语义）|
| 归档后发消息 | `POST /:id/messages` 拦 `role==='user'` → 409 `CONVERSATION_ARCHIVED`；assistant 回执放行 |
| 回收站 | 删除 = **软删进回收站**（此前是硬删连消息一起抹、不可恢复）；可 restore |
| 永久删除 | 只在回收站内出现，二次确认 |
| `DELETE /clear` | 语义改为「全部移入回收站」（不再真删）|
| 列表隔离 | 归档/回收站列表**独立拉取**（`loadConversationsByScope`，不写 `store.conversations`）|
| UI | 侧栏 hover / 右键 / ActionSheet 归档入口 + 底部「已归档」折叠分组 + 回收站入口；归档会话打开时顶部横幅 + 输入框禁用（一步「取消归档，继续对话」）|

### 3.2 收口（同一语义唯一实现）

- 新增 `apps/server/src/services/conversation-lifecycle.ts`（95 行）：
  `hardDeleteRow`（**唯一真删出口**，清理 `message` / 摘要 / 授权 / `task_plan_item` / 会话行，集中一处）、
  `softDeleteRow` / `restoreRow` / `setArchivedRow` / `emptyTrash` / `parseScope` / `lifecycleClause` / `lifecycleOf`
- `clip.ts`、MCP `api_conversation_delete`、store 本地模式全部改走软删或唯一出口；
  静态守门测试钉住「删除点不许再手写 `DELETE FROM conversation WHERE`」
- `createTask` 统一拦截归档/回收站会话（`CONVERSATION_NOT_FOUND` / `_TRASHED` / `_ARCHIVED`，查库失败 fail-open），
  覆盖前端 SSE / IM / 定时任务全部入口；`llm-tasks.ts` 按 `CONVERSATION_*` 前缀映射 **409/404**（不是 500，前端才能提示去恢复）；`im.ts` 返回 `{handled:false, reason:'conversation_unavailable'}`

### 3.3 数据层（4 处同步，治 schema 漂移老毛病）

| 位置 | 改动 |
|---|---|
| `packages/core/src/db/schema.ts` | +`archived_at` / `deleted_at` / `last_activity_at` |

- 用 **nullable 时间戳而非布尔**：既表达状态又携带「何时进入」。
- `last_activity_at` 刻意**独立于 `updated_at`**：自动归档（P2）判据必须是「真实对话活动」，

- 存量行回填 `last_activity_at = COALESCE(last_activity_at, updated_at)`；加 `idx_conversation_lifecycle (deleted_at, archived_at)`。
