## 3. 设计

### 3.1 新内置 skill × 2（`builtinSkillDefaults` 内新增）

- `skill_douyin_sell`「抖音图文带货」：账号定位 → 选品（佣金/销量/人群匹配/季节性/体验）→ 图文结构（封面 + 3~9 张轮播 + 文案 + 话题标签）→ 挂车发布 SOP → 数据复盘（曝光/点击/转化漏斗）→ 优化迭代。含广告法极限词、功效宣称、虚假宣传合规红线。
- `skill_douyin_traffic`「抖音引流」：风口选题（大模型使用方法、智能体创建教程、AI 工具实测等）→ 爆款结构（3 秒钩子 → 痛点 → 解法 → 演示 → CTA）→ 逐镜脚本 → 系列化与人设 → 评论区运营 → 合规（不承诺收益/不造谣/不搬运）。
- 两个 id 同步加进 `SKILL_BODY_REFRESH_IDS`（内置 body 刷新白名单，否则老库拿不到新版）。

### 3.2 新内置智能体 `a_builtin_douyin_agent`（抖音运营助手）

- 定义放新纯数据模块 `apps/server/src/builtin-douyin-agents.ts`（与 office/task-mode 同模式，不 import db，便于单测断言）。
- `type: 'harness'`、`agent_kind: 'main'`、`is_builtin: 1`、`force_sync: true`、`category: '办公'`、`maxReActSteps: 40`。
- 工具挂载：file 三件、python_exec（佣金/发布计划测算）、image_analyze（看参考图文/竞品截图）、**api_image_generate**（封面/商品图/图文素材）、browser_navigate + browser_get_page_content、call_agent/list_sub_agents/spawn_subagent（委派 pageAgent 查平台规则/热点/竞品）、list_models、task_plan/task_step/ask_user/confirm_user。
- `sub_agent_ids: ['a_builtin_page_agent']`；`skill_ids: ['skill_douyin_sell','skill_douyin_traffic','skill_markdown_doc']`。
- 提示词：一体两线（引流涨粉 + 带货变现），先诊断账号现状再定目标；不承诺涨粉/收益、不刷量、平台合规。

### 3.3 场景配置表 `scene_config`（本次核心）

```sql
CREATE TABLE IF NOT EXISTS scene_config (
  id TEXT PRIMARY KEY,
  key TEXT NOT NULL UNIQUE,          -- 场景 key（'office'/'douyin'/用户自建…）
  name TEXT NOT NULL,                -- 标签（'抖音运营'）
  icon TEXT,                         -- element-plus 图标名；空=自动
  color TEXT DEFAULT '#3b82f6',
  description TEXT DEFAULT '',
  agent_id TEXT,                     -- 绑定的智能体 id（动态创建模式的核心字段）
  prompt TEXT DEFAULT '',            -- 场景系统提示词（追加在智能体提示词后）
  skill_keywords_json TEXT DEFAULT '[]',
  examples_json TEXT DEFAULT '[]',
  is_mode INTEGER NOT NULL DEFAULT 0, -- 1=模式场景（不进欢迎卡轮播）
  sort_order INTEGER NOT NULL DEFAULT 0,
  enabled INTEGER NOT NULL DEFAULT 1,
  is_builtin INTEGER NOT NULL DEFAULT 0,
  force_sync INTEGER NOT NULL DEFAULT 0,
  user_id TEXT NOT NULL DEFAULT 'guest',
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

- **种子源**：新纯数据模块 `apps/server/src/builtin-scene-defs.ts`（17 条 = `scenes.ts` 现 16 条转录 + douyin 1 条）。内置行 `force_sync=1`：启动时代码收敛覆盖（与 agent seed 同语义），用户自建行不动。
- **CRUD**：新路由 `apps/server/src/routes/scene-configs.ts`：
  - `GET /api/scene-configs`（按 sort_order）
  - `POST /api/scene-configs`（动态创建模式：key 唯一、name 必填、绑定任意 agentId + skillKeywords + prompt + examples）
  - `PATCH /api/scene-configs/:id`（仅非内置；内置行拒绝并提示 reset）
  - `DELETE /api/scene-configs/:id`（仅非内置）
  - `POST /api/scene-configs/:id/reset`（内置行恢复代码默认）
- `db.ts` 新增 `resetBuiltinScene(id)`（与 `resetBuiltinAgent` 同模式）。
- 路由注册进 `index.ts`（放在 `/api/agents` 旁）。

### 3.5 数据流（动态创建模式）

```
用户/应用 POST /api/scene-configs { key:'x', name:'我的模式', agentId:'<任意智能体>', skillKeywords:[…], prompt:'…' }
  → scene_config 表落行
前端（刷新或下次 loadScenes）→ GET /api/scene-configs → sceneConfig store
  → ChatWelcome 欢迎卡多一张「我的模式」；点卡 → setScene('x') → 切换到绑定智能体 + 注入场景提示词 + 关键词匹配挂 skill
```

即：**「模式」= 一行配置（智能体 + skill 关键词 + 场景提示词 + 示例）**，与用户对现状的理解一致，只是从写死变成可增删改。

## 4. 影响面与风险

| 项 | 级别 | 说明 |
|---|---|---|
| 旧库无 scene_config 表 | low | `CREATE TABLE IF NOT EXISTS` + seed 幂等；seed 只在表上做，不动 agent/skill 既有逻辑 |
| 后端不可达时前端场景空 | low | store 初始值 = scenes.ts 内置默认；加载失败保留现值（不清空） |
| 内置场景被用户改坏 | low | 内置行 PATCH/DELETE 拒绝，reset 一键恢复 |
| 与 scenes.test.ts 计数断言冲突 | low | 同步更新 16→17 / 12→13 |
| dev 在跑任务 | — | 不编译不测试；`tsx watch` 会在保存时自动重载，语法错误会立刻暴露在 dev 日志 |
| 双源漂移（scenes.ts ↔ builtin-scene-defs.ts） | medium | 既有同模式（db.ts seed ↔ 前端 agent.ts 默认值）；两文件头部注释互相指向，后续只加不改 |
