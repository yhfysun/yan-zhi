# 办公模式浏览器现场注入——方案（2026-10-25）

## 背景与目标

办公模式（对话居中）下，用户与 AI 协作时预览面板（右侧浏览器/文件面板）里往往已经开着
若干网页 —— 用户正在看什么、agent 之前开过哪些页，这些"工作环境"信息此前**只有调用
`browser_get_tabs` 工具才能拿到**，模型在第一轮并不知道自己面对的浏览器现场。

目标：办公模式下，把预览框状态（是否展开）与浏览器 tab 清单（tabId / 标题 / URL /
用户页还是 agent 页 / 加载中）**默认注入所有智能体的系统提示词，包括子智能体**
（`call_agent` 静态子体与 `spawn_subagent` 运行时生成的虚拟子体），让模型开局即了解
工作环境，减少一轮"先 get_tabs 再说"的盲探。

## 核心决策

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 注入位置 | **只进系统提示词，不进用户回合** | 沿用运维现场注入（ops-context，2026-10-21）的教训：塞用户回合会污染入库消息、每轮重复计 token；系统提示词每轮重组，现场天然保鲜 |
| 新鲜度策略 | **拉模式，每任务 / 每次子体 spawn 现拉** | 不做事件推送与缓存：pageAgent 等浏览器型子体是主要消费者，按 spawn 时刻现拉最有价值；一次 get_tabs <100ms |
| 数据通道 | **browser-bridge 直连桌面主进程** | server→主进程 loopback HTTP 已是浏览器执行面的正路（"执行面直连化"）；不引入渲染层在线依赖。桥不可用（web / 移动端 / 独立 server）自动不注入 |
| 模式门控 | **office-only**（`resolveConversationMode(convId) === 'office'`） | 预览面板（ChatPreviewPane + BrowserPanel）只存在于办公模式的 Chat.vue；门控放在调用方 llm-task-manager，服务模块保持零 llm-task-manager 依赖（避免环） |
| tab 清单格式 | **复用 `formatBridgeResult('get_tabs')`** | 同一语义只有一处实现；为提示词另写一份清单格式必然漂移（本项目多次吃过亏） |
| 面板状态来源 | 主进程现成的 `webviewPanelVisible` | 由 `browserView:resize`（非零尺寸 = 可见）/ `browserView:hide`（面板级）维护，截图隐藏态告警已在消费；只需在 `get_tabs` 响应里带出（新增字段，向后兼容） |
| 失败容错 | 桥不可用 / 超时（2s）/ 业务错 → 返回空串，**绝不阻断任务** | 与记忆 / 经验 / 运维现场注入同一风格；模型仍可用 `browser_get_tabs` 自查 |

## 注入的段落形态

```
## 浏览器现场（桌面预览面板，组装本提示词时的快照）
预览面板：展开（页面用户当前可见，可直接读取/操作）          ← 或"收起（页面处于隐藏态：……先请用户展开预览面板……）"
浏览页 2 个：
- tabId=tab-1 [当前] [用户页·勿关]  月度报表 (https://example.com/report)
- tabId=tab-2 [可关] [加载中] 搜索结果 (https://search.example.com/?q=…)
说明：以上为快照，随操作变化；需要最新列表用 browser_get_tabs；对指定标签页读取/操作可直接传 tabId，不必先切换标签页。
```

（tab 行、可关提示、卡死页提示与 `browser_get_tabs` 工具结果逐字同源。）

## 实现地图

| 文件 | 角色 |
| --- | --- |
| `apps/desktop/main.cjs`（get_tabs case） | 响应新增 `panelVisible: webviewPanelVisible`（webview / 非 webview 引擎都带） |
| `apps/server/src/browser-bridge.ts` | 抽出 `callBrowserBridgeRaw`（返回原始 JSON，供字段级消费）；原 `callBrowserBridge` 变薄包装（业务错格式化 + `formatBridgeResult`），行为逐字不变 |
| `apps/server/src/services/browser-field.ts`（新） | 现场组装**唯一出口** `loadBrowserFieldContext(convId)`：桥可用性检查 → 2s 超时拉取 → 拼装段落；任何失败返回 '' |
| `apps/server/src/llm-task-manager.ts` | 两个注入点（均 office 门控）：① `createTask` 主循环（运维现场块之后）—— 覆盖对话 / 定时 / IM / 后台建会话全部入口；② `runSubAgentImpl` 提示词合流点 —— 静态子体与 spawn 虚拟子体同走一处 |
| `apps/server/test/browser-field.test.ts`（新） | 三层守门：真跑拼装（真实桥 + 真实 fetch）/ 降级（env 缺失、死端口、业务错）/ 源码守门（注入点与门控不被顺手删、`panelVisible` 数据源不丢、不得另写清单格式化） |

## 非目标（明确不做）

- 不做 tab 事件推送 / 状态缓存（拉模式够用，见上）；
- 不加设置开关（用户拍板"默认注入"，office-only 即范围；如需关闭可后续加 env 开关）；
- 不动 `formatBridgeResult` 工具结果路径、不动前端；
- web / 移动端不注入（桥天然不可用；移动端本就无浏览器面板）。

## 已知边界

- `webviewPanelVisible` 的既有容错：切到"空白新页"这类罕见状态下可能误报"收起"——与
  截图隐藏态告警（既有消费者）同容错，未为此改动可见性语义（面板可见性由
  `shouldBeVisible` 单一闸门把守，2026-10-22 已修过一轮误置假）。
- 旧版桌面端不带 `panelVisible` 字段 → 按展开兜底（宁可漏报"收起"，不诱导模型反复请用户展开）。

## 验收

- 单测：`apps/server` 新增 11 例全绿；桥守门（e2e / direct / parity / error-hint）与
  llm-task-manager 相关回归全绿；`tsc --noEmit` 零错误。
- 手工：办公模式打开预览面板（含用户手开页 + agent 页）发消息 → 「查看提示词」快照含
  "浏览器现场"段且标注正确；收起面板再发一轮 → 状态变"收起"；dev 模式会话无此段。
