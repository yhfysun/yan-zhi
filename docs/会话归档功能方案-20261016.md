# 会话归档功能方案（2026-10-16）

> 状态：**决策已定，实施中**。所有结论均带源码路径 + 行号证据（基于 `dev0.1-mobile` HEAD `c9c7d77`）。

---

## 0. 一句话结论

做 **「归档 + 回收站」两件事**，共用一套 nullable 时间戳字段：

- `archived_at INTEGER NULL` —— 归档时间戳（**不用 `archived` 0/1**）
- `last_activity_at INTEGER NULL` —— 自动归档的判据（独立于 `updated_at`）
- `deleted_at INTEGER NULL` —— 回收站（**把现在的硬删除改成软删除**，这是全项目最大的数据安全隐患）

过滤必须 **收口在后端**（照现有 `mode` 隔离的范式：**过滤放后端而不是前端，DB 层收口才是真隔离** —— `apps/server/src/routes/conversations.ts:20-22` 注释原话）。

## 2. 参考实现（硬证据）

### 2.1 Claude Code（VS Code 扩展官方文档）

- hover → `Rename` / `Archive` → 进列表底部 **`Archived sessions`** 分组
- **默认 14 天无活动自动归档**，排除 open / unread / in a group
- 恢复：展开分组 → `Unarchive session`；hover 分组标题可**一键全部恢复**
- `v2.1.257` 之前该行为 `Delete session`（不可恢复）；升级后那些会话出现在 `Archived sessions` —— **删除语义被重定义为归档**

### 2.2 ChatGPT（官方帮助文档 + 第三方实测）

- 归档 = **只读**：打开归档会话可以重读但**不能继续发消息**，底部有绿色 `Unarchive` 按钮
- 归档入口：会话 ··· 菜单 → `Archive`（**无需二次确认**）
- 管理入口：Settings → Data controls → Archived chats → Manage
- **搜索覆盖归档会话**（重要的找回路径）
- 删除 = 立即不可见，**30 天内永久删除**，不可恢复
- 批量：`Archive all chats` / `Delete all chats`

### 2.3 Cursor

- 归档移出主列表，**不删除数据**；入口在 `Filter by → Status → Archived` 或列表底部折叠 `Archived`
- 恢复：hover `↻` restore 或右键 → Restore
- 独特用法：`Cursor: Delete All Unarchived Chats...`（按时间批量删未归档）⇒ **归档是批量删除的"保护网"**

### 2.4 WorkBuddy（本机 `~/.workbuddy` 实际库结构）

迁移框架：`~/.workbuddy/.workbuddy-sqlite-migrations/0000..0016`（带版本号顺序迁移）。

baseline `sessions` 表：`deleted_at`（软删）、`last_activity_at`（不活跃判定）、`status`、`title`/`custom_title` 分离、`is_playground`/`is_background_automation` 分类、`project_id` 归属、`0013_add_session_unread.sql` 加 `unread`（与 Claude Code 自动归档的排除条件同源）。

**提炼**：`软删除 + 活动时间戳 + 顺序迁移框架` 是三家共有的底座。

## ★ 3. 最终决策（2026-10-16 用户拍板）

| # | 决策点 | 结论 | 依据 |
|---|---|---|---|
| 1 | 归档会话能否继续对话 | **只读**：可查看/搜索/导出，**不可发新消息**；须先「恢复」才回到主列表并继续 | ChatGPT 明确只读、Anthropic SDK「archive 后禁止发新事件」、Claude Code/Cursor 均需 Unarchive |
| 2 | 是否同批做回收站 | **做**：删除改软删（`deleted_at`），回收站可恢复，永久删除仅回收站内可见并二次确认 | 现在是硬删不可恢复，风险 highest |
| 3 | 自动归档 | **默认关**，设置页提供 14 / 30 / 90 天 / 从不 | 不做未经用户同意的自动化 |
| 4 | UI 范围 | 侧栏 hover + 右键 + 批量 + 底部「已归档」折叠分组；**工作台 TaskListSection 同步** | 两处现逻辑重复，抽 composable 单一实现 |

## 4. 设计

### 4.1 数据模型（**4 处必须同步**）

| # | 文件 | 位置 |
|---|---|---|
| 1 | `packages/core/src/db/schema.ts` | 建表 37-52 + 迁移块 |
| 2 | `apps/server/src/db.ts` | 建表 304-319 + 迁移块 |
| 3 | `packages/shared/src/types/index.ts` | `Conversation` 接口 |
| 4 | `packages/ui/src/stores/chat.ts` | `rowToConv` |

字段选择理由：

- **`archived_at` 而非 `archived INTEGER`**：nullable 时间戳既表达"是否归档"又携带"何时归档"，与 WorkBuddy `deleted_at` 同范式。
- **`last_activity_at` 独立于 `updated_at`**：已核实 `PATCH /:id` **不刷** `updated_at`（`conversations.ts:86-190` 无该 SET），当前刷新点只有发消息（`:440`）、MCP 更新（`api-tool-executor.ts:3047`）、工作流改 agent（`builtin-workflow-agents.ts:1407`）。看似够用，但**将来有人在 PATCH 里补刷 updated_at，14 天计时就被静默重置** ⇒ 独立列（符合"同一语义只能有一处实现"）。
- **`deleted_at`（回收站）**：点删除不再丢消息。

### 4.2 后端 API

| 端点 | 改动 |
|---|---|
| `GET /` | 加 `?archived=active\|archived\|all`，默认 active；**两条 SQL 分支都要改**（`:46-50` 与 `:53-55`） |
| `PATCH /:id` | 支持 `archived`（注意：body 带 `title` 会强制 `title_source='user'`，`:106-109`） |
| `DELETE /:id` | 改**软删**（置 `deleted_at`），保留 message / file / summaries |
| `POST /:id/restore` | 清 `deleted_at` |
| `DELETE /:id/permanent` | 真删（保留现清理全链） |
| `GET /trash` | 回收站列表 |
| MCP `api_conversation_update` | **不暴露** archived（避免模型把用户会话归档掉） |

> ★ 归档/恢复/删除/恢复统一走明确端点，**多处相同语义 = 漂移**。

### 4.3 UI

- 侧栏行 hover / 右键菜单 / 批量 → 「归档」「删除」
- 底部折叠：**「已归档」**、次级入口「回收站」
- 归档会话进入详情页：**输入框禁用 + 顶部提示"该会话已归档，恢复后可继续"**（对齐 ChatGPT 只读语义）
- 工作台 `TaskListSection.vue` 同步（抽 composable 复用）

### 4.4 自动归档（默认关）

设置项：`永不 / 14 / 30 / 90 天`。触发：启动时 + 定时扫描。排除：运行中、未读、置顶、空间内。`apps/server/src/routes/clip.ts:134` 另有一处删除需确认是否纳入。
