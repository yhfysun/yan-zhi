# 宠物伴星（Pet Companion）功能方案 · 2026-10-27

> 对标 ChatGPT Desktop / Codex 的 Pets 功能：悬浮在桌面上的动画伴星，实时反映任务状态，
> 右击弹**半圆常用菜单**（槽位可编辑），左键展开**任务小面板**，任务完成/需要输入时**系统通知**。
>
> 原型：[docs/prototypes/pet-companion-proto.html](../prototypes/pet-companion-proto.html)
> （可拖拽、右击、点开面板、顶部可切状态、底部演示条可增删任务）

## 一、应用现状分析（本方案的地基）

### 1.1 任务状态源 —— 全部现成，零后端改动

| 需要的状态 | 现有来源（packages/ui/src/stores/chat.ts） | 说明 |
|---|---|---|
| 运行中 | `runningConvIds` / `isConvStreaming(id)` (L475) | 多会话真并行，Set 结构直接可遍历 |
| 运行统计 | `runStatsByConv` (L482)：status/startedAt/endedAt | 已用时直接取，SSE 终态驱动 |
| 已暂停 | `pausedConvIds` (L4031) | 2026-10-27 刚修好的暂停记账 |
| 需要输入 | `scopedPending` 四件套 `byConv` (L980-1002)：反问 / 确认向导 / 越界授权 / 工具授权 | 按会话分桶，正好当"哪个会话在等用户"的判定 |
| 进度 | `plansByConv` (L1018) + 会话 `taskPlan` | 计划步骤 done/total，面板里画进度条 |
| 会话标题/智能体 | `conversations` 列表 + 会话 `agentId` 绑定 | 面板行文案 |
| 任务结束时机 | `emitTaskFinished` (L743) / `taskFinishHooks` | 完成通知的挂点，回调里带 convId |
| 实时性 | 会话级长连订阅 (L3648 起，WS `subscribe_conversation`) | 终态毫秒级推送，宠物跟随零轮询 |

结论：**宠物是个纯渲染层**——新建一个 pet store（或 composable）从 chat store 派生状态即可，服务端一行不改。

### 1.2 桌面壳能力 —— main.cjs 全套先例

- 透明无边框窗：框选遮罩窗（`getOverlayWindow` L8469，transparent + skipTaskbar + alwaysOnTop）
- 点击穿透/不抢焦点：隐私屏窗（L9348，`focusable:false` + `setIgnoreMouseEvents(true)`）
- 系统通知 IPC：`rc:notify`（L9253）——已验证 Notification 可用，加一个通用 `notify:show` 即可
- 托盘：`createTray`（L9701）——隐藏宠物的兜底出口
- 子窗口 API：`electronAPI.childWindow.open`（TaskRunWindow/DiffWindow 在用）
- 全局快捷键：`globalShortcut` 已 import

### 1.3 无既有实现
全仓 grep `pet|宠物|mascot` 无命中，纯新增，不碰存量逻辑。

## 二、产品形态

### 2.1 一句话定位
**"桌面上的任务伴星"**：不打开主窗口就能看到任务在不在跑、有没有等你，一键直达会话。

### 2.2 三件交互（原型已全部做出）

1. **宠物本体**（约 112×118px，可拖拽，位置记忆）
   - 状态动画全部由宠物包精灵图承担：idle 待机 / running 跑 / needs-input 等待 / paused 趴睡 / ready 挥手 / error 哭泣
   - 状态靠**动作 + 名字牌文案**表达；光环、数字角标、状态气泡已移除（用户明确不要装饰性元素）
2. **右击 → 半圆常用菜单**（上半圆 6 槽位，靠近屏幕顶自动翻下半圆）
   - 默认槽位：新建任务 / 任务面板 / 逗一下 / 通知静音 / 隐藏宠物 / 设置
   - **槽位可编辑**：右击菜单时按住编辑开关（或菜单尾"编辑"项），候选池点选替换；槽位配置持久化
   - 候选池（首版）：截图、远控、切换智能体、暂停/恢复/停止当前任务、回最近未读、换形象
   - 菜单动效：槽位从宠物中心弹出（scale+位移弹性曲线），逐个 40ms 级联
3. **左键 → 任务小面板**（316px 宽，出现在宠物旁，自动避让屏幕边）
   - 分三组：**需要处理**（反问/授权卡/出错）→ **进行中**（含暂停）→ **刚完成**（未读）
   - 行内：标题、智能体、已用时、计划进度条；**需要输入的行内联快答输入框**（答案走既有 `submitPendingQuestion`）
   - 行内快捷操作：暂停 / 恢复 / 重试 / 查看 / 📌**跟随**（pin 后宠物只跟随该任务；清掉回到自动跟随）
   - 点击行 → 主窗口前置并 `selectConv(convId)`（必须走 selectConv，见既有坑位记录）
4. **快问输入条**（hover 宠物浮现，原型已做出）
   - 形态：胶囊输入条贴在宠物正下方——左端**智能体胶囊**（点击轮换智能体），中间输入框，右侧 🎙（二期语音）+ ↑ 发送
   - Enter 直接派活：无运行任务 → 主窗口后台新建会话并以该文本发起任务（不弹窗、不打断当前工作）；已有任务在跑 → 走既有 `injectQueuedMessage` 并入下一轮
   - 定位对标 ChatGPT Pets 的 Quick Chat：宠物从"显示器"升级成"入口"——不打断当前工作流就能下单
   - 派活后宠物切入 running 动画、面板新任务置顶
5. **「逗一下」动作菜单**（原型已做出，2026-10-28）
   - 入口：半圆菜单默认第 3 槽（6 槽，弧半径 96→114），也在候选池里，可被编辑掉
   - 形态：点开后宠物**上方**弹出横排动作条（6 个胶囊），与任务面板 / 形象托盘 / 半圆菜单三者互斥，Esc 或点空白关闭；靠近屏幕顶自动翻到宠物下方，左右出屏自动钳位
   - 六个动作（零新增素材，全部复用精灵图既有行）：
     | 动作 | 精灵行 | 叠加层 |
     |---|---|---|
     | 摸摸 | 行 0 待机 | 缩身害羞 CSS（−5° + scale .95）+ ♥ 心形粒子 ×4 |
     | 招手 | 行 3 挥手 | — |
     | 张望 | 行 7 观察 | 左右扫视 ±4° |
     | 打盹 | 行 6 趴/睡 | 下沉呼吸 + `z` 粒子 |
     | 转圈 | 行 0 → 行 2 → 行 0 | 绕竖轴 `rotateY(360°)`（带透视，不是平面旋转）+ 起手 −16° 反向蓄力；投影转到侧面骤窄的两次窗口（≈190–360ms / 520–680ms）切到"转身感最强"的奔跑行，遮掉半透明消失感 |
     | 跳一跳 | 行 0 | 复用 `hop-lg`（squash & stretch）+ 影子收缩 + 落地尘土 |
   - **瞬态语义**：动作是覆盖层（`actionOverride`：行/帧数/fps/到期时间），**不改状态机**；2~3 秒后自动回落到当前状态，运行中/等待中/出错态不受影响；拖拽时让位给拖拽反应；连点同一动作可重播

6. **形象托盘**（双击宠物或半圆菜单「换形象」打开）
   - 只列开源宠物包（`pet.json + spritesheet.webp`），当前 6 只：Boba / Tiko / 旺财 / 噜噜 / Noir / Mallow；手绘 SVG 形象已全部移除
   - 共享同一套状态行映射（0 待机 / 1 走 / 2 跑 / 3 挥手 / 4 等待 / 5 哭泣 / 6 趴睡 / 7 观察 / 8 侧身）→ **加新形象 = 放一个宠物包**，零改造
   - 选择持久化（`yz:pet:char`），托盘当前项高亮，名字牌/状态文案随形象
   - 对标 ChatGPT Pets 的宠物选择器；P2 的自定义宠物（GIF/图集导入）复用同一托盘入口

### 2.3 状态优先级（对齐 Codex 机制）
宠物同时只显示一个状态，按优先级取最高：

```
needs-input > error > ready(完成未读) > paused > running > idle
```

`needs-input` 是最高优：宠物存在的核心价值就是"该你的时候叫你"。

### 2.4 通知规则
| 事件 | 通道 | 文案示例 |
|---|---|---|
| 任务需要输入（反问/确认/授权卡出现） | 系统通知 + 角标 | 「智能体在等你：找到 3 个数据源…」 |
| 任务完成 | 系统通知 + 角标 | 「任务完成：三季度销售对比报表」 |
| 任务出错 | 系统通知 + 角标 | 「任务失败：目标目录不可写」 |
| 暂停/恢复 | 仅面板/动画变化 | 不打扰 |

- 通知带 convId，点击通知 = 主窗口前置并跳该会话（Windows 上 `Notification.click` 事件）。
- 静音开关分两档：**全部静音**（角标变灰仍计数）与 **只留"需要输入"**（完成/出错不弹）。
- 聚合：同一会话 5s 内多条事件只弹最后一条，防止刷屏。

### 2.5 隐藏与呼出
- 半圆菜单「隐藏」/ 右击菜单 Hide；隐藏后从**托盘菜单**「显示宠物」或全局快捷键呼出。
- 全局快捷键默认 `Alt+P`（可在设置改），行为 = 显示/隐藏切换。
- 播放全屏视频/演示时自动隐藏（检测前台全屏窗口，沿用全屏隐藏逻辑可用简单版：用户手动隐藏优先）。

## 三、技术方案

### 3.1 架构（三层）

```
主进程 (apps/desktop/main.cjs)
  └─ pet-window: 透明、无边框、skipTaskbar、alwaysOnTop('floating')、不进任务栏
      · setIgnoreMouseEvents({forward:true}) 动态切换：只有宠物/菜单/面板矩形吃事件
      · IPC: pet:set-state(渲染层→主进程同步徽标/托盘 tooltip)、notify:show、pet:open-conv
渲染层共享包 (packages/ui)
  ├─ stores/pet.ts —— 从 chat store 派生：tasksView computed、petState、priority、unread
  ├─ components/pet/PetCompanion.vue —— 宠物本体 + 动画（SVG，原型直接移植）
  ├─ components/pet/PetRadialMenu.vue —— 半圆菜单 + 槽位编辑
  └─ components/pet/PetTaskPanel.vue —— 任务小面板
宿主挂载
  · 桌面端：pet-window 独立窗口加载轻量入口（只挂三件组件 + chat store 精简订阅）
  · Web/移动端：不弹独立窗；移动端（Capacitor）首版不做，二期做成 TabBar 上
    的「任务角标 + 点开底部动作面板」，复用同一 pet store
```

**pet-window 与主窗口的状态同步**：pet-window 里跑同一套 chat store 会引双份 WS 订阅。
采用**主窗口权威**模式——主窗口照常跑业务，通过 IPC（`pet:sync-state`）把派生后的轻量任务视图
（≤10 行、每行 ≤200 字）推给 pet-window；pet-window 只做渲染 + 交互回传
（`pet:action` → 主窗口执行暂停/恢复/selectConv）。避免双订阅、双连 WS、内存翻倍。

### 3.2 关键实现点

| 点 | 做法 | 风险与对策 |
|---|---|---|
| 鼠标穿透 | 默认 `setIgnoreMouseEvents(true,{forward:true})`，渲染层用 `document.elementFromPoint` 判指针是否落在宠物/菜单/面板上，动态关穿透 | forward 在 Windows 上有已知的 hover 事件延迟，实测校准；面板打开时整块区域关穿透 |
| 置顶层级 | `setAlwaysOnTop(true,'floating')`；全屏应用之上不保证——接受（Codex 同样行为） | — |
| 多显示器 | 窗口位置持久化到 settings（`pet:{x,y,hidden,slots,muted}`）；启动时钳回可见区域 | 拔掉副屏后窗口丢失 → 钳回主屏 |
| 通知点击 | `Notification.click` → `mainWindow.show()+focus()` → 发 `pet:open-conv` 给主窗口渲染层 | Web 端降级为应用内 toast |
| 快捷键 | `globalShortcut.register('Alt+P')`，与现有全局快捷键统一登记处 | 冲突检测：注册失败静默降级为托盘呼出 |
| 位置拖拽 | 渲染层 pointer 事件 + IPC 通知主进程 `win.setPosition`（或整窗可 drag region） | 拖拽结束才落盘，避免高频写 |

### 3.3 状态派生（stores/pet.ts 核心，纯函数可单测）

```ts
type PetTaskView = {
  convId: string; title: string; agentName: string;
  status: 'running'|'paused'|'needs-input'|'completed-unread'|'error';
  plan?: { done: number; total: number };
  elapsedSec: number;
  question?: string;   // needs-input 时的提问摘要
  errorMsg?: string;
};

// 优先级同 §2.3；pin 的任务覆盖自动跟随
function petStateOf(tasks: PetTaskView[], pinnedId?: string): PetState;
```

`needs-input` 的判定 = 四类 scopedPending 任一在该会话非空（含 pathAuth/toolAuth——授权卡本质也是"等你点头"）。

### 3.4 与既有机制的关系
- `emitTaskFinished`/`taskFinishHooks`：宠物订阅完成事件发通知；不改动既有钩子语义。
- 交互卡 30 分钟超时（tool:idle）：卡片被收掉后宠物自动从 needs-input 回落，天然一致。
- 暂停恢复（pausedConvIds）：直接消费，无新逻辑。
- 托盘：宠物隐藏状态进托盘 tooltip（「宠物已隐藏 · Alt+P 呼出」）。

## 五、备选形态对比（为什么选独立透明窗）

| 方案 | 好处 | 坏处 |
|---|---|---|
| **A. 独立透明置顶窗（选定）** | 真·悬浮在一切窗口之上；拖到屏幕任意处；与主窗口解耦（主窗最小化宠物仍在）；原型可直接移植；Codex 同款形态 | 需处理鼠标穿透/多显示器/焦点策略；多一个渲染进程（轻量入口可控在 ~30MB） |
| B. 主窗口内的浮动组件 | 零主进程改动，一天内上线 | **不是真悬浮**：被其它应用盖住就看不见，主窗最小化即消失——与"伴星"定位根本冲突 |
| C. 托盘图标 + 托盘菜单 | 最省事、最稳 | 无动画无情感；Windows 托盘角标表达力弱；"任务完成"只能靠系统通知，观察不到"正在跑" |
| D. 系统通知 AppIcon 徽标 | Windows 徽标数可显示计数 | 只有一个数字，无状态区分，无法交互 |

结论：A 是唯一满足"悬浮 + 状态动画 + 半圆菜单 + 小面板"全部诉求的形态；B 可作为 Web 端降级（P2-12）。

## 八、AI 造宠物 + 宠物记忆（2026-10-28 用户拍板方向）

### 8.1 大模型直接写代码造形象、造动作，并固化成宠物包

**核心想法**：宠物包本质是「manifest + 绘制脚本」（Coopanion 的 figure pack 已验证这个范式），
而写代码正是模型的主场——**用户一句话描述，模型产出一个可运行的宠物包，预览满意后固化安装**。

**流程（用户视角）**：
1. 设置 → 宠物工坊 →「AI 造宠物」：输入描述（"一只穿雨衣的柯基，会摇尾巴"）或上传参考图
2. 模型生成 `pet.json + figure.js`（canvas/SVG 程序化绘制 + 动作表），进程内沙箱**实时预览**
3. 预览页带状态切换器（待机/跑/等/完成/出错 + 各动作按钮），不满意就对话式改（"尾巴再大一点""加个跳舞动作"）
4. 满意 →「固化」：写入插件目录（`contributes.pets`），出现在形象托盘；可导出 zip 分享

**技术要点**：
- 模型产出的 `figure.js` 遵守固定接口：`createFigure(opts) → { draw(ctx, t), actions: {...}, dress?: axes }`，
  渲染层只认接口，不认具体画法——模型想画像素风/矢量风/3D 感都可以
- 安全：脚本走**既有插件 JS 沙箱**（plugin-host-bridge），默认无网络/文件权限
- 质量兜底：生成后自动跑校验（帧循环无跳变、无外部资源引用、体积上限、动作表 schema）+ 用户预览拍板
- 成本：一次生成一次 LLM 调用（产出几百行 JS，模型完全胜任）；迭代轮次由用户把握
- 与 7.1 的统一：AI 生成的包和下载的包走**同一条装载路径**，只是来源不同（generated 标记）

**为什么值得做**：这是差异化最大的一项——宠物生态里"会自己造宠物的桌宠"，而且我们已有插件体系 + 沙箱 + 模型能力，三块都现成。

### 8.2 宠物记忆：挂进我们自己的记忆体系

**原则（用户拍板）**：不自造一套 PARTNER.md，**直接用应用的记忆体系**（memory 表 + 维度 + 检索）。
现有契约已就绪：`GET /memory/list?dimension=profile|agent|session|daily`，`type` + `agent_id` + `tags` + `metadata`。

**设计**：
- 新增维度 **`pet`**（type=`pet`，metadata `{ packId, kind }`）：
  - `kind=event`：被摸头/被拖拽/被喂食/触发动作等交互事件（"10-28 被摸了 12 次头，喜欢被摸"）
  - `kind=pref`：用户偏好（"不喜欢宠物盖住输入框""叫它豆豆"）
  - `kind=summary`：宠物对当天对话/任务的情绪摘要（"今天帮你盯了 3 个任务，两个超时"）
- **写入时机**：交互事件按频次聚合后写（不是每次点击写一条）；任务终态时生成一句情绪摘要；用户对宠物说话时抽取偏好
- **读取时机**：构建宠物人格提示词时检索 top-k（近期事件 + 相关偏好 + 摘要），影响动作选择与台词
  （被摸头多的宠物会主动蹭头；被拖拽多的会躲；记得你叫它豆豆）
- **UI**：宠物设置页「它记得的事」列表（可删除/纠正）；记忆管理页增加「宠物」维度筛选
- **隐私**：全部本地（应用本身本地优先）；记忆开关在宠物设置里

**落地拆步**：
- P1：pet 维度 + 交互事件记忆 + 设置页列表（最小闭环）
- P2：情绪摘要生成 + 提示词注入 + 记忆驱动动作

## 七、宠物插件生态（2026-10-27 用户新增方向：宠物可由用户自建形象与动作）

**核心原则：官方掌握「交互壳」（状态机/半圆菜单/任务面板/通知），插件只贡献「皮」（形象 + 动作 + 可选音效）。**
这样第三方宠物不会破坏任务状态语义，创作门槛也能压到最低。

### 7.0 对标情报（2026-10-27 调研）
- **Codex 宠物生态已成规模**：codexpets.org / petdex.dev 收录 **5200+ 只社区宠物**，标准包格式 `pet.json + spritesheet.webp`，**9 个动作状态**是社区事实标准（idle/running/waiting/review/jump/drag/look±16向 等）。
- **主流形态是 chibi 全身像**：有手有脚（甚至有鞋），跑动四肢摆动、被拖拽会吊在光标上乱蹬（Shimeji 传统）。无手无脚派也存在（蘑菇王桌宠「完全无手无脚」），但属于少数风格声明，不是主流。
- **动作丰富度是卖点**：商城文案突出「挥手/奔跑/跳跃/拖拽反应/跟随光标/16 向注视」；选购指南甚至以「跑动时轮廓是否可辨认」作为推荐标准。
- **动画品质的分水岭不在帧数，在运动规律**（Toyful《Very Very Valet》拆解 + 迪士尼十二原则）：pose→pose 之间用**曲线**而非匀速正弦；squash & stretch「几乎不可能做过火」；walk→run 之间加一档"scramble"加速；情绪用独立 emote 层（粒子/动态眼）叠在任何动作上。
- **桌面宠物是"余光产品"**（Bongo Cat 设计笔记）：一眼就要读懂、一秒就要退场——反馈全部**参数化**（悬停 0.05s / 按下 0.1s / 释放 0.3s 过冲缓动；emoji 上升 200px·r、横抖 ±25px、末尾淡出），而不是逐个手搓。
- **启示**：①形象默认全身带四肢；②动作覆盖越全越有"活"感（拖拽反应 + 踱步闲逛是低价高收益项）；③动画质量靠**squash/stretch + anticipation + 影子/尘土/瞳孔追踪这套"juice"**，不靠堆帧；④宠物包格式直接兼容 `pet.json + spritesheet.webp`，**5200+ 只存量宠物可零改造导入**。

### 7.0b 形象与动画品质基线（2026-10-27 三次修订：只用开源宠物包）
**结论（用户实评 + 对标验证）**：手绘 SVG 形象的上限达不到 Codex 商城水准，**手绘形象已全部移除，原型只用开源宠物包**：
- 已接入 **6 只开源宠物包**：Boba（水獭，11 行版）、Tiko（机器人）、旺财（布偶猫）、噜噜（水豚）、Noir（侦探蛛）、Mallow（小怪）——全部为 `pet.json + spritesheet.webp`，帧 192×208、8 列，9 行/11 行两种版本，**零改造跑通**，验证 7.1 的「兼容存量宠物包」假设成立。
- 默认形象 = Boba；托盘只列宠物包，可随时切换。手绘 SVG 那四只已全部删除。
- 渲染器按行映射：`{状态: {行, 帧数, fps}}`，用 `background-position` 步进（`setInterval` 驱动，不用 rAF——宠物独立窗会被系统节流）。社区标准行序：0 待机 / 1 走 / 2 跑 / 3 挥手 / 4 等待 / 5 哭泣 / 6 得意 / 7 观察 / 8 侧身；Boba 11 行版第 9/10 行是拖拽动作。
- **素材来源与许可**：全部来自 petdex.dev 开源宠物画廊（Boba 作者 railly 等）。原型仅作本地演示；正式分发前需逐个宠物包确认许可，或改用官方自制包。
- **视觉简化（用户反馈）**：去掉了宠物背后的**黄色光圈**（状态光环）和**数字角标**——状态已由精灵图动作 + 名字牌文案表达，不再叠加装饰。

**动画品质层**（宠物包由精灵图帧动画承担；光环/尘土等 CSS 动效不再叠加到宠物包上）：
| 原则 | 实现 |
|---|---|
| Squash & Stretch | 蓄力压扁→腾空拉长→落地压扁，原点在地面 |
| Anticipation | 起跳前下压；状态气泡从 0 弹出 |
| Follow-through | 尾巴/耳朵独立相位；落地二次回弹 |
| Slow in/out | 过冲缓动曲线，不用匀速 |
| Secondary action | 影子反缩放、落地尘土、状态切换 pop |
| Appeal | 瞳孔追鼠标、空闲小动作、情绪粒子 |

**验收口径**：112px 实际尺寸下轮廓可辨、状态可读、有重量感。

### 7.0c 对标 Coopanion（2026-10-28 调研，GitHub 861★）
Coopanion（Coo）是当前最成熟的同类开源桌面宠物，架构值得直接借鉴：

**1. 形象包不是一张图，是可脚本化的「figure pack」**
- `figure.json`（manifest v2 / api v2）：id、多语言名称、作者、**entry + export（指向 figure.js 的工厂函数）**、调色板轴（含帽子/耳环/眼镜/项链等装扮轴）、动作表、音效槽
- 形象由 JS 绘制（Coo 是 C 形体+两条短腿的程序化身体），**动作是语义化清单而非固定几个状态**：
  `jump / hop / look / turn / nod / shake / spin / sit / sleep / dizzy / walk / run / wave / bow / shiver / flap / dance / cry / confused …`
  每个动作带时长和 `lasting` 标记，App 和模型按语义调用（能对它说「跳个舞」）
- 兼容性承诺：声明 api 2 的形象包在后续版本继续加载

**2. 它把「宠物」做成了有世界观的平台**
- **Worlds 扩展**：QQ 机器人、画室、**小游戏**——"还能打游戏"就是来自扩展体系
- **活动气泡**：思考/阅读/搜索/写作/操作电脑时显示不同动画图标 + 文件名，气泡可点击穿透（内容型气泡，不是装饰）
- **记忆**：`PARTNER.md` 整份进提示词，工作区每次变更存档（git 版本历史）
- **电脑操作**：点按钮/打字/切窗口，动作前先征求同意
- **语音**：按住说话，本机 FunASR/Whisper 按语言选择
- **边缘生活**：住在屏幕下沿、沿边缘走路、跑到另一头

**对我们的取舍**：
| 借鉴点 | 决策 | 理由 |
|---|---|---|
| 语义动作词表 | **采纳（P1）** | 我们只有 6 个状态；扩展成动作库后，半圆菜单/用户指令/模型都能触发（"跳一下""打个招呼"），拟人感直接翻倍 |
| 可脚本化 figure pack | P2 采纳 | 精灵图覆盖 5200+ 存量宠物的生态先吃掉；脚本化包留给高级作者（api 2 兼容承诺的做法值得抄） |
| Worlds/扩展 + 小游戏 | P2 采纳 | 小游戏作为扩展挂在宠物上（逗猫棒/接奶茶），能显著提升留存；复用我们既有插件体系 |
| 装扮轴（配色/配饰） | P2 | 与 7.2 的「宠物工坊」合并做 |
| 活动气泡（显示正在做什么+文件名） | P1 考虑 | 与"黄圈/角标"不同：这是内容型气泡，展示任务实质；可在 P1 做开关 |

## 九、3D 渲染链路（2026-10-28 原型验证）

### 9.1 为什么要有 3D
精灵图宠物包是**纸片人**：每帧一张 192×208 位图，`rotateY` 只是把这张纸在 3D 空间里转，转到 90° 时投影宽度为 0——「转圈」必然出现极短的消失（现有 2D 原型靠切"转身感最强"的奔跑行遮，治标不治本）。

对标核实（避免拍脑袋）：**Coopanion 也不是 3D**。它的 `kit/rig.js` 是 Live2D 式 WebGL 网格蒙皮 + 形变器树（鲸鱼娘 = 25 张纹理 + `model.json`；Coo 本体是 SVG path 代码绘制）。它的"活"来自逐帧参数化变形（19 表情 / 18 动作 + 头发裙摆弹簧），偏航一般也就 ±30°，同样转不了 360°。

要真正的转身，只有骨骼 3D：`three.js + glTF/VRM`，转圈就是 `rotation.y += 2π`，顺带白送骨骼动画、受光、表情口型。

### 9.2 原型结论（[docs/prototypes/pet-3d-proto.html](../prototypes/pet-3d-proto.html)）
用**程序化几何体**做占位宠物（不依赖任何模型资产），把整条链路先跑通：

| 链路项 | 结果 |
|---|---|
| 透明画布（`alpha:true` + `setClearAlpha(0)`） | ✅ 桌面壁纸透出，等价于真实置顶窗的 alpha 画布 |
| three.js 来源 | ✅ 直接吃仓内既有依赖 `three@0.185.1`（packages/ui 已依赖），不是新增技术栈 |
| 六态 | ✅ 待机/运行中/等待/暂停/完成/出错，全部程序化姿态（呼吸、踏步、竖耳、坐伏、连跳、抖动） |
| 逗一下六动作 | ✅ 摸摸/招手/张望/打盹/转圈/跳一跳；**转圈实测 0→360° 完整回正**，不再是纸片侧线 |
| 拖拽 | ✅ 射线打 z=0 平面 + 包围盒命中，拖动时影子留在地面 |
| DOM 叠层跟随 3D | ✅ 动作条/名字牌/粒子按 `Vector3.project(camera)` 定位（实测动作条中心与头部投影误差 <1px） |
| 功耗 | ✅ 30fps 限帧开关 + HUD 实时显示 fps / 三角形数（4926）/ draw calls（15） |

### 9.3 升级路径（占位 → 真模型）
- **换模型只改一处**：`buildPet()` 返回的骨骼引用（head/arms/legs/eyes/tail）→ 换成 `GLTFLoader` + `AnimationMixer`，动作表从「程序化改姿态」换成「播剪辑」。状态机、拖拽、叠层、限帧全部不动。
- **素材生态**：VRM/VRoid Hub 社区模型可直接用（需 `three-vrm`，约 +1~2 天）；没有合适剪辑就用 Mixamo retarget。
- **双渲染器共存**：`PetRenderer` 接口本来就是为此留的——精灵图包（5200+ 存量）与 3D 模型并存，按包类型选实现；3D 不是替换生态，而是多开一档。
- **必须认的三个代价**：①精灵图包不能自动转 3D（位图没有几何信息）；②透明置顶窗常驻 WebGL 有 GPU/电耗，必须限帧 + 失焦降级；③单个 VRM 模型 5~20MB，应用体积与首屏加载都会涨。

### 9.4 拆步
- P1-3D①：`buildPet` 换成 VRM 加载 + 动作剪辑映射（~3~5 天）
- P1-3D②：pet-window 接 WebGL 画布 + 失焦降帧 + 隐藏时停渲染（~1 天）

### 9.5 真 VRM 接入（2026-10-28 已跑通）
原型里加了「载入 VRM 模型」：占位几何体 ↔ 真 VRM 一键切换，**只换驱动层，状态机/拖拽/叠层/限帧全不动**。

- 依赖：`@pixiv/three-vrm@3.5.5`（要求 three ≥0.137，仓内 three@0.185.1 直接满足），走 import map 从 CDN 拉，未进 package.json
- 模型：three-vrm 官方示例 `VRM1_Constraint_Twist_Sample.vrm`（**仅本地演示**，正式分发要换有明确授权的模型）
- 实测：70118 三角面 / 21 draw calls；六态 + 六动作全部跑通，**转圈是骨骼绕竖轴真转 360°**，侧面不再是纸片
- 两个接入坑（已解，写在这里省下次排查）：
  1. **朝向**：该样本原生朝 +Z，`scene.rotation.y = Math.PI` 会背对镜头——不能照抄示例代码，要用包围盒+试渲染确认
  2. **T-pose**：VRM 默认 T 字站立，必须给大臂加基础下垂姿态（本例 `upperArm.rotation.z = ±1.2`），否则待机时一直张着胳膊；状态/动作都在这套基础姿态上叠加
- 剩余差距：示例是无表情差异的测试模型（有 blink 等表情通道），真要做"宠物"得挑低身高的 Q 版模型；VRoid Hub 上可商用模型需要逐个看授权

### 9.6 人形模型的"活着"三件（2026-10-28 已做进原型）
用户拍板：**人形模型也可以，不必等 Q 版**。补齐三项"余光产品"要素：
- **视线跟随光标**：只加在 normalized head/neck 上（±0.42 / ±0.18 rad，钳制），实测光标在右侧 head.rotation.y=+0.33、左侧 −0.42
- **沿屏幕底边踱步**：待机 9~20s 后随机选点走过去（0.85 单位/秒），面朝行进方向（±90°），走动时摆腿；离开待机 / 有动作 / 拖拽时立即取消
- 空闲小动作：待机呼吸 + 头部微转（原有）
