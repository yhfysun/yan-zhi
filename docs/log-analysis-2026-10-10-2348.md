## 二、根因清单（每条都有日志铁证）

### 🔴 R1 —— 锚定永不建立（**这是"任务跑不通"的直接主因**）

**症状链**：navigate 报 ok → 紧接着 get_page_content 报"该会话尚未绑定浏览器页面" → 模型以为没生效 → 换 URL 重试 → 无限循环。

**代码根因**（`apps/desktop/main.cjs` + `browser-target.cjs`）：

`decideAnchorUpdate(action, hadExplicitTab, resolvedTabId, resultTabId)` 的 `resolvedTabId` 用的是
`resolveTarget()` 的返回 —— 而 `resolveTarget` 在**未锚定**时对建页类动作返回 `tabId: null`。

此时下游 `waitForGuest(tabId || activeTabId, ...)` 靠 **`activeTabId` 兜底**拿到 guest
⇒ navigate **看起来成功**（`wc` 非 null），但主进程传入的 `resolvedTabId` **仍是 null**
⇒ `decideAnchorUpdate('navigate', false, null, undefined)` 返回 **`{mode:'none'}`**
⇒ **锚永远不建立** ⇒ 后续所有读类动作全被 `resolveTarget` 第 ⑤ 条拒绝。

**实测复现**（本次我用纯函数真跑）：
```
resolveTarget(c1, null, 'navigate', {anchored:null, activeTabId:'tab-1', isMine:mine})
  → {"ok":true,"tabId":"tab-1"}          # 修复后：回落 activeTabId
decideAnchorUpdate('navigate', false, 'tab-1', undefined)
  → {"mode":"anchor","tabId":"tab-1"}    # ✅ 锚建立
```
但**修复前**（`activeTabId` 未传入 → `tabId:null`）：
```
resolveTarget(...) → {"ok":true,"tabId":null}
decideAnchorUpdate('navigate', false, null, undefined) → {"mode":"none"}   # ✗ 锚永不建立
```

> 那条会话**已经改对了这一处**（`browser-target.cjs` 第 102-106 行新增 `activeTabId` 回落 +
> `main.cjs` 第 2743 行传入 `activeTabId`）。**方向正确**，见第四节评估。

### 🔴 R2 —— 每次失败都"自建新 tab" ⇒ tab 无限堆积 ⇒ 应用卡死

**铁证**：
- `tab-1` → `tab-3` **跳格**（23:40:52 → 23:41:18）= 孤儿 tab 堆积
- `MaxListenersExceededWarning: 11 did-stop-loading listeners`（23:46:14）
- 3 分钟内 36 次 navigate，每次 14.4s

**代码根因**：`evictLruTabIfNeeded()` / `MAX_TABS = 8` / 空闲巡检 **全部只遍历 `browserViews`（旧 BrowserView 引擎）**。
`createBrowserTab()` 的 **webview 分支**（第 1593-1605 行）此前直接 `webviewTabs.set(...)` 就 return
—— **无上限、无 LRU 逐出**。而 webview 引擎下 **每个 tab = 渲染层一个 `<webview>` = 一个 Chromium 渲染进程**
⇒ agent 因 R1 反复重试时，tab 无上限堆积 ⇒ 内存/CPU 爆炸 ⇒ **整个应用卡死**（用户实报"pageAgent 一跑就卡住"）。

### 🔴 R3 —— `reasoning_content` 400（**这条是白天"修过"却仍复现**）

**铁证**：`23:02:57 [renderer] LLM 请求失败: 400 ... The reasoning_content in the thinking mode must be passed back`

**代码根因**：`packages/core/src/llm/client.ts` 第一版修复写成
`if (m.reasoningContent && role==='assistant') out.reasoning_content = ...`
—— 漏了「模型某轮**只吐 tool_calls、不吐 reasoning**（落库 NULL）」这种情况 ⇒ **字段整个缺失** ⇒ 400。
实据：会话 `f0a901e3` 22:46:28 的消息（tc=1 / rc=NULL）→ 下一轮即 400。

> 那条会话**已改对**：抽出 `resolveReasoningField()`（纯函数），assistant 且（有 tool_calls 或 content 非空）
> 就**必带**，无 reasoning 兜底**空串**（不是省略字段）。

### 🟡 R4 —— `on` 档死降级把 8s 失败拖成 23s + 文案误导

**铁证**：`22:46:37` 桥报 `loadURL of null` → `降级回 SSE 委托` → `22:54:37` 才报超时（**480s**)。

**代码根因**：直连化后渲染层**已不执行** browser_* ⇒ SSE 路径**必然无订阅者** ⇒ 必等超时。
且桥把「动作执行失败」编码成 **HTTP 200 + `{error}`**（业务返回），调用方却 `catch` 就降级。
⇒ 最终文案是"前端暂时不可达"，把"主进程页面未就绪"**误导成**"前端断了"，模型据此编出
"browser frontend unreachable"。

> 那条会话**已改对**：新增 `isBridgeTransportError()`，只有传输层失败才降级；HTTP 200+`{error}` 直接回模型。

### 🟡 R5 —— `about:blank` 被判"无效 URL"

`main.cjs:2963` 硬性要求 `/^https?:\/\//`。模型想"重置页面"时会试 `about:blank` **必失败**（无提示）。
→ 小问题，但会浪费一轮重试（本次模型连试了 `example.com`、`about:blank` 等探测）。

### 🟢 R6 —— 会话记录里模型的行为问题（非代码 bug）

模型在 3 分钟内**换了几十个 URL 乱试**（`example.com/`、`example.com/?x=1`、`douyin.com/`…），
说明它拿不到「导航失败原因」的有效反馈 → 只能穷举。**R1/R4 修好后此项自动消失**。

### 🔴 R1 第四次根因（**本次新发现并已修**）

**那条会话的三次修复其实没真正生效** —— 回落闸门定为 `isMine(fb)`，而
`isMine` 的实现是 `agentTouchedTabs.get(t) === convId`，该表**只在动作成功执行后才登记**
⇒ **首次** navigate 时一个 tab 都没登记 ⇒ `isMine` 恒 **false** ⇒ 回落**仍不生效** ⇒ 锚还是建不起来。

**实测复现**（真跑纯函数）：
```
// 修复前（只有 isMine）
resolveTarget('c1', null, 'navigate', {anchored:null, activeTabId:'tab-1', isMine:()=>false})
  → {"ok":true,"tabId":null}          # ✗ 首次场景回落失效
// 修复后（isMine 或 isCurrentView）
resolveTarget('c1', null, 'navigate',
  {anchored:null, activeTabId:'tab-1', isMine:()=>false, isCurrentView:t=>t==='tab-1'})
  → {"ok":true,"tabId":"tab-1"}       # ✅ 锚建立
```

**修复**：回落闸门放宽为「`isMine(fb)` **或** `isCurrentView(fb)`」。
- 安全性论证：`activeTabId` 是**本面板**正在显示的页（用户肉眼可见），不可能是别的会话的页；
  跨会话越权的真实威胁是「显式传未登记的 tabId」—— 那条由 `resolveTarget` ①② 分支拦住（**未动**，实测仍拒绝）。
- 测试：新增 `⑭` 块 **4 项**（首次回落 / 非当前页不回落 / 显式越权仍拒 / main.cjs 必须真引用 activeTabId）。
- 变异测试：① 屏蔽 `isCurrentView` → 1 红；② main.cjs 改 `() => false` → 1 红。**两处都抓住**。

### ⚠️ 三个盲点 / 风险

1. **`decideAnchorUpdate` 的 `hadExplicitTab` 语义** —— 会话里讨论过但**没最终定案**。
