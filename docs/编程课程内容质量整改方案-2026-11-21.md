# 编程课程内容质量整改方案（2026-11-21）

## 一、问题定性：不是 UI 问题，是正文由模板批量拼凑

用户实测编程通识 P14「拆解文件、权限、编码与日志的机制」后反馈：正文是套模板的口水话，没讲任何具体知识。核对源码后确认成立。

### 证据链（源码级）

1. **模板生成器**：`packages/shared/src/learning/v2-curated/programming/programs.ts:569` 的 `generatedCourseSteps(course, stage, lesson)` 用变量插值拼出千篇一律的五步正文：

   ```
   第2步 body = `写出这个知识点的输入、状态、输出、异常和资源释放路径，并说明它如何接入${course.frameworks}。反例必须能指出：如果跳过边界、配置、权限或生命周期，程序会以什么方式失败。`
   ```

   截图中的原句与此逐字一致。它只是把 `lesson.title`、`course.frameworks` 换掉，**对任意课程都是同一段空话**。

2. **批量应用范围**：`programs.ts:607` 的 `PROGRAMMING_OTHER_COURSE_SEEDS` 对 **17 个课程包（除 java-enterprise）的全部 ready 课时**逐课调用该生成器 → 约 600 课时 × 5 步正文全部是模板话术。

3. **二次套壳**：`packages/shared/src/learning/v2.ts:371` 的 `enrichReviewedSteps()` 又对未显式提供 `objective/practice/checkpoint` 的步骤套第三层模板：

   ```
   objective   = `本步要能说清：${step.note}`
   practice    = `围绕"${step.title}"写下三行记录：观察到什么、依据是什么、还可能错在哪里。`
   checkpoint  = `关闭提示，用"主张—依据—边界"三句话复述"${step.note}"...`
   ```

   截图里的「本步要能说清：机制要能画成状态…」「写下三行记录…」正是这层生成的。

### 质量基准对照

手写课（`java-foundations.ts`）的正文：

> javac 做词法、语法、类型和语义检查，再输出包含常量池、字段、方法和字节码的 class 文件。编译成功不代表运行时类路径完整。

具体、有机制、有边界、可验证。模板课则把「输入/状态/输出/异常/资源释放」和「HTTP、SQL、OpenTelemetry、GitHub Actions、Docker」等不相干名词堆在一起，学生读完不知道文件权限、编码、日志到底是什么。

**违反的设计准则**（`docs/学习模式设计准则.md`）：
- 「教案正文只写学科事实、背景、机制、例子和论证。写作意图、学习流程说明、对读者的提醒不得混入正文」
- 「每个学习步骤必须能直接教学……不能只给一句摘要」

## 二、规模与约束

- 影响面：模板课约 600 课时（17 课程包），手写精品课仅 Java 主线 22+ 课时。
- 约束：不可能一轮把 600 课时全部手写；且用户明确「随便翻一两课就这样」→ 需要**用户随手翻任意课都能看到真内容**，局部修补无效。
- 原则：**宁可少而实，不要多而空**；新增内容必须逐条联网核对（沿用 v2-curated 现有 sourceRefs 约定）。

## 三、分层方案（请用户定范围）

### 方案 A：全量手写（不推荐）
600 课时 × 5 步逐课写真实正文。质量最高，但工作量极大、周期长，且本轮无法交付可验证结果。

### 方案 B：按课程包分批重写（推荐）
1. **先改通用模板生成器**：把 `generatedCourseSteps()` 的正文从「元话术」改为「具体机制描述 + 可验证动作」，至少保证每步 body 含至少一个该课领域的真实概念、一个具体命令/配置/符号、一个失败边界。
2. **按用户高频路径优先手写**：先用户截图所在的编程通识课包（P14 独立语言课程），再按 17 包使用频次排序逐批重写。
3. **去掉 `enrichReviewedSteps()` 的流程话术层**：让 objective/practice/checkpoint 也写学科内容，而不是「复述三句话」。
4. 每批改完保留该包的 sourceRefs 核对记录，补内容契约测试。

### 方案 C：降级为"大纲 + 外部权威链接"（快速止血）
承认应用内写不完，把模板正文替换为：精简的真实要点（每步 2-3 句）+ 指向官方文档/源码的直接链接，明确标注「深入阅读见来源」。见效快，但学习体验仍不如手写。

## 四、验收判据（无论选哪个方案）

1. 随机抽 10 课，每课 body 必须包含至少一个**领域专有名词的具体解释**（如"文件权限的 rwx 位分别约束读/写/执行"而非"写出这个知识点的输入"）。
2. 不得出现「写出这个知识点的…」「三行记录」「主张—依据—边界复述」等通用模板话术。
3. 内容契约测试（`v2-curated` 测试）扩展：断言模板话术从生成的 steps 中消失。
4. Web 生产构建通过。
