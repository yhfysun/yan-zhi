# 按计划步骤统计耗时 — 方案（2026-10-23，已实施）

## 背景（用户原话）
> 「这里把任务耗时加上，然后最耗时的 3 个任务也要着重标注看看下次怎么优化？」
> 「不按工具来，按照规划的任务步骤；没有规划任务就只统计总时间」
> 「所有工具接口都是服务端的」

当前实现（已提交 `068fbae`）在过程摘要行加了总耗时，Top3 按**工具调用**算（结果消息时间 − 发起消息时间）。
问题：用户要看的是**计划步骤**的耗时；而 `task_plan_json` 的 steps 只有 `{title, note, status}`，没有时间戳。

## 方案

### 1. 数据模型
`conversation.task_plan_json` 的 `steps[]` 增加：
- `startedAt`：首次进入 `running` 的毫秒时间戳（幂等，重复 running 不覆盖）
- `finishedAt`：进入 `done` / `failed` 的毫秒时间戳
- `activeMs`（P2）：返工时累计活跃时长

计划级别再增加 `startedAt` / `finishedAt`。

### 2. 写入收敛到服务端（唯一写入点）
- `apps/server/src/services/task-plan-file.ts`
  - `backendTaskPlan`：初始化步骤，不写时间戳
  - `backendTaskStep`：状态迁移时写 `startedAt` / `finishedAt` —— 唯一写入点
- `packages/ui/src/stores/chat.ts`
  - `persistPlan()` / `clearPlan()` 不再 `PATCH taskPlan`，只做本地展示，以服务端 `plan:updated`（`persisted: true`）为准
  - 「清除计划」是用户显式动作 → 新增 `DELETE /api/conversations/:id/plan`（清库字段 + 删工作目录 `plan.md`）
  - 加静态守门测试：前端源码不得再对 `taskPlan` 发 PATCH（防双写回归）

### 3. UI 展示
- `packages/ui/src/composables/chat/round-timing.ts` 增加：
  - `planStepDurations(plan)` → `[{ index, title, ms }]`
  - `slowestPlanSteps(plan, n = 3)`
- 摘要行：**总耗时恒定显示**（用户提问 → 最后一条消息）
- Top3：**仅在计划有计时时**显示，取 `finishedAt - startedAt` 最大的三步，用现有橙色胶囊，标的是**步骤名**而不是工具名
- **没有计划 → 不显示 Top3，只留总耗时**
- 步骤列表里每步尾部显示该步时长，Top3 加橙标

### 4. 边界
- 跨轮接力：单步可能横跨数小时 → 单步 >10 分钟且期间无工具调用，标注「含等待」
- 存量计划无时间戳 → 只显示总耗时，不猜
- 返工：`done` 后又 `running` → 重置 `startedAt`，累加 `activeMs`

### 5. 验收
- 带 `task_plan` 的任务：摘要行有总耗时 + Top3 计划步骤时长
- 不带计划的任务：只有总耗时
- 重启/历史数据：不报错、不显示 Top3
- 提交前：core / server / desktop 三处 typecheck + 相关单测

## 6. 实施结果（2026-10-23）

三处拍板：
- Top3 只在**最后一轮**摘要下显示（计划是会话级的，避免多轮重复同一份计划）。
- 任务结束后在摘要下提供可折叠「全部 N 个步骤」，点击任一步打开详情弹窗。
- 「含等待」只在详情弹窗内标注（判定需要按时间窗查消息，列表不做额外查询）。

落地文件：
- 服务端：`task-plan-file.ts`（计时唯一写入点）、`plan-step-detail.ts`（时间窗聚合）、
  `routes/conversations.ts`（`GET /:id/plan/steps/:index/detail`、`DELETE /:id/plan`）、
  `llm-task-manager.ts`（重规划 preserved 保留计时）。
- 前端：`round-timing.ts`（计划步骤耗时 / Top3）、`stores/chat.ts`（删除 persistPlan、clearPlan 改 DELETE）、
  `ChatMessageList.vue`（Top3 + 全部步骤）、`ChatInputArea.vue`（运行中步骤行）、`PlanStepDetailDialog.vue`。
- 守门：`no-taskplan-dual-write.test.ts`；服务端 `task-plan-timing` / `plan-step-detail` 单测。
