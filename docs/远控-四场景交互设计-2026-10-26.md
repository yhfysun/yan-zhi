# 远控 · 四场景交互设计（2026-10-26）

> 可切换原型：`docs/prototypes/remote-matrix-2026-10-26.html`
> 对标对象：UU 远程、向日葵、ToDesk、TeamViewer / AnyDesk、scrcpy（结论均带来源，见文末）

## 一、先行结论（四条硬规则）

1. **模式常显**：手机控桌面只有两种输入口径 —— 直接触控（点哪指哪）与触控板（拖动移指针、点按在指针原位左键）。切换必须在会话内一级入口，且按钮上常显当前模式名。
2. **只读不自闭**：只读必须是常驻底栏 + 一键恢复，不重连；恢复后自动回到可控。行业里静默丢输入是通病（UU 的「观看模式」是少数做对的）。
3. **双屏可选**：显示器切换只放在顶部页签 / 悬浮球循环 / 编号缩略图，**不要做手势**（会与系统手势打架）。一屏一页签（UU、TV、AnyDesk）与拼成超宽（UU 超级屏、ToDesk 全景）是两种布局，不能只做一种。
4. **点按可见**：每次注入都要有光圈反馈；被拒/只读时给**橙色被拦**反馈，而不是毫无反应。

## 二、四场景矩阵

| 场景 | 控制器 | 当前实现 | 目标口径 | 主要差距 |
|---|---|---|---|---|
| 手机 → 电脑 | 手机（`RemoteControl.vue`） | 直接触控 + 触控板 + 手势机，已有 | 默认直接触控；长按 450ms 右键；双指滚/捏合；侧栏常显模式 | 缺显式右键按钮；指针模式缺中心锚点提示 |
| 电脑 → 电脑 | 桌面窗口（同一页面） | 键鼠直通；全屏/窗口 | 快捷键本机 vs 透传分流；多屏一窗一屏 + 超宽两种布局 | **无「发送系统键」开关**；多屏只有顶部下拉 |
| 电脑 → 手机 | 桌面（`android-mirror` + scrcpy 独立窗口） | scrcpy 原生窗口，未接入远控页 | 接入统一会话页；返回/Home/任务/音量显式按钮；中文走直注入或 HID | 两套心智；中文未验证；缺保活/音频开关 |
| 手机 → 手机 | 手机 | **无链路**（android-mirror 仅 desktopOnly） | 远端独占手势；只看/可控两档权限；被控端授权提示 | 通道、权限模型、会话恢复全缺 |

## 三、落地清单

### P0（先让「能用」成立）

1. **输入配额已删除**（本次已做）：原来按 2000 条/10 分钟限流，滚轮是连续输入，几十秒烧光后整场会话静默只读。现改为「不设条数配额」，保留急停 / 危险组合键黑名单 / 本应用窗口点击保护 / 全量审计。改动：`apps/server/src/plugins/remote-control.ts`。
2. **只读/被拒要有可见状态**：任何 `input.rejected` 都进常驻状态（底栏或顶栏胶囊），并给出可恢复动作；不重连。
   - 文件：`packages/ui/src/views/RemoteControl.vue`（`input.rejected` 分支）、`packages/ui/src/components/RemoteControlHost.vue`（授权弹窗里的「仅观看」选项）。
3. **手机控桌面补「右键」显式入口**：侧栏或操作抽屉里加「右键」按钮（当前只有长按与双指轻点）。
4. **电脑控手机接入统一会话页**：`android-mirror` 的启动结果进入 `/remote` 会话视图（同一套顶栏/侧栏/显示器页签），不要在另一个窗口里另起一套。

### P1

5. **「发送系统键」开关**（电脑端）：Ctrl / Alt / Shift / Win 修饰条 + Ctrl+Alt+Del 按钮；默认本机响应，显式开启才透传。
6. **多屏两种布局**：顶部页签 + 「一窗一屏 / 超宽拼接」二选一；手机端页签在顶部右侧常驻（>1 屏）。
7. **手机控手机**：先打通「只看」链路（投屏），再上可控；被控端必须有前台提示与撤销入口。
8. **中文输入**三条路的口径落定：文本直注入（默认）/ 物理 HID 透传（开关）/ 逐键（仅 ASCII，不默认用）。

### P2

9. 文件拖拽入窗（Win↔Win），手机侧只走文件传输面板。
10. 会话恢复：断线重连后回到原操控态并提示「已恢复」。
11. 画质档位跟手（帧率/分辨率/真彩），手机端提供「跟随本机」消黑边。

## 四、待确认（阻塞「副屏没了」的定位）

副屏选择在前端是 `displays.length > 1` 才显示，数据有两条来源：

- WebRTC：被控端 Electron `screen.getAllDisplays()` → `RemoteControlHost.vue` 发 `displays`；
- JPEG：代理脚本 `op: 'monitors'` → 服务端 `assembleJpegDisplays`。

需要现场确认：进会话后点右侧「操作」抽屉，**有没有「显示器」这一行**？

- 没有 → 控制端压根没收到清单（两条枚举都失败）；
- 有但只有一项 → 枚举只返回一块屏，问题在被控端。

## 五、不要照抄

- 三指滚动当默认滚轮（与系统截屏冲突，且不可改）。
- 默认触控板却不给光标与模式提示。
- 只读态静默丢事件，用户狂点以为卡死。
- 全屏隐藏所有入口、不留悬浮球或唤出热区。
- 多屏只给纯文字下拉、无缩略图；强制拼超宽导致小屏不可读。
- 隐私屏本地解除后不锁屏、策略不持久。
- 会话录制不在被控端提示。
