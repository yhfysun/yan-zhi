# 超级剪贴板 —— 功能方案(对标鱼皮《剪切助手》)

日期:2026-10-27 ｜ 状态:待确认 ｜ 原型:[docs/prototypes/clipboard-proto.html](prototypes/clipboard-proto.html)

## 一、需求与对标

**需求**:在言智里加剪贴板能力,UI/交互参考程序员鱼皮的《剪切助手》,可用全局快捷键召唤。

**《剪切助手》的核心交互**(据其官网文章与发布视频整理):

| 能力 | 说明 |
|---|---|
| 快捷键召唤 | 正常 `Ctrl+C` 后按 `Ctrl+O` 唤起历史面板,键盘搜索并选择内容粘贴,可自定义 |
| 类型自动识别 | 链接展示标题+logo、图片/文件展示大小、文本展示字数 |
| 分组 | 常用内容归档成组,可当备忘录用 |
| 快速粘贴 | `Ctrl+数字键` 直接粘贴最近 N 条 |
| 单条快捷键 | 给高频话术单独设快捷键,一键粘贴 |
| 横/纵布局 + 深浅色 | 两种排布,主题跟随 |
| 分享 / 云同步 | 一键生成分享链接;多设备共享记录 |

**本应用现状(复用度很高的部分)**:

- `main.cjs` 已有全局热键唯一实现 `setGlobalHotkey`(截图 `Ctrl+Alt+A`、AI 急停 `Ctrl+Alt+Esc`),新增一条热键成本很低;
- Electron `clipboard`、`Tray` 已在 main 引入,托盘菜单有刷新钩子,可加「打开剪贴板」;
- 设置页已有「快捷键」分区(录制/恢复默认/冲突提示,见 `docs/快捷键管理-方案-20261017.md`),新热键直接挂进去;
- UI 设计令牌(`tokens.css`:纸墨中性骨架 + 靛蓝主色)、深浅主题、Element Plus 现成;
- 有 AI 会话与移动端/远控 —— 剪贴板天然可以和 **AI 处理**、**跨设备** 结合,这是剪切助手没有的差异化。
- 注意:`views/ClipWorkbench.vue` 是**剪辑模式**(视频剪辑),与剪贴板无关,不冲突。

## 二、形态选型(逐条列优劣)

### 方案 A:独立置顶小窗(推荐)
- **好处**:真正的全局——任何应用在前台时按热键都能召唤,选完直接粘贴回原应用,不打断工作;失焦自动隐藏;独立于主窗口生命周期,可只加载一个轻量面板路由;与剪切助手 / EcoPaste 同款形态。
- **坏处**:多一个 `BrowserWindow` 的生命周期管理;要处理多显示器定位、置顶层级与焦点归还;开发量比浮层略大。

### 方案 B:主窗口内浮层
- **好处**:实现最省,复用现有渲染层和路由,样式天然统一,无多窗口问题。
- **坏处**:热键语义残缺——用户在 Excel/钉钉里按热键,必须先拉起整个主窗口(打断当前工作,粘贴完还得切回去);主窗口在托盘后台时体验更差。与「快捷键召唤」的核心诉求不符。

### 方案 C:混合(全局键→小窗,应用内另加浮层)
- **好处**:场景全覆盖;应用内用浮层更快。
- **坏处**:两套 UI 同一逻辑,维护双份;首期成本高。

**结论**:首期做 **A**。主窗口/托盘上的「打开剪贴板」入口复用同一小窗,不做第二套 UI;若后续应用内高频使用再评估 C。

## 三、UI 设计(以原型为准)

- **面板**:432×600,圆角 14,屏幕居中,120ms fade+scale 弹出;`Esc` 或点击外部关闭;失焦自动收起。
- **结构**:品牌头(言智 logo + 标题 + 多选/横纵布局/深色/设置)→ 搜索框(打开即聚焦)→ 类型 Tabs → 列表 → 底部状态栏(条数/占用、分组、清空)。
- **条目**:序号角标(1~9 对应快速粘贴)、类型图标/缩略图、两行预览、元信息(来源应用 · 时间 · 字数/大小);置顶项排最前。
- **悬停**出快捷操作(置顶/复制/AI/更多);**右键**完整菜单(复制、粘贴为纯文本、置顶、分组、文件夹显示、删除、AI 子菜单)。
- **类型识别**:纯文本 / 富文本 / 链接(域名+标题)/ 图片(尺寸+大小)/ 文件(大小)/ 代码 / JSON / 颜色(色块)。
- **横/纵布局切换**:纵向列表(默认)与横向卡片网格,选择记忆到设置。
- **深浅色**跟随应用主题。

**快捷键表**:

| 按键 | 作用 |
|---|---|
| `Ctrl+Alt+V` | 召唤/收起面板(全局,可配可禁用) |
| `1`~`9` | 直接粘贴第 N 条 |
| `↑` `↓` | 移动选择 |
| `Enter` | 粘贴选中项 |
| `/` | 聚焦搜索 |
| `Tab` / `Shift+Tab` | 切换类型类目 |
| `Esc` | 关闭 |

> 现用 `Ctrl+Alt+A` 做截图、`Ctrl+Alt+Esc` 做 AI 急停,`Ctrl+Alt+V` 与其同族;与 Windows 自带 `Win+V` 不冲突。

### 拖动与拖出(剪切助手同款)

- **面板拖动**:按住标题栏(品牌区)拖动,双击回屏幕中央,位置记忆到设置。Electron 实现:标题区 `-webkit-app-region: drag`,按钮等控件 `no-drag`。
- **条目拖出**:文本/HTML 用 Chromium 原生拖放直接拖出窗口(Word、聊天框等);图片/文件在 main 进程走 `webContents.startDrag({ file, icon })`,拖到资源管理器/聊天软件即等于"复制文件本体"。
- **拖拽期间暂停"失焦自动收起"**——否则拖到一半面板先消失;拖出是独立通道,不改写系统剪贴板内容。
- (P2)**条目拖入分组**:面板内把条目拖到分组标签上即归档。

## 四、AI 融合(本应用差异化)

- 右键/悬停 **AI 子菜单**(已实装):翻译成英文 / 翻译成中文 / 总结要点 / 润色改写 / 解释这段代码 / 提取为表格 ——
  面板把「预设指令 + 内容」发给主窗口,复用现有聊天链路(send()),结果进入当前会话,可继续追问。
- **截图 OCR**(已实装,2026-10-29):截图工具条新增「识别文字」「识别并翻译」。
  - 识别文字:走 `/api/tools/ocr`(RapidOCR 优先、tesseract 兜底),结果在框选窗内以面板展示,可编辑/复制/翻译;
  - 识别并翻译:识别后自动判定语言,把「翻译成中文/英文」请求交给当前会话,框选窗关闭;
  - 大图先缩到 1600 宽再识别(整屏图直接丢给 OCR 要几十秒,精度几乎无差别);客户端 45s 超时 + 20s 看门狗,
    会话已结束/超时都会给出明确提示,不会停在「正在识别…」。
- **多选 → AI 合并整理 / 发送到会话**(P1 未做):勾选多条交给 AI 合成文档或表格。
- (P3)手机复制的内容出现在电脑面板里(复用移动端 + 远控通道),对标剪切助手的跨设备同步。

## 五、数据与隐私

- **采集**:main 进程轮询(600ms),文本/HTML/图片/文件分别处理;内容 hash 去重(重复复制只提到最前)。
- **存储(P0 实装口径)**:主进程自持 `userData/clipboard-history.json` + `userData/clipboard-assets/`(图片 PNG),
  配置在 `userData/clipboard-config.json`。**不依赖服务端** —— 采集在 main,后端未起也要能记;P3 跨设备同步再迁到服务端 SQLite。
  单条文本上限 100KB、富文本 256KB,缩略图用 JPEG(base64),避免 JSON 膨胀。
- **隐私**:敏感内容自动跳过(私钥、AWS AK、`sk-` 密钥、JWT,默认开启);排除应用列表(P1);历史上限默认 500 条(置顶不参与淘汰)。
- 面板写回剪贴板后有 1.5s 采集静默期,避免"粘贴旧条目"被当成新复制。

## 八、原型说明

`docs/prototypes/clipboard-proto.html`,可直接按键体验:

- `Ctrl+Alt+V` 唤起/收起(真实可按),`Esc` 关闭;
- 搜索实时过滤;类型 Tabs 切换;悬停条目出快捷操作;右键出完整菜单与 AI 子菜单;
- `1~9` 快速粘贴、`↑↓` 选择、`Enter` 粘贴、`/` 聚焦搜索、`Tab` 切类目;
- 右上角:多选(`AI 合并整理` / `发送到会话`)、横纵布局、深浅色、设置抽屉;
- 按住**标题栏**拖动面板(双击回屏幕中央);按住**条目**可拖出(浏览器内只能看到拖影,真实应用里会落到 Word/聊天框/资源管理器);
- 面板外点击关闭,模拟失焦收起;托盘图标点击也可唤起。
