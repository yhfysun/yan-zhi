## 二、目录规范（已落地）

```
<根>/.yan-zhi/tasks/<YYYY-MM-DD>-<任务名>/
  ├ uploads/        用户上传的文件、图片（source=user）
  ├ intermediate/   任务过程中生成的所有中间文件
  └ deliverables/   最终交付文件（含生图 / 生视频 / 模型声明的交付物）
```

**根的选择**：空间 `dirPath` > 全局工作目录 > 数据根（`DATA_DIR`）。

**任务名**：取 `conversation.title`，去掉 `\ / : * ? " < > |` 与控制字符，空白折叠为 `-`，首尾去 `-` 与 `.`，限长 40，空则 `未命名任务`。
**日期**：取 `conversation.created_at`（本地时区）。

**落盘归属**：

| 产出方 | 目标分类 |
|---|---|
| 用户上传（附件 / 超长粘贴 / 粘贴的图片） | `uploads` |
| `api_image_generate` / `api_video_generate` | **`deliverables`** |
| `file_write`（带 `category` 参数） | 按 `category` 映射 |
| 截图类临时文件（`computer_screenshot`） | 维持 30 分钟临时区，不入三目录 |

**单点定义**：`packages/shared/src/utils/artifact-paths.ts` —— 纯函数，前后端共用（浏览器不能依赖 `node:path`）。
服务端 `apps/server/src/services/artifact-dir.ts` 负责查 DB 拿标题/创建时间/空间目录，解析根并 `mkdir -p`。
前端经 `GET /api/conversations/:id/artifact-dir?category=…&ensure=1` 取同一个结果（桌面端用绝对路径，浏览器/移动端用相对路径），失败时按 shared 规则本地兜底。

## 三、契约与渲染（已落地）

### 3.1 媒体工具返回契约

生图：`{ok, type:'image', model, url, description, file}`
生视频：`{ok, type:'video', model, taskId, status, url, description, file}`

- 删掉 `note`（正是它诱导模型复述「本机备份 A:/B:」路径）
- `url` 优先本地可访问地址 `/api/generated/{images|videos}/<conversationId>/<文件名>`
- `description` 图片取 `revised_prompt || prompt`，视频含时长分辨率
- `file` 保留本机绝对路径，供「另存为 / 打开所在目录 / 导出 Word」使用
- 静态服务新增三段式路由；两段式保留，兼容旧 `DATA_DIR/generated-*` 文件

工具描述（`packages/core/src/tool/builtin/api-tools/media.ts`）改为：
> 工具返回 `{type, url, description}` —— 界面已按 url 自动渲染预览，正文里不要贴 JSON、不要贴本机绝对路径、不要复述「本机备份」；确实需要图文混排说明时才用 markdown `![](url)` 引用，且同一张图最多出现一次。

同时服务端系统提示词直接注入三个分类目录的绝对路径（`llm-task-manager.ts` 工作目录段之后），模型不必自己拼「日期-任务名」。

### 3.2 渲染与交互

**占位尺寸（严格受控）**

| 场景 | 占位 |
|---|---|
| 正文 md 图片（模型总结 / 用户上传） | 限高 160px，`max-width:100%`，圆角，`cursor: zoom-in` |
| 工具调用过程中的图片（生图结果） | 限高 96px + 一行文件名/操作条 |
| 截图预览（`computer_screenshot` 等） | 限高 180px，仅流式期间展示 |
| 视频 / 其他文件 | **不内联播放器**，只显示一行「文件名 + 另存为」链接 |

**统一交互**（正文图片、工具结果图片、用户上传图片、文件面板/交付卡片里的图片走同一套）

| 操作 | 行为 |
|---|---|
| 单击 | 选中（作为 Ctrl+C 的复制对象）；文件面板里单击仍是打开预览 |
| 双击 | 灯箱放大查看（滚轮缩放、Esc 关闭、点遮罩关闭） |
| 右键 | 菜单：放大查看 / 另存为… / 导出 Word / 打开所在目录 / 复制图片 / 复制路径 |
| Ctrl+C | 复制选中的图片；有文本选区或焦点在输入框时不拦截 |
| 工具结果区 | 直接给出缩略图 + 文件名 + 导出 Word / 另存为，不必展开原始 JSON |
| 文件面板 / 交付卡片 | 右键复用同一菜单（普通文件只给 另存为 / 打开目录 / 复制路径） |

**实现**：`composables/useMediaPreview.ts`（模块级单例状态，任意挂载点共用同一灯箱与菜单）、`components/media/MediaViewer.vue`、`components/media/MediaContextMenu.vue`、`components/chat/ToolMediaPreview.vue`。

### 3.3 Word 导出

用户提问「图片能下载 Word 吗、md 总结前端能直接导出 Word 吗、需要模型提供工具吗」——**不需要模型工具**，前端直接导出更可靠：

- **单张图片 / 工具结果图片** → 右键「导出 Word」或缩略图上的按钮
- **整轮任务结果（md 总结）** → 助手消息操作区的「导出 Word（含图片）」按钮，正文里的 `![](url)` 按出现顺序内嵌
- 实现：`utils/docx.ts` 用现有依赖 `jszip` 手写最小 OOXML（`[Content_Types].xml` / `_rels/.rels` / `word/document.xml` / `word/_rels/document.xml.rels` / `word/media/*`），**真 .docx**，Word / WPS 均可打开，零新增依赖
- 图片按像素尺寸等比缩放（宽度上限 16cm），尺寸由前端 `Image.naturalWidth/Height` 读取
- 产物落**交付目录**并登记到文件管理；浏览器/移动端退化为直接下载
- 系统提示词已声明「界面内置导出 Word，不必自己用 python_exec 生成」

## 五、兼容与降级

- **历史数据**：已有 `conversation_file.path` 保持原样可读，不做迁移；渲染层对新旧两种工具返回格式都兼容（先认 `type/url`，回退认 `remoteUrl/screenshotUrl/videoUrl`）。
- **旧媒体文件**：`DATA_DIR/generated-images|videos` 仍由两段式路由服务。
- **浏览器/移动端**：无系统保存框、无「打开所在目录」，降级为浏览器下载与提示；本次不做移动端长按菜单。
- **静态路由顺序**：`/api/generated/:kind/:conversationId/:name` 必须注册在两段式之前，否则 `:name` 会吞掉三段路径。
