# 移动端遗留项：API 地址无写入入口、Android 返回键未处理

- **状态**：未解决
- **严重度**：medium
- **发现日期**：2026-09-19（汇总既有记录）

> 本文件汇总移动端（Capacitor）此前发现但未修的遗留项，逐条独立可做。

## 1. `mobile_api_base` 全项目无写入入口

**现象**：移动端无法配置后端 API 地址，装到手机上就连不上自建后端。

**根因**：`packages/ui/src/api/client.ts` **读取** `mobile_api_base`，
但全项目没有任何地方**写入**它 —— 没有设置项、没有首次启动引导。

**次生问题**：`API_BASE` 是**模块级常量**，即便想办法写入了，也**必须重启 App** 才生效。

**修复方向**：补一个设置入口（写入 localStorage），并把 `API_BASE` 改为惰性读取
或在写入后主动刷新，避免要求用户手动重启。

## 2. Android 返回键未处理

**现象**：在 Android 上按返回键，行为未定义（可能直接退出应用，
而不是「返回上一页 / 关闭当前抽屉」）。

**修复方向**：引入 `@capacitor/app` 的 `backButton` 事件，按当前路由/浮层状态决定
「返回上一层」还是「退出应用」。

## 3. `apps/mobile/src/main.ts` 初始化链曾缺 catch（已修，留档备查）

**历史现象**：任一步 reject（SQLite 插件未就绪 / 原生 ABI 不匹配）
→ `app.mount` 不执行 → **纯白屏、无任何提示**。

**现状**：已补 `catch + finally` 挂载兜底。此处留档是因为该模式容易在新增初始化步骤时被打破 ——
**新增任何 `await` 初始化步骤时，必须确保最终一定会走到 `app.mount`。**

## 参考（已落地的经验，勿重复踩）

- `apps/mobile/index.html` 的 viewport **必须有 `viewport-fit=cover`**，
  否则样式里 20+ 处 `env(safe-area-inset-*)` 恒为 0，刘海屏顶栏被状态栏压、底部被手势条盖。
- 移动端样式**别只挂 `@media (max-width:767px)`**：元素已由 `v-if="isMobile"` 门控，
  再挂媒体查询是重复门控，Capacitor **横屏**（视口常 800px+）会出现「渲染了但没样式」
  → 表现为底部 TabBar / 自绘顶栏整体消失。
