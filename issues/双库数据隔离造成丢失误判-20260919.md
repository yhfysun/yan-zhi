# dev 与打包版各自读写独立数据库，数据互不可见

- **状态**：未解决（属设计现状，但会造成「数据丢了」的误判）
- **严重度**：medium
- **发现日期**：2026-09-19

## 现象

用户反馈「感觉有两套库，和之前安装运行的数据又不一样了，而且百炼平台也没了」。

## 根因

后端数据库位置由 `DATA_DIR` 环境变量决定（`apps/server/src/db.ts`：
`dataDir = DATA_DIR || <db.ts 所在目录>/..`）：

- **打包版**：`main.cjs` 的 `ensureServerDataDir()` 会注入 `DATA_DIR`
  → `%APPDATA%/yan-zhi/server-data/data.db`
- **dev 模式**：不注入，落到源码目录
  → `apps/server/data.db`

**两个文件完全独立，数据零交集。** 实测对照：

| 项 | 打包版（userData/server-data） | dev（apps/server） |
|---|---|---|
| 文件大小 | 12.98 MB | 53.90 MB |
| 会话数 | 7 | 11 |
| 平台数 | 1（仅 agnes） | 3（本地模型 / agnes / 百炼） |
| 模型数 | 12 | 270（百炼 255） |
| `conversation_file` | 0 条 | 4 条 |

会话标题逐条比对**无任何重名**，确认是两套完全不同的数据。
「百炼平台没了」= 当前打开的是打包版，而百炼只在 dev 库里。

## 影响面

- 用户会产生「我的数据/配置丢了」的错误判断，反复排查不存在的故障。
- 平台与模型配置（含 API Key）在两边独立维护，切换运行方式时要重新配。
- 排障时极易查错库 —— 本问题是**记忆里明确记过的坑**（「别查错库」），仍再次踩中。

## 复现步骤

1. 用 dev 模式（`pnpm dev`）配好百炼平台、生成产物。
2. 关掉 dev，启动打包版 exe。
3. 打包版里看不到百炼平台，会话列表也不同。

## 修复方向（需先确认产品口径）

这是**有意设计**还是**历史遗留**，需要用户拍板：

- **若有意**：在两类构建里都明确显示「当前数据目录」入口（如关于页/设置页），
  让「跑在哪套数据上」可见，消除误判。**不建议**改动数据位置。
- **若属遗留**：让 dev 模式也读 userData 的库（即 dev 也设 `DATA_DIR`），
  两者共用一套数据；代价是 dev 调试可能污染用户真实数据，需谨慎。

> 无论走哪条，至少要有一个「当前数据目录」的可见入口 ——
> 这是本问题真正的痛点是「不可见」，而不是「有两套」。

## 相关

- 排障时先确认在哪台机器、哪种运行方式（dev / 打包），再动手查库。
- 本机数据库清单（2026-09-19 实测）：
  - `%APPDATA%/yan-zhi/server-data/data.db` ← 打包版
  - `%APPDATA%/yan-zhi/data.db`（0.37MB，历史遗留，疑似已废弃）
  - `apps/server/data.db` ← dev
  - `%APPDATA%/yan-zhi/yan-zhi.db` ← Electron IPC 库（`main.cjs` 使用，后端碰不到）
  - `tmp/*/data.db` 多个 ← 测试冒烟产物，可清理
