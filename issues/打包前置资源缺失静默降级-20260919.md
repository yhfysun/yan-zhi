### 改了什么

1. **`apps/desktop/scripts/build-all-editions.cjs:preflight()`** —— 从"只警告"改为**缺失即自动生成**：
   - `resources/python` / `resources/python-tools` 任一缺失 → **调用 `scripts/build-python-runtime.mjs`**；
   - 生成失败**中断构建**（不再打出"看着成功、实则缺能力"的包 —— 这正是本 issue 的原始病灶）；
   - 确需跳过（离线 / 自带系统 Python）→ `YZ_SKIP_PYTHON_RUNTIME=1`，且打印**显式声明**横幅
     （降级从"静默"变"显式"）。
2. **`scripts/package.cjs:preflight()`** —— 同样在桌面目标下检查并提示（缺失时告知会**自动生成**）。
3. **`scripts/build-python-runtime.mjs`** 三个真问题（"自动生成"落地时暴露）：
   - ★ **GitHub 在受限网络不可达**（`UND_ERR_CONNECT_TIMEOUT`）→ 默认改 **npmmirror 镜像优先**
     （`registry.npmmirror.com/-/binary/python-build-standalone/...`，实测 39MB 秒开），GitHub 作兜底；
     文件名里的 `+` 编码为 `%2B`（否则静态服务器当空格 → 404）。
   - ★ **下载必须流式落盘**：本机沙箱下 `arrayBuffer()` 对 40MB+ 大文件会超时中断，逐块读 + 写流稳定。
   - ★ **tar 不能用带冒号的绝对路径 / `-C`**：git-bash 的 GNU tar 把 `C:\x.tar.gz` 当远程归档
     （`Cannot connect to C: resolve failed`）→ 改为「切 cwd + 只用归档基名」。
   - 顺带：清理临时目录改为**非致命**（沙箱/杀软拦截删除时不再让整个生成返回非零）；
     `--force` 完整路径也写依赖指纹（此前只在快速路径写，导致下次误判"依赖变化"白跑 pip）。
4. **`prepare-server-runtime` / electron-builder 无需改** —— `extraResources` 配置本就正确，
   此前只是"源目录不存在"。

## 原始记录（保留以溯因）

## 现象

执行三档打包时，日志出现两行警告但**构建照常成功**：

```
• file source doesn't exist  from=apps/desktop/resources/python
• file source doesn't exist  from=apps/desktop/resources/python-tools
```

打出的包里没有内置 Python 运行时。

## 根因

`apps/desktop/resources/` 目录是**空的**。该目录本应在构建前由
`scripts/build-python-runtime.mjs` 生成（下载 python-build-standalone 并预烤依赖），
但打包链路里**没有调用它**，`electron-builder` 对 `extraResources` 里缺失的源目录
只打警告、不失败。

## 影响面

- 成品缺少内置 Python 运行时 → `python_*` 类工具回退到系统 python
  （用户机器上没装 python 就直接不可用）。
- 随包 Python 脚本（doyz / security / pdf_preview）缺失 → 相关功能失效。
- **静默降级**：构建不报错，问题要到用户使用时才暴露，属最难查的一类。

## 复现步骤

1. 删除 `apps/desktop/resources/python` 与 `python-tools`（或全新 clone，本就不存在）。
2. 执行 `pnpm build:desktop:all` 或 `pnpm --filter @yan-zhi/desktop electron:build:basic`。
3. 构建成功、无错误；检查产物 `win-unpacked/resources/` → 无 `python/` 目录。

## 当前缓解

`apps/desktop/scripts/build-all-editions.cjs` 已加**前置检查**（`preflight()`）：
这两个目录缺失时会打印醒目警告块并提示生成命令，但**仍不阻断构建**
（有意为之：日常出包不应因可选资源缺失而卡住）。

## 修复方向（需用户拍板）

- **选项 1（推荐）**：把 `build-python-runtime.mjs` 接进打包前置链，
  在 `preflight` 检测到缺失时**自动生成**（首次约需下载数十 MB）。
- **选项 2**：把「是否内置 Python 运行时」做成显式构建开关，
  默认不内置但**必须在构建日志里明确声明**「本次不含 Python 运行时」，
  让降级从「静默」变为「显式」。
- **选项 3**：维持现状，但把 `preflight` 的警告升级为**构建结束时的总结提示**，
  确保它不会被日志淹没。

> 无论选哪个，核心诉求是：**让「成品少了能力」这件事不再静默**。
