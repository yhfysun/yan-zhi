**方向理解错了**。本轮四项：

### ⑦ 打包后的应用图标不对（Android 工程从未换过 logo）

**现象**：APK 装出来是**蓝色大脑电路板 + 青绿底**，而言智 logo 是「言」字书法 + 米白底。

**根因**：项目里**从来没有**任何图标生成脚本。`apps/mobile/android/.../res/mipmap-*` 一直是：
- 位图：**09-05** 用旧的蓝色脑图生成过一次；而言智 logo 是 **09-13** 才放进 `assets/icons/` →
  **之后再没重新生成**；
- `mipmap-anydpi-v26` 的 adaptive 描述 + `drawable*/ic_launcher_*.xml`
  还是 **2025-03-31** 的 Capacitor 脚手架默认（青绿 `#26A69A` + 默认 vector）。

**修复**：新增 `apps/mobile/scripts/gen-android-icons.cjs`（用已在依赖树里的 `sharp`，
官方 `@capacitor/assets` 不在本仓且离线装不上），按 Android 官方密度表生成：
- legacy 位图 `ic_launcher.png` / `ic_launcher_round.png`：48/72/96/144/192（round 用圆形遮罩）
- adaptive 前景 `ic_launcher_foreground.png`：108/162/216/324/432，
  内容缩到 **60%** 居中（Android 只保证中间 66/108≈61% 不被裁切，留余量防书法笔画尖角被切）
- 背景改品牌米白 `#F5F2EC`；adaptive 描述加 `monochrome`（Android 13+ 主题图标）
- ★ **删掉**脚手架默认的 `drawable/ic_launcher_background.xml`（青绿 vector）与
  `drawable-v24/ic_launcher_foreground.xml`（默认 vector）—— 留着会在某些密度/API 组合下被优先解析
- 接入 `build:android`（**必须在 `vite build` 之前**）

### ⑧ 模型下拉点击弹两个窗

**根因**：移动端模型钮与桌面端模型胶囊是**两个独立的 `el-popover`，却共用同一个
`modelPopOpen`**。窄屏只用 CSS `display:none` 隐藏了桌面胶囊的**触发器**，
但 **el-popover 的内容是 `Teleport` 到 body 的，不受父容器隐藏影响** →
点一次移动端按钮，两个弹层同时打开。

**修复**：① 移动端用独立的 `mobileModelPopOpen`；② 两个入口 `v-if` 严格互斥
（`.toolbar-mobile-selects` 加 `v-if="isMobileShell"`，桌面胶囊加 `v-if="!isMobileShell"`）；
③ 收尾 watch 同时盯两个开关。

### ⑨ 长按没有实现

**根因**：`composables/useLongPress.ts` **从未被任何组件引用**（简版实现，只有 touchstart），
而真正需要它的地方（会话列表、空间节点、文件树、消息气泡）**全都只绑 `@contextmenu`（右键）**。
移动端没有右键 → 界面上写着「右键会话进入批量」，用户**怎么按都出不来**。

**修复**：重写 `useLongPress`（Pointer Events，`pointerType === 'touch'` 才生效，
按住 500ms 触发，触发后**吞掉紧随的一次 click** 防误点，移动超容差即取消）；
接到会话项（2 处）、空间节点、会话树背景；提示文案按触屏/鼠标分流
（`长按会话进入批量` / `右键会话进入批量`）。

### ⑩ 数据初始化不行，要点进模型平台/智能体平台才有数据（**blocker 级**）

**现象**（用户原话）：首屏数据空，必须手动进「模型平台」「智能体平台」才有。

**根因链**（CDP 实测 console 原文）：
```
真机顺序 = WebView 先加载前端 → 内嵌 Node 后端后启动
  → 首个 fetch 打在还没监听的端口 → ERR_CONNECTION_REFUSED
  → apiFetch 的 fetch **没有 catch** → 抛 TypeError: Failed to fetch
  → licenseStore.init() 挂掉 → 路由守卫抛错
  → [Vue Router] Unexpected error when starting the router
  → .chat-page **从未挂载** → useChat.onMounted() 根本没执行
  → 平台/模型/智能体/技能**全空**
```
即使绕过崩溃，还有**极不对称的半初始化**：`loadAgents`（排第一、**无重试**）永久失败 →
`agents` 静默变 `[]`；而 `loadPlatforms`（有 `getWithRetry`，重试 ~10.5s）在重试窗口里
恰逢后端起来 → 成功。于是"平台有、智能体没有"。

**修复（四层，缺一不可）**：
1. **`apiFetch` 把网络层错误转成 `ApiError{status:0}` 返回**（不再抛）—— 这是根，
   `ApiError` 的设计契约本就是"失败是返回值，不是异常"；
2. 新增 `api/backend-ready.ts` 的 `waitForBackend()`：探测**免授权**接口
   （`/license/default`，避免被门禁 401 误判成"后端没起"），拿到任何 HTTP 响应即就绪，
   幂等记忆（就绪后立即返回，零额外延迟）；
3. **授权校验（路由守卫第一道）先等后端就绪** —— 一次等待、全局受益
   （它过了才挂载页面、才跑各 store 的 onMounted）；
4. `useChat.onMounted` / `Models` / `Agents` 的 onMounted 也各加一道 `waitForBackend`；
   `getWithRetry` 显式把 `status === 0` 当作可重试。

**验收**：后端延迟启动场景下，**+13s 时已完全自愈**：
`platform 1 / models 12 / agent 20 / skill 43 / hasChatPage:true`（修复前全 0、页不挂载），
**不再需要进那两个页面**。

### ⑪ 不应该默认登录 guest 账号

**根因**：`stores/auth.ts` 的 `isLoggedIn = !!user`，而 `loadUser()` 在桌面端无 token 时会主动
`POST /auth/guest` 拿 token 并把 user 填成 guest → 侧栏/顶栏渲染出「g + **绿点（登录指示）** +
guest」+「退出登录」，用户看到的就是"默认帮我登录了一个 guest 账号"。

★ 但 **guest 本身不能删**：`apps/server/src/auth.ts` 的 `authMiddleware` **恒定**把请求身份置为
`{userId:'guest', username:'guest'}`（全库 seed 数据 `user_id` 都是 `'guest'`，
恢复到多用户鉴权才需改回"有 token 用其身份"）。guest 是**内部数据归属身份**。

**修复**：把"身份"与"登录态"拆开 —— 新增 `isGuestIdentity()`（认 `username==='guest'`
与 `id==='guest'` 两种来源），`isLoggedIn = !!user && !isGuestIdentity(user)`，
并导出 `isGuest` 供 UI 显示"未登录（本地模式）"；侧栏未登录分支改为**所有端都显示**
（桌面端此前因 `isElectron` 什么都不显示，于是 guest 分支成了唯一可见的身份区）。

**验收**：`auth store {isLoggedIn:false, isGuest:false}`、`loginDot` 不显示、
页面文本无 "guest"、无退出登录下拉。

## ① 【blocker，最高优先级】Chat 页整页崩溃 —— `watch(..., { immediate: true })` 的 TDZ

**这是用户说「UI 还错乱了」的直接原因，也是上一轮改动引入的回归。**

### 现象

对话页**只剩底部 TabBar + 一句智能体名**（`bodyLen: 19`），对话区/顶栏/输入框全部不渲染：

```js
{ hasApp: true, hasChatPage: false, hasTopbar: false, bodyLen: 19,
  bodyHead: "任务 模型 智能体 我的 日常办公助手" }
```

控制台（Vue Router 会把它包成路由错误，容易漏看）：

```
WARNING [Vue Router warn]: uncaught error during route navigation:
ERROR ReferenceError: Cannot access 'stop' before initialization
   at watch.immediate (…/composables/chat/useChat.ts:1299:11)
```

### 根因

上一轮新增的 `ensureModelWhenReady()`（`useChat.ts`）里：

```js
const stop = watch(refs, async () => { … stop(); … }, { immediate: true });
```

`immediate: true` 的回调是**同步执行**的（在 `watch()` 返回之前就跑完），
而回调体里引用了 `const stop` —— 此刻 `stop` 仍在 **TDZ**（未初始化）→ 抛 `ReferenceError`。
该错误发生在 `onMounted` 的 `await` 恢复之后 → 冒泡为未捕获异常 → **整页挂载失败**。

★ 同源坑见本项目 skill 的「坑 3：`watch(..., { immediate: true })` 的 TDZ」——
**任何"回调里要引用 watch 自身句柄"的写法都必须避开 TDZ**。

### 修复

1. **不要有 `const x = watch(...)` + 回调里调 `x()`**。改用外层可变槽位 + 判真调用：
   ```js
   let unwatch: (() => void) | null = null;
   const stopWatch = () => { if (unwatch) { unwatch(); unwatch = null; } };
   unwatch = watch(…, { immediate: true });   // 回调里只调 stopWatch()，不碰 unwatch 本身
   ```
2. 顺带加**早退**：数据已就绪（`modelsLoaded`）时直接补选一次，**根本不挂 watch** ——
   既省一个监听，也让"正常路径"完全不经过 immediate 分支。

### 附带教训（诊断方法论）

★ 页面**怪异地只剩外壳**时要**先抓控制台异常**，别先怀疑样式/CSS。
本次我一开始以为 `context-sidebar` 的横屏样式没生效，连续两轮探针都在查 CSS；
`hasChatPage: false` 这个信号出现后才转去抓异常，一次命中。

1. `const showFeatureNav = ref(isMobile.value)` —— **移动端一进来就整屏展开**（覆盖率 73%），
   把首页主体全盖住 → 用户感知为「首页一进去就是错乱的」；
2. `max-height: calc(100vh - 96px)` **完全没考虑 TabBar**。

### 修复

- `showFeatureNav` 改为恒 `false`（移动端没有理由默认展开，与桌面端一致）；
- 面板高度改为 `calc(100% - 72px - 12px)` ——
  **基于 `.home-page` 容器百分比**而不是视口：`.home-page` 是 `flex:1`、
  其底边**已经**等于 TabBar 顶边（外壳在 `.main-content` 上给了 `padding-bottom`），
  所以与平台/横竖屏无关，也不会"改一处漏一处"；
- 补 `.platform-mobile` 分支（横屏视口 800px+ 不命中媒体查询）。

验收：`bottom 776 < tabTop 788`（不再重叠）、`elementAtPanelBottom = feature-nav-item-info`
（面板底部最上层是面板自己，不是 TabBar）。

### ★★ 变异测试抓出我自己 4 处「摆设断言」（全部已修）

1. `tabBarIcons()` 用 `indexOf('mobilePrimaryItems')` **先命中模板里的 `v-for`**（不是 `const` 声明）
   → 截出来全是模板文本、`icon:` 匹配 0 个 → 断言假红。改为锚定 `const mobilePrimaryItems`。
2. 断言「不得含 `hoverSub === 'agents'`」**被我自己的注释绊倒**（删除处留了说明性注释含该字样）

★ 结论：**不写变异测试的守门断言不能算有效**。本次 4/4 都是变异测试才暴露的。

## APK 打包链路（本轮实跑记录，2026-09-22）

```bash
# ① 前端
cd apps/mobile && node node_modules/vite/bin/vite.js build          # 23.3s
# ② 内嵌后端（含 monorepo 打包 + workspace stub + npm install）

# ③ 同步 Android 工程
node node_modules/@capacitor/cli/bin/capacitor sync android         # 2.2s

#    PowerShell: $env:JAVA_HOME='C:\APP\Java\jdk-21.0.12.1+1'
#                $env:ANDROID_HOME='C:\Android\Sdk'
#                Set-Location 'C:\yz\apps\mobile\android'
#                .\gradlew.bat assembleDebug --no-daemon            # BUILD SUCCESSFUL in 21s
# ⑤ 拷贝产物
node scripts/copy-apk.cjs                                           # → dist-release/app-debug.apk
```

★★ **junction 必须在 PowerShell 下用**：`C:\yz` → 项目根。
git-bash 的 `cd` 会**解析回真实路径** → CMake 对象路径又变 270 > 250
（`CMAKE_OBJECT_PATH_MAX`），报错一字不差、极易误判成代码问题。
判据用 `$PWD.Path`（.NET `GetCurrentDirectory()` 仍返回真实路径，不可信）。

★ `copy-apk.cjs` 会**递归扫** `android/app/build/outputs/apk/` 下所有 `.apk` 并平铺拷到 `dist-release/`，
警告 `Promise.all` 里 swc/tsc 的 `Failed to minify` 是噪声（不影响产物）。
