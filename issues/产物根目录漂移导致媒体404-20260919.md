# 产物根目录随工作目录漂移，导致历史媒体产物 404

- **状态**：未解决
- **严重度**：high
- **发现日期**：2026-09-19
- **影响版本**：dev 与打包版均存在

## 现象

会话里此前生成的图片，过一段时间再打开会出现：

1. 图片预览提示「找不到此图，请重新生成」（且提示越来越卡）；
2. 文件管理弹窗的「已交付」段落为空；
3. 用户被迫反复重新生成，旧图成为磁盘孤儿。

## 根因

产物根目录由三级回落决定（`apps/server/src/services/artifact-dir.ts:99`）：

```
产物根 = 会话所属空间的 dirPath  >  serverState.workspaceDir（全局工作目录）  >  DATA_DIR（数据根）
```

**这个根是「读取时重新计算的」，而不是「落盘时固化的」。**
工作目录一旦变化，同一个会话的产物根就跟着变，读取侧（静态媒体路由
`apps/server/src/index.ts:191`）按**当前**根去解析，自然找不到文件。

实测证据（dev 库 `conversation_file` 表，4 条 `category=deliverable` 记录）：

| 会话 | DB 登记 path | 落盘实际位置 | 状态 |
|---|---|---|---|
| `cc65f6ad-…` | 绝对路径 | `<仓库根>/.yan-zhi/tasks/cc65f6ad-…/deliverables/` | 文件存在 |
| `4f79228e-…` | **相对路径** `.yan-zhi\tasks\…` | `apps/server/.yan-zhi/tasks/4f79228e-…/deliverables/` | 文件存在 |
| `ed2a49af-…` | 绝对路径 | `apps/server/.yan-zhi/tasks/ed2a49af-…/deliverables/` | 文件存在 ×2 |

**关键点：图片一张都没丢，文件全部真实存在于磁盘。** 但同一份数据库里出现了两个产物根
（`<仓库根>/.yan-zhi` 与 `apps/server/.yan-zhi`），且有一条登记的是相对路径 ——
读取侧按当前根解析时指向了空目录。

`artifact-dir.ts` 的注释其实预警过这个形态：
「落盘成功但预览窗/另存为报 readFileBase64 不存在」。

### 为什么目前查不出「哪个根」是当前根

静态路由 `index.ts:191` 的候选目录**只在 `info.root` 内部**生成：

```ts
const info = resolveArtifactDirFor({ conversationId, category });
const candidates = buildArtifactRelDirCandidates({ conversationId, title: info.title, category, ... });
const file = findArtifactFileInDirs(candidates, info.root, name);  // ← 根只有一个
```

已有「旧日期-标题目录」回退，但**没有跨根回退**。

## 影响面

- 所有经 `mediaTarget()` 落盘的媒体产物：图片 / 视频 / 音频 / 文件
  （`apps/server/src/mcp/api-tool-executor.ts:407`）。
- 触发条件：用户切换过工作目录，或会话从「未绑定空间」变为「绑定空间的 dirPath」。
- 历史图片全部受影响，且用户侧表现为「数据丢了」，实际是路径错位。

## 复现步骤

1. 在工作目录 A 下某会话生成一张图片 → 落到 `<A>/.yan-zhi/tasks/<convId>/deliverables/`。
2. 把全局工作目录改成 B（或给该会话绑定一个带 dirPath 的空间）。
3. 重新打开该会话，查看那张图片 → 预览 404，文件管理「已交付」为空。
4. 检查磁盘：文件仍在 `<A>/…` 下，完好无损。

## 修复方向

**方向 A（最小改动，先救回已有文件）**
静态路由在 `info.root` 未命中时，追加探测其它候选根（`DATA_DIR`、仓库根、
`serverState.workspaceDir`）。改动小、可立即救回现存产物，但**不阻止以后继续漂移**。

**方向 B（治本）**
让「落盘时记录的根」成为权威：`conversation_file.path` 一律存**绝对路径**并在读取时优先信任它
（相对路径的历史记录做一次性回填）。工作目录只影响**新写入**落点，读取永远按登记路径解析。

> 建议 A + B 一起做：A 立刻恢复可用性，B 根治漂移。
> 另需一次性迁移脚本，把已有相对路径登记补成绝对路径。
