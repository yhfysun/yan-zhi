## 1. `electron:build` / `:full` / `:basic` 三条命令完全相同

**现状**（`apps/desktop/package.json:13-17`）：三条脚本逐字相同，
都执行 `set-edition.cjs basic` + `electron-builder.full.yml`。

```
electron:build       → set-edition basic + full.yml
electron:build:full  → set-edition basic + full.yml   ← 与上面完全一致
electron:build:basic → set-edition basic + full.yml   ← 与前两条完全一致
```

**问题**：`full` 这个名字暗示「完整版/全量版」，实际打的是 **basic 档**，
容易误导（本次排障时用户与我都一度以为 `desktop:full` 是三档之一）。

**影响**：仅命名与认知负担，功能无缺陷（当前只有三档，`full` 属历史遗留命名）。

**修复方向**（任选）：
- 把 `electron:build:full` 标记为 deprecated 并在脚本里打印提示；
- 或直接删除该别名，只保留 `:lite` / `:basic` / `:pro` / `:all`。

## 2. 三档包体积完全相同（各约 191MB），未按档裁剪

**现状**：lite / basic / pro 三个包里，**代码与资源完全相同**，
唯一差异是打进 `app.asar` 内部的那份 `edition.json`。

**根因**：档位差异是**运行期**通过 `edition.json`（构建档 + 预置码档）
→ `main.cjs` 注入 `YZ_EDITION` / `YZ_DEFAULT_EDITION` → 后端算 `allowedModes` 实现的。
本轮**不做**按档裁剪资源。

**影响**：阉割版（lite）的包与高级版（pro）一样大，分发体积上无收益。
若产品上需要「轻量包」，这是必须补的一环。

**修复方向**：若确需按档裁剪，需要在 `electron-builder` 的 `files:` / `extraResources`
里按档位条件排除资源（如插件、工作流引擎、部分内置 skill），
并把 `edition.json` 的写入时机与裁剪规则对齐。

> ⚠️ 做裁剪前务必确认：**档位是编译期固化的**（`edition.json` 打进 asar），
> 因此裁剪后**三档仍必须逐档重编**，不存在「编一次裁三次」的省事路径。

## 3. `bin/build.sh` 在本机 Git Bash 下不可用（环境问题，非脚本缺陷）

**现象**：直接执行 `bash bin/build.sh` 时，`pnpm` 报
`sed: command not found` / `dirname: command not found` 等错误。

**根因**：本机 Git Bash 的 shim 环境不完整（coreutils 大面积失效），
导致 `C:\Program Files\nodejs\pnpm`（启动脚本依赖 `sed`/`dirname`）无法运行。

**现状**：**CMD / PowerShell 下 pnpm 正常**（`pnpm --version` 返回 9.12.0），
因此 `.bat` 路线不受影响。**Windows 用户请用 `bin\build.bat`。**

**备注**：这是本机环境特性，不需要改脚本；但在 `bin/README.md`
里已注明「Windows 优先使用 .bat」，符合现状。
