# 会议纪要（meeting-notes）

从会议录音转写、聊天记录或零散文字，整理成结构化会议纪要。提取议题、讨论要点、决议、待办（负责人+截止时间）、遗留问题。

## 何时触发

- 用户说"整理会议纪要""总结会议""从录音整理纪要""提取待办""会议总结"等
- 用户贴了一段会议转写/聊天记录，要整理
- 用户要会后发纪要

## 标准流程

1. **获取素材**：录音转写文本 / 聊天记录 / 手写要点
2. **识别要素**：议题、讨论、决议、待办、遗留
3. **结构化**：按模板组织
4. **核对待办**：每条待办要有负责人 + 截止时间（缺则标"待定"并提醒补全）
5. **输出**：纪要正文 + 待办清单（可单独贴出便于跟踪）

## 纪要模板

```markdown
# 会议纪要：XX 评审会

- 时间：2026-08-30 14:00-15:30
- 地点：XX 会议室 / 线上
- 主持：张三
- 参会：张三、李四、王五、赵六
- 记录：AI

## 议题与讨论

### 议题 1：XX 方案选型
- 李四：方案 A 成本低但扩展性差
- 王五：方案 B 长期更优
- 讨论：...

### 议题 2：XX 排期
- ...

## 决议
1. 采用方案 B（王五负责细化，9/2 前出方案）
2. XX 模块 9/10 前上线

## 待办
| # | 事项 | 负责人 | 截止 | 状态 |
|---|------|--------|------|------|
| 1 | 细化方案 B 设计 | 王五 | 9/2 | 待办 |
| 2 | XX 接口联调 | 李四 | 9/5 | 待办 |
| 3 | 测试用例补全 | 赵六 | 9/8 | 待办 |

## 遗留问题
- 方案 B 的 XX 依赖是否就绪？（李四跟进）
- 外部接口配额需申请（张三跟进）
```

## 待办提取要点

- 每条待办提炼成动宾短语（"细化方案 B 设计"而非"方案 B"）
- 负责人用具体人名，"大家""相关同学"要落到个人
- 截止时间写绝对日期（9/2）而非"下周"
- 无法从素材确定负责人/时间时，标"待定"并在纪要末尾提醒会上补全

## 从录音转写

若给的是录音文件，先用转写：
```bash
# whisper（本地）
whisper meeting.mp3 --language zh --output_format txt
# 或调用转写 API
```
拿到文本后再按上述流程整理。

## 从聊天记录整理

- 按时间顺序读，识别"议题切换"信号（"下一个""接着讨论"）
- 提取带动作词的消息（"我来""你负责""9/5 前完成"）作为待办候选
- 提取"一致同意""就这么定"作为决议

## 注意事项

- 纪要客观记录，不夹带整理者主观
- 讨论部分只记要点和分歧，不必逐字
- 决议要明确无歧义，有争议的标注"多数同意/暂定"
- 待办是纪要的核心价值，务必可执行、可跟踪
- 会后尽快发出（24h 内），避免遗忘
- 敏感信息（价格/人事）按需脱敏再分发
- 可把待办同步到任务系统（Jira/飞书任务）便于跟踪
