## 1. 发布页结构（待实抓，对照抖音）
```
上传页关键锚点（文本/placeholder 匹配，待实抓校准）
├─ 上传入口：拖拽区 / button 上传
│   → browser_upload（filechooser 模式：clickSelector 点上传按钮自动投递本地文件）
├─ 标题/文案编辑器：div[contenteditable=true]（placeholder「填写作品标题…」）
│   → 受控 contenteditable：focus 后 document.execCommand('insertText', false, 文案)（同抖音，走真键盘）
├─ 「发布」按钮：底部主提交
│   → 疑似被悬浮层/转码遮罩遮挡 → 已由通用 click 处理（e4247a6）
├─ 合集入口：有权限才显示（快手合集开通条件与抖音不同，待实抓四层排查）
└─ 发布成功判据：轮询「发布成功 / 审核中」文案 + 作品管理列表出现新视频
    ★★ 严禁再次 navigate 回上传页（会重置流程、清空已填标题——抖音已踩过）
```

## 3. 实抓清单（拿到登录会话后执行）
```
browser_action { action:'get_dom', maxNodes:3000, depth:25 }   ← 上传页整页（搜「发布」「合集」「标题」文本）
browser_action { action:'get_dom', maxNodes:1500, depth:15,
                 selector:'[contenteditable]' }                ← 标题编辑器
```
- 记录「发布」按钮的文本 / placeholder / aria-label（用于 `:contains` 或 index 定位）
- 记录审核态文案（发布成功 / 审核中 / 驳回原因）——填进 §1 成功判据
- 记录合集入口的有无 + 点击后的开通条件弹层（二级实名？绑定手机？申请？）
- 类名无语义 + 改版频繁 → **每次发布前先实抓一次**，用「文本/placeholder」定位；点不动时 x/y 兜底（仅最后手段）
