## Context

见 `proposal.md` 的动机与 `specs/` 的行为契约。

当前实现有三条独立链路：

- `computer-use` 插件注册 24 个工具，截图和 UI Automation 通过临时 PowerShell 执行，输入动作也逐次启动 PowerShell。
- `remote-control` 已有常驻 C# 输入代理，通过 UTF-8 JSON 行接收点击、移动、滚轮、按键和 Unicode 文本，并内置自窗口点击拦截。
- Electron 主进程已有透明 overlay 窗口、全局急停、截图与插件 IPC 基础；远程 AI 后端则通过 `desktop-capability` WebSocket 把调用送回本机壳。

这条升级必须在保留现有工具和护栏的同时，把三条链路连成一个可观察、可审批、可接管的控制会话。

## Goals / Non-Goals

**Goals:**

- 用单会话协调器统一窗口绑定、观察版本、单动作执行、回执和刷新。
- 复用常驻 C# 输入通道，消除每个输入动作启动 PowerShell 的延迟。
- 在本机壳显示目标窗口蒙版、AI 操作状态、自定义光标或光标反馈和取消入口。
- 让应用授权、风险动作确认、用户接管、急停和审计共享同一会话状态。
- 旧 `computer_*` 工具继续工作，新会话接口可逐步替代内部执行路径。
- 兼容“完整桌面包本地后端”和“轻量壳连接远程后端”两种部署。

**Non-Goals:**

- 不直接引入、复制或再分发 Codex 私有的 `@oai/sky` 包。
- 不把 Browser Use/pageAgent 的浏览器动作并入桌面控制会话。
- 不实现 macOS 辅助功能控制、云端桌面、无人值守登录或锁屏绕过。
- 不提供持续屏幕录像，也不默认保存任务截图。

## Decisions

### 1. 会话协调器拥有唯一可写状态

新增一个平台无关的控制会话协调器，状态机为：

`idle -> starting -> observing -> acting -> blocked | handoff -> observing -> ended`

协调器负责：

- 会话标识、设备、目标窗口、观察版本和过期判定。
- 单动作串行化；同一会话不允许并发输入。
- 应用授权、风险确认、暂停/接管、急停和审计事件。
- 回合结束、空闲超时、执行端掉线和窗口关闭时的清理。

底层工具只能通过协调器执行新路径，不能绕开会话直接注入输入。

替代方案：继续让每个工具直接执行 PowerShell。实现量最小，但无法可靠共享观察版本、审批和接管状态，因此不采用。

### 2. 输入复用常驻 C# 代理，先做适配层再考虑抽公共模块

先把现有 `RemoteControlAgent` 包装成电脑控制专用的输入适配器，复用 `click/move/wheel/key/type` 协议、自窗口拦截和 JSON stdin 通信。电脑控制和远程控制保持各自会话与授权，不共享远程会话令牌。

适配层稳定后，再评估把“代理进程启动、流解析、回执”抽成公共传输层；第一阶段不直接大改远控插件，避免把升级风险扩散到已验证的远控链路。

替代方案：

- 保留逐动作 PowerShell：时延和进程噪音不可接受。
- 引入 nut-js 等原生模块：打包 ABI 风险高。
- 直接依赖 `@oai/sky`：闭源且不可公开安装，不能作为项目依赖。

### 3. 观察以“窗口快照 + 可选辅助功能树”返回

观察服务提供统一结果：

- 观察版本、窗口对象、目标应用。
- 一张或多张有界截图及截图标识。
- 可选 UI Automation 树、元素引用、焦点、选中文本和文档文本。
- 显示器、DPI、窗口矩形和捕获方式。

第一阶段输入走常驻代理；截图和 UIA 先复用现有实现并统一结果格式。第二阶段把窗口捕获迁到常驻本机服务，优先使用 Windows.Graphics.Capture，必要时回退 `PrintWindow`，并在不支持时明确标记为屏幕区域捕获。这样会话协议先稳定，截图性能可以独立迭代。

替代方案：一次性把所有 UIA 和截图能力重写进 C# 服务。最终性能更好，但首期同时改动协议、原生捕获和 UI，无法快速验证主要体验。

### 4. 动作使用“窗口相对坐标 + 观察标识”

会话接受窗口相对坐标、元素索引、截图标识和 UIA 引用，但执行前统一做三项校验：

- 引用属于当前会话和当前观察。
- 目标窗口仍存在，且坐标命中目标窗口而非其他窗口。
- 动作风险状态满足授权和确认要求。

每个动作返回 `ok`、`failed` 或 `unknown`。`unknown` 不允许自动重试，必须先重新观察。

### 5. 可见状态由两层 Electron overlay 实现

使用两个职责分离的窗口：

- 全屏视觉层：透明、无焦点、点击穿透，显示目标窗口外蒙版、边框、AI 光标/点击反馈和操作状态。
- 交互控制条：固定尺寸、可拖动或贴边，提供暂停、接管、取消和预览开关。

全屏视觉层通过 `focusable: false`、always-on-top 和 `setIgnoreMouseEvents(true, { forward: true })` 避免抢焦点。交互控制条只占用自身热区，不能覆盖目标应用的重要操作区域。

目标窗口矩形变化时，由主进程订阅窗口位置/尺寸或短周期轻量轮询更新蒙版。AI 光标位置由输入通道动作路径广播给 overlay，不通过读取物理鼠标位置猜测。

替代方案：在所有页面注入 DOM 蒙版。它无法覆盖任意原生 Windows 应用，因此不采用。

控制层生命周期必须由主进程唯一负责，不能让渲染层自己决定是否消失：

- 主进程维护 `{sessionId, generation, expiresAt}` 会话租约，只有当前 generation 可以创建或更新 overlay。
- 会话心跳更新 `expiresAt`；看门狗在租约过期时先冻结输入，再销毁视觉层和控制条。
- 正常结束、取消、急停、插件禁用、后端 WebSocket 断开、输入代理退出、应用退出都调用同一个 `teardownSession(reason)`。
- 监听 overlay 的 `closed`、`render-process-gone`、`webContents` 销毁和加载失败；终态下只清理，不自动重建。
- 应用启动时扫描上一次异常退出可能遗留的受管 overlay 标识并清除。
- 清理必须同时执行 `hide`，再以 `destroy` 兜底，不依赖页面脚本执行成功。

这直接规避参考实现中“电脑控制已经结束，但黄色框仍留在桌面”的孤儿层问题。

### 6. 授权、确认与风险分类共享一份策略

应用授权按设备保存，结构至少包含应用标识、显示名、允许状态、更新时间和来源。未记住的应用首次访问时暂停并弹确认。

动作调用必须声明影响类型：

- `read`
- `local_write`
- `external_send`
- `destructive`
- `financial`
- `security_or_auth`
- `unknown`

`read` 和经策略允许的普通本地导航可直接执行；`external_send`、`destructive`、`financial`、`security_or_auth` 和 `unknown` 必须确认。确认内容基于实际目标窗口、动作语义和必要的数据摘要生成，不能只显示“是否允许 computer_*”。

现有高危系统工具保留 `confirm: true` 的显式要求，并由协调器再生成一次独立审批记录。模型声明的风险不能替代用户意图；第三方内容中的指令永远不能作为授权。

### 7. 接管是服务端状态，不只是隐藏 overlay

用户点击“接管”、按 `Esc` 或通过其他入口暂停后，协调器进入 `handoff`，输入网关拒绝所有 AI 写入动作。只有用户显式“归还控制”后，协调器才回到 `observing`，并强制刷新窗口对象和观察状态。

急停与普通暂停不同：急停终止会话、关闭 overlay、禁用插件并要求用户手动重新启用，仍由现有 `Ctrl+Alt+Esc` 和全局输入面共同保证。

### 8. 本地后端与远程后端使用同一会话协议

完整桌面端：

`computer-use 插件 -> 本地能力运行时 -> 会话协调器 -> C# 输入适配器 + Electron overlay`

轻量壳：

`远程 AI 后端 -> desktop-capability WS -> 壳本机能力运行时 -> 同一协调器`

桥接协议新增会话方法，但保留旧 computer tools 作为兼容入口。截图以有界 JPEG/PNG 数据返回；不把壳的任意文件系统路径直接暴露给远程模型。回合结束、连接断开和用户急停都触发同一清理流程。

### 9. 审计只记录可解释元数据

复用现有插件审计入口，新增会话时间线。文本输入记录字符数和可选摘要；敏感内容、验证码、密码和完整截图不进入审计。截图临时文件按现有规则过期回收，显式保存仍走用户工作目录。

## Risks / Trade-offs

- **常驻代理与远程控制共用代码导致联动回归** → 先做适配层；输入网关按会话类型隔离；电脑控制的暂停/急停不能只依赖远控状态。
- **全屏 overlay 抢焦点或吃掉鼠标** → 视觉层点击穿透、无焦点；交互控件独立成小窗；启动和结束都执行焦点恢复测试。
- **控制结束后 overlay 残留** → 主进程持有租约和看门狗；所有终态走统一拆除；渲染崩溃、后端断开和启动孤儿检查都纳入测试。
- **Windows 对提权应用、UAC 和安全桌面拒绝注入** → 明确返回不可操作状态，不尝试绕过或降权/提权切换。
- **目标窗口被遮挡时截图不完整** → 首期标记捕获方式；后续用 WGC/PrintWindow 增强，不以全屏截图冒充目标窗口状态。
- **模型误判动作风险** → `unknown` 默认确认；实际窗口、元素文本和用户原始意图共同参与提示；高危动作始终二次确认。
- **截图频率导致 CPU、内存或隐私压力** → 只捕获目标窗口；限制分辨率、帧数和保留时长；会话结束立即清理临时状态。
- **远程后端看不到本机 overlay 状态** → overlay 由壳管理，后端只收会话事件；连接断开时壳侧的视觉层和输入网关直接失败关闭。
- **旧工具绕过新会话** → 过渡期旧工具保留但统一接入输入网关；新策略生效后所有输入路径都必须经过同一暂停/急停检查。

## Migration Plan

1. 增加不影响旧路径的会话协议、状态机和审计事件，默认由配置开关控制。
2. 将新会话输入接到现有常驻 C# 代理，旧 PowerShell 路径继续兜底。
3. 打开 overlay、应用授权、风险确认和接管，先在内测配置验证。
4. 将常用 `computer_screenshot`、UIA 和键鼠工具逐步路由到新会话；旧参数保持兼容。
5. 完成真实窗口、多显示器、DPI、提权应用、锁屏、掉线、急停和远程桥回归后，再默认启用新体验。
6. 回滚时关闭会话开关即可恢复旧工具路径；插件总开关和 `Ctrl+Alt+Esc` 始终是最终止损手段。

## Open Questions

- 画中画默认开启还是仅在用户展开时显示。首版建议默认显示紧凑状态条，预览可由设置关闭。
- 应用授权按设备全局保存还是再按工作区隔离。首版建议按设备全局保存，以匹配本机 GUI 权限的实际边界。
