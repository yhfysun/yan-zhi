## 已由我决定、尚未经你确认（第三批实施前需拍板）

### D1. 运行面板的覆盖面：所有模式都有对话栏，不按 lead 切换
proposal 第 3 节写的是「AI 模式对话居中 / 运行模式对话在右」，字面读起来像**切换 lead 会换布局**。
实际实现：`WorkflowWorkbench.vue` 是固定三栏（左列表+历史 / 中运行台 / 右对话），lead 只改宽度与顺序，
**两种形态都能对话、都能运行**，不做互斥切换。

- 为什么这么改：你最初的诉求是「手动运行 + AI 模式两个模式」。但工作流这两件事共享同一个产物与上下文，
  做成互斥会让「手动跑完想接着问一句」必须切形态；而 four-mode 的契约又是「共享上下文」。
- 需要你确认的：**接受现在的三栏常驻，还是严格按 proposal 做成互斥两态？**
- 影响面：改法不难（v-show 切换 + lead 驱动显隐），但会改变交互心智。

### D2. 选择工作流的入口放在左栏列表，没做「输入框内选子智能体」
proposal 5.8 写的是「`WorkflowPicker.vue`：输入框里勾选可用工作流 → 写入会话 builtin_tool_ids」。
第三批会做，但**位置**我倾向放在**输入框的「+」菜单里**（与技能/工具挂载一致），而不是独立浮层。

### D3. 手动运行不落产物（第三批修，但方案有两种做法待选）
design 决策 8 给了二选一，我没敢自己定：
- A：`conversation_file.conversation_id` 允许写 runId（复用一张表，查询侧要全部过滤）
- B：新增 `run_artifact(run_id, path, ...)` 表（干净，但多一套表 + 多一套读取通道）
- **需要你先定 A/B**，再动手（影响文件管理弹窗的「已交付」段是否会出现无主会话的产物）。

### D4. 单节点调试的快照存内存、不落库（30 分钟后失效）
好处：零迁移、零清理负担。代价：**刷新页面或重启后端后，调试会话就没了，要重新「运行到此节点」**。
如果你希望调试会话能跨重启续用，需要给 `workflow_run` 加 `snapshots_json` 列（增量迁移）。

### D5. 定时任务是否复用「运行历史」的展示
`task_type='workflow'` 的执行结果目前计划回写到绑定会话（与 call_agent 委派一致）。
**没有**计划把定时触发的运行单独做成一个「调度记录」页 —— 会复用现有运行历史列表。

## 我按项目惯例自行决定、风险较低（如不认同可推翻）

- 新增模式不填 `pluginId` → 非 desktopOnly，三端可用（工作流能力不依赖桌面能力）。
- `wf` 场景 `agentId` 沿用 `a_default_assistant`（不新建智能体），第三批换成 `a_builtin_workflow_assistant`。
- `DEFAULT_OVERRIDABLE` 只放行 llm 采样参数 / loop 上限 / memory topK；改代码逻辑类字段（code.expression 等）不放行。
- 取消是**协作式**（节点间生效，不掐断进行中的 LLM 请求），运行历史里落 `aborted` 而非 `failed`。
- 调试快照与 `aborted`/`paused` 运行随 30 分钟生命周期清理；重启回收 `running + paused`。
