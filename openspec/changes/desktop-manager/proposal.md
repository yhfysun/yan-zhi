# 提案：桌面管理插件（文件整理 + 图标围栏 + 悬浮组件）

> 用户原话（2026-10-26）：「加个桌面管理插件？就像腾讯的桌面管家一样」「图标围栏也要做的」「我要能看到整理前后效果」
> **修订（同日）**：「注意这个也是个插件，可以打包的时候不带，然后在加载」—— 交付形态改为**可后装的独立插件**。

## 交付形态（本次修订的核心）

| 项 | 决定 |
|---|---|
| 是否随安装包发布 | **不随包**。不加进 `build/plugins.catalog.json`，安装包里没有这个插件 |
| 分发方式 | `.yzp` 包，走既有 `/api/plugins/install` → `plugins/installed/desktop-manager/` |
| 装载方式 | 与内置插件同一形态（backend/index.js + frontend bundle 经 `yz://plugin/<id>/` 运行时装载），不重启重打包 |
| 兼容门禁 | manifest `engine` 声明最低宿主版本（依赖新增的桌面窗口 API），不满足则安装时拒绝 |
| 卸载 | 插件卸载时负责恢复桌面图标（见 §风险），不留系统残留 |

因此**基座只增加通用能力，不增加任何桌面整理业务代码**。

## 问题

Windows 桌面是用户最常用的临时工作台，也是最快失控的地方。现有产品（腾讯桌面整理、猎豹轻桌面、Stardock Fences）把这件事做成独立软件，和智能体工作流割裂。

本仓已有：完整插件体系（manifest + contributes + 权限档 + .yzp 安装）、插件前端运行时装载、`electronAPI` 透传、C# Win32 助手运行时编译通道、透明/穿透/多显示器窗口实践。缺的是**给插件用的桌面层窗口能力**。

## 目标

1. **智能体能整理桌面**：扫描 → 方案 → 确认 → 执行 → 整批回滚。只移不删。
   **两种整理策略并存**：**规则模式**（纯确定性，不调用大模型，离线可用，默认）与 **AI 模式**（模型只处理规则定不了的文件与组命名，失败自动回落规则）。
2. **图标围栏（P0）**：接管桌面图标显示，按围栏分组排布，拖拽调整，双击照常启动。
3. **悬浮组件**：时钟、待办、智能体状态等，两种层级（贴桌面 / 置顶）。
4. **大模型可写**：日常组件写声明式 JSON（沿用 `ydash` 范式）；新组件类型写代码，人工审核后启用。
5. **基座最小侵入**：只新增通用「插件桌面窗口 + 桌面外壳」API，任何插件都能用。

## 非目标

- 不做开始菜单/任务栏/资源管理器替换。
- 不整理 Desktop 以外的目录（除插件自建目录）。
- 不接管窗口管理。
- 不做文件内容去重/云同步。
- **不把桌面管理业务塞进基座**（这是本次修订的红线）。

## 关键取舍

| 取舍 | 决定 | 理由 |
|---|---|---|
| 整理策略 | **规则默认 + AI 增强**，两者共用同一套方案/执行/回滚链路 | 规则模式零成本、可复现、可离线；AI 只补规则覆盖不到的边界，不接管全流程 |
| 围栏实现 | 隐藏系统图标 + **插件自绘**网格窗口 | 系统 ListView 只能改坐标，做不出围栏视觉；跨进程改坐标要注入内存 |
| 窗口能力归属 | 基座提供**通用** `pluginWindow`/`desktopShell` API；围栏/组件 UI 全在插件 bundle | 否则插件无法后装；通用能力可被其它插件复用，不是一次性投入 |
| 图标来源 | 插件通过 `desktopShell.fileIcon` 取真实图标，读 Desktop 文件夹 | 与文件系统天然一致，整理后围栏自动同步 |
| 组件渲染 | 全部在插件前端 bundle 内，宿主不注册渲染器 | 插件可后装 → 渲染器不能落在 `packages/ui` |
| 危险操作 | 移动前确认、全程 oplog、一键回滚 | 桌面文件是用户资产 |

## 风险与兜底

- **AI 不可用**（未配模型/超时/输出不合格）→ 自动回落规则模式并在方案页明确标注「AI 不可用，已按规则生成」，绝不静默、也不产出半截方案。
- **隐藏图标是全局态**：插件崩溃/卸载/宿主退出都可能让桌面空着 → 兜底做在**基座**（`desktopShell` 的会话级恢复：宿主退出、插件停用、窗口异常关闭时自动还原），不能只靠插件自觉。
- **老宿主装新插件**：manifest `engine` 门禁 + 安装预览页提示所需宿主要求。
- **钉不到桌面层**：回落普通窗口并明确提示，不静默降级。
- **安全软件敏感行为**：仅用户显式开启执行，全部进插件审计。
