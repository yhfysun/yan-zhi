## Context

当前 `ToolMarket.vue` 是一个 300 行的单体视图，使用 `el-tabs` 切换四个面板（MCP 服务/内置工具/自定义工具/同源商城）。项目的其他类似页面（`Agents.vue`、`Skills.vue`）已经采用了"本地列表 + 远程商城"的双 Tab 模式作为参考。`Mcp.vue` 是独立的 MCP 管理页面，`ToolMarket` 中不应包含重复的 MCP 管理功能。

设计系统方面，项目使用 Element Plus + 自定义玻璃态（glassmorphism）风格，CSS 变量包括 `--glass-bg`、`--glass-border`、`--color-primary` 等。

## Goals / Non-Goals

**Goals:**
- 简化 IA：二区块布局（MCP 概览 + 商城卡片），替代 4-Tab 结构
- 统一商城视觉：商城以卡片形式呈现（本地商城 + 远程商城源）
- 本地商城作为唯一入口管理内置+自定义工具，只有这里能新增自定义工具
- MCP 概览只做轻量展示 + 跳转，不重复实现完整管理
- 保持与 Agents/Skills 页面一致的交互风格

**Non-Goals:**
- 不修改后端 API、数据库 Schema、Store 业务逻辑
- 不修改 `Mcp.vue` 或 `/mcp` 路由
- 不改变现有工具的数据结构
- 不做路由级拆分（不在本次变更中拆为子页面）

## Decisions

### 1. 页面布局：二区块竖排 vs 二栏并排

**选择：二区块竖排布局**（block layout）

- MCP 服务概览区（上方，紧凑卡片列表）
- 商城卡片区（下方，网格卡片布局）

**理由**：两个区块内容量差异大（MCP 概览轻量，商城卡片可能较多），竖排布局更灵活。若使用双栏，MCP 侧空间浪费，商城侧被挤压。

**替代方案**：双栏并排 — 可同时看到两个区域，但浪费空间。

### 2. 本地商城：嵌入页面 vs 展开式抽屉 vs Dialog

**选择：点击本地商城卡片 → 展开 inline 子视图**（类面包屑导航）

用户点击"本地商城"卡片后，页面内切换为本地商城详情视图，展示：
- 内置工具列表（只读卡片）
- 自定义工具列表（可编辑/删除/开关）+ 新增按钮
- 面包屑或返回按钮 → 回到商城卡片网格

**理由**：保持单页体验，避免弹出 Dialog 打断操作流，比 Dialog 更适合内容量大的场景，比子路由更简单。

### 3. 远程商城卡片交互

**选择**：点击远程商城卡片 → 同样展开 inline 子视图展示该远程源的工具列表

与本地商城一致的交互模式，仅隐藏"新增自定义工具"按钮、改为"安装到本地"按钮。

### 4. MCP 概览区设计

**选择**：横向滚动的紧凑卡片行 + "查看全部"链接跳转 `/mcp`

只展示已连接的服务名、工具数、状态指示灯，不包含完整管理功能。每行最多 4 个卡片。

### 5. 复用 Agents/Skills 的参考模式

Agents 和 Skills 页面都使用了 "el-tabs 本地/远程商城"模式。本次重构后的 ToolMarket 将更简洁地统一这一模式——用一个商城卡片网格替代 Tab 切换。

## Risks / Trade-offs

- **[风险] 用户习惯改变**：原有 4 个 Tab 切换被替换为新的导航模式，老用户需要适应。
  → **缓解**：新 IA 更直观，本地商城 + N 个远程源卡片一目了然，学习成本低。

- **[风险] MCP 功能降级感知**：ToolMarket 不再提供完整 MCP 管理，用户需要跳转到 `/mcp`。
  → **缓解**：MCP 概览区提供"管理全部 MCP 服务 →"链接，确保可发现性。已有独立导航项指向 `/mcp`（如果需要的话）或通过 Chat 中的 MCP 挂载功能。

- **[妥协] inline 子视图状态管理**：页面内"子视图切换"需要维护当前选中商城的状态。
  → **缓解**：使用一个 `ref<string | null>` 追踪当前展开的商城 ID（`null` 表示在主网格视图），简单可靠。
