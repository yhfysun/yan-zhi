## Context

当前 Skills.vue 使用 Element Plus 的 `el-tabs` 组件提供 4 个 Tab（商店/远程商城/已安装/自建）来组织内容。页面有超过 500 行代码，包含多个弹窗（新建 Skill/预览/导入/远程源添加），导致单一组件承载过多职责。

路由中已预留 `/skills/:id` 路由（第66行），但目前未用于子页面导航。

约束：
- 保持使用 Element Plus 组件库
- 保持现有的玻璃态（glassmorphism）视觉风格
- 不修改后端 API 接口
- 数据模型（skill store）基本不变

## Goals / Non-Goals

**Goals:**
- 将 Tab 切换改为卡片式商城首页布局
- 本地商城作为默认卡片，点击进入本地商城子页面
- 本地商城子页面：展示内置 Skill + 自定义 Skill，支持新增/编辑/删除自定义 Skill
- 首页展示远程商城卡片，每张卡片对应一个远程源
- 支持新增/删除远程商城卡片
- 远程商城卡片点击进入浏览该源的 Skill 列表
- 保持现有的安装、卸载、启用/禁用等功能

**Non-Goals:**
- 不修改后端 API
- 不修改数据模型
- 不改变 Skill store 的核心逻辑
- 不新增路由（复用现有 `/skills` 和 `/skills/:id`）

## Decisions

### 1. 使用路由参数 `id` 区分首页和子页面

**选择**：复用已有 `/skills/:id` 路由，用 `id` 参数值区分不同商城：

| 路由 | id 值 | 含义 |
|------|-------|------|
| `/skills` | 无 | 商城首页（卡片网格） |
| `/skills/local` | `local` | 本地商城详情 |
| `/skills/remote-{sourceId}` | `remote-{sourceId}` | 远程商城详情 |

**替代方案**：
- 新增多个子路由 — 过度设计，当前不需要
- 用 query 参数 — URL 不语义化

### 2. 单文件组件 vs 拆分子组件

**选择**：拆分为多个子组件，每个子组件独立职责：

| 文件 | 职责 |
|------|------|
| `Skills.vue` | 容器页 — 根据路由参数决定渲染首页或子页面 |
| `components/MarketplaceCards.vue` | 商城首页 — 卡片网格布局 |
| `components/LocalSkillMarket.vue` | 本地商城 — 内置 Skill + 自定义 Skill，新建/编辑/删除 |
| `components/RemoteSkillMarket.vue` | 远程商城 — 浏览远程 Skill 列表，安装到本地 |
| `components/SkillEditor.vue` | 已存在的编辑弹窗逻辑拆出（可选，如果编辑器复杂） |

**替代方案**：
- 保留单文件内 conditionally render — 文件会持续膨胀，不利于维护

### 3. 远程商城卡片 UI

**选择**：每个远程商城源渲染为一张独立卡片，包含：
- 商城名称、URL（截断显示）
- 快捷操作图标：浏览（点击进入）、测试连接、删除
- "添加远程商城"按钮也以卡片形式呈现（虚线边框，带 + 图标）

### 4. 本地商城卡片 — 首页置顶

**选择**：本地商城卡片始终排在第一位，使用视觉差异化（如强调色边框或图标），表示这是默认/自带商城。

### 5. 自定义 Skill 的新建入口

**选择**：新建按钮仅出现在本地商城子页面顶部工具栏。其他远程商城页面不显示新建按钮。

## Risks / Trade-offs

- **组件拆分复杂度**：从 1 个文件到 3-4 个文件，增加了一定复杂度。但每个文件职责单一、行数可控（<300 行），长期维护更友好。
- **路由参数解析**：需要在 Skills.vue 中根据 `id` 参数切换页面视图，边界情况（无效 id）需处理。
- **保持功能完整**：现有的安装/卸载/导入/导出/编辑/预览功能需确保不遗漏。应逐项对照原有代码迁移。
